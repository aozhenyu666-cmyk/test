# 0.25.1 安卓运行验收

工作分支：`codex/yishou-everyday-tools`；[草稿 PR #42](https://github.com/aozhenyu666-cmyk/test/pull/42)。没有合并、发布或更新固定下载地址。正式下载地址可能仍是旧版，请使用本分支构建中的 `yishou-debug-apk`。

## 环境与方法

在 GitHub Actions 的 KVM 模拟器运行 Android 10（API 29）和 Android 14（API 34），安装真实主线 APK、仪器测试 APK，以及独立的外部应用 `com.yishou.gatefixture`。外部应用仅供测试，不打入一手 APK。

文字、识图和语音合成使用模拟器中的本地 MockWebServer，经过真实 HTTP、鉴权、响应解析、ViewModel、Room、Activity 和前台服务。没有读取用户密钥、调用付费模型或联系他人。系统的无障碍、悬浮窗、麦克风前台服务和看屏授权走实际 Android API，没有用假的服务替代。

## 运行中找到并修复的问题

1. 冷启动直接进入分类页时，在导航图建立之前执行跳转会崩溃。现在等待导航入口就绪后再消费待跳转路由。
2. 聊天历史中的失败记录重新打开后未恢复 `error`，无法重试。现在从已保存的错误记录恢复重试状态。
3. ChatClient 使用异步 HTTP 取到响应头后，仍在调用方主线程读普通响应体；HTTP 503 与非流式回退也有同样问题。模拟器捕获 `NetworkOnMainThreadException`，判卷因此失败，看屏整理甚至会崩溃。响应读取和关闭已移到 IO 线程，流式增量仍回到调用方处理。
4. 陪练提前结束后，投屏原本等一分钟巡检才停。现在结束时立即停止看屏服务，释放投屏和镜像资源。
5. Android 10 上移动悬浮窗后，无障碍树仍缓存子节点移动前的坐标。拖动结束现在发出子树更新事件；标题也提供标准点击动作，供无障碍工具展开。

## 验证边界

- 外部应用拦截使用独立测试应用，不等于已经在用户手机上安装 B 站、抖音实测。厂商后台启动限制、保活和撤权行为仍由具体手机决定。
- 本地 HTTP 替身验证接口协议与模块接线，不证明某个真实服务商的密钥、额度、网络或返回质量正常。
- 模拟器验证语音服务、接口音频播放和控制流程；不证明实体麦克风的识别准确率、扬声器回声和嘈杂环境效果。
- 没有把严格模式、反拒绝交流策略或更强的系统限制加入此次改动；这部分按用户要求另行处理。
