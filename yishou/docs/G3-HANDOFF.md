## 接线上的约定

- `Focus.kt`、`judge/`、`thread/`、`reflex/` 没改。`FocusRun` 在原会话外保存包名白名单、通讯包名和提醒进度；`state` 仍是 `StateFlow<FocusSession?>`。
- 名字只用来展示和导入，拦截只认包名。未匹配的名字必须手选或明确去掉。没有猜不到就放行的兜底。
- 系统放行沿用原来的系统界面集合和桌面、输入法、相机、拨号查询。任何时候都能进系统设置关闭无障碍或卸载。
- 专注期间不查收费站通行证，也不沿用伴读的材料应用许可。休息的白名单和工作一致。
- 结束后还能在专注页补记最后一组，账本从同一份历史读取，避免落两份数据。
- 主界面关闭不结束计时；系统强行停止应用、用户关掉无障碍、厂商清理后台不能由应用保证恢复。体检能显示服务是否连接。

## 待确认 / 没有在这里保证的

- 没有准点闹钟授权时用普通闹钟；锁屏省电下提醒可能延后，时间和拦截仍按保存的结束时间判断。界面没有暂停或缩短总时长的入口。
- 通知权限由原权限页申请；没有授权时系统不一定显示提醒。切段声音沿用系统通知音和系统音量，静音、勿扰的表现要实机测。
- “完成几组”只记录用户点击，不验收内容；没有点击的组保持未标记，提醒不会卡住下一组。
- 历史最多 200 场，超过后最旧的专注账也会从每日账读取范围里淘汰。

## 真机要测（未测）

1. 粘贴六行计划，确认应用名字对应正确；未装的应用是否红字，手选后是否能开始。
2. 工作和休息各打开 B 站、抖音；已有收费站放行时也要拦，白名单里的聊天和通讯应用能正常用。
3. 先停在娱乐应用，再从通知或一手开始，切回时是否被拦；系统禁止后台弹窗时是否出现专注遮罩。
4. 一组结束两下震动、一声提示；零休息、换节奏和延长后，下一段的闹钟、通知和页面一致。
5. 提前结束等三分钟；回桌面、切应用、锁屏、返回首页后再进，计时都重新开始。
6. 划掉主界面、锁屏十分钟后返回：场次和拦截继续；进程被系统回收后恢复当前场次；过期重启只归档一次。
7. 到点或提前结束，结束通知显示组数，晚间账本有任务和分钟，最后一组能补记。
