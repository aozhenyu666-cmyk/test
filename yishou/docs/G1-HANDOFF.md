# G1 接线交付

本分支基于 G0 工作树开发，没有合并或发布。范围是任务卡 G1，实际判卷器仍待 C1。

- `judge/Api.kt` 保留任务卡接口；`YishouApp.judge` 当前使用 `FakeJudge`，替换该行即可接 C1。假实现只做连续四字匹配，不具备语义判定可靠性。入口有显式开发提示，不能按正式版验收。
- `ProbeRecorder` 使用注入时钟，入口用单调时钟。轨迹只在本次会话内存中保存，没有新增数据库表。换题/进程退出后轨迹不保留。
- 粘贴位置随着后续插入与删除移动；批量输入使用任务卡中的 8 字/100 毫秒启发式。它无法可靠区分所有粘贴与输入法联想；语音有独立开始事件与文本回填事件，不算启发式粘贴。
- 入口题包必须带答案及【要点】，拆分后要求 2–4 个要点，过线为要点数减一（至少一项）。旧题 JSON 未保存要点时不会自动推断，仍需提供符合格式的题包。题库去重不会自动丰富旧题。
- 入口先显示题面与探针输入；要点通过后只显示选项；选对后走 PassIssuer，选错不放行。耗时仅决定冻结/半截念头提示，不直接签发。
- 同题最多三次要点提交；两题失败或无可用题保留 G0 等待兜底。
- 提交后展示未命中的判据；参考答案在选择后才显示。慢启动的短答案先请求半截念头，即使判卷返回通过也不会立即亮选项。

交接重点：真实语音与输入法组合事件、冻结解除、最多三次、前后台切换、错误重试、题包去重升级与 C1 替换。构建结果以 PR 的 CI 链接为准；没有做真机验收，也没有整合到主线。
