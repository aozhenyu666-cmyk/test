## 产品定位与透明原则

「一手」是用户给自己用的数字健康应用：打开娱乐应用前，先就当前学习任务走一步思考，走得有效就获得一段使用时间。名字取自下棋——对方落子，你应一手。

### 它做三件事

1. 保存一个当前学习任务和它的断点（已知什么、卡在哪、下一问）。
2. 由大模型扮演陪练：每轮给一点分析和一个问题，并判断用户的回答是否算一个有效的思考步骤。
3. 在用户打开自选的娱乐应用时，先显示思考页；回答有效后，在设定时长内不再提示。

### 透明原则（写进代码注释和应用内的“关于”页）

- 仅供用户本人在自己的设备上使用，所有权限由用户在系统设置中手动授予。
- 应用图标、名称正常显示；运行时保持一条常驻通知，写明“一手正在运行”。
- 用户随时可以在系统设置里关闭无障碍服务或卸载应用，本应用不做任何阻止。
- 无障碍服务只读取当前前台应用的包名，不读取屏幕内容、输入内容或其他应用的数据。
- 数据只保存在本机。唯一的网络请求是把用户的任务文本和回答发送到用户自己配置的大模型接口。
- 每日使用总量的限制交给用户另装的「不做手机控」，本应用不重复实现。

## 技术栈与工程约束

| 项 | 选择 |
|---|---|
| 语言与界面 | Kotlin + Jetpack Compose |
| 系统版本 | minSdk 26（Android 8.0），targetSdk 34 |
| 本地存储 | Room（SQLite） |
| 网络 | OkHttp，调用 OpenAI 兼容的 Chat Completions 接口 |
| 密钥保存 | EncryptedSharedPreferences |
| 前台应用识别 | AccessibilityService，只订阅 TYPE_WINDOW_STATE_CHANGED，只读 packageName |
| 思考页显示 | 启动本应用自己的 Activity（FLAG_ACTIVITY_NEW_TASK），不使用悬浮窗权限 |
| 定时任务 | WorkManager（每晚总结）；AlarmManager（陪练窗口开始提醒） |
| 语音 | 系统自带 TextToSpeech 朗读问题；语音输入用系统 SpeechRecognizer，M3 再做 |

### 工程约束

- 单模块工程，结构简单，方便我自己读懂。
- 大模型接口的地址、密钥、模型名都放在设置页，由我自己填写，代码里不写死任何服务商。
- 所有大模型请求设 30 秒超时，失败时按“离线处理”一节执行，不能让界面卡住。
- 代码里不出现与本说明无关的权限申请。

## 数据模型

只有本应用写入数据库。同一时间只有一个“当前任务”。

| 表 | 字段 | 说明 |
|---|---|---|
| Task | id, title（对象）, goal（目标）, material（材料摘录，可空）, isCurrent, createdAt | 学习任务；切换当前任务时旧任务保留 |
| Breakpoint | taskId, known（已知）, stuck（卡点）, nextQuestion（下一问）, updatedAt | 每个任务一条，每轮结束后覆盖更新 |
| Round | id, taskId, source（gate / window）, triggerPackage（可空）, coachMove（陪练的分析与问题）, userAnswer（原话）, effective, moveType, reason, feedback, judged（是否经大模型判定）, createdAt | 每一轮一条，原话原样保存 |
| Pass | id, packageGroup, startAt, endAt, roundId | 一次放行，到期自动失效 |
| DailySummary | date, rule（条件 → 做法 → 预期结果）, tomorrowQuestion, stats（当日轮数、有效数、窗口分钟） | 每晚生成一条 |

moveType 取值：中间结论、比较、预测、反例修正、现实行动、无。

## 核心流程

三个流程共用同一个“一轮”：读断点 → 陪练出一手 → 用户回答 → 判定 → 更新断点、保存 Round。

### 流程 A：入口思考页

1. 无障碍服务收到前台切换事件，读取 packageName。
2. 不在关注列表里：什么都不做。
3. 在关注列表里，且该应用组有未到期的 Pass：什么都不做。
4. 否则启动思考页 Activity，显示当前任务标题、断点里的“下一问”，以及陪练这一轮的一手。
5. 用户输入回答。少于 15 个字时提示“再多写一步”，不发送请求。
6. 发送判定请求（见下一节）。
7. 判定有效：显示反馈，创建 Pass（默认 10 分钟），关闭思考页，回到原应用。
8. 判定无效：显示反馈和理由，用户可以再答一次，或点“回到桌面”。
9. 陪练窗口进行中：思考页不发放 Pass，只显示“窗口进行中”和“回到陪练”按钮。
10. 同一应用组在 Pass 到期后再次打开，重新进入思考页。

### 流程 B：陪练窗口

1. 到设定时间，发出通知“陪练窗口开始”，点开进入窗口页。
2. 窗口页显示倒计时（默认 45 分钟）、当前任务和断点，然后连续进行一轮又一轮。
3. 每轮出题后用 TTS 朗读问题。
4. 用户 3 分钟没有提交：朗读一次“当前卡点 + 一个起手提示”。再过 1 分钟仍无提交，再朗读一次。同一问题最多提醒 2 次，之后只显示“未回应”，不再提醒。
5. 用户可以点三个按钮：“我在想”（重置计时，不提醒）、“我不知道”（请求一个更具体的支架）、“先停”（保存断点后结束本轮，窗口计时继续）。
6. 倒计时结束：显示本窗口的有效轮数，最后一轮的断点自动保存。

### 流程 C：每晚总结

1. 到设定时间，WorkManager 读取当天所有 Round 和当前断点，发送总结请求。
2. 返回“一条规则”和“明天第一问”，存入 DailySummary；“明天第一问”同时写进断点的 nextQuestion。
3. 当天没有任何 Round：不发送请求，只记录“当日无记录”。
4. 总结页有“导出”按钮：生成一段 Markdown（任务、断点、当天原话、规则），通过系统分享面板发给 GPT、Gemini 或 WorkBuddy。

## 离线处理

大模型请求失败或超时，思考页显示“暂时无法判定”。用户可选择“保存并通过”：回答原样保存，judged = false，发放一次 5 分钟 Pass。每天最多 3 次，超过后只能重试或回到桌面。

## 对手的提示词与判定格式

共三种请求。系统提示词放在代码的常量文件里，方便以后修改。所有请求都要求模型只返回 JSON；解析失败时重试一次，仍失败按离线处理。

### 1. 共用系统提示词

```
你是一个学习陪练，像下棋的对手：每次出一手，等对方应一手。
你帮助用户推进他当前的真实学习任务，而不是闲聊。

出一手的规则：
- 先给一项有用的分析或短支架（最多两句），再给一个具体问题。
- 问题要引用断点、材料或用户上一句原话，不要问“你在干嘛”“有没有努力”。
- 按卡点选支架：
  缺因素 → 提示漏掉的一个相关条件，问它如何改变判断；
  缺关系 → 并列两个已知事实，问它们怎样联系；
  缺预测 → 限定一个会变化的条件，问会有什么后果；
  跳步 → 复述前后结论，问中间缺的那一步；
  材料不足 → 指出该去看哪一段，问看到了什么。
- 不夸奖，不说教，不催促。

判定的规则：
有效的一手包括：补出一个有依据的中间结论；比较两项的一个关键差异；提出预测并说明条件；找到反例并修正判断；完成一个现实动作并说明结果。
答错但有推导，算有效，在反馈里纠正。
“收到”“完成了”“我会努力”、只复述问题、只写感受、没有推导的结论，都不算有效。
用户说“不知道”时判为无效，但下一手必须给出更具体的支架。
```

### 2. 开局请求（没有上一轮时）

用户消息包含：任务标题、目标、材料摘录、断点。要求返回：

```json
{
  "coach_move": "分析或支架 + 一个问题",
  "stuck_type": "缺因素 | 缺关系 | 缺预测 | 跳步 | 材料不足"
}
```

### 3. 判定并出下一手

用户消息包含：任务、断点、本轮的 coach_move、用户回答原话。要求返回：

```json
{
  "effective": true,
  "move_type": "中间结论 | 比较 | 预测 | 反例修正 | 现实行动 | 无",
  "reason": "一句话：为什么算或不算",
  "feedback": "对回答的一句具体反馈或纠正",
  "breakpoint": {
    "known": "更新后的已知",
    "stuck": "更新后的卡点",
    "next_question": "下一问"
  },
  "next_coach_move": "下一手：分析或支架 + 一个问题"
}
```

### 4. 每晚总结

用户消息包含：当天全部 Round（原话、判定）和当前断点。要求返回：

```json
{
  "rule": "条件 → 做法 → 预期结果；证据不足时为空字符串",
  "tomorrow_question": "明天第一问，必须引用当天原话",
  "note": "一句话：今天实际推进到了哪里"
}
```

## 设置项

| 设置 | 默认值 | 说明 |
|---|---|---|
| 关注的应用 | 抖音、B站、贴吧、三角洲行动 | 从已安装应用列表里勾选，可分组 |
| 每次放行时长 | 10 分钟 | 按应用组设置，范围 5–30 分钟 |
| 离线放行 | 每次 5 分钟，每天最多 3 次 | 见“离线处理” |
| 陪练窗口时间 | 待填 | 每天一个，时长默认 45 分钟 |
| 无回应提醒 | 3 分钟后第一次，再 1 分钟后第二次 | 同一问题最多 2 次 |
| 每晚总结时间 | 待填 | |
| 接口地址 / 密钥 / 模型名 | 空 | OpenAI 兼容接口，由用户填写 |
| 朗读开关 | 开 | 系统 TTS |

设置页另有“当前任务”编辑区：标题、目标、材料摘录、断点三项，可手动修改，也可以新建任务并切换。

## 里程碑与验收

每个里程碑在真机上验收通过再进入下一个。M1 跑通就已经能用：没有思考页，也可以每天打开应用走几轮。

| 里程碑 | 内容 | 真机验收 |
|---|---|---|
| M1 棋盘与一轮 | 数据库、设置页、当前任务编辑、开局与判定请求、一轮的完整界面 | 填一个真实任务；回答“完成了”被判无效；写一个有推导的回答被判有效；断点更新，重启应用后还在 |
| M2 入口思考页 | 无障碍服务、关注列表、Pass、离线处理、常驻通知 | 打开抖音出现思考页；有效回答后回到抖音，10 分钟内再开不提示；到期再开又出现；断网时可“保存并通过”，第 4 次不行 |
| M3 陪练窗口 | 定时通知、窗口页、TTS 朗读、无回应提醒、三个按钮；窗口内思考页不发 Pass | 窗口开始收到通知；3 分钟不答听到第一次提醒，再 1 分钟第二次，之后不再提醒；窗口中打开抖音只显示“回到陪练” |
| M4 每晚总结与导出 | WorkManager 总结、总结页、导出 Markdown | 到点生成规则和明天第一问；第二天开局的问题就是它；导出能分享到微信或 GPT |

整体验收：打开抖音被拦下，走一手，判定有效，放行；第二天第一次打开思考页时，问题能接上昨天的断点。

## 第一版不做的事

- 不做防卸载、隐藏图标、设备管理员权限或任何阻止用户关闭本应用的功能；这类需求由「不做手机控」承担。
- 不读取屏幕内容、通知内容或其他应用的数据。
- 不做电脑端、云同步、账号系统。
- 不接 MCP、不接其他 AI 应用，只通过导出的 Markdown 手动交接。
- 不做多任务并行，同一时间只有一个当前任务。
- 不做每日总量限制和统计图表。
- 不做语音输入（M3 之后再评估）。
