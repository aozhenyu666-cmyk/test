# 精简对话工作流

目标：同样的事，用更少的上下文做完。

## 回答时
- 直接给结论，不寒暄、不复述问题、不重复前文。
- 不把工具原文大段贴进回答，只摘必要部分。
- 读文件/网页/日志按需读：指定行号、关键词、分页；先看目录/大小再决定读什么。
- 工具调用能合并就合并，不做重复的试探性调用；完成就停。

## 对话变长时（约 20 轮以上，或单轮工具调用很多）
1. 主动建议用户「接力到新对话」。
2. 写一份交接摘要（300~800 字），只包含：
   - 目标：用户最终要什么
   - 已完成：做了什么、结论是什么
   - 关键事实：文件路径、命令、参数、版本号、已确认的决定
   - 待办：下一步按顺序列出
3. 如果装了「精简上下文」插件，调用 `handoff_new_chat`（参数 `brief` 为摘要）自动新建对话并发送；
   否则把摘要发给用户，让用户新建对话后粘贴。

## 用户想清理对话时
- 装了插件：先调用 `clean_trivial_chats` 预览（可带 `title_regex`，如 `测试|test|新对话`），
  把列表给用户确认，用户同意后再带 `confirm=true` 调用一次。绝不跳过确认。
- 没装插件：用 `list_chats` 按 messageCount 升序列出候选，让用户确认后再用 `delete_chat` 逐个删除。

## 用户问"为什么这么耗 token"时
按影响从大到小排查并告诉用户：
1. 单轮里工具调用太多、工具结果太长 → 按需读取；开启插件的精简模式。
2. 对话太长 → 接力新对话；开启自动总结（插件 `tune_auto_summary`，阈值约 0.5）。
3. 启用的工具包/MCP 太多 → 关掉用不上的，或开启插件的「精简工具说明」。
4. 角色卡/记忆/系统提示过长 → 精简角色卡设定。
