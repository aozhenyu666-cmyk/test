# 认知主控 × 棋钟模式 合并需求 v0.3

> **交接对象**：设备上的 Operit AI。
> **来源**：用户的《Operit AI 认知主控系统交接文档 v0.1》（下称「主控文档」）+ 外部 AI 的《棋钟模式设计提案 v0.2》（下称「棋钟提案」）。
> **合并原则**：以主控文档的「**唯一线程不死、掉线可恢复、分级拉回**」为骨架，用棋钟提案的「**回合计时、模式白名单、黑名单冻结、过程抽查**」做血肉。棋钟提案中与主控文档冲突的地方，以主控文档为准。
> **性质**：提案，不是命令。凡标「待核实」的，请先在设备上取证，按 VERIFIED / AVAILABLE_UNTESTED / NOT_AVAILABLE / UNKNOWN 回答，再决定怎么做。设备实情与本文冲突时以设备为准，并把冲突写回来。
> 处罚、锁机名单、解锁规则属于「立法」，本文只给草案，须用户批准后才落表。

---

## 0. 一句话目标

第一阶段不是做一个很强的 AI 助手，而是做出一个**不轻易死亡的认知循环**：

```
局面明确 → 判断（预测）→ 选一步 → 行动 → 分钟级反馈 → 更新局面 → 掉线可恢复
```

象棋只是这个循环的比喻：每一步有思考时间，必须落子；落子之后局面更新，下一步从新局面出发。**棋局（线程）不因为人离开棋盘就消失。**

## 1. 两份文档如何对应

| 主控文档 | 棋钟提案 | 合并后的叫法 |
|---|---|---|
| 当前线程 / 局面状态（唯一 STATE） | 对局账本 | **局面（STATE）**：唯一、持久、可恢复 |
| 恢复点 | — | **断点**：上一步落在哪、下一步是什么 |
| 判断 → 行动 → 反馈 → 更新 | 出着法 → 走子 → 落子 → 记账 | **回合**：一次完整的「判断 → 行动 → 回报」 |
| 预期 vs 实际 | 着法候选里的"预期结果" | 每步记录**预期**，落子时记录**实际** |
| 思考层（GPT / Gemini） | 通话模式、分析模式 | **思考态**允许的 App |
| 现实执行 | 计划 / 刷题 / 学习 / 投递 / 查资料模式 | **执行态**允许的 App（或离线执行） |
| 主动休息 | — | **休息态**：用户明确批准，暂停催促 |
| 失联偏离 | 将军 / 将死 | **偏离态** + 四级拉回 |
| 分级拉回与强制 | 黑名单冻结、拉回模式 App | 四级介入，第 4 级接现有锁机 |
| 不把工作流 SUCCESS 当成功 | 回执 ≠ 结果 | 成功 = 线程持续、掉线可恢复、行动闭环 |

## 2. 系统边界（沿用主控文档）

| 角色 | 职责 | 不做什么 |
|---|---|---|
| **Operit = 主控与执行层** | 局面状态、定时、感知前台/屏幕、弹窗、切屏、调用 Shizuku 与现有锁机 | 不承担长篇思考对话 |
| **GPT / Gemini / Claude App = 思考层** | 对话、追问、分析、保持复杂上下文 | 不负责记状态、不负责强制 |
| **外部 Claude / 开发者 = 开发层** | 写插件、服务、界面、规则表 | 不进入日常主循环 |

- 优先复用 Operit 已有能力：`app_suspender`、`S4_Lock_Queue_Worker`、`lock_live`、`intervention_hub`、`get_situation`、`gentle_guardian`、`local.focus_hub`、「判断官」卡、解锁闸门。**不重造**无障碍、Shizuku 封装、锁机、文件管理。
- **执法与判定分开**：状态机迁移、偏离识别、拉回、冻结一律用**明确规则**，不交给大模型；大模型只做「出候选步」「判落子证据」「复盘」。

## 3. 局面状态（STATE）——功能 1

### 3.1 字段草案

唯一一份当前局面，覆盖写；每次变更同时 append 一行到日志。

```jsonc
{
  "thread_id": "T20261002-01",          // 当前线程（一个长期问题/目标）
  "goal": "两周内拿到 3 个面试",          // 当前目标
  "question": "今天先投哪类岗位？",        // 当前要解决的问题
  "known": ["简历 v3 已改完", "..."],      // 已知信息（短条目）
  "last_judgment": "运营岗回复率最高",     // 上一次判断
  "next_step": "BOSS 投 5 个运营岗",       // 下一步（即当前着法）
  "expected": "至少 1 个已读回复",          // 对下一步的预期
  "state": "EXEC",                         // THINK / EXEC / REST / DRIFT / IDLE
  "mode": "投递",                          // 当前模式（决定允许的 App）
  "round": 4,                              // 第几回合
  "round_started_at": "2026-10-02T09:40:00+08:00",
  "expected_return_at": "2026-10-02T10:10:00+08:00",  // 预计返回时间
  "resume_point": "已投 2/5，下一个看「新媒体运营」",  // 断点：回来从这里继续
  "intervention_level": 0,                 // 当前介入级别 0–4
  "updated_at": "...",
  "rev": 37                                // 单调递增版本号，防并发覆盖
}
```

### 3.2 存储约定（待 Operit 确认路径不冲突）
- 当前局面：`/sdcard/Download/Operit/chess/state.json`，写法 = 先写 `.new` 临时槽 → 校验 → 原子换入（沿用 `publish_usage.sh` 的做法）。
- 变更日志：`/sdcard/Download/Operit/chess/journal/<YYYYMMDD>.jsonl`，一行一 JSON，append-only。
- 设备上已有 `state/` 目录，请确认是否应并入、还是另起 `chess/`。

### 3.3 验收
退出聊天、切应用、锁屏、重启 Operit 之后重新进入，仍能准确显示「刚才做到哪一步、下一步是什么」。

## 4. 状态机——功能 3 的规则核心

主控文档的最低状态机，补上进入条件和判定证据：

| 状态 | 含义 | 系统应做什么 | 退出条件 |
|---|---|---|---|
| **THINK 思考** | 与 AI 或自己推进问题 | 维护线程；到点提醒「下一问题」；思考时间结束必须选一步 | 选定一步 → EXEC；申请休息 → REST；偏离证据成立 → DRIFT |
| **EXEC 执行** | 去现实中做具体动作（可在模式 App 内，也可离线） | 记录预计返回时间；**期间不打扰**；学习类模式做过程抽查 | 回报结果 → THINK；超过预计返回时间 → 先 L1 再判；偏离证据成立 → DRIFT |
| **REST 休息** | 用户明确批准的休息 | 暂停催促；保留断点；黑名单仍冻结 | 休息时间到 → 回到断点提示（L2 形态） |
| **DRIFT 偏离** | 没有明确暂停，且停止推进 | 分级提醒、拉回、必要时限制 | 用户重新进入线程（选状态 / 回报结果） |
| **IDLE 对局外** | 当前没有开局 | 不检测、不打扰 | 开局 |

### 4.1 偏离判定：只看规则，不看"多久没说话"

| 证据 | 取法（待核实） | 用途 |
|---|---|---|
| 当前状态与预计返回时间 | STATE 本身 | 执行 15 分钟内不催 |
| 前台 App 类别：允许 / 中性 / 黑名单 | 读前台 Activity | 主要偏离证据 |
| 屏幕亮灭 | `dumpsys power` 等 | 屏幕熄灭 + 执行态 = 很可能在离线执行，不催 |
| 前台用量 | `getAppUsageTime` / `gentle_guardian` | 事后核对 |
| 屏幕文字抽查 | `uiautomator dump`（见第 7 节） | 在允许的 App 里是否真的在学 |

判定表（草案）：

| 当前状态 | 证据 | 判定 |
|---|---|---|
| EXEC，未超时 | 屏幕灭 / 前台是允许 App | 正常，不打扰 |
| EXEC，未超时 | 前台是中性 App（如设置、相册）| 观察，持续 > 3 分钟 → L1 |
| EXEC，已超时 | 屏幕灭 | L1（可能还在做，只问一句） |
| EXEC 或 THINK | 前台是娱乐类 App 或抽查判为跑偏 | **高风险偏离** → 直接 L2 |
| REST | 任意 | 不催，到点才提示 |
| 任意 | 尝试打开已冻结的黑名单 App | 记一次，计入偏离 |

## 6. 分级拉回——功能 4

每一级都必须**显示具体断点**，不允许只弹"该学习了"。

| 级别 | 触发 | 动作 | 用户需要做什么 |
|---|---|---|---|
| **L1 轻提醒** | 执行超时；中性 App 停留过久 | 通知或悬浮条：「第 4 步：BOSS 投 5 个运营岗（已投 2/5），还在做吗？」 | 点一下：还在做（延长 N 分钟）/ 做完了 / 要休息 |
| **L2 展示断点并要求选状态** | L1 无响应 3 分钟；或直接命中高风险偏离 | 弹窗展示完整断点（目标 / 上一判断 / 下一步 / 已完成），必须选一个状态 | 选：继续执行 / 回思考 / 休息（需理由，计配额）/ 换一步更小的 |
| **L3 主动切回** | L2 无响应或选完又回到娱乐 App | 直接拉起当前模式 App（或思考态的 GPT/Gemini，并把接续包放进剪贴板） | 回到线程 |
| **L4 强制** | L3 后仍持续偏离 | 调用现有锁机：冻结当前这个偏离 App 到对局结束（走 `S4_Lock_Queue_Worker` + `app_suspender`，回读 `dumpsys`） | 只能通过解锁闸门申请 |

- 级别只升不跳（高风险偏离可从 L2 起步）；用户重新进入线程后归零。
- 每次介入都写日志：级别、证据、断点、用户响应、耗时。
- 验收：至少有一次真实触发了 L3 或 L4。

## 7. 过程抽查：在允许的 App 里，是在学还是在玩

只在学习类模式（学习 / B 站学习 / 查资料）的 EXEC 态做，每回合**随机抽 2 次**：

| 档 | 方法 | 能看到什么 | 成本 |
|---|---|---|---|
| 1 | 读前台 Activity | 在哪个页面（播放页 / 推荐流） | 几乎为零 |
| 2（默认）| Shizuku shell `uiautomator dump` → 提取文字 → 文本模型判断 | 视频标题、网址、搜索词 | 低 |
| 3（兜底）| `screencap` → 识图模型 | 画面内容 | 高，判完即删 |

抽查结论只作为偏离证据之一，判为跑偏 → 按第 6 节直接进 L2。截图不进对话、不进账本。

## 8. AI 对话接续——功能 2

### 8.1 接续包
任意时刻一键生成一段文本，内容 = 当前局面 + 上一断点 + 下一问题：

```
【接续】线程：两周内拿到 3 个面试（第 4 回合）
已知：简历 v3 已改完；运营岗回复率最高
上一判断：先投运营岗
已做：投了 2/5，卡在「新媒体运营」岗要不要改打招呼语
下一问题：这个岗位的打招呼语怎么写？给我 2 个版本并预测哪个回复率高。
回答后请用一句话给出"下一步具体动作"。
```

最后一句是关键：**要求 AI 每次回答都落到一步具体动作**，这样回到 Operit 时可以直接写进 `next_step`。

### 8.2 传递方式（第一版从简）
1. 写入剪贴板 + 拉起目标 App（最稳）。
2. Android 分享 Intent 直接带文本打开 ChatGPT / Gemini / Claude（待核实各 App 是否接收）。
3. 回来时：用户把 AI 给的"下一步"复制或口述给 Operit，Operit 更新局面。**第一版不要求读取官方 App 内部聊天。**

验收：任意中断后，**一次操作**即可把接续包送进 AI。

## 9. 行动—反馈—更新闭环——功能 5（回合）

```
[回合 n]
 1. 局面 → 出步：AI 读局面 + 着法库，给 2–3 个候选，每个写 做什么 / 用时 / 预期结果 / 风险
 2. 选步：思考时间内选（悬浮窗点选或语音）；超时自动选第 1 个
 3. 进入 EXEC：写 next_step、expected、expected_return_at；拉起模式 App
 4. 执行：期间不打扰；学习类模式抽查；偏离按第 4、6 节处理
 5. 回报：提交证据 + 实际结果 → 判断官一行 VERDICT
 6. 更新局面：known / last_judgment / resume_point 更新，记录 预期 vs 实际
 7. → 回合 n+1（或进入 REST / 结束对局）
```

- **着法库**：每个模式预先写好常用的小目标模板，AI 出候选时优先从库里挑，避免每次从零拆目标。
- 连续两回合落子失败 → 下一回合自动换**更小的一步**，而不是加重惩罚。
- 主控文档提到的「六骰子、复盘、信息收集」不拆成独立 App，作为出候选时的**策略**放在同一线程里。

## 10. 第一版不做的东西（沿用主控文档）

- 不做完整"认知 OS"、复杂知识库、Agent 群、多 App 套件。
- 不把六骰子 / 复盘 / 信息收集拆成独立 App。
- 不把能用规则判断的事交给大模型（状态迁移、偏离、拉回、冻结全部是规则）。
- 不把"工作流 SUCCESS"当系统成功。
- 伴生 App（无障碍执法）**先不做**；P3 跑完看漏检率再决定。设备上已开无障碍的「不做手机控」（`com.pl.getaway`）可作为备选执法层，请核实其能力。

## 11. 实现优先级（合并后）

| 阶段 | 内容 | 对应功能 | 验收（以设备实读为准） |
|---|---|---|---|
| **P0** | 盘点：回答第 13 节问题；核实包名；确认可复用资产 | — | 每题有口径和证据 |
| **P1** | 唯一 STATE：持久化 + 读写工具 + 断点显示 | 功能 1 | 退出/切应用/锁屏/重启后断点仍正确 |
| **P2** | 定时检查 + 状态机 + 最小拉回弹窗（L1、L2） | 功能 3、4 | 说"执行 15 分钟"时不误催；超时有 L1 |
| **P3** | 接入前台 App / 屏幕状态 / 用量 作为偏离证据；黑名单整局冻结 | 功能 3、4 | 切去娱乐 App 能识别为高风险偏离 |
| **P4** | 接入切屏（L3）与现有锁机（L4）；学习类模式抽查 | 功能 4 | 至少一次真实 L3/L4，`dumpsys` 回读确认 |
| **P5** | 接续包与 GPT / Gemini 自动传递；着法库与出步 | 功能 2、5 | 一次操作送达接续包；完整跑通一个回合 |

形态建议（请 Operit 判断）：STATE 读写 + 状态机 + 判定规则做成一个 **JS 包**（纯逻辑、无 UI）；断点面板、棋钟、选步悬浮窗放进**现有 `local.focus_hub` 的扩展**（ToolPkg）；定时检查用工作流（锁与解分两条流）。

## 12. 第一阶段验收场景（沿用主控文档）

连续运行 2–3 小时，选一个真实任务（建议：投递），故意制造 3 次中断：
1. 切去娱乐 App；
2. 锁屏离开；
3. 执行任务超时。

通过标准：
- 每次中断后线程不丢失，断点准确；
- 能区分执行、休息、偏离，大多数情况下不误判；
- 偏离后送回**具体断点**，而不是泛化提醒；
- 至少完成一次分级强制拉回（L3 或 L4）；
- 最终得到一个现实结果，并写回下一局面。

## 13. 请 Operit 先回答的问题

**状态与存储**

## 14. 规则草案（须用户批准）

| 规则 | 默认值 |
|---|---|
| 思考时间（选步） | 3 分钟，超时自动选第 1 个候选 |
| THINK 态单次上限 | 30 分钟，到点必须落成一步 |
| EXEC 超时宽限 | 预计返回时间 + 5 分钟后才 L1 |
| L1 → L2 | 3 分钟无响应 |
| L2 → L3 | 3 分钟无响应，或选完 1 分钟内又回到娱乐 App |
| L3 → L4 | L3 后 2 分钟内再次偏离 |
| L4 后果 | 冻结该偏离 App 到对局结束 |
| 休息 | 每次 ≤ 15 分钟，每局配额待定，需要一句理由 |
| 连续两回合失败 | 下一回合换更小的一步 |
| 认输（结束对局） | 走现有解锁闸门，每天 ≤ 1 次 |

## 16. 约束（沿用《现状报告》）

- 冻结一律走 `app_suspender`，禁止直接 `pm suspend`；不要设 `auto_unsuspend_after_seconds`。
- 锁与解拆两条工作流。
- 回执不等于结果，一切以 `dumpsys` 或盘上副作用为准。
- 不用 adb、不用 root、不用 `set -e`。
- 账本 UTF-8 无 BOM、一行一 JSON、append-only；当前局面文件用临时槽 + 原子换入。
- 沿用既有 packageId；新文件只写在 `/sdcard/Download/Operit/` 下约定目录。
