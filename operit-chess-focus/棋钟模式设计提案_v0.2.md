# 棋钟模式（Chess-Clock Focus）设计提案 v0.2

> v0.2 变更：用户已确认 GPT = 文字交流分析；黑名单加入浏览器、快手、微博、知乎；新增「B 站学习」模式；新增第 6.5 节「过程抽查：怎么知道是在学还是在玩」。

> 交接对象：设备上的 Operit AI。
> 写作方：外部 AI（未接触设备，只读过《Operit 现状与需求报告》和 Operit 1.12.2 官方源码）。
> 性质：**提案，不是命令**。凡标「待核实」的，请先在设备上取证、按 VERIFIED / AVAILABLE_UNTESTED / NOT_AVAILABLE / UNKNOWN 回答，再决定怎么做。设备上的实际情况与本文冲突时，以设备为准，并把冲突写回来。
> 处罚、锁机名单、解锁规则属于「立法」，本文只给草案，须用户批准后才落表。

## 1. 一句话目标

把一天切成若干「对局」，每局由固定节奏的「回合」组成。每回合先花几分钟选定**一步可验证的小目标（着法）**，再在限定时间内只用**这一模式允许的 App** 把它走完，最后交出证据「落子」。模式之外的干扰 App（抖音、B 站、贴吧、小红书、闲鱼、红果短剧……）在对局期间打不开。

## 2. 象棋概念对照

| 象棋 | 本系统 | 说明 |
|---|---|---|
| 棋盘 | **模式** | 一个模式 = 一个用途 + 一组允许的 App。例如「投递模式」只允许 BOSS 直聘 |
| 对局 | 一个时段（如 09:00–12:00） | 开局时选模式；对局中**只能在回合交界处换模式**，防止靠换模式逃逸 |
| 思考时间 | 回合开头 3 分钟 | AI 给出 2–3 个候选着法和各自的预期结果，用户选一个 |
| 超时 | 3 分钟内没选 | **自动走第一个候选**，不允许"想太久不下" |
| 走子 | 执行时间（按模式 25–45 分钟） | 期间只允许该模式的 App |
| 读秒 | 最后 5 分钟 | 悬浮窗或语音提醒一次 |
| 落子 | 回合结束提交证据 | 截图 / 用量 / SP 任务完成 / 一句话总结，由判断官判 |
| 将军 | 打开了模式外的 App | 先警告，宽限 N 秒后拉回模式 App |
| 将死 | 多次将军或触碰黑名单 | 走现有锁队列冻结该 App |
| 悔棋 / 认输 | 紧急退出 | 走现有解锁闸门（口令 + 冷静期 + 配额 + 审讯），有代价，留记录 |
| 复盘 | 每日 22:30 / 23:10 | 并入现有 LIFE_DailyMeasure / E4_Evolve_Cycle |
| 定式 / 开局库 | **着法库** | 每个模式预先写好常用小目标模板，免去每回合从零拆目标 |

> 「拆目标难」的解法是**着法库 + AI 只出候选、不让用户凭空想**：用户只需要从 3 个里挑 1 个，比自己拆容易得多。

## 5. 一个回合的流程

```
[回合开始]
  ├─ 1. 出着法：AI 读 着法库 + 当前模式 + 今日进度(SP/棋盘) → 给 2–3 个候选
  │        每个候选写：要做什么 / 预计用时 / 完成后得到什么 / 失败风险
  ├─ 2. 选着法：用户 3 分钟内选（语音或点选）；超时自动选第 1 个
  ├─ 3. 布阵：确认黑名单已冻结；拉起模式 App
  ├─ 4. 走子：巡场——前台 App 不在白名单 → 将军(警告) → 宽限 N 秒 → 拉回
  ├─ 5. 读秒：剩 5 分钟提醒一次
  ├─ 6. 落子：提交证据 → 判断官一行 VERDICT
  └─ 7. 记账：append 到 chess/<date>.jsonl → 下一回合
[对局结束] 解冻黑名单（或保持，看规则） → 当日复盘
```

## 6. 架构建议：执法与 AI 分开

整个设计的关键点：**执法必须是确定性的、实时的，不能依赖大模型，也不能依赖 15 分钟一跳、失败率 20–40% 的定时工作流。**

| 层 | 职责 | 是否用 AI | 实时性要求 |
|---|---|---|---|
| 执法层 | 冻结黑名单、检测前台、拉回模式 App | 否 | 秒级 |
| 裁判层 | 出候选着法、判落子证据、复盘 | 是 | 分钟级 |
| 记录层 | 回合账本、对局状态、配额 | 否 | — |

### 路线 A：纯 Operit 实现（先做，成本低）
- **黑名单冻结**：复用 `S4_Lock_Queue_Worker` + `app_suspender`（报告里已经跑通，不新造）。冻结一次，持续整局，所以不需要实时检测就能挡住黑名单。
- **白名单巡场**：这一块 Operit 原生能力最弱。源码核对（见第 7 节）显示 Operit 没有"其他 App 被打开"这种触发器，只能轮询。可选：
  - (a) 工作流定时轮询：最短间隔待核实，且稳定性有问题，不推荐作为主手段；
  - (b) 在 `super_admin:terminal` / Shizuku shell 里跑一个轻量循环，每 2–3 秒读一次前台 Activity。**能否常驻、会不会被杀，待核实**。
- **界面与棋钟**：ToolPkg（需要面板、计时显示、桌面小组件）。**先确认能否扩展现有 `local.focus_hub`（尤其子包 `focus_hub_strict`），而不是新建一个包**。
- **裁判**：复用「判断官」卡（输出格式不变），着法生成新增一张卡或复用「任务服务（PARTNER-1）」。

### 路线 B：伴生 App 负责执法（巡场不可靠时再上）
- 自建一个小 Android App，只做执法：无障碍服务实时感知前台变化 + 悬浮窗遮挡 + 拉回模式 App。**不含任何 AI**。
- 它通过广播通知 Operit（Operit 工作流支持 `intent` 触发器，见第 7 节），Operit 负责出着法、判证据、记账。
- 好处：秒级、不依赖 Operit 常驻；坏处：要用户手动开无障碍权限，vivo 后台保活需要加电池白名单。
- **替代方案**：设备上已装的 `com.pl.getaway`（「不做手机控」）已开着无障碍服务。如果它支持白名单模式和定时，可以直接当执法层，省掉自建 App。**请核实它目前的用途和能力**。

**推荐顺序**：A 的黑名单冻结 + 棋钟 + 裁判先跑起来 → 观察 3 天白名单巡场漏了多少 → 再决定是否上 B。

## 6.5 过程抽查：怎么知道是在学还是在玩

用量统计只能证明"百度网盘开了 40 分钟"，证明不了是在看课还是在看电影；B 站、浏览器更是如此。所以学习类模式（学习 / B 站学习 / 查资料）在走子期间加**随机抽查**，从便宜到贵三档：

| 档 | 方法 | 能看到什么 | 成本 | 待核实 |
|---|---|---|---|---|
| 1 | 读前台 Activity（`dumpsys activity activities` 中的 resumed 项） | 在哪个 App、哪个页面（如播放页 / 首页 / 推荐流） | 几乎为零 | 各 App 页面类名是否有区分度 |
| 2 | **读屏幕文字**：Shizuku shell 执行 `uiautomator dump` 得到界面 XML，提取文字后交给文本模型判断 | 视频标题、网页地址栏、搜索词、题目文字 | 低（纯文本，无需识图） | shell 能否执行；与 getaway 的无障碍服务是否冲突；耗时 |
| 3 | 截屏：`screencap -p` → 识图模型（当前绑定 `glm-5.3-flash`）判断 | 画面内容（对付视频这类文字少的界面） | 高（识图 token、隐私） | shell 能否截屏；图片存放位置与清理 |

建议：
- **默认用档 2**（读文字比截图便宜得多，视频标题和网址通常就够判断）；档 2 拿不到有效文字时才升级到档 3。
- 每个回合**随机抽 2 次**，不要固定间隔（固定间隔可以被"卡点"）。
- 判断交给「判断官」，输入只放：模式、本回合着法、抽到的文字或图片结论。输出仍是一行 `VERDICT=...`。判"跑偏"算一次将军。
- 截图只在内存或临时目录里短暂存在，判完即删，不进对话、不进账本；账本只记结论和文字摘要。
- 抽查不是新的"惩罚"，只是给落子判定提供过程证据，跑偏的后果仍按第 9 节规则走。

## 9. 规则草案（须用户批准）

| 规则 | 草案默认值 |
|---|---|
| 思考时间 | 3 分钟，超时自动选第 1 个候选 |
| 将军宽限 | 15 秒 |
| 将死条件 | 同一回合将军 3 次，或尝试打开黑名单 App |
| 将死后果 | 本回合记负；该 App 冻结到对局结束 |
| 落子失败（无证据或判不通过） | 记负；下一回合着法自动缩小一档（更小的目标） |
| 认输 | 走现有解锁闸门；每天最多 1 次；记账 |
| 换模式 | 只能在回合交界 |

> 设计原则：**连败时把目标缩小，而不是加重处罚**。目的是让人一直能"下出一步"，避免整个系统因为太苛刻而被弃用。

## 11. 约束（沿用《现状报告》4.1 / 4.3）

- 冻结一律走 `app_suspender`，禁止直接 `pm suspend`；不要设 `auto_unsuspend_after_seconds`。
- 锁与解必须拆两条工作流（同一流双触发会并发执行）。
- 回执不等于结果：一切以 `dumpsys` 或盘上副作用为准。
- 不用 adb、不用 root、不用 `set -e`。
- 账本 UTF-8 无 BOM、一行一 JSON、append-only。
- 沿用既有 packageId；新文件只写在 `/sdcard/Download/Operit/` 下约定目录。
