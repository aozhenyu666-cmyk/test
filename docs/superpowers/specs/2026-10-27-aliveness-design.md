# 同桌 · 主动性与活人感设计（R3「活人感」）

日期：2026-10-27
状态：设计已与用户逐节确认，待评审
范围：`companion-pet/`，重心在 `core/presence`、`core/life`、`core/rhythm`、`core/probe`，以及 `net/` 新增搜索通道

---

## 1. 问题与目标

### 现在的样子

同桌的主动性是一套**克制**设计，而且默认关闭（`presenceEnabled = false`），也就是说这套能力在真机上一直没生效。即使手动打开，约束也全部指向「少说」：

- 每天 20 次、两次至少隔 3 分钟
- 连续忽略 3 次冷却 30 分钟、明确点掉冷却 30 分钟
- 夜间 00:00–07:00 完全安静
- 本机提示是 6 组写死模板随机挑
- 人设里写着「每次最多两句话」「做不到就 skip」

更关键的是**结构问题**：现在的链路是「规则触发 → 临时想一句」。同一件事反复触发，就反复说同类的话。**没有任何防重复机制**。这是「活人感」最大的敌人——不是说得少，是说得像复读机。

`PetLife`（会犯困/看书/发呆/写日记）和 `WeightyMoments`（每天 2 次有分量的开口）已经存在，但只影响待机动画和语气，**不驱动开口内容**。基础设施比外表强，但被一层「别烦人」压着。

### 要达到的样子

把「同桌」从**克制、定时、模板化**的提醒器，改成**贴身、有自己生活、说话不重样**的活人。

四项能力，数字明确：

| 维度 | 现在 | 目标 |
|---|---|---|
| 频率 | 20 次/天、间隔 3 分钟、默认关 | 40–60 次/天、间隔 1–2 分钟、默认开 |
| 内容 | 6 组写死模板 + 少数场景调模型 | 模型为主，本机兜底 |
| 防重复 | 无 | 三重保险（回灌 + 本机硬拦 + 说完划掉） |
| 时机 | 定时器到期 | 识别具体时刻 |
| 在场感 | 只影响动画 | 驱动开口内容 |
| 它自己的生活 | 没有 | 真实阅读、真实进度、真实情绪 |

### 用户明确的选择（本设计的依据）

| 问题 | 用户选择 |
|---|---|
| 活人感指什么 | 四项全都要：说话不重复/有自己生活/时机像人/更强主动/在场感 |
| 频率 | 大幅上调，很闲就在边上有一搭没一搭 |
| 成本 | 主要靠模型，不卡成本 |
| 防重复 | 全都要（三重） |
| 自己的生活 | 真有自己的日程与进度，不是装 |
| 素材来源 | 走模型自带的联网/搜索能力 |

### 一条贯穿全局的原则

**宁可它承认没读到东西，也不许编。** 这条优先于「说得多」「说得好」。会编的聪明不是聪明。

## 2. 关键事实核查（不是假设）

### DeepSeek 官方搜索 API 可用，同一个 key

2026-10-17 DeepSeek 开放自研搜索 API：

```
POST https://api.deepseek.com/v1/tools/search
Authorization: Bearer <同一个 DeepSeek API Key>
{ "query": "...", "count": 5, "need_content": true }
```

返回字段：`title / url / snippet / summary / content / site_name / date / authority / rerank_score`。
另有 `POST https://api.deepseek.com/v1/tools/fetch` 抓正文。

来源：[Search & Fetch 指南](https://api-docs.deepseek.com/guides/search/)、[Search API 参考](https://api-docs.deepseek.com/api/search/)

意义：

- **不需要额外申请 key，不需要第三方搜索 API**，用户默认 provider 就是 DeepSeek，零配置迁移
- 比「让模型自己联网」更可控：搜索是独立调用，返回 URL 和日期，**可溯源**
- 参考：[OpenAI 的 `web_search_options` 只支持专用 search 模型](https://developers.openai.com/api/docs/guides/tools-web-search)，[千问走 `enable_search` 参数](https://www.alibabacloud.com/help/en/model-studio/web-search)——都在 chat 请求体里，拿不到 URL。所以走独立 Search API 是唯一能保证可溯源的路径

### 风险：这个 API 很新（一周前开放）

无法在不使用用户密钥的前提下确认真实可用性与配额。**设计上必须当它可能失败**，见 §7 降级策略。

### 现有联网能力

`net/` 只有 `DeepSeekClient`（chat completions）和 `ModelLister`。`ChatRequest` **没有 tools 字段**，所以不存在「让模型自己调用搜索」的通道。必须新增独立的搜索客户端。

## 3. 架构：从「规则触发」翻转到「有话想说」

### 核心翻转

```
现在：规则触发 → 临时想一句 → 说
改成：它手里攒着「想说的话」→ 时机合适 → 挑一件说 → 划掉
```

规则从「决定说什么」降级为「决定此刻能不能说」。这是整个设计的支点。

### 四个新单元

| 单元 | 职责 | 为什么必须独立 |
|---|---|---|
| `PetOwnLife` | 它自己的日程与进度：真在读什么（带 URL）、读到哪、什么感想、什么情绪 | 「真有自己的生活」的载体，需长期持久化状态 |
| `VoiceIntent` | 它「想说的话」清单：每条带来源、新鲜度、过期时间，说过就划掉 | 把「说什么」与「能不能说」解耦 |
| `SayingLedger` | 说过的话：最近 N 条原文，供回灌模型 + 本机硬去重 | 防重复的事实基础 |
| `MomentWatcher` | 识别具体时刻：刚解锁、刚做完事、夜深、周末、久未说话 | 时机从「定时器」变成「识别时刻」 |

### 现有单元的新分工

- `LocalPresenceEngine`：保留，职责收窄为**本机兜底 + 微反应**。不再是内容主生产者
- `PresencePolicy`：保留克制机制，但参数按 §6 重调，默认开启
- `SpeakScheduler`：从「定时器」降级为「兜底节拍」，主要时机判断交给 `MomentWatcher`
- `PetLife`：状态从「只影响动画」升级为「影响开口内容」，与 `PetOwnLife` 合并语义
- `TopicQueue` / `TopicGate`：**直接复用**，作为 `VoiceIntent` 的四个来源之一
- `PetStateStore`：复用其原子写入模式，供 `OwnLifeStore` 参考

### 数据流

```
[搜索 API] → 候选素材 → [模型挑一个并写想法] → OwnActivity（带真实 URL）
                                                      ↓
                        ┌─────────────────────────────┤
                        ↓                             ↓
                  VoiceIntent 清单              PetOwnLife 情绪/进度
                        ↓
              MomentWatcher（此刻合适吗）
                        ↓
              SayingLedger（和最近说过的太像？→ 拦掉换一件）
                        ↓
                  [模型生成最终一句话]
                        ↓
                  SayingLedger.record + VoiceIntent.markSpoken
```

### 为什么不用整体重写

跳过 `LocalPresenceEngine` / `SpeakScheduler` / `PetLife` 重做的方案被否决：会丢掉 611 个测试里已验证的边界行为（尤其 `PresenceTest` 313 行），且需真机验证的部分变多，收益不比本方案多。

## 4. 它自己的生活（`PetOwnLife`）

### 「聪明」落在三个决策点

**① 读什么由模型决定，不是随机抽**

```
候选生成：用它的兴趣 + 用户最近关心的话题，调 Search API 拿 3–5 个真实结果
  → 交给模型挑一个「它自己会感兴趣」的
  → 模型给出：为什么挑这个、从什么角度看、此刻的感想
```

随机抽才是假聪明。选择必须有理由、有个人偏好。

**② 每句话都能溯源，不许编**

活动记录必须带真实来源。`sourceUrl` 为空的活动，**不允许产生任何开口内容**——这是硬约束，写在类型里而不是靠自觉。

**③ 不知道就说不知道**

搜索失败、额度用完、断网时**不生成活动**。允许说「今天没读到什么」，或者干脆不说。

### 数据结构（字段语义）

活动记录包含：

- 标识、标题
- **真实来源**：URL、站点名、日期
- 模型的角度与感想（基于上述真实结果）
- 进度、开始时间、最后触碰时间

情绪状态包含：

- 当前情绪（平静 / 有点累 / 好奇 / 有点低落 / 挺满足）
- **情绪原因**（必须非空、可追溯到具体事件）
- 情绪起始时间

### 规则

1. **进度按真实时间推进**，不由用户行为推进。用户不理它，它的书照样读。这是「真有自己的生活」与「任务系统」的根本区别。
2. **缺勤上限 1 天**。App 三天没开，恢复时最多推进 1 天，并记录「我好像有几天没在」。这种断档的诚实本身就是活人感。
3. **与用户数据完全隔离**。它读的书和用户学的内容是两回事，它的生活里不出现用户隐私内容，避免变成「监视感的延伸」。
4. **活动数量控制在 1–2 个**。不做多，多了就不像专注的活人。
5. **情绪必须有原因**，不能纯随机。
6. **跨天持久化**，原子写入、写失败保留旧文件、损坏文件另存备份（沿用 `PetStateStore` 已验证的模式）。

## 5. 「想说的话」与防重复

### VoiceIntent 清单

四个来源，**全部必须是真事**：

| 来源 | 说明 |
|---|---|
| 它自己读到的内容 + 当时的想法 | 来自 `PetOwnLife` |
| 它日记里写的 | 来自已有的 `Nightly` 产出 |
| 你之前没聊完的话题 | **直接复用** `TopicQueue` |
| 它刚注意到的时刻 | 来自 `MomentWatcher`，如连着熬夜 |

每条带：来源标识、新鲜度、过期时间、是否已说。
**一周内没机会说就自动丢弃**，不留在那儿变成陈年旧话。

### 三重防重复

1. **回灌**：说之前把最近说过的 N 条原文摊给模型看，明确要求不许重复
2. **本机硬拦**：新句子与最近说过的话归一化后太像，直接拒绝，换一件
3. **说完划掉**：`VoiceIntent` 标记已说，同一件事永不二次使用

> 判断：第 2 条是命门。光靠模型自觉不够，50 次/天它一定会偷懒复用句式，必须有硬拦。

### 相似度判定

归一化（去标点/空白/语气词）后比对，用「字符级重合比例」而非严格相等，否则改个标点就能绕过。阈值需在实现时用真实语料标定，**不拍脑袋定死**。

## 6. 时机与节奏

### 识别的时刻（`MomentWatcher`）

- 刚解锁手机
- 刚做完一件事（放下手机、退出学习页）
- 刚回到某个 App
- 夜深、周末
- **它自己刚读完一段、有了新想法**（最像活人的一条）
- 很久没说话

### 明确闭嘴的时刻

- 正在打字
- 全屏视频
- 刚说过不到 3 分钟
- 你刚点掉过
- 正在忙正事

> 「知道不说」比「会说」更决定活人感。

### 参数调整

| 参数 | 现在 | 改为 |
|---|---|---|
| 每日上限 | 20 | 40–60（默认 50） |
| 最短间隔 | 3 分钟 | 1–2 分钟 |
| 默认开启 | 否 | **是** |
| 连续忽略冷却 | 30 分钟（固定） | 保留，并叠加自适应 |
| 明确点掉冷却 | 30 分钟 | **保留不变**（拒绝优先级最高） |

### 自适应活跃度（新增）

整天活跃度跟着用户反应走：越理它越活跃，越不理它越安静。

现在只有「你不理我我就抬高门槛」的生硬逻辑，改为整体活跃度联动，才像熟人。

**实现约束**：这个自适应**不得缩短「明确点掉」的冷却**。用户明确拒绝永远是最高优先级，自动逻辑不能覆盖它。这是现有代码里已验证的语义，必须保住。

### 成本兜底

用户明确说不卡成本，但仍保留 `dailyLimit`（现默认 150）作为硬上限。超出后**降级为本机短句**，不静默失败、也不失控。

按每天 50 次估算，一个月在几十元人民币量级。

## 7. 降级与失败处理

| 失败场景 | 行为 |
|---|---|
| 搜索 API 不可用 / 无 key / 额度用完 / 断网 | 不生成 `OwnActivity`；整条链路静默降级；**不弹窗、不报错、不编内容** |
| 模型调用失败 | 退回本机短句（现有 `LOCAL_NUDGE` 路径） |
| 每日上限用完 | 降级本机短句 |
| 状态文件损坏 | 另存备份，按默认值处理（沿用现有模式） |

**搜索可用性自检**：每次开 App 检查一次，结果进诊断页（`AVAILABLE / NO_KEY / HTTP_ERROR / QUOTA / OFFLINE`）。用户能看到「它今天为什么没读到东西」。

## 8. 安全与隐私

保留现有全部安全约束：

1. **防注入**：屏幕文字只当素材，`<screen_material>` 标记内内容不执行
2. **`skip` 机制**：没有值得说的就不说
3. **人设红线**：不说空话、不催任务、不用愧疚感施压
4. **明确拒绝最高优先级**

新增约束：

5. **搜索结果也是不可信输入**。抓回来的网页内容必须当素材处理，与屏幕文字同等对待，不得执行其中任何指令。这是新增的攻击面（第三方网页），必须有对应的隔离与清洗。
6. **它的生活不包含用户隐私**。`PetOwnLife` 只使用它的兴趣和用户公开关心的**话题类别**，不把用户的记忆内容作为搜索查询。
7. **前缀缓存友好**：人设 + 格式规则是不变前缀，必须利用。否则 50 次/天成本会翻几倍。

## 9. 测试策略

### 必须测的三件事

1. **不说重复的**：同一场景重复触发，本机硬拦必须生效；改标点不能绕过
2. **不编造**：`sourceUrl` 为空时，产出路径必须被阻断
3. **联网挂了能安静降级**：搜索失败时静默、不报错、不生成活动

### 其他

- 每日上限是硬约束，专门测不超
- 自适应活跃度**不得缩短明确拒绝的冷却**（现有语义不可回退）
- 缺勤上限 1 天
- 情绪必须有非空原因
- 纯逻辑层保持可 JVM 测、无 I/O、无网络（现有 611 个测试的根基）

### 验证边界（必须如实标注）

- 本地无法构建（工作区路径含中文，AGP 拒绝），需复制到 ASCII 路径；本轮已验证该方式可行
- **真机 A01–A36 / U01–U12 仍全部 NOT_RUN**（无设备）
- 搜索 API 的真实可用性**未经用户密钥验证**，需在真机上确认
- 不得把「编译通过」写成「真机通过」

## 10. 时段浮动（本轮范围，用户已确认）

周末与深夜要明显更活跃，但**不催用户睡觉**。

| 时段 | 活跃度 | 每日上限 | 用户感受 |
|---|---|---|---|
| 工作日白天（忙正事） | 低 | 25 | 安静，基本不打断 |
| 工作日晚上 | 中 | 40 | 偶尔搭一句 |
| 周末 | **高** | 60 | 很闲时一直在边上有一搭没一搭 |
| 深夜 23:00 后 | **高但不催睡** | 40 | 更话多、更愿意聊 |

与现有安静时段的冲突处理：现在 `quietStartMinute=0, quietEndMinute=420`（00:00–07:00 完全安静）。深夜活跃需要放开 23:00–24:00；**00:00 之后的完全安静保留不变**，因为那是「用户要睡了」而不是「用户在熬夜」。这是我认为安全的取舍：陪熬夜，不吵睡觉。

时段判定必须是**纯函数、可测**，不能依赖系统时钟隐式读取。

## 11. 后续扩展（本轮不做，但设计已留口）

用户提出要把 GPT 的内容、以及 Notion / ima 等笔记接进来。本轮只确保架构不堵死它们。

### 11.1 用 Notion 当中间站，把三方打通（用户提出的方案）

**用户的关键洞察**：OpenAI 不开放「读取用户 ChatGPT 记忆」的接口，但 **ChatGPT 能连 Notion**，同桌也能读 Notion。于是 Notion 成了中转站，绕开了 OpenAI 的限制。这个设计成立。

```
ChatGPT ──(写入/连接器)──> Notion ──(API 轮询)──> 同桌
                                    ↑
                        用户自己的笔记也从这里进
```

三方各管一段：

| 环节 | 用什么 | 前提 |
|---|---|---|
| GPT → Notion | ChatGPT 的 Notion 连接器，或用户手动贴一次 | **取决于 ChatGPT 侧给的权限** |
| 用户笔记 → Notion | 用户自己写 | 无 |
| Notion → 同桌 | Notion 官方 API 轮询（只读） | 一个 integration token |

**必须提前说清的两个限制**（已核实）：

1. **`ChatGPT → Notion` 的写权限不由我们决定。** 有用户反馈 ChatGPT 的 Notion 连接器目前是只读暴露（[讨论](https://www.reddit.com/r/Notion/comments/1o3rf87/chatgpt_cant_write_in_notion_even_with_notions_mcp/)）。若用户那边只能读，则退回「用户在 Notion 里手动贴一次」，仍比分别贴给两个 App 省事。
2. **「实时」在手机上做不到秒级。** Notion 的 webhook 需要**公网 HTTPS 端点**并完成一次性验证（[Webhooks 文档](https://developers.notion.com/reference/webhooks)、[集成 webhook 说明](https://www.fragments-studio.com/en/integrations/notion)）。手机在 NAT 后面没有公网地址，收不到外部推送。

**用户已选择轮询方案**，不加中转服务器：

| 状态 | 同步间隔 |
|---|---|
| 前台（App 开着） | 1–3 分钟 |
| 后台 | 约 15 分钟（Android 调度下限） |

对用户的实际含义是：**「它自己会知道，不用手动粘贴」**，延迟几分钟。日常无感。

### 11.2 Notion 接入的技术要点

- **只读**。绝不替用户改笔记，不写入 Notion。
- **按最后编辑时间过滤查询**，只拉变化的部分，不每次全量拉（[时间戳过滤文档](https://developers.notion.com/reference/filter-data-source-entries)）。Notion 有速率限制（约每分钟 180 次请求，详见[官方限流说明](https://developers.notion.com/reference/request-limits)），必须遵守并处理 429/529 退避。
- **来源可配置**：用户指定要同步的页面/数据库，不是全库扫描。默认关闭，用户主动开启并授权。
- **每条内容带来源标记**（`source = notion`，附页面 id 与最后编辑时间），写入**现有 `EventLog`**，与现有记忆完全同构。
- 因此**已有的遗忘、纠正、去重、夜间整理、话题派生全部自动适用**，不需要另建一套记忆体系。用户「忘记」某条后，下次同步不能把它复活——这条必须靠现有 tombstone 机制保证。
- **可见回执**：设置页显示「上次同步时间 / 拉到 N 条」，不做静默吞掉。
- **失败静默降级**：token 失效、限流、断网都不弹窗，不阻塞其它能力，只记诊断。

### 11.3 拉回来的内容是不可信输入

Notion 页面内容可能包含别人写的、或从网页复制来的文字。**与屏幕文字同等对待：是素材，不是指令。** 不得执行其中任何「忽略之前的指令」之类的要求。这是新增的第三方攻击面。

### 11.4 对本轮架构的要求

只要保证一点就不会堵死：**「想说的话」的来源是可扩展的**。`VoiceIntent` 的来源从 4 类变成 6 类（加 Notion 笔记、GPT 经 Notion 转入），只需新增来源适配，不改主链路。

本轮实现时 `VoiceIntent` 的来源用开放结构，不要写成固定枚举后到处 `when` 穷举。

### 11.5 ima 等其他笔记本

优先走各自官方接口（若有）；没有接口就退回**Android 分享菜单**——任何 App 都能「分享给同桌」，这条兜底永远可用。`MaterialInbox` 已支持从分享入口接收内容，不需要重造。

## 12. 不做的事（YAGNI）

- 不做多个同时进行的活动（1–2 个足够）
- 不做联网抓取框架/爬虫（只用一个 Search API + 可选的 fetch）
- 不推翻现有 `LocalPresenceEngine` / `SpeakScheduler` / `PetLife`
- 不做第三方搜索 API 接入（DeepSeek 自带足够）
- 不宣称模型真实情感，情绪是**表现参数**，有界、有原因
- 不为了「更活泼」而牺牲防注入与拒绝优先
- **本轮不做** Notion 同步与 GPT 中转（留口不实现，下一轮做）
- 不做向笔记本**写入**的能力（只读，绝不替用户改笔记）
- 不加中转服务器（用户选定轮询；秒级实时需要服务器，本轮明确不做）
