# 先诊断再回答：参谋的“认知主控”

## 要解决的问题

用户一口气说一大段（抱怨、猜测、半成品的想法）时，模型会逐条回应：你说 A 它答 A，你说 B 它答 B。它像在搬运信息，不像在帮你解决问题。

换一个更“自主”的模型（比如 Fable）能缓解一些，但贵，而且换个模型、开个新对话，这种能力就没了。所以这里把它做成插件的一个流程，接什么模型都能用。

## 为什么不是“三个 AI 轮流分析”

另一种方案是：同一个模型扮演侦察者、裁判、主控，连调三次。没有这样做，原因有三个：

1. **同一个模型的三次调用不是三个独立视角。** 第一遍漏掉的变量，第二遍大概率也会漏掉。真正能补上盲区的是**不同的信息**，不是同一个模型多说几遍。
2. **手机上每多一次调用，就要多等几秒到十几秒。** 一句话要等三轮，很快就不会再用了。
3. **“相亲博主”式的一针见血，主要靠信息，不靠智商。** 他们能抓住矛盾点，一是见过足够多的同类案例，二是记得当事人之前说过什么，三是会先问清事实再下结论。单次对话的模型一样都没有，Fable 也没有。

所以这里只多一次调用，把力气花在**喂给它的材料**上。

## 流程

```
用户发了一条长消息（≥ 60 字）
  ↓
诊断（一次不带工具的调用）。它会拿到：
  · 用户这次说的话 + 前 3 轮说的话 + 参谋上一轮的回复
  · 事实：最近 7 天每天投入多少时间（按目标分）、计划了几项、完成了几项、
          计时中离开去休息了多久、复盘里说卡在哪；各个考试的期限
  · 案卷：偏好、承诺（说过要做的事）、反复出现的说法
  ↓
诊断输出 JSON：
  用户说的问题 / 真正的问题 / 说法和记录的冲突（必须带证据）/
  没检验过的前提 / 还缺的信息 / 动作 / 第一句话
  ↓
动作三选一：
  ask      信息不够 → 这一轮只问一个能区分两种判断的问题，不给方案
  redirect 问错了问题 → 第一句就指出真正的问题
  answer   信息够了 → 直接回答真正的问题
  ↓
主回复（照常带工具），按诊断结论回复，不逐条回应
```

短消息（“明天 3 点提醒我写周报”）不诊断，没有额外等待。设置 → 参谋节奏 → “先诊断再回答”可以关掉。

诊断结论显示为回复上方的一张卡片：标签是动作，标题是“真正的问题”，点开能看到冲突、前提和缺的信息。这样你能看出它是怎么判断的，判断错了也能当场纠正。

## 案卷

`remember` 原来只记偏好。现在分三类：

| 类型 | 什么时候记 | 用来做什么 |
|---|---|---|
| 偏好 | 稳定的习惯、约束 | 排计划时避开 |
| 承诺 | 你说“我要 / 打算 / 从明天起……” | 和实际记录对照，看有没有兑现 |
| 反复 | 同一种抱怨第二次出现 | 识别出“老问题”，不再每次当新问题处理 |

“说的”和“做的”对不上，是诊断能抓到的最有力的矛盾。这些数据（计时、计划完成情况、离开记录）插件本来就在记，以前只是没拿来和你说的话对照。

## 没有更强的模型，怎么判断这套东西有没有用

不要靠感觉，也不需要请一个更强的模型来打分。用你自己的历史当标准答案：

1. 找 5 个过去的问题，**要求是你现在已经知道当时真正卡在哪**。比如当时抱怨的是 A，后来发现其实是 B。
2. 把当时的原话（越原始越好，口水话也保留）分别发给：
   - 普通对话（关掉“先诊断再回答”）
   - 开着诊断的参谋
3. 每次只看第一轮回复，问三个问题：
   - 它有没有指出 B，或者问出一个能引向 B 的问题？
   - 它有没有逐条回应 A 的每个细节？逐条回应算失败。
   - 它说的“冲突”有没有编造证据？编了就是严重失败。
4. 5 个案例里，诊断版比普通版多命中 2 个以上，才算有用。否则就改 `DIAG_PROMPT`，或者干脆关掉。

更长期的标准在插件自己的数据里：开着诊断的这几周，计划完成率和目标投入时间有没有变化。回复写得再像“解惑者”，行为没变就等于没用。

## 已知的限制

- 诊断的质量取决于模型。便宜的模型可能会凑出空泛的“前提”和“冲突”。提示词要求冲突必须引用材料里的证据，但没有代码去核对。
- 事实只覆盖 SP 里有的数据：计时、计划、复盘、离开记录。你在 SP 之外做的事，它看不到。
- 案卷最多保留 40 条，每次对话只带最近 15 条进主回复；诊断时会带上全部。
