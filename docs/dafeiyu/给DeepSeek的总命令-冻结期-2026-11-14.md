## 1. 要做的事（按顺序，一项审查通过再做下一项）

> **2026-11-14 更新**：第一项已由 Claude Code 完成（连同模式发现、模式卡、法典视图、预案日落的第一版），第二项完成一部分。详见《第九轮进度》最后一节。**从第二项剩下的部分接着做。**

### 第一项：行为片段记录（只记录，不改任何行为）——✅ 已完成

越早上线，后面的行为大脑越早有数据。

- 把每次 `/plan` 的手机快照压成**片段**：开始、结束、时长、App、是否娱乐、处境（无局 / 局内哪一局 / 计划模态 / 休息 / 深夜）、前因（刚醒 / 刚收局 / 刚被锁 / 刚被退回）、后果（接着开了局 / 换了个娱乐 App / 被锁 / 破窗）。同一 App 中途离开不到 2 分钟算同一段。
- 每天零点生成**日摘要**：各时段娱乐分钟数、局数、空局数、交付数、敷衍数、切出数、预案触发数、**他自己开的局数**。
- 只记包名和时长，**不记屏幕文字**。
- 测试 ≥ 25 条；用两周模拟快照回放，片段边界和日摘要逐条对得上。

细节见《第九轮补充-行为大脑》K1。

### 第二项：四个数——主动开局比、空局率已在日摘要里；交付率等第三项；局内偏离分钟待做

每天从日摘要算，显示在「计划」页顶部和周报第一行：

| 数 | 算法 |
|---|---|
| 主动开局比 | 他自己开的局 ÷ 系统开的局 |
| 交付率 | 通过验收的局 ÷ 开了的局 |
| 空局率 | 空局 ÷ 开了的局 |
| 局内偏离分钟 | 局内在不允许的 App 里的总分钟 |

测试 ≥ 10 条。

### 第三项：计划页 + 工作包 + 验收前置

这是本期最重要的一项。现在计划只写「10:00–12:00 求职局」，局开了他不知道第一步做什么，触发器问「推到哪了」也问不出东西。

**计划里的每一局都是一个工作包**，前一晚由鲸澜备好，早上计划模态里他确认：

| 字段 | 必填 | 例 |
|---|---|---|
| 目标 | 是 | 投出 3 份简历 |
| 第一步 | 是 | 打开 Boss 直聘，筛选上海后端 1–3 年，看前 10 个 |
| 后续步骤 | 否（≤ 5） | 选 3 个 → 改简历第二段 → 投 → 截图 |
| 必需应用 / 允许应用 | 是 | Boss 直聘；WPS、浏览器 |
| 交付物 | 是 | 3 张投递成功截图 |
| 验收方式 | 是 | 截图时间在开局后、识图读到「已投递」、3 张 |
| 卡住时 | 否 | 20 分钟无进展 → 局官开「卡在哪」小局 |

规则（代码检查）：
- **第一步**：一个 2 分钟内能开始的物理动作；含一个动词、含一个应用或物件、≤ 40 字。
- **缺交付物或验收方式的工作包进不了计划。** 验收方式只有三类，优先前两类：
  - 证据：截图（时间 + 识图）、文件变化、使用时长、外部提交，代码判；
  - 依据：对照答案 / 原文 / 他之前的记录，代码判；
  - 判断：按事先写好的评分标准、引用原文打分，判官模型判。每天最多 2 个。
- **开局一律走** `POST /bouts {action:'open', protocolId, apps, packet}`。`apps` 已经有了，`packet` 是本项新增。计划到点自动开局（`planwire` 的 `startBout(r.start)`）也要把 apps 和工作包带上，**现在没带，这是已知缺口**。
- 局官的触发全部对着工作包问：「第一步做了吗」「在第几步」「交付物有几张了」。
- 计划页：草案的每一局、缺字段的标红不能提交、10 分钟倒计时、鲸澜的说明。

测试 ≥ 45 条（工作包 25、验收前置 20）。

### 第四项：重启协议与挣来的娱乐（替换惩罚性设计）

用户容易逃避。糟糕的一天之后再加码，会把人推向放弃。

- **删掉「次日加码」类规则**：空局导致次日预算减少、E3 导致次日切严格模板。改测试时逐条写「原断言 → 新断言 → 为什么」。
- **重启协议**：任何一天交付率 < 30%，第二天计划模态只要求**一个 15 分钟的最小局**，做成就算回到轨道。原则是「不连着空两天」。
- **娱乐用交付挣**：每通过一个局的验收，记入当天的放风额度（默认每局 15 分钟，进设定页）。当天额度用完前，娱乐在非工作时段不受默认管束。这把体系从「监狱」变成「交换」。
- 当天的 E1 / E2 和 L 系列阶梯照旧，它们管的是当下，不是第二天。

测试 ≥ 20 条。

### 第五项：鱼丸人设与催进度拦截

按《第九轮补充二》§1 做，人设卡用 §1.3 的版本（已改得更顽皮：会骂，骂事不骂人；会冷淡；做成事时会突然软）。

- 鱼丸回复里出现进度类问句（「做到哪」「进度」「计划呢」「该去」「完成了吗」等），重写一次；仍命中就这一轮不发，记 `companion-nag-blocked`。
- 鱼丸的主动发球去掉「进度」类型。
- 鱼丸的情绪由情绪池驱动（第七轮 B4）。骂的底线写进代码检查：不攻击外貌、家人、能力本身。
- 鱼丸可以用 `sister_note` 给鲸澜递「线索」（她看到的现象），每天 ≤ 5 条，进待查队列。

测试 ≥ 20 条。

### 第六项：预案引擎的三处收尾

见《第九轮进度》「没做到的」第 1、2、3 条：
