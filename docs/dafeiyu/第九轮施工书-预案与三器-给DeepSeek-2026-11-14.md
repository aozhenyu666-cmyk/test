## 0. 本轮要交付的东西（用户视角）

1. **一个计划界面**：不管他正在和大鱼、小鱼还是鲸澜说话，她们都会把他带到这个界面定今天的计划。每一局都必须写明**用哪些 App、允许哪些 App**，没写明的局不能提交。
2. **严格模式**：他在局里频繁切出、中途切走时，系统自动进入严格模式。此后**只能使用这一局允许的那几个 App**，其余立即锁，不给宽限。
3. **预案**：系统对一切情况都有预案（什么时候、什么条件、做什么、怎么解除）。预案是数据，AI 能起草、能启用、能收紧，**改动几秒内生效，不用重启 App**。
4. **自建流程**：除了按时间段的大局，还有小局。小局里什么是触发器、发什么消息、怎么验收、跳出什么界面、界面上只能做什么，全部可以配置。他和 AI 说一句，AI 就能搭出一整套流程。
5. **去掉固定锁**：引擎启动不再按内置名单锁 App。锁只来自生效中的预案。
6. **验收是数据**：验收 = 输入方式 + 判定方式。句式框架只是判定方式的一种。规则可以和 AI 商量着改，系统按数据自动优化。
7. **工具层**：Gemini Live 是第一个接入的调度工具，以后的工具按同一接口接入。
8. **哨兵**：一个单独的 App 监督 DSH Go 是否在运行。DSH Go 或引擎掉线时，哨兵接管锁机。

**总原则：高度灵活，但控制力强。** 灵活指规则、流程、验收标准都是数据，能随时改。控制力强指执行全部在代码里，模型只负责起草和少量判定。改紧立即生效，改松有门槛。

## 3. 核心概念：三器 + 预案

```
          ┌──────────── 预案（何时 / 条件 / 动作 / 解除）────────────┐
          │                      全部是数据                          │
 事件 ──→ 调度器：开局、排局、严格模式、锁、开工具（Gemini Live 等）     │
          │                                                          │
          ├──→ 触发器：发什么、从哪发（语音 / 卡片 / 通知 / 工具）        │
          │                                                          │
          └──→ 验收器：收什么（输入方式）、怎么判（判定方式）、不过怎么办  │
                                                                     │
 哨兵（单独 App）：DSH Go 或引擎掉线 → 按最后一份快照接管锁机 ←──────────┘
```

- **调度器**管资源：时间、App、注意力、工具。
- **触发器**管动作：在某一刻给出一个具体指令。
- **验收器**管证据：收什么、怎么判。
- **预案**把三者连起来：事件发生时，按条件决定调度什么、触发什么、要求验收什么。

## 4. A 组：预案引擎（替代固定锁）

### A1 预案的格式

```json
{
  "id": "switch-storm",
  "名称": "局内频繁切出",
  "状态": "生效",
  "何时": { "事件": "切出", "窗口": "10m", "次数": 3, "仅局内": true },
  "条件": { "and": [ { "in": [ { "var": "bout.kind" }, ["题局", "思维局", "学习局"] ] } ] },
  "动作": [
    { "严格模式": { "放行": "本局应用", "直到": "本局结束" } },
    { "说": { "谁": "局官", "话": "十分钟切出三次。只剩本局应用。" } }
  ],
  "解除": ["本局结束", "破窗"],
  "来源": "内置",
  "版本": 1
}
```

| 字段 | 含义 |
|---|---|
| `状态` | `草稿` / `影子` / `生效` / `停用`。**影子**：只记录「如果生效会做什么」，不执行 |
| `何时` | 事件（见 A2）+ 计数窗口 |
| `条件` | JSON Logic 表达式。能读的变量白名单：当前局、时段、今日数据、前台 App、今日已触发预案 |
| `动作` | 动作库里的动作（见 A3），按顺序执行 |
| `解除` | 只能从固定出口里选：本局结束 / 到点 / 答出指令 / 破窗 / 用户确认 |

### A2 事件

切入 App、切出 App、某 App 连续使用达到 N 分钟、今日累计达到 N 分钟、局开始、局结束、拍超时、回答被判敷衍、回答被判混乱、到点（时刻）、亮屏、无局计时到点、产出物提交、验收不过。

### A3 动作库

| 动作 | 效果 | 落到手机 |
|---|---|---|
| `严格模式` | 只放行指定 App（本局应用 / 指定列表），其余立即锁，无宽限 | `session { allow, graceMs: 0 }` |
| `锁` | 锁指定 App 到某时刻 | 已有 block |
| `全机锁` | 只放行局页和紧急应用 | `session { allow: [] }` |
| `开局` | 按协议开一局 | 局引擎 |
| `开工具` | 开 Gemini Live 等工具（见 E 组） | 工具层 |
| `说` | 某个角色用语音或卡片说一句话 | 声音接口 / 卡片 |
| `出卡片` | 弹出一张界面卡片（见 C3） | 卡片渲染器 |
| `进入计划` | 进入计划模态 | 已有 |
| `记账` | 只记一条，什么都不做 | 账本 |

**紧急应用（电话、短信、地图、支付）任何动作都锁不住**，沿用 `NEVER_LOCK`。

### A4 去掉固定锁

1. `DEFAULT_WALL` 的默认锁改成一条内置预案「全天默认锁」，**状态为停用**。
2. 第八轮的 E1–E3、L1–L3 改写成六条内置预案，状态为生效，行为与现在逐条一致（用第八轮的测试证明）。
3. 深夜锁保留为内置预案，状态为生效。
4. 引擎启动时只做一件事：加载所有生效中的预案。**没有预案触发，就没有任何锁。**

### A5 热生效

用户以前遇到的问题：AI 改了设置，要退出 App 重进才生效。本轮的硬要求：

- 预案的任何改动（新建、启用、停用、改阈值），**5 秒内**下发到手机并生效。
- 走现有的 `/plan` 下发通道。改动后立即触发一次下发，不等下一次轮询。
- 测试：改动后 5 秒内，手机侧 `ruleBook` 的快照里能看到新状态（Kotlin 单测 + e2e）。

### A6 每一次锁都能解释

锁屏页和墙界面上，每一个生效中的限制都显示三行：**哪条预案、哪个条件成立了、怎么解除**。他永远不会遇到「不知道为什么被锁」。

**最小交付**
- [ ] 预案格式 + JSON Schema + 加载校验（未知事件、未知动作、条件里出现白名单外变量、解除出口不合法，都拒绝加载）
- [ ] JSON Logic 求值器（白名单运算符，无 eval），测试 ≥ 30 条
- [ ] 事件总线与动作执行，测试 ≥ 40 条
- [ ] 固定锁改为停用预案；E1–E3、L1–L3、深夜锁改为内置预案；**第八轮相关测试一条不改全部通过**
- [ ] 热生效 ≤ 5 秒的测试
- [ ] 锁的三行解释
- [ ] 影子模式：影子预案的「本应执行」记账，面板可查

**超额项**
- [ ] 新预案默认先跑 1 天影子，第二天看数据再生效（他可以跳过）
- [ ] 预案版本历史，一键回到昨天的版本

## 5. B 组：计划界面与严格模式

### B1 计划界面

一个全屏界面，入口：
- **任何角色**（大鱼、小鱼、鲸澜）在当天还没有生效计划时，第一句话就把他引到这里（代码检查：当天无计划时，她们的回复必须附带「去定计划」卡片）。
- 计划模态（第八轮 P1）的所有入口。
- 墙和局的首页顶部。

每一局一行，字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 局名 / 协议 | 是 | |
| 开始 / 时长 | 是 | |
| **必需应用** | 是 | 这一局要用的 App。例：刷题 → 题库 App；学习 → B 站；局本身就在 DSH 里则写 DSH |
| **允许应用** | 是 | 严格模式下放行的 App（默认 = 必需应用 + 词典/计算器这类工具） |
| 产出 | 是 | 收局交什么 |
| 预案强度 | 是 | 宽 / 常 / 严：决定这一局挂哪些预案、阈值多少 |

**任何一局缺必需应用或允许应用，计划不能提交**（代码拒绝，并指出是哪一局）。

AI 预填：按协议类型和历史使用数据给出建议的 App 列表（例：上次学习局实际用了哪些 App）。他只需要确认或改。App 选择器列出已安装应用，并按最近使用排序。

### B2 严格模式

- **进入**：由预案触发（默认：局内 10 分钟切出 3 次；或局内切到非允许应用超过 60 秒）。也可以在计划里把某一局直接设成「全程严格」。
- **规则**：只放行这一局的允许应用 + 紧急应用 + DSH 自身 + 桌面。打开其他任何 App **立即锁**，不给宽限。
- **退出**：只能走预案的解除出口（本局结束 / 破窗）。
- **AI 的权限**：AI 可以随时把一局切进严格模式；**不能**把严格模式提前解除。

**第二期（超额）**：App 内细粒度放行。借 GKD 的规则格式和 Mindful 的思路：允许微信，但拦朋友圈和视频号；允许 B 站，但只放行搜索到的那一个视频页。

**最小交付**
- [ ] 计划界面（全屏）+ 字段校验 + 必需/允许应用必填
- [ ] 三个角色在无计划时引向计划界面（代码检查，测试）
- [ ] 应用选择器 + 按历史预填
- [ ] 严格模式的进入、规则、退出；测试 ≥ 25 条
- [ ] 真机：严格模式下打开非允许 App 立即被锁

## 6. C 组：流程 v2——大局、小局与界面卡片

### C1 流程格式 v2

在 J2 协议 v1 上扩展，**v1 文件不改一个字也能加载**。新增三样：

1. **小局**：一局里可以嵌小局，也可以单独由事件触发。例：学习局里每 10 分钟嵌一个 2 分钟的「回想」小局；或者「每次解锁手机」触发一个 30 秒的「你现在要干什么」小局。
2. **每一步可以带一张卡片**（C3）：跳出什么界面、界面上能做什么、这期间允许哪些 App。
3. **每一步的验收是一份验收规格**（D 组），不再只是 v1 的几个过关条件。v1 的过关条件自动转成等价的验收规格。

示意：

```yaml
协议版本: 2
id: recall-micro
名称: 回想小局
类型: 小局
时长: 2m
步骤:
  - id: ask
    触发: { 通道: 语音, 谁: 局官, 话: "停。不看屏幕，刚才讲了什么？" }
    卡片: { 模板: 指令卡, 放行应用: [], 可做: [按住说话, 拍照] }
    先想: 5s
    验收: { 引用: 验收包/回想-30字 }
    不过: 熔断三级
```

`先想: 5s`：指令念完后麦克风锁 5 秒，倒计时结束才收音（Gemini 方案里「闭眼想 5 秒」的代码版）。

### C2 执行器不改

**第八轮的教训：不改执行器。** v2 在加载时编译成执行器认得的步骤（和思维局的展开同一个做法）。小局在编译时展开成嵌套的子执行器，或者由事件总线（A2）单独开局。五个行为局和思维局的现有测试一条不改，全部通过。

### C3 界面卡片

卡片是**数据描述的界面**，AI 可以填写，渲染器只有一个。卡片模板：

| 模板 | 用途 |
|---|---|
| 指令卡 | 一句指令 + 倒计时 + 作答区（语音 / 文字 / 拍照） |
| 清单卡 | 勾选项；全部勾完才能继续 |
| 选择卡 | 二选一或多选一 |
| 计时卡 | 只显示倒计时和当前局 |
| 提交卡 | 交文件 / 截图 / 照片 |
| 说明卡 | 一段文字 + 一个「知道了」 |

每张卡片可以声明：
- `放行应用`：卡片显示期间允许切去哪些 App（空 = 一个都不行）
- `可做`：界面上出现哪些按钮（白名单）
- `全屏`：是否盖住一切（用已有的拦截页能力）
- `可填`：哪些字段由 AI 或用户在运行时填写

渲染：先查 DSH Go 已有的原生插件视图机制（`docs/design/native-plugins-views.md`、`plugin-ui-v3.md`），能用就用；全屏卡片走已有的 `InterceptPageActivity`。

**最小交付**
- [ ] 流程 v2 格式 + Schema + 编译器；v1 文件原样加载的测试
- [ ] 小局：嵌套与事件触发两种，测试 ≥ 20 条
- [ ] 六种卡片模板 + 渲染器 + widget 测试 ≥ 24 条
- [ ] `先想` 麦克风延迟
- [ ] 卡片的 `放行应用` 与严格模式联动（卡片显示期间放行名单 = 卡片声明的）

## 7. D 组：验收即数据

### D1 验收规格

验收 = **输入方式** + **提取** + **判定** + **不过怎么办**。

```yaml
验收:
  输入: [语音, 文字]          # 可选：语音 / 文字 / 照片 / 截图 / 文件 / 工具复盘 / 应用时长
  提取: [字数, 垫词数, 模糊词数, 因果连接词数, 关键词命中]
  规则: { "and": [ { "<=": [ { "var": "字数" }, 25 ] }, { ">=": [ { "var": "因果连接词数" }, 1 ] } ] }
  模型判: { 标准: "是否说清主语、动作和结果", 及格: 70 }   # 可选
  不过: 熔断三级
```

- **提取器**就是能力库里的度量积木（字数、垫词、模糊词、因果连接词、具体名词、结论句……），第八轮最新提交已经补了「字数上限、模糊词数、因果连接词数」。照片和截图先识图，语音先转写，再提取。
- **规则**用 JSON Logic（A1 的同一个求值器）。代码判。
- **模型判**是可选的，只在代码判不了的地方用（例如「复述是否抓住题意」）。模型输出必须引用作答原文，引不出来作废。
- **规则和模型判同时存在时，规则先判；规则不过就不调模型。**

### D2 熔断三级（通用）

所有验收的「不过」默认走这一条，防止死锁：

| 第几次不过 | 处理 |
|---|---|
| 1 | 指出具体违反了哪一条（从规则里自动生成，例：「超过 25 字；没有因果连接词」） |
| 2 | 给一个填空脚手架（验收包里写；没写就用通用模板「____ 是因为 ____，所以 ____」） |
| 3 | 记为「盲区」，放行进入下一步。盲区自动排进第二天的复考 |

答错（作答了但不对）和敷衍（口水话 / 不作答 / 超时）继续分开记。敷衍走预案（A 组），不走熔断。

### D3 验收包

句式框架、字数限制都只是验收包的内容，不写死在代码里。内置几个包作为起点：

| 包 | 内容 |
|---|---|
| 精简-25字 | 15–25 字；必须有主语、动作、对象；模糊词 0 |
| 因果链 | 至少 1 个因果或对比连接词 |
| 骨架挂载 | 必须出现「属于 / 机制 / 区别」三类表述（关键词规则 + 可选模型判） |
| 盲测回想 | 80–200 字；垫词占比 < 5%；结构为 1 句总纲 + 3 个支点 + 1 句结论（模型判结构，代码判垫词和字数） |
| 回想-30字 | 不看原文，30 字内说出刚才的内容；含至少 1 个原文中的具体名词 |

**爬坡**：盲测回想包有三档（30–50 字 / 80–120 字 / 150–200 字）。连续 3 天通过率 > 80% 自动升一档；< 40% 降一档。

### D4 和 AI 商量着改规则

- 他可以对任何一个角色说「这个验收太松了 / 太严了 / 改成……」。AI 把它改写成新版验收包，**改紧立即生效，改松走冷却期**（沿用墙的「待生效」，默认 2 小时）。
- 每周日，系统统计各验收包的通过率、熔断第 3 级的比例、他标记「判错了」的次数，AI 据此起草调整建议，作为影子版本跑一周，数据更好才替换。
- 每次改动都是一个新版本，可以回退。

**最小交付**
- [ ] 验收规格格式 + 执行；v1 过关条件自动转换
- [ ] 输入方式：语音、文字、照片、截图、文件（照片和截图走识图提取；文件取大小与文本）
- [ ] 熔断三级，测试 ≥ 15 条
- [ ] 五个内置验收包 + 爬坡
- [ ] 对话改规则（改紧立即、改松冷却），测试
- [ ] **并入第八轮 J7**：从其他 App 分享进来的内容作为「文件 / 截图」输入，修改时间早于开局的拒收

## 8. E 组：工具层（Gemini Live 是第一个）

### E1 工具接口

所有外部工具按同一接口接入：

| 接口 | 含义 |
|---|---|
| `可用()` | 手机上有没有、能不能拉起 |
| `能做` | 看屏 / 听 / 说 / 高频追问 |
| `开(简报, 时长)` | 生成简报、写剪贴板、拉起工具 |
| `舱` | 工具运行期间的放行名单（默认只放行工具本身） |
| `收()` | 读回复盘，作为验收输入 |

### E2 Gemini Live 适配器

把现有的 `gemini.js` 收进这个接口。简报不再是固定模板，而是**由当前流程步骤生成**：本步骤的指令、节奏、验收包的规则（转成自然语言告诉 Gemini 怎么追问）、复盘格式。

**判定仍然归 DSH**：Gemini 只负责高频追问；收局时读回复盘，交给 D 组的验收器判。Gemini 嘴上说「通过」不算数。

### E3 工具也是预案动作

`开工具` 是 A3 的一个动作，所以「敷衍三次就开 Gemini 审讯」本身就是一条预案。以后接入新工具，只要实现 E1 的接口，预案和流程里就能直接用。

**最小交付**

- [ ] 简报由流程步骤生成

## 9. F 组：AI 自建（并入第八轮 J8）

他和任何一个角色说一句话，AI 就能搭出预案、流程、卡片、验收包。统一走五步：

1. **描述**：一句话说清要什么。
2. **起草**：AI 只能用已有的事件、动作、卡片模板、提取器、工具。
3. **检查**（代码）：格式；流程可终止；条件变量在白名单里；没有越权（见下表）。
4. **模拟**：配合 / 沉默 / 口水话三种假用户各跑一遍，全部正常结束。
5. **影子或试用**：预案先跑影子，流程先标试用；按数据决定转正。

**AI 权限表（代码执行）：**

| 对象 | AI 能直接做 | 需要他确认 | 冷却 |
|---|---|---|---|
| 预案 | 新建影子；启用收紧类；把一局切进严格模式 | 停用；放宽阈值 | 2 小时 |
| 流程 / 小局 | 起草、进试用 | 转正（数据达标后自动） | — |
| 卡片 | 起草、填写运行时字段 | — | — |
| 验收包 | 收紧 | 放宽 | 2 小时 |
| 哨兵 | 无 | 无 | 只能在哨兵 App 里走解除闸门 |

需要新的事件、动作、卡片模板或提取器时，AI 写一份提议到 `docs/dafeiyu/提议/`，由执行 AI 实现。

**最小交付**
- [ ] 五步流水线，覆盖预案、流程、卡片、验收包四种对象，测试 ≥ 30 条
- [ ] 权限表全部由代码执行，每一行至少 2 条测试
- [ ] 三个角色都有「搭一个……」的入口；起草结果在界面上能预览、能一键试用

## 12. 我额外加的五条

1. **影子模式先行**：任何新预案默认先跑 1 天影子。系统不会因为一条写错的规则把他锁死。
2. **每个限制都能解释**：锁屏上永远显示「哪条预案、哪个条件、怎么解除」。看不懂的锁会把人逼去卸载，fish-build-27 就是这么没的。
3. **一键回退**：预案、流程、验收包都有版本，可以一键回到昨天。灵活的系统必须能撤销。
4. **模型挂了照样执行**：判定、计时、锁全部在本地代码。模型不可用时，代码判的照常判，模型判的项标「待判」，不阻塞流程。
5. **北极星指标**：周报第一行是「他主动开局次数 ÷ 系统开局次数」。三个器做得好不好，最终看他自己开局的比例有没有涨。
