### 1.1 已经在真引擎上跑通（本轮修好的 4 个根因）

用户手测截图里的现象，前两个直接对应：

| 现象 | 根因 | 修法（已提交） |

| 回执 `FAILED agent_no-topic`，新装后**永远不主动说话** | `/plan` 和发球都要求"必须有话题"；新装记忆库是空的 | 话题变成可选：没话题就用手边的情况和人设起头（`plan.js` `free`、`index.js compose`） |

## 2. 端到端测试怎么用

```bash
bash tooling/companion-e2e/run.sh
```

- 第一次会按 `runtime/locks/dsh-<版本>/package-lock.json` 装同版本的 DSH 引擎（镜像地址自动换成 registry.npmjs.org）。
- `fake-llm.mjs` 是假模型（DeepSeek 的 Anthropic 兼容接口 `/v1/messages`，流式），每次回复故意慢 1.5 秒，模拟真机上模型慢。它按请求内容回：主动发球 / 判球 JSON / 聊天先复述再表态。每个请求记在 `.work/llm.log`。
- `app.mjs` 模拟 App：Dart 的 RPC 信封（`POST /api/<method>`，`{type:'client-request',rpcId,method,payload:{args}}`）和 Kotlin 打插件路由的顺序。
- 失败时看三个文件：`.work/dsh.log`（引擎）、`.work/llm.log`（模型收到什么）、`.work/home/companion/ledger.jsonl`（账本）。

**坑**：别在引擎正在跑一轮时 `kill -9`，会把会话日志写坏（之后 `session/prompt` 报 `stored log is corrupt`）。`run.sh` 用普通 `pkill`，等进程退出再启动。

## 3. 必修清单（按优先级）

### P1 浮层改成真正的悬浮窗（用户第一个测出来的）

**现象**：浮层弹出后切到别的 App 再回来，浮层消失，这一球作废。
**根因**：`loop/proactive/ProactivePageActivity.kt` 是一个 Dialog 主题的 Activity（`singleInstance`、`excludeFromRecents`）。
- `onStop()` 里没回应就 `report(Dismissed)` 并 `finish()`。
- 切出去就是 onStop，等于"他划掉了"，调度器还把它当成一次"看过不理"来学习，学的方向是错的。
- 因为 `excludeFromRecents`，从最近任务里也找不回来。
- 我加的聊天框也活在这个 Activity 里，所以切出去聊天就断了。

**改法**：主动发球不再用 Activity，改成悬浮窗。
- App 里已经有现成的悬浮窗基础设施，直接复用：`pet/PetOverlay.kt` 加 `pet/AskBar.kt`。窗口类型无障碍开着时用 `TYPE_ACCESSIBILITY_OVERLAY`，否则用 `TYPE_APPLICATION_OVERLAY`，权限分支在 `OverlayAccess`。宠物气泡和"问一句"输入框都在这里。
- 用户的总控、一手里也做过浮窗，可以参考：`aozhenyu666-cmyk/test` 仓库的 `deepseek/zk-client-v2` 分支 `zongkong/`，以及 `ccr-a5172662-j1jcik` 分支 `yishou/`。
- 新浮窗要满足：
  1. 显示这一球的文字、对话记录、输入框、发送、收起、"别烦我 1 小时"。
  2. **切 App 不消失**（悬浮窗本来就跨 App）。只有他点收起或回复了才关；到了回应窗口（20 分钟）还没动静，就收成气泡，不删掉。
  3. 发送走 `ProactiveRuntime.say(text) { reply, error -> }`（已实现：`POST /say`，再长轮询 `/result`，每次等 8 秒，总共 2 分钟）。
  4. 回执语义：第一次发送算 `Answered("chat")`；点收起算 `Dismissed`；切走什么都不报。
  5. 跟 `VisibleSurface` 的规则一致：同一时间只占一个可见面，收起时释放。
- `Coordinator` 的 `ACTIVITY` 渠道改调新浮窗；Activity 版本删掉，或者只留作无障碍没开时的兜底。

**验收**：§5 的 5-2、5-3、5-4。

### P2 手机侧调度只听插件（开口频率乱、"说不了"的另一个原因）

**根因**：手机侧 `loop/core/ProactiveScheduler.kt` 自己还有一整套节流，和插件的 `/plan` 叠在一起：
- 随机间隔 45 分钟–3 小时（`minIntervalMs` / `maxIntervalMs`）；
- 每天 6 次（`dailyMax`）；
- 他回一句就推迟 20 分钟以上（`userActiveDeferMs`）；
- 被忽略后间隔翻倍，最多 8 倍；连续 3 次被忽略就暂停（`pauseAfterIgnored`）；
- 409（`no-topic` / `agent-busy`）被当成"没送达"，`retrySoon` 快速重试（这就是截图里同一分钟三条失败）。

这些规则插件那边全都有、而且更准（水位、阶梯、额度、正在聊）。两层叠加的结果是谁也说不清什么时候会开口。

**改法**：
1. 插件在线时，`/plan` 的回答就是唯一的决定：`speak:true` 就在 `nextCheckAt` 发；`speak:false` 就按 `nextCheckAt` 定闹钟，什么都不发。
   - 现在 `applyPlan` 只挪闹钟、不看 `speak`。到点后 `evaluate()` 又按自己的规则决定发不发。
2. 插件在线时，手机侧的随机间隔、每日上限、回话推迟、忽略翻倍和暂停都不再生效，只保留为"插件连不上"时的兜底。
3. `AgentWire.decode`：409 的 `agent-busy`、`no-topic`、`in-conversation`、`desk-busy` 映射成"这次不说"，不算失败，不进 `notDeliveredStreak`，也不快速重试。回执页显示成人话。
4. 设置页"间隔 / 每日上限"在插件在线时显示成只读，注明"由大肥鱼决定"；插件那边的教练和伙伴频率已经在 `/config` 里能调（`coachMinGapMs` / `coachHourlyMax` / `coachDailyMax` / `minGapMs` / `hourlyMax` / `dailyMax`）。

**验收**：§5 的 5-1、5-5、5-6。

### P3 锁屏页（拦截页）

**现状**：`InterceptPageActivity` 一离开（`onStop`）就算 `exit()`，回到桌面，这是对的。但大肥鱼说"锁"之后，他从桌面再点开游戏：
- 只有在 3 分钟内，`ProactiveRuntime.onForeground` 才会再锁一次（`FORCE_HOLD_MS`）；
- 超过 3 分钟要等下一次 `/plan`（切 App 时最多每 15 秒问一次）。

**改法**：
1. 拦截页里加同样的聊天框（复用 P1 的组件）。跟大肥鱼讲通了（判球判成真反驳，插件会进入 20 分钟宽限期，`/plan` 的力度降到 1），就放行：手机收到力度 < 3 时，如果当前开着的锁是 `REASON_COMPANION` 加的，就调 `InterceptGuard.onReleased(eventId, RELEASE_RULE)` 并关掉页面。
2. 锁屏页显示的标题、原因要来自大肥鱼（`/plan` 的 `force.why`），不要只写"娱乐拦截"。

**验收**：§5 的 5-7、5-8。

### P4 专注监督页（用户第二个测出来的）

**现象 1**：点"把当前前台应用设为任务应用"永远提示"读不到前台应用"。
**根因**：`loop/focus/FocusControlActivity.kt` 约第 108 行读 `LoopRuntime.lastForeground`。人站在这个页面上点按钮时，前台就是 DSH 自己（`front == packageName`）。这个按钮在任何情况下都不可能成功。
**改法**：换成应用选择器：列出可启动的应用（`PackageManager.queryIntentActivities(ACTION_MAIN + CATEGORY_LAUNCHER)`），带图标、名字、搜索，最近用过的排前面。需要在 Manifest 的 `<queries>` 里声明 launcher intent。

**现象 2**：按返回键直接退出整个 App。
**根因**：`FocusControlActivity` 是独立的原生 Activity，返回就 `finish`，而它往往是被单独拉起来的，背后没有 Flutter 页面。
**改法**：返回时回到 DSH 主界面的设置页（`startActivity(MainActivity)`，带 `FLAG_ACTIVITY_REORDER_TO_FRONT`，或者用路由参数打开对应页面）。或者干脆把这个页面改成 Flutter 页面，原生只保留监督逻辑。

另外截图里宠物悬浮窗压在按钮上：宠物贴边吸附时要避开屏幕中部的可点区域，或者本 App 在前台时自动收起宠物。

**验收**：§5 的 5-9、5-10。

### P5 回执页说人话

截图里是 `FAILED agent_no-topic`、`agent_agent-busy` 这种内部代码。
**改法**：在 `lib/ui/phone/proactive_page.dart` 加一张映射表，例如：

| 代码 | 显示 |
|---|---|
| `no-topic` | 没话可说（旧版本才会有） |
| `agent-busy` / `in-conversation` | 你们正在聊，这次不插嘴 |
| `no-session` | 还没选大肥鱼的会话 |
| `no-agent` | 会话没加载起来 |
| `deadline` / `timeout` | 模型太慢，超时了 |

`FAILED` 只给真失败用；"这次不说"另外显示成灰色。

### P6 模型慢

用户的模型（Gemini Flash 一类）回得慢，直接影响乒乓的手感。
- 主动发球的期限：`CoordinatorConfig.agentTimeoutMs = 45 秒`；文本超过 `replyFreshMs = 2 分钟` 就作废。
- 判球期限 10 秒（原 6 秒），输出上限 1200（原 200，先思考的模型思考也吃额度）；超时/解析失败退回规则，原因写进引擎日志 `[companion] judge fallback: …`。
- `/say` 总期限 2 分钟。

**改法**：
1. 浮层里发出去之后显示"大肥鱼在想…"，过 10 秒还没回就显示"模型有点慢"。不要让人以为坏了。
2. 判球可以单独配一个更快的模型（`judgeTargetOf` 现在跟会话用同一个）。在 companion `/config` 加 `judgeProvider` / `judgeModel`，没配就沿用会话的。
3. 在 `/status` 里给出最近 10 次发球、判球、聊天的耗时，设置页显示中位数，用户一眼就能看出是不是模型的问题。

### P7 新装引导

新装（尤其是 `.fish` 这种独立包）什么都没有。主动搭话页顶部加一张"能不能主动开口"清单，每项可以点进去开启：
1. 已选大肥鱼的会话（`/status` 的 `sessionId`）；
2. 无障碍已连接；
3. 悬浮窗权限（P1 之后必须有）；
4. 通知权限；
5. 精确闹钟；
6. 电池不限制。

页面上已有的"现在的状态"区可以扩成这张清单。

## 4. 不要做的事（踩过的坑）

- 不要在 Kotlin 里再写一套"该不该开口"的规则。决定只在插件里做，手机只执行（P2）。
- 不要用 Activity 做"要一直在"的界面。切出去它就进 onStop，系统随时可能杀掉它（P1、P4）。
- 插件 `lib/` 里加了新文件，必须同时写进 `BuiltinPluginGuest.kt` 的 `PLUGINS` 清单，否则真机报 `MODULE_NOT_FOUND`。`test/manifest.test.mjs` 会检查这一点，别跳过它。
- 发给会话的消息必须带 `source`（见 §1.1）。插件自己的话用 `{kind:'dsh-go-companion'}`，他本人的话用 `{kind:'user', rpcId:…}`。
- 设备时钟是 UTC，引擎跑在 `TZ=GMT`。所有"今天""几点"都按手机传来的 `timeZone` 算（插件已经这样做了）。
- `BuiltinPluginGuest.writeFiles` 内容没变就不写，改了插件要让引擎真的重启才会生效。
- 用 PowerShell 的 `>` 取设备上的二进制文件会写坏，用 Git Bash 或 `cmd.exe`。
- arm64 包装不进 x86_64 模拟器。云端出的是 arm64 包，只能装真机；要在模拟器上跑，就本地打 x86_64 包。

做对的：P1 跨 App 悬浮窗（切 App 不消失、20 分钟收成气泡、聊天走 say()）；P2 插件在线时只按 /plan 定时、
"这次不说"不算失败；P4 应用选择器 + 返回回主界面；P5 人话回执；P6 判球模型可配 + 耗时中位数；P7 能力清单；
测试没有被改弱（新增了 P6 检查、Windows 兼容）。

验收中发现并已修（本次提交）：
1. **P2 让大肥鱼几乎永远不主动开口**：手机问 /plan 带 `roll:100`（旧设计只拿 /plan 定时间），插件规定 roll < 门槛才开口，
   100 永远不中 → 只剩"一早第一球"和阶梯能发。改：不带 roll，插件自己掷。e2e 加"按手机真实请求体问 12 次至少开口一次"。
2. **连发两球**：手机每次切 App 都问 /plan，speak 就立刻提交，去重键每次不同。改：固定去重键 `companion:plan`、
   已有调度球在队列/路上就不再提交；插件 /plan 在有球在路上时回 `in-flight`。
3. **P3 锁几秒就自己解开并把游戏打开**：力度 < 3 就释放锁，但锁屏页一弹前台就是 DSH、赶回桌面后前台是桌面，力度本来就是 0。
   改：只有插件明说 `force.release=true`（他讲通了、在宽限期）才放行。e2e 加对应两项。
4. **悬浮窗和气泡抢走返回键**：窗口可聚焦，在屏幕上时游戏里按返回会被吞掉；气泡挂得很久。改：默认 FLAG_NOT_FOCUSABLE，
   点输入框才拿焦点，打字时按返回收键盘、还焦点；气泡永远不聚焦。
