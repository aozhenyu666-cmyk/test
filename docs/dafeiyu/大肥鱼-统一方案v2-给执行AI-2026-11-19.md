> 2026-11-19。基线：分支 `feat/dafeiyu-v3-on-1016`、fish-build-186（commit `c7877bcd` 及其后的文档提交）。
> 读者：负责落地的执行 AI（Hydrogen）。先读《大肥鱼-整体说明-给外部AI-2026-11-18.md》了解系统全貌，再按本文施工。

## 0. 用户的裁定（不要改动）

1. **严格保留。** 用户之前卸载 App 是因为锁机崩溃，不是因为太严。外部评审说"太严有风险"，这条只作参考。严格不减；但**每一种严格都要可靠、可解释、有出口、有上限**。
2. **功能一个都不删。** 每个功能都是用户和 AI 反复讨论后加的。方案是"收编"：让功能变成某个统一出口的输入或视图，不是删除。
3. **功能之间不能互相矛盾**，要彼此连通、调用一致。这是本轮的主题。
4. **可靠第一。** 任何改动先保证不锁桌面、不锁 DSH 自己、不死循环、引擎挂了也能脱身。

## 1. 外部评审意见怎么取舍

| 意见 | 采纳方式 |
|---|---|
| 太严格，有风险 | **不降低严格程度。** 改为：① 加一个"强度档"（温和 / 标准 / 严格），默认"标准"，等于现在的数值；② 每天硬干预（锁、接管、强拉 Gemini）设总上限；③ 每一次锁都必须带"为什么"和"怎么解"；④ 自律等级上去以后自动放宽。用户想更严就切到"严格"。 |
| 功能之间可能矛盾 | **全部采纳。** 收成七个"唯一出口"，见第 3 节。 |
| 需要连通、完整调用 | **全部采纳。** 第 4 节的不变式要写成测试，保证以后加功能也不会再打架。 |

## 3. 目标架构：七个唯一出口 + 一张强度表

**原则：功能只负责"提请求"，统一出口负责"合成、执行、记账"。** 所有功能都保留，只是不再各自直接改 config 或直接叫手机。

```
 各功能（雷达、契约、预案、墙、接管、切换次数、姐妹工具、推进器 …）
        │  只提请求：lockRequest / passRequest / speakRequest / geminiRequest / taskWrite / timeEntry
        ▼
 ┌──────────────────────────────────────────────────────────┐
 │ ① 锁总线 → 裁决器 → 唯一的 lock（手机只认它）              │
 │ ② 放行账（3 类口）                                          │
 │ ③ 发球仲裁（优先级表 + 总节流）                             │
 │ ④ Gemini 闸门（所有拉起都经过它）                           │
 │ ⑤ 任务单表 work.json（五套队列变成视图）                    │
 │ ⑥ 时间账（额度、挣来、解锁、扣罚、通行证在同一本账）        │
 │ ⑦ 评价：日判为主，其余都从同一账本派生                      │
 └──────────────────────────────────────────────────────────┘
        ▲  所有阈值都从 ⑧ 强度表 读（温和 / 标准 / 严格 × 自律等级）
```

### ① 锁总线 → 裁决器（解决 C1）

- 新增 `lib/lock_bus.js`：维护锁请求表 `lock-requests.json`。每条请求的形状：
  ```
  { id, source, kind: 'allowlist'|'deny'|'open', apps, allow, until, why, unlockHow, priority }
  ```
  `source` 取值：`radar` / `contract` / `preset` / `wall` / `takeover` / `switch` / `sister` / `night` / `gemini-cell` / `lease`。
- 现有写 `refuseUntil` / `blockExtra` / `aiWorkSession` / `presetStrict` 的地方，**改成同时写一条锁请求**。第一个版本保留旧字段，保证兼容。
- `unified_arbiter.js` 和 `lock_decision.js` 从锁请求表合成唯一的 `lock`。优先级沿用 P0–P6，**接管定为 P2.5**：高于专注严格局，低于契约逾期。
- 手机端新增开关 `arbiterEnforce`（默认关）：
  - 关：保持现状，`ArbiterShadow` 继续只做影子对比；
  - 开：`InterceptRuntime.onForeground` 和 `ProactiveRuntime.enforce` 只按 `ArbiterDecision.decide` 执法，旧的 force / refuse / session / block 只用来兜底显示。
  - **永不锁总闸、测试模式、紧急解除在两种模式下都优先于一切。**
- 锁页文案只取 `lock.why` 和 `lock.unlockHow`，保证"显示的就是执行的"。

### ② 放行账（解决 C2）

七个放行口收编成三类，原有入口都保留，只是改调同一个函数：

| 类 | 收编进来的入口 | 规则（标准档） |
|---|---|---|
| **紧急解除**（应急） | 本地 `disarm`、插件 `/emergency-pass`、破窗 `breakglass`、Gemini 卡"延后 10 分钟" | 每天总共 3 次，每次 10 分钟；必须写理由；记账；计入日判；不扣信用分（扣分会逼人绕道）。插件和本地共用一个计数：本地优先，事后同步到插件 |
| **挣来的时间**（交换） | 每通过一局验收 +15、题库答对 10 题换 5 分钟、`grant_break` | 全部存进时间账 ⑥，用的时候从同一个池子扣 |
| **通行证**（用途） | `grant_task_lease` | 只给双用途 App；默认 15 分钟，最长 30；一天第 9 张起要理由 |

- `request_relax`（申请明天放松）不算放行口，保留为"改规则"的通道，走原来的冷却期。
- 新增 `lib/pass_ledger.js`，提供 `requestPass(kind, {...})`，返回同一种结构：`{ ok, until, why, countToday, left }`。

### ③ 发球仲裁（解决 C4、C9 的一半）

新增 `lib/speak_arbiter.js`。把 `planRoute` 里那串 if-else 改成：**先收集所有候选，再按一张表挑出一个。**

| 优先级 | 候选 | 说明 |
|---|---|---|
| 1 | 安全类：night（深夜收手机）、接管 | 不受节流限制，只受接管自身的间隔约束 |
| 2 | 硬时间点：契约验收点、截止日、morning-gate、review、task-due / busy-done | 每类有自己的冷却 |
| 3 | 推进：bout-gap、auto-open 后的告知、plan-draft、patrol | 受总节流 |
| 4 | 连麦相关：gemini-recap、gemini-left、gemini-checkpoint、gemini-voice-check | 连麦中只允许这一组 |
| 5 | 陪伴：restless、notes-chase、骰子随机球、推进器 fill | 受总节流，最容易被挤掉 |
| — | 雷达球 | 跟着锁走：锁了才说一句，不另占名额 |

**总节流（标准档）：**
- 每小时最多 4 球；
- 两球间隔至少为伙伴档间隔（默认 8 分钟，思考层可在 5–30 分钟间调）；
- 第 1、2 级不受这两条限制。

**沉默阶梯和敷衍冷处理**：在仲裁里统一处理。只有第 1 级可以绕开；第 2 级只在"硬时间点"那一刻绕开一次。

每次选择都写账本 `speak-pick`，记下候选列表和选中了谁，方便以后复盘"为什么那时她说了那句"。

### ④ Gemini 闸门（解决 C3）

新增 `lib/gemini_gate.js`。所有拉起 Gemini 的路（7 路）都调 `requestGemini({source, topic, brief, mode})`：

- **自动拉起**（非用户主动点击）：两次之间至少隔 20 分钟；每天上限 6 次（标准档）；连麦中不拉；连麦结束后 10 分钟内不拉；深夜、安静时段、紧急解除期间不拉。
- **用户主动点击**（骰子"连 Gemini"、任务卡按钮）：不受冷却和上限限制，只记账。
- 简报统一走 `trigger.js` 的设定、事实、回执拼装，避免各处的简报格式不一样。

### ⑤ 任务单表（解决 C5）

- 新增 `work.json`。每一项是一个工作包：
  ```
  { id, source: 'plan'|'daily'|'contract'|'horizon'|'bout'|'sister',
    title, minute?, due?, packet, apps, status, links:{horizonId, contractCpId} }
  ```
- 五个旧文件**读一次自动迁移**。之后各页面和工具照常读写，但**写入统一走 `workStore.upsert`**，旧文件改由 workStore 镜像生成（保留一个版本，用于回滚）。
- 推进器、日判（计划数）、四个数、晚报、思考层**全部只读 workStore**。
- 三层主线里推一项到今天（`push_to_today`）：产生一个 `source: 'horizon'` 的工作包，并带上 `links.horizonId`。工作包完成时，主线进度自动 +1。

### ⑥ 时间账（解决 C6）

扩展 `quota.js` 为 `time_ledger.js`。一天一本账，条目类型：

```
fun_base(+120) / game_base(+60) / earned_bout(+15) / earned_bank(+5) / break(+n)
penalty(-n) / used_fun / used_game / used_dual_outside_pass / converted_game_to_fun
```

- 剩余额度只有一个算法；中枢、锁页、两姐妹的上下文、晚报都显示同一个数。
- 扣罚只从挣来的部分扣，不扣基础额度，并且在账上看得到。

### ⑦ 评价统一（解决 C7）

- **主结论：硬日判**（空转 / 部分 / 达成）。所有页面第一行只显示它。
- 战力分改名为"投入分"，作为辅助数字；**硬日判是"空转"时，投入分最多 39 分**，避免和判决打架。
- 自律等级改为按 14 天窗口计算：主动开局比、交付率、空转天数、紧急解除次数，降级比升级快。它**只**用来选择强度表里的列（见下）。
- 信用分（trust）只影响"通行证能否直接批"，不再影响锁。

### ⑧ 强度表（解决 C9，也回应"太严"的担心）

新增 `lib/intensity.js`：一张表，所有阈值都从这里读。各模块不再各自写死数字。

| 阈值 | 温和 | **标准（默认 = 现在的数值）** | 严格 |
|---|---|---|---|
| 伙伴档最快间隔 | 15 分钟 | 8 分钟 | 5 分钟 |
| 每小时最多球数 | 3 | 4 | 6 |
| 局后几分钟推 / 几分钟自动开 | 10 / 20 | 5 / 10 | 3 / 6 |
| 切换次数：窗口 / 摇骰 / 锁 | 10 / 4 / 7 | 10 / 3 / 5 | 15 / 3 / 4 |
| 娱乐 / 游戏额度（分钟） | 150 / 60 | 120 / 60 | 90 / 45 |
| 接管：每次最长 / 每天最多 | 30 分钟 / 2 次 | 45 分钟 / 3 次 | 60 分钟 / 4 次 |
| 自动拉 Gemini：每天上限 | 4 | 6 | 8 |
| **每天硬干预总上限**（锁 + 接管 + 自动拉 Gemini） | 8 | 12 | 20 |
| 紧急解除：每天次数 | 3 | 3 | 2 |

- **用户自己选档**：在中枢切换，或对姐妹说。
  - 改严立即生效；改松从第二天生效。这和规则.md 的"改松要冷却"是同一个逻辑。
- **自律等级自动往松挪一档**：14 天达标就往松挪一档（但不会低于用户自己选的那一档的下一档）；不达标就恢复。这就是"权力还回去"的落地方式。
- **每天硬干预达到总上限后**：当天剩下的时间只保留深夜锁和契约逾期锁，其余干预改为只提醒，并在晚报里写明"今天硬干预已经用满"。这是防止多个机制同时加码的总闸。

## 4. 不变式（必须写成测试，以后任何改动都不许破）

新建 `test/invariants.test.mjs`。每条至少一个用例；能做成"随机状态生成 + 断言"的就做。

| # | 不变式 |
|---|---|
| I1 | 系统底座（桌面、DSH 自己、系统界面、输入法、NekoBox、急事 App、选图选文件页）在任何模式、任何组合下都不会出现在 `lock` 的锁目标里，也不会被 `decide` 判为锁。 |
| I2 | 只要 `lock.mode != open`，`why` 和 `unlockHow` 都不为空；锁页显示的文字等于 `lock.why`。 |
| I3 | 任意时刻至少存在一个"能脱身"的出口：紧急解除还有次数，或者锁有 `until`，或者有回位动作。 |
| I4 | 紧急解除期间：`lock.mode == open`；不接管、不自动拉 Gemini、不发第 2–5 级的球。 |
| I5 | 发球仲裁每次最多选一球；除第 1–2 级外，每小时不超过强度表的上限。 |
| I6 | 两次自动拉起 Gemini 至少间隔强度表规定的时间；连麦中不发起拉起。 |
| I7 | 同一个工作包在 workStore 里只有一份；五个旧视图各自统计的"今天几件"相等。 |
| I8 | 时间账里的剩余额度在中枢、锁页、上下文、晚报四处完全一致。 |
| I9 | 硬日判为"空转"时，投入分 ≤ 39。 |
| I10 | 每天的硬干预次数 ≤ 强度表上限；超出后只剩深夜锁和契约逾期锁。 |
| I11 | 改松（强度档、App 分层、规则.md）不会当天生效。 |
| I12 | 以上各条在 0:00–23:59 任意时刻都成立：用假时钟分别在 1:20、3:40、8:30、14:10、22:10 跑一遍。 |

## 6. 施工纪律

1. **不删功能。** 旧入口保留，改为调统一出口；旧字段至少保留一个版本作为兜底。
2. **默认行为不变。** 标准档 = 现在的数值；新开关默认关。用户感知到的变化只能来自"矛盾被消除"。
3. **规则在代码里，模型只说话。** 新的统一出口全部写成纯函数，给模型的工具只能"提请求"。
4. **改严立即，改松延后。** 适用于强度档、App 分层、规则.md、额度。
5. **每个阶段都要有测试。** 新增的不变式测试一条都不许跳过、不许改成 skip；测试必须与当天时刻无关。
6. **测试命令**：
   - 插件：`cd app/assets/engine/plugins/dsh-go-companion && node --test test/*.test.mjs`
   - Kotlin 和 Flutter 只能在 CI 上编译验证（`.github/workflows/build-dafeiyu-apk.yml`，推送 `feat/dafeiyu-v3-on-1016` 自动触发）。Flutter analyze 会把 info 当成失败处理。
7. **新增的 `lib/*.js` 必须写进 `app/android/app/src/main/kotlin/io/github/ccch1mneyyy/dsh_app/runtime/BuiltinPluginGuest.kt` 的清单**，否则 `test/manifest.test.mjs` 会失败，真机上也不会部署。
8. **有源码扫描类测试**，例如 `voice.test.mjs` 要求 `stage: silence.stage` 这一写法原样存在。改到相关代码时先跑一遍测试。
9. **CI 偶发 Maven 429 限流**，属于基础设施问题：重推或手动 re-run 即可，不要为此改代码。
10. **不碰上游 DSH 的部分**，不改包名，不改签名配置。
11. **提交说明用中文**写清"收编了哪个矛盾（C 几）、哪条不变式（I 几）现在由测试守着"。
