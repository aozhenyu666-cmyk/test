#### R4-0 改了什么

真机现象是「点对话框，输入法一弹出就被踢出去」，刷个不停，放行名单也不管用。

根因（和指令里 Claude Code 查到的一致，代码核对无误）：
`LoopRuntime.onEvent` 把**每一个** `TYPE_WINDOW_STATE_CHANGED` 的 `packageName` 原样交给
`ProactiveRuntime.onFrontChanged`。输入法弹出时那个包名是输入法自己，连麦舱期间
`listed()` 只认 `sessionAllows()`（Gemini 白名单 / `NEUTRAL` / DSH 自己），输入法不在里面，
于是判成「切到别的 App」，当场 `Force` 上锁并弹拦截页。`/plan` 回来又 `enforce(fresh=true)`
一次，配合输入法反复弹出收起，就成了来回闪。

改动：

1. 新增纯函数 `phone/a11y/FrontChange.kt`：
   - `isLayer(pkg, imePkgs, selfPkgs)` —— 输入法（以 `InputMethodManager.getEnabledInputMethodList()`
     为准，`inputmethod` / `.ime` / `.input` 名字规则只作兜底）、`android` / `com.android.systemui`、
     权限弹窗（`permissioncontroller`）、安装器（`packageinstaller`）、DSH 自己（含 `.fish`）都算
     「盖在上面的一层」；
   - `switched(pkg, ...)` —— 只有真实 App 才算换了前台 App，`null` / 空白 / 一层都不算。
2. 三处共用这一个判断，不再各写一套：
   - `ProactiveRuntime.onFrontChanged`（`LoopRuntime` 那条路径）；
   - `applyPlan` 里的连麦舱检查；
   - `NowFeed`（原来的 `isNoise` 并进 `FrontChange`，行为等价并有名字规则兜底）。
3. 连麦舱期间 `sessionAllows()` 也读用户的放行名单（`InterceptRuntime.config().whitelist`），
   不再只认插件白名单——这对应真机上「放行都不起作用」。
4. 去抖两处：
   - 锁页本身属于「自己」，`switched()` 直接返回 false，所以不会再被自己的页面刷起来；
   - `forcedApp` / `forcedAt`：同一个包在 `FORCE_HOLD_MS` 内只锁一次；离开被拦的 App
     （回桌面、进 DSH）就把去抖清掉，下次再进来重新锁——不会因为去抖放过他。
5. `PhoneA11yService.onServiceConnected` 注册输入法列表与 DSH 自己的包名。
6. 单测 `FrontChangeTest.kt` 7 条：输入法不锁、systemui/权限弹窗/安装器不锁、DSH 自己不锁、
   真实 App 算换 App、`null` 与空白不算、放行名单不影响「算不算换 App」的判定、
   注册表版本（不带参数的 `switched`）同样成立。

#### 没做的（R4-0 范围内明确跳过）

- **「输入法变化时刷新」**：Android 没有可靠的「输入法列表变了」广播。现在的做法是
  服务连上时取一次 + 名字规则兜底，新装的输入法靠名字规则也能认出来。若真机上出现
  认不出的输入法，把包名加进 `LAYER_WORDS` 或改成每次窗口事件读一次（会多一次 binder 调用）。
- **不放第三种名单**：按要求只保留 `NEVER_LOCK`（代码写死）与用户放行名单，没有新增名单。

## CI 结果

**R4-0 的代码检查没跑成：卡在 GitHub 的 JetBrains releases CDN 上，四次全挂在同一个外部故障。**

| # | run / attempt | 失败点 | 原因 |
|---|---|---|---|
| 1 | [`42568326461`](https://github.com/aozhenyu666-cmyk/test/actions/runs/42568326461) a1 | Kotlin 单测 | wrapper 下载：`services.gradle.org` → `github.com/gradle/gradle-distributions/.../gradle-9.3.1-all.zip` 504 |
| 2 | 同上 a2 | Kotlin 单测 | `kotlin-compiler-embeddable-2.2.21.jar` 从 `github.com/JetBrains/kotlin/releases/download/v2.2.21/...` 拿到 504 |
| 3 | 同上 a3 | Kotlin 单测 | 同 2（`2.2.21` 仍 504） |
| 4 | [`42571251328`](https://github.com/aozhenyu666-cmyk/test/actions/runs/42571251328) | Kotlin 单测 | `kotlin-compiler-embeddable-2.4.0.jar` 同源 504 |

排查结论：

- **不是仓库源顺序**：`settings.gradle.kts` 里 `google()` / `mavenCentral()` / `gradlePluginPortal()`
  已经排在阿里云前面。
- **不是 Maven Central 本身**：直连
  `repo.maven.apache.org/.../kotlin-compiler-embeddable-2.2.21.jar` 返回 **200**（56,908,512 字节）。
  504 出在它 302 之后的落点 `github.com/JetBrains/kotlin/releases`——那个 CDN 正在故障。
- **不是我们的代码**：四次都没走到 `:app:compileArm64DebugKotlin`，第一次连 wrapper 都没下完。
- **重试参数没用**：已在 CI 单测那条命令上加
  `-Dorg.gradle.internal.repository.max.retries=10` 与 `initial.backoff=2000`，
  但 504 是**持续**返回而不是抖动，重试改变不了结果。

已做的、对以后有用的那条：`Use the official Gradle distribution on CI` 步骤本身 success，
说明 Claude Code 把 CI 的 wrapper 指向官方源那个改法是对的。

按第四轮指令 §4「同一个 CI 失败修 3 次还没过」→ 停在这里，等人处理：

- 要么等 GitHub 的 JetBrains releases CDN 恢复（这类 504 历史上几小时内会自己好）；
- 要么绕开那条重定向：给 `kotlin-compiler-embeddable` 单独指定一个不 302 到 GitHub 的仓库
  （例如 `https://maven.pkg.jetbrains.space/public/p/kotlin/` 或先把 jar 预置进
  `~/.gradle/caches`）。这一条要改仓库源或加缓存步骤，属于基建改动，等拍板。
