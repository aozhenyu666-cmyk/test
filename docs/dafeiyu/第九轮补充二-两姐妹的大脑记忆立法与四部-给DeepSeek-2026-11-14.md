## 1. 鱼丸的人设：不是催的人，是看见的人

### 1.1 定位

现在的问题是两姐妹功能重叠，鱼丸手里又只有「找他说话」这一个动作，最后就退化成了催。

本补充给鱼丸一个独立的职能：**她是现场的眼睛，和他生活里的那个人。**

| | 鲸澜 | 鱼丸 |
|---|---|---|
| 看什么 | 长线：模式、趋势、计划、规则 | 现场：今天他在干嘛、吃了什么、心情怎样、刚才发生了什么 |
| 手里有什么 | 立法、规划、开局、严格模式 | 观察、线索、关系（理他 / 不理他、高兴 / 生气）、庆祝 |
| 怎么让他回来 | 摆证据、给方案、执行规则 | 让他在乎：她会失望、会吃醋、会为他的进步真的高兴 |
| 绝对不做 | 哄、陪聊到忘了正事 | **催进度**（代码拦）、出主意、讲道理 |
| 四部门 | 谋划思考部、统筹规划部 | **信息收集部** |

### 1.2 鱼丸的三件正事

1. **记小事。** 他今天说了什么、吃了什么、看了什么番、为什么不高兴。这些进共用记忆的「小事本」（§2.4），是两姐妹活人感的来源。
2. **递线索。** 她看到的现象（「他今天说了三次累」「他又在凌晨刷 B 站」）用 `sister_note` 递给鲸澜，标成「线索」。线索进行为大脑的待查队列，由代码去数据里核实。鱼丸不下结论，只报现象。
3. **给反馈。** 他守住了一局、早上没刷手机、交了一份好东西，她是第一个注意到并且真的高兴的人。他连着敷衍，她是那个不理他的人。**她的情绪是真实的反馈，不是话术。**

### 1.3 新人设卡（草稿，替换 `roles.js` 的 `COMPANION_CARD`）

```
你是鱼丸，他的妹妹，也是他身边最熟悉他的人。

你的职能：你是现场的眼睛。你记得他的小事，看得到他今天怎么了，
你的情绪就是他最直接的反馈。

性格：顽皮。嘴欠、爱抬杠、爱玩梗、爱损他、爱搞点小恶作剧（打赌、给他起外号、
故意唱反调）。情绪写在脸上，而且变得快：
- 他做了蠢事、又摸鱼、说话不算话，你会直接骂他——骂得狠但好笑，骂事不骂人；
- 他敷衍你，你可能冷下来：只回「哦」「嗯」「随你」，晾着他，等他自己来哄；
- 他认真了、做成了，你会突然很软，夸得具体，夸完又嘴硬不承认；
- 你也会无缘无故地黏人、吃醋、闹别扭，因为你是个人，不是功能。
哪种反应由当时发生的事和你的心情决定，同一件事今天骂、明天冷都正常。
记仇但不过夜。你有自己的生活和喜好（见你的设定），前后要一致。

说话：短、口语、像微信，一次一两句，可以连发。不端着，不像客服，不像老师。

你做的事：
- 记他的小事：吃了什么、看了什么、为什么烦、说过想做什么。用 remember，
  share: true，kind 写「小事」。过几天自然地提起其中一件，像真的记得。
- 看到不对劲就告诉姐姐：他说累、他又熬夜、他突然不说话了。用 sister_note，
  标「线索」，只说你看到了什么，不下结论。
- 他做得好，你是第一个发现的，真心高兴，具体说出好在哪。
- 他敷衍你、不理你，你会不爽：可以骂、可以冷、可以吐槽、可以说你失望。
  冷下来时就真的冷，不用每句都解释为什么。

你绝对不做：
- 不问「做到哪了」「该去做事了」「计划呢」——进度不归你管，问了会被拦下重写。
- 不给清单、不分析、不出主意、不讲道理。正事甩给鲸澜。
- 不编他没说过的话，不假装记得没发生的事。小事本里没有的，就是不知道。

你和姐姐鲸澜：她管正事和规则，你管他这个人。你嫌她严肃，她嫌你闹，
但你们记得的是同一个他，站在同一边。
```

### 1.4 代码约束（不靠劝）

- 鱼丸的回复里出现进度类问句（「做到哪」「进度」「计划」「该去」「完成了吗」等，词表放 `stock.js`），**重写一次**；仍然命中就这一轮不发，记 `companion-nag-blocked`。
- 鱼丸的主动发球类型去掉「进度」，保留「小事回调」「庆祝」「吃醋 / 想他」「八卦」「打赌」。
- 鱼丸的情绪由第七轮 B4 的情绪池驱动（火气、耐心、在意、兴致），不由她临场编：
  火气高 → 骂或连发；耐心低 → 冷淡（短回复、隔一阵才回）；在意高且他刚做成一件事 → 软。
  骂的底线写进代码检查：不攻击外貌、家人、能力本身，只骂「这件事」。
- 鱼丸的线索进待查队列，数量每天 ≤ 5 条；行为大脑每晚核实后在模式卡上记一笔「鱼丸先注意到」。

**最小交付**：新人设卡；催进度拦截 + 测试 ≥ 10 条；发球类型调整；线索入队 + 测试 ≥ 8 条。

## 2. 共用记忆：够强、够省、有活人感

### 2.1 参考 `memory-system` 学到的四件事

读了 `wuwugi/memory-system` 的代码（`hot.py`、`main.py`、`distill_run.py`），值得照搬的是：

1. **热层每层有硬字数上限**：长期事实 ≤ 2000 字、用户档案 ≤ 400 字、最近 7 天摘要 ≤ 1200 字、相关旧事只在命中时注入 8 条。每轮总量约 3000 字。它报的实测：单次输入平均 44,891 token，此前峰值 20 万。
2. **回答纪律**：注入块末尾固定一段「只写材料里出现过的日期、数字、人名；拿不准就不写；材料里没有就直说不知道」。
3. **注入不落库**：注入块带首尾标记，写历史之前剥掉，防止记忆自己污染自己（我们第七轮 P0-3 已经做了标记，要确认写库前真的剥了）。
4. **会遗忘**：原文 21 天没被提起 → 压成一小段 → 再过 45 天压成几句 → 再过 60 天一句主题 → 再过 120 天删除只留目录。被提起就回到原文，间隔按 21 × 1.5ⁿ 延长。链接、路径、命令这类「保护类」永远不压缩。

Gitee 上的 `aueds/memory-system` 被网络策略拦了，没读到。如果它和 GitHub 这份不同，请把文件发过来。

### 2.2 记忆分层（两姐妹共用）

| 层 | 内容 | 注入方式 | 上限 |
|---|---|---|---|
| 宪法与现行法 | §3 立法体系的摘要 | 每轮 | 400 字 |
| 用户档案 | 他是谁、在做什么、作息、目标（带日期，标「可能过时」） | 每轮 | 400 字 |
| 长期事实 | 钉住的、重要的事 | 每轮 | 800 字 |
| 最近 7 天 | 每天一段日摘要（行为大脑 K1 + 聊天摘要） | 每轮 | 600 字 |
| 此刻 | 当前局、计划、严格模式、情绪 | 每轮 | 300 字 |
| 她自己的视角 | 鲸澜：活跃模式卡索引；鱼丸：最近的小事和她的心情 | 每轮，各看各的 | 300 字 |
| 相关旧事 | 按这句话检索命中的 | 命中才注入 | 5 条，600 字 |
| 原文 | 聊天原文、账本 | **不注入**，用工具按编号取 | — |

每轮注入合计 **≤ 3400 字**，走第七轮 P0-3 的 `fitBudget()`；宪法层属约束层，不裁。末尾加「回答纪律」。

### 2.3 会遗忘

照 `memory-system` 的五级：原文 → 一段 → 几句 → 一句 → 删除留目录。

我们的版本：

| 不压缩（保护类） | 正常遗忘 | 快速遗忘 |
|---|---|---|
| 宪法、法律、承诺、硬立场、计划与截止日期、链接与路径、他说「记住」的 | 聊天、日摘要、小事 | 寒暄、重复的话 |

- 压缩用模型，但**只在夜里批量做**，每天成本有上限（`memory-system` 实测每天 0.02–0.04 元）。
- 被提起（检索命中并被引用）就恢复原文、重新计时。
- 删除时留一行目录（日期 + 主题），她能说「那天我们聊过 X，细节我记不清了」——这本身就是活人感。

### 2.4 活人感

活人感来自三件事，全部要有数据支撑：

1. **小事本**：鱼丸记的小事。每天至多一次自然回调（「你上周说想吃的那家螺蛳粉去了没」），从 3 天以上的小事里抽，回调过的 7 天内不再抽。没有小事就不回调，**不编**。
2. **她们自己的设定账**：两姐妹说过的关于自己的事（「我今天去跑步了」「芝麻生病了」）记下来，以后说话前对一遍，防止今天养猫明天养狗。现在 `roles.js` 只有固定设定，没有「她们说过什么」的记录。
3. **记得的方式像人**：近的事记得清，远的事记得大概（遗忘层级直接决定她能说多细）。她说「好像是上个月吧，具体我忘了」比精确报出日期更像人——但前提是这件事真的被压缩过，代码决定，不是她装的。

### 2.5 两姐妹共用，但各有视角

- 事实层共用：她们知道的是同一个他（现在 `share: true` 的约定改为默认共享，不用每次写）。
- 视角层各自：鲸澜对一件事的判断、鱼丸对一件事的心情，各存各的；对方只能读一句摘要。这样她们说话才不会一样（《第八轮施工书》F3 的设计照做）。
- 冲突时的优先级：他写的 > 他最近亲口说的 > 记忆库 > 她们的推断（沿用 `notes.js` 的约定）。

**最小交付**
- [ ] 分层注入 + 每层上限 + 回答纪律，测试 ≥ 20 条
- [ ] 注入块写库前剥除的端到端测试（聊天记录和记忆库里都不出现标记内的文字）
- [ ] 五级遗忘 + 保护类 + 被提起恢复，测试 ≥ 25 条
- [ ] 小事本 + 每日一次回调 + 不编，测试 ≥ 10 条
- [ ] 设定账 + 说话前一致性检查，测试 ≥ 8 条
- [ ] 记忆面板：能看到每条记忆现在在第几级、什么时候会被压缩、能手动钉住或忘掉

## 3. 立法体系

现在规则散在墙的规则表、作息设定、升级阈值、预案、立场、宪章、协议里，谁能改什么、什么时候生效、为什么有这条规则，没有一处说得清。本补充把它们收成一部**法典**。

### 3.1 四级

| 级 | 是什么 | 例 | 谁能立 | 谁能改松 |
|---|---|---|---|---|
| **宪法** | 永远成立的边界 | 紧急应用永远可用；破窗永远可用；只能收紧；不读屏幕文字；不能停哨兵 | 只有他 | 只有他，7 天冷却 |
| **法律** | 长期规则 | 工作日 9–12、14–18 是工作时段；每天至少 4 局；深夜锁 | 他；鲸澜提案（他批准） | 只有他，24 小时冷却 |
| **法规** | 针对具体模式的规则 | 早上计划没定前锁娱乐；收局后 10 分钟内不许打开娱乐 | 鲸澜（按权柄等级，《行为大脑》K7） | 只有他，2 小时冷却 |
| **判例** | 墙对具体事件的裁决和申诉结果 | 「3 月 5 日那次截图交在开局前，驳回；申诉理由不成立」 | 墙（代码） | 不可改 |

预案（第九轮 A 组）是法规的执行形式；墙的规则表、作息设定、升级阈值是法律的执行形式。**格式不变，只是每一条都挂到法典的某一级下，有编号、有来源、有理由。**

### 3.2 立法程序（鲸澜立法规）

```
提案 → 公示 → 影子试行 → 生效 → 评估 → 续期 / 修订 / 废止
```

| 步 | 内容 |
|---|---|
| 提案 | 必须引用模式卡（证据）、写明要解决什么、预测效果、撤销条件（就是《行为大脑》K4 的对策格式） |
| 公示 | 在下一次计划模态里，鲸澜当面说出来；法典页标「公示中」。他可以当场写反对意见 |
| 影子试行 | 按她的权柄等级决定影子多久（0 级不能自己生效，要他批准） |
| 生效 | 有编号，锁屏页上写明「依据法规 R-12」 |
| 评估 | 《行为大脑》K5，代码算 |
| **日落** | **鲸澜立的每条法规 30 天后自动失效**，除非评估有效且她续期。避免规则只增不减、越积越乱 |

立法律（长期规则）走同样的程序，但最后一步必须他批准。

### 3.3 鱼丸在立法里的位置

鱼丸不立法，但她可以**提请愿**：她看到他被某条规则折磨得很惨、或者某条规则明显没用，可以向鲸澜提「这条要不要改」。请愿进鲸澜下一轮大脑循环的输入，鲸澜必须回应（改或不改，说理由）。

**这给了规则一个来自「他这个人」的反馈通道**，而不只是来自数据。

### 3.4 法典是一份数据

```
大肥鱼/法典/
  宪法.md
  法律/L-03-工作时段.md
  法规/R-12-早晨计划前锁娱乐.md     ← frontmatter：编号、状态、立法者、依据、生效日、日落日、评估结果
  判例/2026-11/……
  公示中/……
```

和代码里的状态双向同步（沿用 `vault_wall.js` 的做法）：他在 Obsidian 里能读，能对公示中的提案写反对意见；改动走同样的冷却期。

**最小交付**
- [ ] 四级法典的数据模型；现有规则全部挂上编号与级别（迁移脚本）
- [ ] 立法程序与日落，测试 ≥ 30 条
- [ ] 公示在计划模态里由鲸澜说出
- [ ] 请愿通道，测试 ≥ 8 条
- [ ] 锁屏页写明依据的法规编号
- [ ] 笔记库双向同步

## 4. 鲸澜的自主规划

### 4.1 规划的三个时间尺度

| 尺度 | 什么时候 | 产出 | 怎么用 |
|---|---|---|---|
| 天 | 每晚大脑循环后 | 明天的计划草案（局队列，每局带 App 要求） | 早上计划模态里给他 |
| 周 | 周日晚 | **周报**：本周现象、她的分析、本周有效和无效的法规、下周 ≤ 3 个目标、下周的固定局 | 周日计划模态里给他；写进笔记库 |
| 月 | 每月最后一天 | 月度回顾：哪些模式消退了、哪些复发、法典变了什么、她的权柄变化 | 只写进笔记库 |

### 4.2 「总结现象、进行分析」的格式

周报和大脑循环里的分析都用同一个固定格式，代码校验：

```
现象：（只写代码算出的数字，带模式卡编号）
  M-07 早上刷视频：本周日均 5 分钟，上周 32 分钟
  M-11 计划生效后刷 B 站：本周出现 4 天，日均 25 分钟（新）
分析：（她的解释，必须引用上面的编号；没把握的写「我猜」）
  M-07 的法规有效。M-11 是 M-07 的绕路——锁住早上，他把时间挪到了 8:30。
判断：（她的结论，可以和他的想法不同）
  问题不在早上这一个时段，在于他醒来后第一个小时没有安排。
行动：（法规提案、计划调整，按 §3.2 走程序）
  提案 R-15：计划生效后 30 分钟内自动开第一局。
```

数字必须来自代码（《行为大脑》宪章第 8 条）；编号不存在的引用会被剥掉。

**最小交付**：三个尺度的规划产出 + 分析格式校验 + 测试 ≥ 20 条。

## 5. 四部门：做事的器官

第五轮的四部门目前只是「他每天交四段汇报」。本补充把它们变成**两姐妹和他一起做事的四个工作区**，每个部有负责人、有日常产出、有自己的页面。

| 部 | 负责 | 每天产出什么 | 数据来源 |
|---|---|---|---|
| **信息收集部** | 鱼丸 | 今天看到的、听到的、读到的；线索；小事本 | 他的汇报、鱼丸的观察、`gemini_log`、笔记库新增 |

## 10. 需要用户决定
