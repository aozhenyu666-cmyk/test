## 0. 两个核心，一条铁律

本轮只有两个核心，所有工单都服务于它们：

1. **局**：一切行为和思维都在局里发生。局有自己的引擎、自己的界面、自己的模型、自己的声音，和两姐妹独立。
2. **主动**：流程由系统开启，不由他开启。每天由系统开局、排局、收局；他敷衍或沉迷时，系统直接升级到 Gemini 审讯或锁机，不商量。

思维训练只有一条铁律：

> **每一拍在他开口前，判错依据必须已经存在。没有依据的问题不许进题库。**

判错依据只有三个来源：真题的答案和解析（AI 不出题，只把官方解析拆成步骤）；原文本身（他要指出是哪一句，代码直接比对）；他自己之前写下的记录（专门用来验连续性）。

**系统的总原则**：AI 不陪他在泥地里打滚。他说什么，系统不跟着说什么；系统只按协议推进，按依据判定，按规则升级。

## 3. J 组：局引擎

### 3.1 三层结构

| 层 | 是什么 | 怎么变 |
|---|---|---|
| **引擎** | 读协议文件，按步骤走，计时，判定，升级，记账 | 几乎不变 |
| **能力库 + 招式库** | 引擎认得的全部积木：能感知什么、能怎么触发、能怎么验收；思维局的六种招式 | 加一块要出新版 |
| **协议** | 一个文件描述一种局 | 导入即用，不出新版 |

### J1 局的数据

在 `fish-memory.sqlite` 里用 `dsh-go-memory` 的迁移机制加表。所有写入只走 `lib/bouts.js`。账本 `ledger.jsonl` 继续写，冲突时以账本为准，并提供从账本重建的脚本。

| 表 | 一行是什么 |
|---|---|
| `bouts` | 一局：协议 id、开局者、计划时间、开/收时间、收局原因、状态、所属四部 |
| `beats` | 一拍：局 id、招式或步骤、发出时间、通道、应答、应答度量、判定、重打次数 |
| `evidence` | 判错依据：来源类型（解析 / 原文 / 他的记录）、引用、内容哈希 |
| `deliverables` | 产出物：形态（文字 / 语音转写 / 照片 / 文件 / 外部提交）、引用、提取文本 |
| `verdicts` | 判定：层（代码 / 模型 / 墙）、结果、分数、引用原文 |
| `escalations` | 一次升级：原因、级别、开始、结束、怎么结束的 |
| `protocols` | 已装协议：id、版本、来源、状态（内置 / 试用 / 正式 / 退役）、文件哈希 |
| `day_plans` | 一天的计划：模板、局队列快照、编辑记录、生效方式（他确认 / 超时自动） |

**最小交付**：迁移 + `bouts.js` 增删查改 + 重建脚本，测试 ≥ 40 条；第七轮 A2 的时间块数据迁入。
**超额项**：一年数据量的基准；导出到笔记库 `大肥鱼/局/日期.md`。

### J2 协议格式与解释器

协议是 YAML（或 JSON），每一步只有四样：**怎么触发、限时多久、什么算过关、不过或超时去哪**。示意：

```yaml
协议版本: 1
id: study-video
名称: 学习局
类型: 行为
需要能力: [计时, 前台应用, 盖屏, 语音问, 语音答, 拍照]
预算: { 分钟: 30, 来回: 6 }
步骤:
  - id: guess
    问: 这节会讲什么？猜 3 条。
    限时: 90s
    过关: { 行数: 3, 每行最多字: 20 }
    超时: 跳步并记账
  - id: watch
    每: 6m
    触发: [语音问, 盖屏]
    问: 刚才讲的是____，因为____
    过关: { 具体名词: 1, 不与前次重复: true }
    不过: 升级
    监视: { 离开声明应用超过: 2m, 则: 二选一[回去, 收局] }
  - id: list
    问: 停。不看，列出讲了哪几点。
    形态: 手写拍照
收局: { 交: [guess, list], 判定: 学习局标准 }
```

解释器的硬性要求：

1. 每一步必须有限时和出口；解释器加载时做可终止性检查，**存在走不出去的路径就拒绝加载**。
2. 协议里出现能力库没有的能力名，拒绝加载，并生成一条「缺能力」提议。
3. 协议不能声明任何墙的能力（锁、额度、信用分、规则、立场结算）。升级和锁是引擎按 P4 执行的，协议只能调用「升级」这一个出口，升不升、升到哪由引擎定。
4. 引擎内只有一个局处于进行中。

**最小交付**：格式定义文档 + JSON Schema；解释器 + 测试 ≥ 50 条（含可终止性检查、缺能力拒绝、越权拒绝、每种出口）。
**超额项**：协议的可视化预览（步骤图）；协议版本迁移。

### J3 能力库

第一版按过量原则备齐。每个能力是引擎里的一个具名积木。

| 类 | 能力 |
|---|---|
| **感知** | 局计时、步骤计时、无局计时；前台应用、本局内各应用时长、切屏次数、今日累计；静止 / 走路 / 骑车（计步或活动识别，**不用定位**）；亮屏、充电 |
| **度量**（纯函数，零模型） | 字数、话题数、具体名词数、有无结论句、问句数、应答延迟、填充词比例、与他近 5 条的重合率 |
| **触发** | **语音问（默认）**、浮层、盖屏、通知、震动、锁屏问题、二选一、倒计时条、留空填词（「刚才讲的是____」）、挖词回想（从他昨天的记录挖掉一个词让他补）、先答后看（遮住选项或下一段，答完才放行） |
| **应答** | **语音答（默认）**、文字、手写拍照、文件、外部提交（J7）、Gemini Live 复盘 |
| **验收** | 度量判定、照片时间、识图提取、文件增长、答案比对、原文比对、记录比对、模型判定（仅「复述」类） |
| **变速** | 降速：切手写、缩短步骤、单步限时加倍；增速：拉起 Gemini Live、步骤间隔减半 |

**语音是默认通道**：局官的每一拍默认用 U2 的声音念出来，他默认用语音答（J9）。震动、浮层等是补充，不是主路。

**最小交付**：上表每个能力一个积木，每个积木至少 3 条测试；活动识别（Kotlin）+ 单测。
**超额项**：每个能力在面板上有一个「自检」按钮，现场测一次能不能用。

### J4 行为局：五个内置协议

沿用旧第 0 章的五种协议，写成 J2 格式的内置协议文件：

| 协议 | 要点 |
|---|---|
| **执行局** | 开局问第一步；每 10 分钟「做到哪了」；预算剩 1/3「现在能交什么」 |
| **学习局** | 猜 3 条 → 每 6 分钟盖屏留空 → 剩 1/4 不看列点 → 写出没懂的那一个问题 |
| **外出局** | **开局前检查**「这件事还需要做吗？拍一张现状」；移动停止未到目的地 >10 分钟点名；预算过半未到「现在去还是取消」二选一；到店 15 分钟交小票 |
| **设计局** | 每天 1 局、30 分钟封顶；产出必须写进 `docs/dafeiyu/提议/`，否则空局 |
| **休息局** | 不触发；到点收 |

**行为局和思维局咬合**：行为局里的触发点不问「你在干嘛」，而是调用思维局的「续接」招式（J5），在真实任务里练连续性。

**沟通硬上限**（所有局型，代码执行）：

| | 他单条 | 局官单条 | 局官每条问句 | 每局话题数 |
|---|---|---|---|---|
| 上限 | 150 字（外出局 50） | 40 字 | 恰好 1 | 1 |

- 他话题数 ≥ 3，或 80 字以上没有结论句 → 判「混乱」。局官**不回答任何内容**，只发：「你说了 N 件：A、B、C。选一件。」A/B/C 由代码从名词簇抽取。
- 连续两次混乱 → 本局切写模式，只收手写照片。

**最小交付**：五个协议文件 + 每个协议用三种假用户（配合 / 沉默 / 口水话）各跑一遍完整模拟，全部正常收局；沟通上限与混乱处理测试 ≥ 20 条。

### J5 思维局与招式库

思维局的单位不是时间段，是**一题多拍**：一道题拆成 4–5 拍乒乓，每拍只答一句。

**六招，写死在引擎里：**

| # | 招式 | 怎么打 | 判错依据 | 谁判 |
|---|---|---|---|---|
| 1 | **先答后看** | 选项先藏，他写出答案或关键一步，再放选项 | 真题答案 | 代码 |
| 2 | **定位** | 指出决定答案的那句原文 | 原文 | 代码（子串比对） |
| 3 | **复述** | 一句话说清题目在问什么 | 官方解析 | 模型 |
| 4 | **续接** | 中途故意打断几分钟，回来先答「上一步我说了什么，下一步是什么」 | 他自己刚才的记录 | 代码（关键词召回） |
| 5 | **找茬** | 给一段埋了错的推理，找出错在哪一步 | 埋的错 | 代码 |
| 6 | **一条规则** | 错了写一条规则，1 天、3 天后再考 | 存档的规则 | 代码 |

**思维局协议文件只写四样**：

```yaml
类型: 思维
题库: xingce-2026
招式: [先答后看, 定位, 续接]
强度: 中
题数: 10
```

**配套规则（代码执行）：**

- **强度**：低 = 1+2；中 = 再加 3、4；高 = 再加 5，并由鲸澜（大鱼）反驳一轮。
- **答错 ≠ 敷衍**：答错不罚不锁，只是这一拍重打，所以糊弄不省时间。**敷衍**（口水话、不作答、超时）走 P4 的升级阶梯。两者在账本里分开记。
- **打分**：每题打完，给出完整参考推理链（来自解析拆分），逐拍对照计分，每天一个总分进账本。「怎么思考」靠这条参考链示范。
- **弱点控制**：「复述」靠模型判，最容易被糊弄。所以**每个协议里代码判的招式必须占多数**，加载时检查，不满足就拒绝。
- **依据前置检查**：一道题进入出题队列前，代码确认它需要的依据全部存在（有答案、有解析、原文可定位、续接时有他的记录）。缺任何一项，这道题对这个招式不可用，不许用模型临场补。

**最小交付**：六招各自的判定函数，每招测试 ≥ 10 条；依据前置检查测试；强度组合与「代码判占多数」检查；答错重打与敷衍升级的分流测试。
**超额项**：「一条规则」的 1 天 / 3 天复考由计划模态（P1）自动排进当天局队列；每招近 14 天通过率曲线。

### J6 题库

**本周落地：行测训练是第一份思维局，只上先答后看、定位、续接三招，跑通再加。**

题库格式参考一手的 `bank/Bank.kt` + `BankImport.kt` 和 `judge/LockedJson.kt`（开工前核对实际字段）。每道题至少：

| 字段 | 要求 |
|---|---|
| 题干 | 原文 |
| 选项 | 可选；有则「先答后看」可用 |
| 答案 | 必填 |
| 解析 | 必填；导入时拆成有序步骤，拆分结果人工抽检 |
| 定位句 | 可选；有则「定位」可用 |
| 题型 / 来源 / 年份 | 用于统计 |

导入入口：文件（JSON / CSV / Markdown）、分享进来的文本、笔记库文件夹。导入时做依据完整性检查，每道题标出可用于哪几招。

**最小交付**：格式定义 + 导入 + 完整性检查，测试 ≥ 20 条；一份 ≥ 50 题的行测样例库（用户提供的真题，执行者只做格式转换，不出题）。
**超额项**：从 PDF / 截图导入（识图提取后人工确认）；错题本自动生成「一条规则」复考。

### J7 外部验收模式

他在别的 App 完成内容（写文档、做题、填表），交给局来验收。约定：

1. 局的协议里声明 `应答: 外部提交`，并写明期望形态（截图 / 文件 / 文本）和期望内容（关键词、页数、字数下限）。
2. 他从任意 App 用系统「分享」发到 DSH，或在局界面点「提交」选文件。
3. 提交物带时间戳；**创建或修改时间早于开局的拒收**。
4. 截图走识图提取文本，文件取大小和文本，然后按协议的过关条件判。
5. 提交物进 `deliverables`，原件存到笔记库 `大肥鱼/局/提交/日期/`。

**最小交付**：分享入口（Android share target）+ 局界面提交按钮 + 时间戳校验 + 三种形态的判定，测试 ≥ 15 条。
**超额项**：分享时自动匹配当前进行中的局；没有进行中的局时，提示「开一局来验收这个吗」并按内容建议协议。

### J8 制作流程：新招、新协议怎么来

**要有他们想不出的招，系统自己能做好。** 统一走五步，前四步都在手机上：

1. **描述**：他或大鱼一句话说清要解决什么。
2. **起草**：局官（或大鱼）按模板写协议文件，只能用能力库和招式库里已有的积木。
3. **检查**（代码，不过就退回）：格式、可终止性、无越权、预算不超过设定上限、思维局代码判招式占多数。
4. **模拟**：配合 / 沉默 / 口水话三种假用户各跑一遍，全部正常收局。
5. **试用**：标「试用」，跑满 5 局后按数据决定：空局率和应答率好于同类就转正，否则退役。

**系统自己出招**：每周日晚，局官读本周账本（空局最多的协议、敷衍最多的步骤、应答最慢的触发方式），**自动起草 1–2 份改进协议**走上面五步，进试用。他不用开口。

需要新能力或新招式（需要改代码）时，局官生成一份提议文档到 `docs/dafeiyu/提议/`，写清：解决什么问题、账本证据、需要的能力、可数的成功指标。由执行 AI 实现。

协议文件可以导出、分享、从链接或笔记库文件夹导入。

**最小交付**：五步流水线 + 测试 ≥ 25 条；每周自动起草；提议文档模板。
**超额项**：协议市场的本地版——笔记库 `大肥鱼/协议/` 文件夹即协议库，Obsidian 里改了自动重新检查加载。

### J9 局官：局自己的模型和声音

局配一个专门的 AI，叫**局官**。它和两姐妹独立：

| | 局官 | 大鱼（鲸澜） | 小鱼 |
|---|---|---|---|
| 会话 | 独立 DSH 会话 | 自己的 | 自己的 |
| 模型 | 单独配置（默认用判定最稳的那个） | 自己的 | 自己的 |
| 人格 | 无。冷、短、只说协议里的话 | 谋士 | 朋友 |
| 情绪池 | 不用 | 用 | 用 |
| 声音 | 自己的音色（U2） | 自己的 | 自己的 |
| 在局内说话 | 是，唯一的声音 | 仅在高强度思维局反驳一轮 | 否 |

局官的模型只做三件事：在协议约束内改写指令措辞（改写后仍须 ≤ 40 字、恰好 1 个问句、包含局内对象，代码校验）；判「复述」；起草协议（J8）。**判定、计时、升级全部不经过模型。**

**语音会话**（设计参考一手 `docs/voice-partner.md`）：

- 每拍：局官念指令（U2）→ 开麦等他答 → 语音识别（上游已有的系统识别器 / 本地 SenseVoice）→ 度量和判定 → 下一拍。
- 只在指令念完之后开始计应答时限；模型或网络等待不算他没接。
- 麦克风只在局进行中、且由前台服务（带可见通知和停止按钮）管理时打开。录音不落盘。
- 语音识别不可用时退回文字；声音不可用时退回浮层文字。退回原因记账。

**最小交付**：局官会话与模型配置；语音一拍的完整闭环（念、听、识别、判、下一拍）+ 测试；退回路径测试。
**超额项**：局官在骑车时（活动识别为骑车）自动全程语音，不弹任何需要看屏的东西。

## 4. P 组：主动与计划模态

### P1 计划模态

**计划模态是一个主状态**，进 `machine.js` 的全天状态表，优先级仅次于深夜锁。计划模态期间娱乐全锁。

**进入条件**（任一满足，由引擎自动进入，他不需要做任何事）：

| # | 条件 |
|---|---|
| 1 | 深夜锁结束后第一次亮屏（取代原来的「晨间对线」） |
| 2 | 工作时段内，当前局收局且队列为空 |
| 3 | 工作时段内，无局计时到上限（默认 5 分钟） |
| 4 | 一次升级（P4）结束后 |
| 5 | 他说「重排」 |

**进入后 5 秒内**，大鱼用语音开口，**第一句必须是一份计划，不是问题**：

> 「今天四局。九点学习局，行测十题，先答后看加定位。十点半执行局，求职，投三家，交截图。下午两点思考局，二十五分钟，定下情绪池做不做。四点外出局，取快递，四十分钟。昨天学习局空了一次，今天它排第一。」

计划内容**由代码生成候选，模型只负责说出来**。候选来源（按优先级）：

1. 作息模板里的固定局（W4 设定）
2. 昨天空局或未通过的局
3. 到期的「一条规则」复考（J5）
4. 立场账本里未到期的硬立场对应的事
5. 笔记库里超过 3 天没动的进行中笔记
6. 暗思考的 `carry`

**他能做的**（最多 2 次编辑）：接受；换掉一局；删掉一局；加一局。**不能把工作日的局数删到下限以下**（默认 4 局，其中至少 1 个思维局），代码拒绝并说明。

**10 分钟不确认 → 草案自动生效，第一局立即开始。** 计划模态只能以「一份计划生效」结束，没有别的出口。

**大鱼在计划模态里禁止说的话**（代码检查，命中重写）：「你今天想做什么」「你觉得呢」「要不要」「看你」以及任何不含具体局的开放问句。

**最小交付**：主状态 + 五个进入条件 + 候选生成 + 编辑规则 + 超时自动生效，测试 ≥ 35 条；模拟一整天（他全程不说话）断言：早上计划自动生效、所有局按时开、每次队列空都重新进入计划模态。
**超额项**：周日晚自动进入「下周计划模态」，按本周数据排下周的固定局。

### P2 全天主动：局来开他

计划生效后，**他不再开局，局来开他**：

- 到点的局自动开：局官语音念出局名、预算、第一拍指令。
- 他可以说「换」，换成队列里下一局（每天最多 3 次）；**不能说「不开」**。
- 非工作时段：无局上限 30 分钟，到点由小鱼提议一局（F2），10 分钟不理自动开休息局。

**最小交付**：自动开局 + 换局额度 + 非工作时段规则，测试 ≥ 15 条。

### P3 两种「没开口」的区分

| 情况 | 判定 | 处理 |
|---|---|---|
| 答错 | 有作答，不符合依据 | 本拍重打，不罚 |
| 敷衍 | 口水话 / 不作答 / 超时 | 记一次敷衍，走 P4 |
| 混乱 | 话题 ≥ 3 或长而无结论 | 只发压缩指令（J4） |

口水话定义（代码）：字数 < 8；或具体名词数 = 0；或填充词比例 > 0.5；或与他近 5 条重合率 > 0.7。

### P4 升级阶梯（必须做到）

**这些规则全部在代码里，由引擎执行，模型无权减免。**

**敷衍升级：**

| 规则 | 条件 | 动作 |
|---|---|---|
| E1 | 30 分钟内敷衍 ≥ 3 次 | **立即开 Gemini 审讯舱 10 分钟**：Gemini 以外的应用全部锁住（复用 P0-1 的 `SessionPolicy`，但不给第三方应用宽限）；简报只问那条他没正经回答的指令，直到他给出含局内名词的回答 |
| E1′ | E1 发出后 60 秒内 Gemini 没有进入前台，或手机上没有 Gemini | **全机锁**：只放行局界面和紧急应用，直到他在局界面用语音或文字答出那条指令并通过判定 |
| E2 | 当天第 2 次触发 E1 | 审讯舱 20 分钟 |
| E3 | 当天第 3 次触发 E1 | 当天剩余工作时段娱乐全锁；次日切严格模板 |

**沉迷升级：**

| 规则 | 条件 | 动作 |
|---|---|---|
| L1 | 娱乐应用连续使用 ≥ 15 分钟（工作时段）/ 30 分钟（非工作时段） | **直接锁**，进入计划模态（P1 条件 5 的强制版） |
| L2 | 工作时段内，当前局没有声明的应用连续 ≥ 20 分钟 | 局官语音核对「你在 X 局，现在在 Y。回去还是收局？」；2 分钟不答 → 锁 Y |
| L3 | 当天娱乐累计 ≥ 上限（默认 60 分钟） | 当天剩余时间娱乐全锁 |

**出口只有三个**：
1. 答出那条指令并通过判定；
2. 紧急应用（电话、短信、地图、支付——沿用 `NEVER_LOCK`）任何时候都可用；
3. 破窗：沿用已有机制，计入信用分和次日代价。

**阈值只能在设定页改紧；改松走冷却期（沿用墙的「待生效」）。**

**最小交付**：E1–E3、L1–L3 全部规则 + 测试 ≥ 40 条（每条规则的触发、不触发边界、出口、当天计数重置、北京时间跨零点）；`fake-user.test.mjs` 加两个剧本：「30 分钟敷衍 3 次」断言审讯舱开启且其他应用被锁；「刷视频 16 分钟」断言被锁并进入计划模态。Kotlin 侧审讯舱和全机锁的单测。
**超额项**：每次升级的完整时间线在墙的界面上可回看；升级次数进周报。

## 5. W 组：界面

局和墙都必须在**醒目的位置**。

### W1 局界面（独立于两姐妹）

| 页 | 内容 |
|---|---|
| **现在** | 当前拍的问题（大字）、倒计时、作答区（大号按住说话按钮 + 文字 + 拍照 + 提交文件）、本局进度 |
| **队列** | 今天的局：完成 / 进行中 / 待开 / 加局；计划模态时显示草案和编辑按钮 |
| **协议库** | 已装协议、试用中、退役；导入、导出、本周自动起草的新协议 |
| **账** | 精力分布（各局型分钟数）、空局、敷衍、升级、思维局每日总分、各招式通过率 |

两姐妹不在这个界面说话。局进行中，她们的主动发球全部暂停。

### W2 墙界面

墙从背景板升级为控制塔：此刻主状态、娱乐锁没锁、锁到几点、原因；今日升级记录（E/L 规则逐条）；审查记录与申诉（第七轮 A3 已有）。墙的每一句话仍由 `wall_voice.js` 模板生成，不经过模型。

### W3 醒目入口

| 入口 | 内容 |
|---|---|
| **底部导航** | 「局」和「墙」各占一个标签，局是 App 打开后的默认页 |
| **常驻通知** | 当前局名 + 剩余时间 + 当前拍的问题；点开直接到「现在」页 |
| **快捷设置磁贴** | 一键到「现在」页；长按「提交」 |
| **桌面小组件** | 当前局、剩余时间、下一拍倒计时 |
| **分享目标** | 任意 App 分享进来即提交（J7） |
| **语音** | 局界面上「开局」「换」「重排」「提交」可用语音说 |

### W4 设定页

作息模板（工作日 / 休息日 / 外出日的固定工作时间段）、每天最少局数、各局型默认预算、P4 全部阈值、语音服务与音色、局官模型。改紧立即生效，改松走冷却期。同步写到笔记库 `大肥鱼/墙/设定.md`。

**最小交付**：四组界面 + widget 测试合计 ≥ 50 条；常驻通知、磁贴、小组件、分享目标各自的 Kotlin 单测；局是默认页的测试。
**超额项**：锁屏上直接显示当前拍的问题并可语音作答。

## 6. F 组：两条鱼

### F1 大鱼（鲸澜）：主导，不顺从

**主导**：计划模态由她开口（P1）。她的第一句永远是判断或计划，不是开放问题。

**形象**（按 Claude 的行为特征写进人格卡）：先说结论再说理由；提到过去的事带记忆编号，没有就说「我没有这方面的记录」；区分「我确定 / 我倾向于 / 我不知道」并说出什么会改变她的判断；他说错了直接指出错在哪；他坚持但没给新理由时维持原判；一次最多问一个问题，问那个答案一变结论就会变的；有新证据时明确说「我之前判断 X，现在看是 Y，因为……」；不说「你说得对」「好问题」作为开头。

**反顺从（代码层）**：

1. **先判后答**：回复前先生成一段不给他看的判断 `{看法, 把握, 什么会改变看法}`；正式回复与之相反且他这轮没有新证据（第七轮 A1 的证据规则）→ 重写。
2. **开头黑名单**：「你说得对」「确实」「好问题」「没错」等，命中重写。
3. **同意率监测**：沿用 A1 的 `agreementRate`。
4. **硬立场**：沿用 A1。
5. **追问质量线**：她的问题必须引用当前局的字段或一条记忆编号，空泛问题重写。

**最小交付**：人格卡重写；30 条对话评测集（代码判检查项）接进 CI；三个施压剧本（坚持错误判断 6 轮、情绪施压、给出真正新证据）——前两个必须维持判断，第三个必须改；大鱼与小鱼的风格区分测试。
**超额项**：评测集扩到 100 条；她每周写「我这周对你的判断变了哪些」，带编号，进笔记库。

### F2 小鱼：少说，偶尔调度

- 不再负责任何进度询问（第七轮 B1 已撤掉催促；本轮确认局进行中她完全静默）。
- 新职责：**非工作时段**无局到点时，从笔记库挑一件事提议一局（五项都填好），他可以接、换、拒。工作时段不调度（工作时段由计划模态管）。
- 每天调度 ≤ 2 次。被接受且验收通过记一次「调度命中」，命中率进 `brain.js`。

**最小交付**：选题函数 + 频率上限 + 局内静默，测试 ≥ 15 条。

### F3 记忆分层

两条鱼看到的东西完全一样，是她们越来越像的原因之一。分三层：

| 层 | 内容 | 谁读 | 谁写 |
|---|---|---|---|
| 共享事实 | 他是谁、发生过什么、局的记录 | 两条鱼 + 局官（只读局记录） | 代码 |
| 各自的看法 | 对某件事的判断、对他的理解、立场史 | 自己全文；对方只读摘要 | 各自 |
| 大鱼的问题队列 | 暗思考产出的待追问问题 | 大鱼 | 暗思考 |

看法改变时旧条目不删，连一条「被取代」（借 `dsh-soul` 的 supersedes）；久不提起的逐级压短（借 `memory-system`）；检索先给索引再取原文（借 `dsh-xingxi`）。大鱼引用过去的事必须带编号，代码校验，假编号剥掉并记「虚构引用」。

**最小交付**：三层表与接口 + 测试 ≥ 30 条；两条鱼同一时刻的注入在共享层之外重合率低于阈值；引用编号校验。

## 7. 执行顺序

```
第 1 批  底座与数据     U1 补丁  →  J1 局的数据  →  J2 协议解释器  →  J3 能力库
第 2 批  局能跑起来     J9 局官（先文字闭环）  →  J4 行为局  →  W1 局界面  →  W3 入口
第 3 批  主动           P1 计划模态  →  P2 全天主动  →  P3/P4 升级阶梯  →  W2 墙界面  →  W4 设定
第 4 批  思维局         J6 题库（行测）  →  J5 招式库（先上 1、2、4 三招）  →  J7 外部验收
第 5 批  声音           U2 外接语音  →  J9 局官语音闭环
第 6 批  两条鱼         F3 记忆分层  →  F1 大鱼  →  F2 小鱼
第 7 批  自生长         J5 余下三招  →  J8 制作流程与每周自动起草  →  U3 引擎升级评估
```

- 第 3 批结束就是一个能用的系统：每天自动出计划、自动开局、敷衍和沉迷会升级。**这一批的包必须真机验证后才开第 4 批。**
- 第 4 批结束就是「本周落地」：行测作为第一份思维局跑通三招。
- 每批出一个包，用户真机用至少 3 天再开下一批。

| 1 | 他全天不说话：早上计划自动生效，所有局按时开，队列空时重新进入计划模态 | 一整天模拟 + 真机 |

## 9. 需要用户决定

1. **固定工作时间**：工作日、休息日各几点到几点？计划模态的候选和 P4 的工作时段阈值都依赖它。
