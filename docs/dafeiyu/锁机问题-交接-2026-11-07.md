# 锁机问题 · 交接文档（给接手的 AI）

> 2026-11-07。用户真机反馈："锁机只能锁一次，之后就控不住了；锁屏页有紧急退出，等于只是个弹窗。"
> 用户说这块交给别的 AI 改。下面是我读代码查到的原因、位置和建议改法。**除了第 4 节列的两处，锁的逻辑我没动。**

## 1. 锁是怎么走的

```
插件 /plan（dsh-go-companion/lib/force.js decideForce）→ force.level ≥ 3
  → Kotlin ProactiveRuntime.applyPlan() 记一个 Force（只保持 FORCE_HOLD_MS = 3 分钟）
  → enforce()：level 4 先 GLOBAL_ACTION_HOME，再 InterceptRuntime.forceBlock()
  → InterceptGuard.force()（loop/core/Intercept.kt）决定 Block / Allow
  → InterceptRuntime.show() 抢 VisibleSurface 槽位 → 启动 InterceptPageActivity（锁屏页）
  → 锁屏页：做题放行（10 分钟）/ 暂停 / 加白名单 / 紧急退出（回桌面）
```

相关文件（都在 `app/android/app/src/main/kotlin/io/github/ccch1mneyyy/dsh_app/` 下）：

- `loop/proactive/ProactiveRuntime.kt`：`applyPlan`、`onForeground`、`enforce`、`FORCE_HOLD_MS`
- `loop/intercept/InterceptRuntime.kt`：`forceBlock`、`show`、`onPageGone`
- `loop/core/Intercept.kt`：`InterceptGuard.force`、`endOpen`、`onExited`
- `loop/intercept/InterceptPageActivity.kt`：`onStop`、`onDestroy`、`exit`
- `loop/core/SurfaceSlot.kt`：`VisibleSurface`，全局同时只许一个 DSH 页面

## 2. "只能锁一次"的原因（按可能性排）

### A. 锁屏页没正常结束，guard 一直以为"还开着"（最可能）

- `InterceptPageActivity.onStop()` 只在屏幕亮着且 `!isFinishing` 时调用 `exit()`。灭屏时被盖住、被系统回收、`isFinishing` 为真时都不调用。
- `onDestroy()` 只调用 `InterceptRuntime.onPageGone()` 释放 VisibleSurface，**不会结束 guard 里的 `openEventId`**。
- 之后每次 `InterceptGuard.force()` 一进来就是 `if (s.openEventId != null) return allow(ALREADY_OPEN / ANOTHER_OPEN)`。锁再也弹不出来，直到 App 进程重启（重启时 `recover()` 会把它记成 `open_lost`）。
- **建议改法**：
  - `onDestroy` 里如果 `!reported`，调用新的 `InterceptRuntime.onPageLost(id)`，再走 guard 的 `endOpen(BLOCKED, "page_gone")`。
  - 再加一道保险：`force()` 发现 `openEventId` 存在，但锁屏页实际不在（`InterceptPageActivity` 没有存活实例，或 `openSinceWall` 超过 `PAGE_TTL_MS`），就先结束旧的再锁。

### B. 聊过天的浮层占着 VisibleSurface 槽位

- 浮层里回一句，会上报 `SurfaceReport.Answered`。Coordinator 把事件关掉（`close()`），但**不发 Withdraw**，所以 `ProactiveOverlay` 的 `releaseForNow()` 不会被调用。浮层窗口还在（20 分钟后收成气泡，气泡也一直占着），槽位一直归 `OWNER_PROACTIVE`。
- `InterceptRuntime.forceBlock()` 第一行：`if (!VisibleSurface.isFree() && !isHeldBy(OWNER_INTERCEPT)) return false`。所以跟她聊过之后，锁一直失败，日志是 `companion force=4 … shown=false`。
- **建议改法（一行）**：`ProactiveOverlay.Card.sendNow()` 里，第一次 `report(Answered)` 之后紧接着调用 `releaseForNow()`；或者 Coordinator 处理 `Answered` 时对 ACTIVITY 面发一个 `Withdraw`（ProactiveOverlay 的 withdraw 本来就只释放槽位、不关窗口）。
- 拒绝模式那条路径我已经这样处理了（见第 4 节）。普通锁还没改。

### C. 赶回桌面后，"连续停留"清零，力度掉回 0

- 插件按 `phone.minutes`（当前 App 连续停留分钟数）判锁。被赶回桌面再打开游戏，NowFeed 的停留从 0 开始，`decideForce` 又回到"说"。只有"今天累计"超过 `lockToday` / `homeToday` 才会再锁。
- Kotlin 侧只保持 3 分钟（`FORCE_HOLD_MS`），过了这 3 分钟重新打开就能玩。
- **建议改法**：插件记住"几点对哪个 App 下了锁"，`lockHoldMs`（比如 20–30 分钟）内这个 App 一出现就直接锁。连续停留也要把短暂离开（< 5 分钟）接上，不清零。

### D. 锁屏页本身就很好绕开

- **紧急退出**：一点就回桌面，记为 `EXITED`，不放行。但见 C，回来后很快又能玩。
- **做题放行**：点数字 + 停留，就能拿 10 分钟通行证。`force()` 承认这张通行证（`releases[pkg]`）。
- 锁屏页是普通 Activity：Home 键、最近任务都能离开（离开会触发 `onStop` → `exit()`）。
- **建议改法**：
  - 锁屏改成跟浮层一样的 `TYPE_ACCESSIBILITY_OVERLAY` 全屏窗口（无障碍服务已经在用），Home 键盖不掉。
  - 紧急退出保留（安全需要），但改成长按 5 秒，并且计数。计数到了插件会知道，让姐姐来找他。
  - 普通锁的放行改成"跟她讲通了才放"（`/say` 判成真反驳 → `release`），不再是做题。

### E. 其他会让锁"没反应"的情况

- `env.dshBusy`（DSH 正在操作手机）→ 放行。
- 无障碍服务没开 → `GLOBAL_ACTION_HOME` 不生效，NowFeed 也拿不到前台。
- 白名单里的 App 永远不锁。

## 3. 怎么验收

1. 打开游戏 → 被锁 → 灭屏 → 亮屏 → 再打开游戏：**要再次被锁**（现在不会，原因 A）。
2. 在浮层里跟鱼丸聊两句不关窗口 → 打开游戏到锁的阈值：**要被锁**（现在不会，原因 B）。
3. 被赶回桌面 → 4 分钟后再开同一个游戏：**要直接锁**（现在不锁，原因 C）。
4. 每次失败都看 logcat 的 `DshProactive` / `DshIntercept`：`shown=false` 的原因要能看出来，建议在 `forceBlock` 返回 false 时打出原因。

## 4. 这一轮我在锁附近改过的两处（拒绝模式需要）

- `InterceptGuard.force(…, strict)`：拒绝模式下不认做题拿到的 10 分钟通行证。
- `ProactiveRuntime.enforce`：**只在拒绝模式下**，如果浮层还占着槽位，先释放（窗口不关）再锁。

拒绝模式本身：他说"拒绝模式 / 拒绝模式 2 小时"，插件把到期时间存进 `config.refuseUntil`，并在 `/plan` 里回 `refuse.until`。手机记住这个时间，每次切到娱乐清单里的 App，**当场**回桌面并锁，不等 /plan 返回。他说"关掉拒绝模式"或者到点才解除；讲理由也不松。
