## 3. 逐条核对上一轮的分析

| 上一轮判断 | 核对结果 |
|---|---|
| 观察球没有观察数据 | **属实**。`compose(_req, …)` 完全不看请求体；`validateRequest` 还会把未知字段丢掉。App 侧 `NowFeed` 早就有前台 App/停留/亮屏/充电，只是没传。→ 已修 |
| 频率太低 | **属实，而且是两层**：插件（每小时 3、每天 6、间隔 45 分钟）+ 手机调度器（随机 45 分钟–3 小时、每天 6、你一回话就推迟 20 分钟以上）。→ 插件侧已修；手机侧见 §5-3 |
| 漠视要等点"看到了"才计时 | **不属实**。插件阶梯从"生成那一刻"算，不依赖点「我看到了」。真正的问题是：阶梯那一级**从没被闹钟排上**——`/plan` 在"刚发完"时按 30–45 分钟冷却回答，手机就把唯一的闹钟定在那里；5 分钟那一级只有恰好你在动手机（窗口事件触发检查）时才可能走到。→ 已修 |
| 两张人格卡都没起作用 | **属实**。→ 已合一（关系库打底，配置覆盖） |
| 回合不沉淀成记忆 | 属实，未做（§5-4） |
| fish-strict 与 companion 上限不合并 | 属实，未做（§5-6） |

另外查出两个底稿没写的问题：

1. **一停就永远停**：连续没接触发 `stop` 后，只有"他回了某一球"才能解除；可 `stop` 本身拦住了所有新球，旧球 2 小时后也不再等回复——死锁。→ 已修：最后一球后歇 3 小时，旧账清零。
2. **换渠道那一级走不到**：规则是"5 分钟换轻球、15 分钟换渠道、连续 2 次没接就停"。可 5 分钟补了轻球，就已经是第 2 次没接，直接停了，15 分钟那级永远到不了——P4 的语音正好挂在这一级上。→ 已修：改成 3 次（原球 + 轻球 + 换渠道），时间从第一球算。

## 4. 这次改了什么

**插件 `dsh-go-companion`**
- 新增 `lib/phone.js`：清洗手机现状，拼成"手边的情况"几行进 prompt（只写事实，不写包名，不让它说"我看到你的手机"）。
- 正开着娱乐 App ≥10 分钟或今天娱乐类 ≥60 分钟，这一球优先打观察；没有手机现状就不打观察球。
- `silence.js` 阶梯重写：时间从第一球算，每级只走一次，错过就跳级；3 次没接才停；歇 3 小时恢复。
- `plan.js`：等待阶梯时回 `ladder-wait` 和下一级的准确时间；掷骰没中时按 `minGap` 而不是写死 30 分钟。
- 教练模式单独一套频率：最小间隔 8 分钟、每小时 6、每天 40（`/config` 可调）。
- 上限只数"新开的球"和"阶梯补的球"，他接住后接着打的不占额度。
- 人格卡合一：读关系库 `persona` 表（价值观/底线/边界/口吻/兴趣）打底。
- 新测试 `cadence.test.mjs`（12 项，含路由端到端）和 `manifest.test.mjs`（部署清单守卫，故意删一行会变红）。

**App（Kotlin / Dart）**
- `NowFeed` 加"今日各 App 累计时长"（同一套无障碍事件，不轮询），跨零点清零但不打断当前停留。
- `AgentWire.requestBody` 可带 `phone`；`ProactiveRuntime` 发球时附上（App 名优先用拦截列表里的中文名）。无障碍从没喂过数据时不带——"不知道"不等于"没在用手机"。
- 一球结束后立刻问一次 `/plan`，让插件的阶梯时间盖过手机调度器随机的 45 分钟–3 小时。
- 主动交流设置页"每日上限"加 20 / 40 两档。
- `BuiltinPluginGuest.kt` 部署清单加 `lib/phone.js`。

**没验证的**：`ProactiveRuntime.kt` 的改动需要 Android SDK 才能编译，这台机器没有；`NowFeed` / `AgentWire` 和整个 `loop/core` 单独编译测试过。**全部未装真机。**

## 7. 离"几十秒看一次屏幕、主动沟通、能控机"还差什么

- **"看"已经有一半**：无障碍事件流本来就在实时更新前台 App 和停留时长，零成本、不读文字。这次只是把它送进了发球。
- **不要每几十秒调一次模型看屏**：贵，且大部分时候没东西可说。建议分四层：
  1. 事件层（一直开着，免费）：前台 App、停留、亮屏、充电；
  2. 本地规则层（免费）：停留超阈值、进了娱乐 App、偏离专注目标——决定"值不值得看一眼"；
  3. 读屏层（便宜，不用模型）：用已有的 `TreeCapture` 读无障碍树文字，只在第 2 层说值得时读；
  4. 模型层：只有前三层觉得有话可说才发球。
- **控机**：主动回合现在刻意禁用了所有工具（`core.js`：proactive turn 不许操作手机）。这是对的。要做"帮你把 B站 关了"，应该是：球里提出一个动作 → 他点"好" → 转成一次普通 DSH 任务、走现有的手机控制和确认流程。不要让主动回合自己动手。
