### 这一拍到底怎么走

```
局官开口（U2 的嘴，局官那把音色）
   ↓  念的这段不计时（hold）
念完 / 念不出退回文字 → 告诉局官「到了」
   ↓  应答时限从这一刻起算（spoken）
开麦（底座系统识别器）
   ↓
听见了 → 交给局官判（boutrun 的 answer）
听不见 → 停在「等一句话」，他自己打字交，或者按停
   ↓
下一句由局官的答复带回来 → 接着念；周期步则等到点再问
```

### 做了什么（四块）

1. **「念完才开始计应答时限」落在 runner 上，不落在界面上**（`protocol.js`）

   `createRunner` 里加一个 `speakBy`：`speakHold(at)` 把时间冻到 `at + SPEAK_HOLD_MAX`，
   `tick()` 先判 `speaking`（返回 `reason: 'speaking'`，不往前算），过了上限就把
   `askedAt` 对到 `speakBy` 再继续判。`spoken(at)` 直接把 `askedAt` 设成 `at`、清掉冻结，
   **不动 index、不动 retries**——念完只是「时间到这儿才算数」，不是替他答了一拍。
   上限 60 秒（`SPEAK_HOLD_MAX`）是兜住声音卡死：不设上限的话，一个卡住的 TTS 会让这一拍
   永远不计时，比罚他听还糟。

2. **语音这一路单独一条入口，文字那两条一个字没改**（`index.js`）

   `POST /bouts` 现在按 `body.action` 分发，四个动作：`ask` / `spoken` / `answer` / `fallback`。
   **没有 `action` 时行为与原来的 `boutsShareRoute` 完全一致**（分享进来的文字照旧是当前这一拍的答案），
   有专门用例钉住这一条。

   `answer` 带 `hold=true` 才冻计时——只有语音这一路开，因为只有它有 `spoken` 那一步来解冻。
   文字面板和分享路径不传 `hold`，行为与老路径逐字一致。`fallback` 不需要有局在跑，
   记一笔 `bout-voice-fallback` 就回，面板能看见为什么退回。

3. **一拍闭环的状态机在 Dart 侧**（`app/lib/companion/bout_voice.dart`）

   为什么不在插件里：插件的 `voice` 能力是「陪听」（`SpeechGate` 只发 speechStart/speechEnd），
   拿不到识别文字；识别文字只有 app 侧的 `MethodChannelVoiceBridge` 有。所以插件只管
   「这一拍该说什么、判过关、记拍」，顺序由手机驱动。

   `BoutVoiceLoop` 七个阶段：`asking → speaking → listening → judging → (下一拍 | waitingAsk | waitingText | done)`。
   `submit(text)` 只在 `waitingText` 时有意义；`stop()` 之后飞回来的识别结果不再交上去判
   （有用例钉住）。

4. **界面上多一页入口**（`app/lib/ui/companion/bout_voice_page.dart` ＋ `feature_catalog.dart`）

   「全部功能」里加一条 `bout-voice`（局 · 语音）。选 `FeatureItem.native` 是因为它最便宜：
   不改通用面板渲染器、不在通用代码里加局的特判，而且自动获得 `dshgo://open/bout-voice` 链接。
   念的句子、听见的话、退回原因、当前阶段都摆在屏上，`waitingText` 时给输入框和「交这句」。

### 我为什么这么选

| 选择 | 没选的那个，以及原因 |
|---|---|
| 识别用底座已有的系统识别器 | 没接本地 SenseVoice：那要 `DshClient` + 模型目录（`_readCatalog` / `_transcribe`），耦合太重。施工书写的是「系统识别器 / 本地 SenseVoice」二选一 |
