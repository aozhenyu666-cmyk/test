# 大肥鱼（DSH Go）功能全景 —— 自包含技术评审材料

> 写给一个比我们更强的 AI。**你不需要读代码库、不需要翻缓存。** 这份文档把该系统做了什么、边界在哪、哪里没做、哪里可能错，全部写在这里。
> 基线版本：`fish-build-159`（commit `2c345866`，2026-11-16）。项目私有，Android 单机，不分发。
> 生成时间：2026-11-17。

---

## 0. 先看这四句话

1. **DSH = DeepSeek Harness**，一个 Android 上的 DeepSeek 客户端：Flutter 外壳 + 内置 Node 运行时 + 本地 Agent 引擎 + 插件系统 + 手机操控能力。
2. **大肥鱼**是在这个基线上叠出来的一整套系统，目标只有一句：**每天把用户的时间变成一串「局」，每一局都做完一件说得清的事。**
3. 实现形态很特别：**执法在代码里（纯函数、可测），陪聊在模型里**。模型没有减免规则的权力，规则也不依赖模型的自觉。
4. 它已经跑了很多轮迭代（当前是第九轮 + v4.1），**功能远超一个"自律 App"，但真机验证几乎为零**。这是最大的未知，请重点从"哪里会在真实使用中崩掉"入手。

## 1. 基线：DSH 本身是什么

| 层 | 技术 |
|---|---|
| 外壳 | Flutter（Dart），Android |
| Agent 运行时 | 内置 Node.js，随 APK 打进 assets，启动时铺到 `/opt/dsh-app/` |
| 模型 | DeepSeek（用户自己的 API Key，走 DeepSeek 官方接口） |
| 插件系统 | 类 Cordis 的插件包（`package.json` + `cordis.patch.yml` + `lib/*.js`），启动时装载 |

**下面所有内容都是我们在大肥鱼这一层加的。**

## 2. 设计前提（理解一切功能的钥匙）

- **单用户、单设备、长期使用**。不是产品，是一个人的工具。没有多租户、没有云同步。
- **数据留在手机上**。记忆库是手机本地 SQLite（`fish-memory.sqlite`），不上传。
- **模型天生宽容**：给它一段像样的话它就说"不错"。所以「验收」不能靠模型自由发挥。
- **模型看不见现实**：它不知道用户到底投没投简历。所以证据必须来自代码能读到的东西（文件、时长、截图时间、外部提交）。
- **验收标准必须在开局前定好**，否则一定被临场放宽。
- **人设不能代替能力**：以前人设里写"她们有权力开局"，但代码里根本没有开局工具，于是只能催。**凡是写进人设的能力，必须有对应的工具或代码路径。**
- **权力要能还回去**：否则系统只会越来越紧，最终用户受不了把它卸掉（历史上真发生过一次）。

## 3. 核心模型：一天的流水线

```
 前一晚                早上                 白天（每一局）                       晚上
┌──────────┐      ┌──────────┐      ┌───────────────────────────┐      ┌──────────┐
│ 鲸澜备课  │ ───→ │ 计划模态  │ ───→ │ 开局 → 第一步 → 触发 → 交付 │ ───→ │ 对账      │
│ (调度)    │      │ (调度)    │      │      ↑ 偏离 → 预案 / 墙     │      │ (验收汇总)│
└──────────┘      └──────────┘      │      ↓ 交付 → 验收器        │      └────┬─────┘
      ↑                              └───────────────────────────┘           │
      └──────────────────── 行为大脑：模式、法规、权柄 ←───────────────────────┘
```

三个器，各管一件事：

| 器 | 管什么 | 具体职责 |
|---|---|---|
| **调度器** | 资源（时间、App、注意力） | 备课、计划模态、开局、预案、墙（锁） |
| **触发器** | 在某一刻给一个具体动作 | 局官（局内）、鱼丸（局外）、Gemini Live 连麦 |
| **验收器** | 证据 | 交付物、验收、对账 |

**「局」（bout）是这个系统的原子单位**，不是时间段。一局 = 一个工作包 + 一个工作时段 + 一套验收标准。

**工作包（work package）七个字段**（每局必须写全，缺一个就不许进计划）：

| 字段 | 例（求职局） |
|---|---|
| 目标（一句话） | 投出 3 份简历 |
| 第一步（2 分钟内能开始的物理动作） | 打开 Boss 直聘，筛选「上海·后端·1–3 年」，看前 10 个 |
| 后续步骤（≤5） | 选 3 个 → 改简历第二段 → 投 → 截图 |
| 必需应用 / 允许应用 | Boss 直聘、WPS / 浏览器、微信（只读） |
| 交付物 | 3 张投递成功截图 |
| 验收方式 | 截图时间在开局之后、能读到「已投递」、3 张 |
| 卡住时 | 第一步做不下去 → 局官切「卡在哪」小局；20 分钟无进展 → 鲸澜介入 |

第一步有代码检查：必须含一个动词、含一个应用或物件、不超过 40 字。

**验收方式只有三类，按可信度排**：

| 类 | 怎么判 | 谁判 |
|---|---|---|
| **证据** | 文件变化、截图（时间+识图）、使用时长、外部提交 | 代码 |
| **依据** | 与标准答案、原文、他之前的记录比对 | 代码 |
| **判断** | 按事先写好的评分标准，引用原文打分 | 判官模型，只在前两类用不上时才用；一天最多 2 个 |

## 4. 四个角色

| 角色 | 是什么 | 说话方式 | 能做什么 |
|---|---|---|---|
| **鱼丸**（妹妹） | 陪伴人格 | 嘴欠、抬杠、玩梗、会吃醋、心疼但嘴上不饶人；短句；不给清单不分析 | 局外拉他回来（「理我一下」）、损他、抢回桌面、聊天陪伴 |
| **鲸澜**（姐姐） | 谋士人格 | 冷静、看得远、结论先行、默认 1–3 句；大事才做五步推演 | 备课、排局、还原局面、摆 2–3 条路（前提/代价/成功率/最晚决策点）、查资料、对账 |
| **局官** | 局内唯一声音 | 极简，只对着工作包问（「第一步做了吗」「现在第几步」「交付物几张了」） | 触发、判偏离、切小局、收交付 |
| **墙** | 不聊天的执法者 | 不说话、不谈判，只出裁决 | 锁娱乐、判验收、出审计、接申诉；纯函数，跑在插件里，不进模型 |

两个姐妹共享同一套记忆，但**人设、口吻、职责严格分开**。每条消息前标〔鱼丸〕/〔鲸澜〕。
姐妹之间可以递话（`sister_note`）：递过去的话 24 小时内出现在对方每一轮的人设里，像"悄悄话"。

└───────────────────────────┬─────────────────────────────────┘
                            │ 本地 HTTP（/dsh-go-companion/v1/*）
┌───────────────────────────┴─────────────────────────────────┐
│ Node 插件层  app/assets/engine/plugins/                       │
│   dsh-go-companion  93 个模块，index.js 7229 行  ← 决策全部在这 │
│   dsh-go-memory     8 个模块（本地记忆权威）                   │

**关键的架构约定**：插件决定「说什么、锁不锁、升到哪级」，手机执行「锁、退回桌面、发通知」。
决策与执行分离，所以决策可以在 Linux 上跑全量测试。

## 7. 功能域清单

### 7.1 主动性（dsh-go-companion）

一个**唯一的决策与回合服务**。手机端闹钟"到点"后调 `POST /request`，这里决定「现在说不说、说什么、说给谁」，每一步写进账本。

状态机：`accepted → claimed → generated | failed | cancelled`，再由 `/outcome` 记 `delivered / displayed / replied / substantive / dismissed`。

核心机制：

- **本地决策零模型**（`POST /plan`）：开关、安静时段、日上限、最小间隔、掷骰、话题选择，全在本地算。没命中就不消耗模型额度。
- **话题花园**：话题不只是"从记忆里捞一条"，而是有生命周期的独立清单。生成类型 `continue/share/explore`，连续两次追问自动换类型避免变问卷。`nextTopic()` 返回 null 就**不发空泛问候**。
- **连续性纪律**：`lastSentSummary`（我说过什么）与 `lastSummary`（我们聊过）严格分开 —— 不会把"我说过"说成"我们聊过"。
- **跟进梯度**：`substantive` 继续 / `brief` 2h 后换轻的 / `avoid` 12h / `refuse` 结束 / `none` 最多两次（4h、一周）。
- **升级阶梯**（`ladder.js` + `escalate.js`）：一球没接 → 5 分钟补一球 → 15 分钟轻球 → 换渠道 → 三球都没接才停，停后歇 3 小时清账。**所有规则在代码里，模型无权减免。**
- **套话守卫**（`stock.js`）：命中「你在做什么」「下一步是什么」「加油」「你可以的」这类模板就重写一次，还像就换一种球。
- **反敷衍冷处理**（`withdrawal.js`）：连续 2 次 brief/evasive 回复且无实质行动 → 45 分钟极简冷淡退场，不再哄不再催。

### 7.2 行为大脑（水位 / 脾气 / 大脑 / 力度）

- **水位 `tide.js`（0–100）**：清醒 / 在滑 / 在沉 / 陷住了。**不是定时器，是连续量** —— 陷得越深开口越勤、语气越硬、手越重；回到清醒就退回去。在沉/陷住时不掷骰子。
- **脾气 `temper.js`**：哄/逗/冷/怼/训 五种底色，随模式（温和 0.25 / 严格 0.7）漂移，偶尔翻脸。
- **大脑 `brain.js`**：Thompson 抽样挑"脸"；近端结果 = 发球后 10 分钟内离开娱乐 App 或认真回球；思维题弱项加权；判断从证据重算，翻了就记 revision。
- **力度 `force.js`（0–4）**：说 / 追 / 屏 / 锁 / 赶。不掷骰子，由前面几层算出来，手机执行锁或回桌面。

### 7.3 行为雷达（v4.1，`behavior_radar.js`）

**0 毫秒先行落锁** —— 先落锁再说话，不是先说话再落锁。

| 条件 | 后果 |
|---|---|
| 晨间还没立项就连刷 ≥3 分钟 | 锁 |
| 连刷 ≥12 分钟，或 15 分钟内切换 App ≥8 次 | 自动封禁 |
| 连续 2 次敷衍 | 30 分钟硬件级拒绝锁 |
| 有判球宽限（`graceUntil`） | 尊重宽限，仍拦截租约偏航 |

### 7.4 记忆（dsh-go-memory）

手机本地记忆权威，唯一写入口和读入口。SQLite（WAL）。

v4.1 的改动（对应"没有记忆"的抱怨）：

- **常驻档案**：不再是"最后一句字面重合"才召回。「嗯」「好烦」这类对不上时**补位**给相关事实。
- **原话留底**（`lib/dialog.js`）：保留他的原始表述，不被摘要替换。
- **随手想起**：每 20 分钟想起一条旧事。
- **笔记库翻页**（`notes.js`）：每 30 分钟两姐妹各翻一篇（新旧各半，系统产出和太短的不翻），进每轮的内容层。
- **kind 认中文**：「小事」这种中文 kind 以前不认，现在认。
- **跨会话共享**：两人记关于他的事都加 `share: true`；v4.1 做到双姐妹记忆互通。

### 7.5 墙（执法）

`wall.js` —— **纯函数规则引擎**，跑在插件里，不经过模型。把"内部规则表"算成「现在娱乐锁不锁、锁到几点、为什么」。

- 规则表存在 config，用户改表不必改代码。
- **笔记库那一半**（`vault_wall.js`）：`大肥鱼/墙/规则.md` 他能在 Obsidian 里直接改（frontmatter 四项）；`待生效.md` 是改松的规则，冷却期过了才生效；`审计/日期.md` 存每次审查原话。
- **墙的眼睛**（`wall_eye.js`，v4.1）：交验收、文件证据在代码层已过时，读立项后新写的 ≤3000 字，问模型「是不是真在做这件事」。规矩很克制：**只能把「过」改成「不过」，判不过必须引得出原文，模型连不上就退回代码结论并说明。截图不读**（DeepSeek 无识图）。
- **申诉**：`/wall/appeal`，`/wall/thread` 存申诉线索。

### 7.6 法典（`codex.js`）

不新造规则，只把散在七八处的已有规则**收成一张有编号的表**，分四级：

| 级 | 含义 | 谁能改 |
|---|---|---|
| 宪法（C） | 永远成立的边界 | 只有他，7 天冷却 |
| 法律（L） | 长期规则（作息、最少局数、升级阈值、深夜锁） | 他改松走 24 小时冷却 |
| 法规 | 设定类，可调 | 他改，24 小时冷却 |
| 判例（P） | 墙对具体事件的裁决 | 不可改 |

宪法里还没真正做到的条目，照实标「尚未执行」，不假装已经有。

### 7.7 立场账本（`stance.js`）

**问题**：她今天说「这件事必须 6 点前做完」，被磨三句就改口「那明天也行」。
**做法**：把「她说过什么」变成带 `until` 的约束对象 —— `hard` 立场在到期前**没有修改它的工具**，只有三件事能让它变：到期、墙按证据判定完成、用户在晨间窗口重定计划。改口有代价。

### 7.8 预判账本（`predict.js`）

鲸澜可以写 claim、可以写自己的解读，但**不能写 verdict**。verdict 只由 `settle()` 按墙的遥测算出，`verdict_source` 固定 `WALL_TELEMETRY`。模型想说一句"果然重演了"没有门 —— 它写的东西进不了这个字段。

### 7.9 工作记忆挂载卡（`mount.js`，C1）

解决「推导到一半断掉，回头不知道自己在解决什么」。一张卡固定三栏：目标（1 条）、已知条件（≤5）、中间结论（≤5）。
**铁律：卡里只能是他自己的话。** `isUserText()` 要求每条 text 是某条用户消息的子串，或他在面板上手写。她自己总结的话进不来 —— 代码校验，不靠她自觉。

### 7.10 挣来的娱乐（`earned.js`）

把「今天能不能玩」从监狱改成交换：每通过一局验收，当天多一段放风额度；额度用完之前，非工作时段的娱乐不受默认管束。

### 7.11 四部自动路由（`departments.js`）

对齐外部思维框架的 operating_protocol，把问题隐式分给四个"部门"：

| 部 | 接什么 |
|---|---|
| `dept:collect` 信息收集部 | 未知事实 / 新材料未核验 / 现场线索整理 |
| `dept:strategize` 谋划思考部 | 前提可疑 / 因果争议 / 替代解释与反证 |
| `dept:dispatch` 统筹规划部 | 优先级取舍 / 时间预算冲突 / 工作包排期 |
| `dept:govern` 督办审计部 | 局中执行 / 交付物验收 / 规则与锁的执行审计 |

### 7.12 思维引擎

- **六骰分级思维**（`six_dice.js`，467 行）：精简总结/事实提取 → 预判推演 → ... 共 6 骰动作 + L2 无状态语义判官。
- **思维题**（`drills.js`）：九种，**不考知识，考精准** —— 一句话说清、给数字、给反例、给前提、下注。每题的合格线写死；上一题没回或答糊弄，下一球先说他、同类题重问。**默认关闭**，说"开始做题"才开。
- **思维局六招**（`thinking.js`）：局内单位不是时间段，是**一题多拍**（一道题拆 4–5 拍乒乓，每拍只答一句）。六招写死在引擎里，协议只能「用哪几招」，不能自己造招。
- **题库**（`bank.js`）：一道题至少要能撑起一次判定 —— 有答案、有解析。缺这两样的题不许进库（否则等于自己出题自己判）。

### 7.13 主动开局与排局（v4.1 的核心新增）

| 工具 | 作用 |
|---|---|
| `open_bout` | **现在就开一局**，带工作包和 App |
| `plan_bouts` | 一次排好今天的局，十分钟后自动生效 |
| `compose_bout_protocol` | 生成局协议 |

配套的纪律改动：

- 工具子集上限 **8 → 14**，待命状态里有：开局、排局、连麦、封 App、递话、收紧。
- 「可逆的直接做，做完一句话告诉他；不可逆的才问」——**替换掉所有「他点头再用」**。
- 计划草案空白时鲸澜自己填（`plan-draft`，一小时最多一次，让位给深夜锁、连麦、忙时和没接的球）。
- 早上立项：鲸澜先从记忆、笔记库、昨天的账里替他排好，他只说"行"或"换"。
- 巡逻从每天 3 次（10/15/20 点）改成 **5 次（9/11/14/16/19 点）**，巡逻时直接开局/立任务。

### 7.14 定时内核（v4.1 最大的一块）

**双实现，刻意为之**：

| 侧 | 文件 | 行数 | 管什么 |
|---|---|---|---|
| Kotlin | `dafeiyu_loop/core/KernelClockEngine.kt` | 719 | 真实唤醒、持久化、开机重算 |
| JS | `lib/clock_kernel.js` | 326 | 逻辑决策、可在 Linux 上测 |

五类定时原语（两侧同构）：

| 原语 | 语义 |
|---|---|
| `ONE_SHOT` | 一次性 |
| `FIXED_RATE` | 固定频率（按锚点对齐，不漂移） |
| `FIXED_DELAY` | 固定延迟（上次结束后算） |

### 7.15 引擎自愈（`EngineAutoHealer`）

上游逻辑是：10 分钟内重启满 3 次就锁死 `Phase.ERROR` 并停服务 —— 在 Android 12+ 幻象进程清杀和厂商杀后台下，引擎会彻底躺平。

这里的拆法：

| 情况 | 处理 |
|---|---|
| 启动 60 秒内连续崩 ≥4 次 | 回 `null`，交安全模式/错误卡片 |
| **运行满 60 秒后被清杀** | **永远允许指数退避重启**：5s→15s→45s→120s→300s，不锁死 |
| 退出码 137/143/9（外部强杀）且此前健康 | 首跳直接用 5s，快速拉回 |

### 7.16 绕过识别（`SystemBypassClassifier`）

识别「从浏览器或应用市场跳转」这类绕过锁的方式：解析 `ACTION_VIEW` 的 web intent 与 `market://` intent，把绕行跳转拿掉。

## 12. 已知缺口 —— 请重点看这一节

按严重程度排：

**1. 真机零验证（最严重）**
所有 v4.1 新功能（行为雷达 0ms 落锁、系统绕过识别、定时唤醒、悬浮窗、引擎自愈）都只在代码和单测层面成立。没有一条在真实 Android 上跑过。任何一层在真机上不成立，测试都发现不了。

**2. 自律等级（W-3）完全没做**
设计里写得很清楚：用户也应有四级自律等级（0 托管 / 1 半托管 / 2 自主 / 3 自律），随战绩升级，升级后系统逐步撤掉管束。全库 grep `自律|autonomyLevel` 在业务代码里**零命中**（只有一处无关的正则匹配"今天很自律"）。
后果：**系统目前只紧不松，没有把权力还回去的机制。** 这是"最终会被卸掉"的结构性风险，设计文档 §3.3 自己承认过。

**3. 双时钟实现有漂移风险**
Kotlin 719 行 + JS 326 行，同构但两份代码。一旦漂移是静默的 —— 只有 `test/v4-autonomy-clock.test.mjs`（229 行）在 Linux 上兜着，测不到 Kotlin 侧的真实唤醒行为。

**4. 判断类验收依赖模型，而模型天生宽容**
设计上「判断类」限制一天最多 2 个，但一旦用上，判官模型的宽容性就是漏洞。墙的眼睛（`wall_eye.js`）只能把「过」改「不过」，方向是对的，但它自己也是模型。

**5. 截图识别不存在**
DeepSeek 没有识图。工作包里大量验收标准是「3 张截图」，实际实现只能验**时间 + 数量**，验不了截图里有没有"已投递"。

**6. 上下文预算紧张**
每一轮要带：人设卡 + 记忆常驻档案 + 笔记库翻页 + 工作包 + 姐妹悄悄话 + 法典相关条目。历史上 `dual.test` 第 7 条就因为长人设卡把妹妹的递话挤出预算而挂过。v4.1 又加了内容，风险上升。

**7. 新语音页从聊天入口进不去**
聊天输入框的语音键仍指向老的 `ui/settings/voice_settings_page.dart`；新的三音色页只在「伴侣中枢 → 音色设置」里。不是 bug，但用户会以为没做。

**8. CI 签名曾经连踩三坑**
`fish-build-149` 到 `159` 之间有 3 笔提交专门修：Windows CRLF 的 base64 密钥、Secret 里混进 BOM 字符、apksigner 变量名写错。说明这条链路脆弱，之后改动容易再踩。

**9. 单一模型供应商**
全部依赖 DeepSeek 官方接口。接口 500/超时在历史上多次出现（真模型试跑时有多句没测成）。

**10. 模块数量已经很大**
`dsh-go-companion` 93 个模块、index.js 7229 行。已经有 `test/manifest.test.mjs` 检查 `lib/` 下每个文件都写进了 `BuiltinPluginGuest.kt`（防漏部署），但整体复杂度仍是维护风险。
