# 微信内部页面识别 · GKD 调研（D4，只出报告）

> 2026-11-08 · 外围任务 D4
> 问题：微信的视频号、朋友圈页面能不能用稳定的节点特征识别？能不能不写代码，装 GKD 加一条本地规则，在这些页面自动返回？
> 结论先说：**两个页面都能靠 Activity 类名稳定识别；节点特征要抓一次目标版本的快照再钉死。GKD 本地规则可以做到自动返回，不用写代码。**

## 1. GKD 是什么、用什么识别

- GKD（`gkd-kit/gkd`，GPL-3.0）是 Android 无障碍自动化 App：监听无障碍事件，用选择器找节点，再执行点击/返回/长按等动作。
- 选择器类似 CSS，但属性来自无障碍节点：`text`、`desc`、`id`、`vid`、`name`（类名）、`clickable`、`visibleToUser`、坐标和父子/兄弟关系。示例：
  `TextView[text="朋友圈"]`、`[vid="cover_layout"] +n [text$="顶级入耳"]`、`@[clickable=true] >(1,2) [vid="cover"]`。
  规则作用域里另有 `activityIds` / `excludeActivityIds`，先把匹配限定在指定 Activity。
  文档：<https://gkd.li/guide/selector>、<https://gkd.li/guide/example>
- 快照审查：GKD 能把某一时刻的截图 + 设备信息 + 界面信息 + 无障碍节点导出成一个 zip；用悬浮窗按钮/快捷开关/HTTP 服务抓取，上传后在网页审查工具里展开节点树、实时试选择器。
  文档：<https://gkd.li/guide/snapshot>，工具：<https://i.gkd.li/>
- 本地规则：`首页 → 订阅 → 本地订阅 → 应用规则`，格式是 JSON5（和远程订阅完全一致），可写 `activityIds`、`matches`、`action`、`actionDelay`、`actionCd`、`actionMaximum` 等字段。
  文档：<https://gkd.li/guide/subscription>
- 动作：源码里的 `ActionPerformer` 包含 `clickNode`、`clickCenter`、`click`、`back` 等；`action: 'back'` 就是系统返回。默认动作是点击。

## 2. 朋友圈：能识别，Activity 足够稳

| 特征 | 值 | 稳定性 |
|---|---|---|
| 包名 | `com.tencent.mm` | 稳 |
| Activity | `com.tencent.mm.plugin.sns.ui.SnsTimeLineUI` | 稳，GKD 官方文档的 activityId 示例里就用了它 |
| 新版 Activity | `com.tencent.mm.plugin.sns.ui.improve.ImproveSnsTimelineUI` | 部分版本用它，和上面一起写进 `activityIds` |
| 页面文字 | 标题「朋友圈」；英文版「Moments」；广告卡片「广告 / Sponsored / 廣告」 | 文字随语言变，但可作为触发器 |
| 节点结构 | 广告卡片是 `ImageView - TextView[text="广告"][clickable=true]`（第三方订阅里的真实规则） | 有快照可验证 |

依据：
- GKD 文档在「应用规则组编辑禁用」里直接把 `SnsTimeLineUI` / `ImproveSnsTimelineUI` 当作 activityId 示例：<https://gkd.li/guide/subscription>
- 第三方订阅 `ganlinte/GKD-subscription` 的 `src/apps/com.tencent.mm.ts` 用这两个 Activity 限定「朋友圈广告」规则，并用 `ImageView - TextView[text="广告"][clickable=true][id!=null]` 选节点。

**不要用 `com.tencent.mm:id/xxx` 这种资源 id 做主判据**：微信的 id 是混淆过的，版本之间会变（社区里不同年份的脚本用的 id 完全不同）。把它们当辅助，不当唯一依据。

## 3. 视频号：能识别，Activity 足够稳

| 特征 | 值 | 稳定性 |
|---|---|---|
| 包名 | `com.tencent.mm` | 稳 |
| 主入口 Activity | `com.tencent.mm.plugin.finder.ui.FinderHomeAffinityUI` | 稳，多个开源项目和 GKD 订阅都在用 |
| 其他页面 | `FinderHomeUI`、`FinderSelfUI`、`FinderConversationUI` | 同一套 finder 包，按需要加 |
| 页面文字 | 顶部「视频号」；信息流 tab「关注 / 朋友 / 推荐」 | 文字随版本略有变化，适合做触发器 |
| 视频区域 | `TextureView` / `SurfaceView`（播放器），不是文本节点 | 不能靠它做识别 |

依据：
- `FinderHomeAffinityUI` 是视频号入口：Xposed 模块 `io.github.MarsGao.speed` 的技术说明和启动命令都直接用它；微信反编译源码里 `FinderHomeAffinityUI extends FinderHomeUI`。
- `ganlinte/GKD-subscription` 的微信规则用 `FinderHomeAffinityUI` + `FinderSelfUI` 限定青少年模式弹窗；`Ujhhgtg/WeKit` 也把「视频号」映射到这个 Activity。

**限制**：视频号内容页/直播页的 Activity 名不一定都叫 `FinderHomeAffinityUI`。要覆盖「一进视频号就返回」，先用快照确认当前版本顶部 tab 的实际节点（类名、text、vid），再把 detail/live 的 Activity 补进 `activityIds`。

## 4. 不写代码的做法：GKD 本地规则

可以，全程只在 GKD 里填 JSON5，不需要编代码、不需要 root。

建议流程：

1. 装 GKD，开无障碍；在 `设置 → 高级设置` 打开悬浮窗按钮。
2. 打开微信朋友圈、视频号，各抓一次快照；到 <https://i.gkd.li/> 打开，展开节点树。
3. 在审查工具搜索框里试选择器（例如 `[text="朋友圈"]`），确认它能选中页面上一直存在的节点；顺便记下当前微信版本的 Activity 名。
4. 回到 GKD：`订阅 → 本地订阅 → 应用规则`，粘贴下面这份，按快照结果改 `matches`。

```json5
{
  id: 'com.tencent.mm',
  name: '微信',
  groups: [
    {
      key: 0,
      name: '进入朋友圈自动返回',
      activityIds: [
        'com.tencent.mm.plugin.sns.ui.SnsTimeLineUI',
        'com.tencent.mm.plugin.sns.ui.improve.ImproveSnsTimelineUI',
      ],
      rules: [
        {
          key: 0,
          // 触发器：页面上稳定存在的节点；抓快照后按实际类名/文字改。
          matches: 'TextView[text="朋友圈"]',
          action: 'back',
          actionDelay: 500,
        },
      ],
    },
    {
      key: 1,
      name: '进入视频号自动返回',
      activityIds: [
        'com.tencent.mm.plugin.finder.ui.FinderHomeAffinityUI',
        'com.tencent.mm.plugin.finder.ui.FinderHomeUI',
      ],
      rules: [
        {
          key: 0,
          matches: 'TextView[text="视频号"]',
          action: 'back',
          actionDelay: 500,
        },
      ],
    },
  ],
}
```

要点：

- `activityIds` 只负责「在哪个页面生效」；真正触发动作还需要 `matches` 命中的节点。所以第 3 步的快照审查不能省。
- 如果「朋友圈」标题不是 `TextView`，把 `matches` 换成快照里实际的类名，例如 `TextView[text="朋友圈"]` → `[text="朋友圈"]` 或 `[vid="..."]`。
- 防止来回弹：保留 `actionDelay`（例如 500–800ms）；必要时加 `actionCd: 2000`（冷却）或 `actionMaximum: 1` + `resetMatch: 'activity'`（每次进页面只返回一次）。
- 需要「只返回、不点任何东西」时，`action: 'back'` 不依赖节点坐标，比 `click` 稳。

## 5. 风险与限制

1. **和 DSH 自己的无障碍/拦截共存**：Android 允许同时开多个无障碍服务；但两边都可能在微信页面动作。先只开 GKD 验证，再和 DSH 同开；如果出现「刚返回又被 DSH 拉回」或反过来，明确各管哪些 App。
2. **微信升级会改类名和节点**：Activity 名相对稳，节点结构不稳。规则里保留 `snapshotUrls`，每次大版本升级后重新抓快照验证；坏了就是改一条 JSON，不用改 App。
3. **快照含屏幕文字**：上传前按官方说明去掉隐私信息（图片打码、JSON 里的节点文字替换）；不要把含聊天内容的快照传到公开仓库。
4. **GPL-3.0**：GKD 本身是 GPL-3.0；我们只是安装它并写本地规则（配置数据），不拷贝它的源码，不涉及把 GKD 代码并进大肥鱼。
5. **自动返回是「一刀切」**：进了就退，用户没法在朋友圈/视频号里停留。要做「只提醒、不返回」或「限时放行」，那是另一套规则/另一个产品决定，不在本报告范围。

## 6. 建议的下一步（不改代码）

1. 在目标微信版本上各抓一张朋友圈、视频号快照，确认第 3 步的两个 `matches`；把实际 Activity 名补全。
2. 用上面这份本地规则在真机上试一天：只开 GKD，确认返回不循环、不误伤聊天/公众号页面。
3. 再和 DSH 同开，观察两边是否抢动作；把结论写回本文件。
4. 如果验证通过，这份规则可以直接给用户手动导入；不需要进 APK，也不合入代码。
