## 0. 先看这几句话

1. **DSH = DeepSeek Harness**：一个 Android 上的 DeepSeek 客户端。Flutter 外壳，内置 Node 运行时、本地 Agent 引擎、插件系统和手机操控能力。上游部分不是我们写的。
2. **大肥鱼**是叠在 DSH 上的一整套系统，目标是：**每天把用户的时间变成一串「局」，每一局都做完一件说得清的事。**
3. 系统由**三个器 + 两条鱼**组成：
   - **调度器**：管资源，包括时间、App、注意力。
   - **验收器**：管证据，包括交付、回执、日判。
   - **触发器**：在某一刻给出一个具体动作，核心是 Gemini Live，它能看屏。
   - **两条鱼**（鱼丸、鲸澜）：两个有个性的 AI 角色，是贯穿全局的主动调控者。
4. 实现原则：**规则和时机写在代码里（纯函数、可测），模型只负责说话和执行。** 模型没有减免规则的权力。
5. 用户只有一个人，设备是 **iQOO 12**（OriginOS、系统自带桌面），数据都在手机本地。连 Gemini 要先开代理 **NekoBox**。
6. **真机验证仍然几乎为零**。这一轮的改动都只在单元测试、集成测试和 CI 构建层面成立。这是最大的未知。

## 1. 用户是谁、要什么（理解一切设计的钥匙）

- 一个人用，长期用；目标是考公和求职。自述"这几个月浑浑噩噩，关键时间节点都错过了，不知道自己做了什么"。
- 想要的是：**一个强大的调控器和验收器**。
  - 什么都没做、一直在玩的时候，系统必须明确说出来。
  - 专注力垮掉的时候，系统能接管，甚至可以拒绝他"再玩一会"。
  - 平时又像伙伴一样聊天，有个性，不只是催他。
- 历史教训：
  - 系统只紧不松，他就会把它卸掉（fish-build-27 就是这样没的）。
  - 他多次主动放弃"主动性"相关设定，最后系统退化成纯锁机 App。
  - 上一轮锁机出了大事故：连桌面和 DSH 自己都锁，导致无法开始测试。
- 他明确的偏好：
  - 白名单思路是对的，干活时只放行哪些 App。
  - 每天娱乐额度 2 小时；游戏单独给，没用完的可以 2:1 换成娱乐。
  - 按周汇总，每周六出周报。
  - 连麦结束时说"出回执"。
  - 推手档和接管档要念出来（语音）。
  - 一局收了 5 分钟不开下一局，可以直接替他开。
  - 接管可以拒绝他。
  - 两条鱼要有自己的个性，也要会自己思考、自我优化。
  - 先做能力，token 成本以后再慢慢平衡。

## 2. 基线与架构分层

| 层 | 技术 | 内容 |
|---|---|---|
| Flutter 外壳 | Dart，`app/lib/dafeiyu/` | 中枢、局工作台、计划、墙、三层战略作战室、分析页、任务卡等页面 |
| Kotlin 原生执行层 | `dafeiyu_loop/`、`phone/a11y/` | 无障碍服务读前台 App、锁页、悬浮窗、定时唤醒、通知、语音 |
| Node 插件层 | `app/assets/engine/plugins/dsh-go-companion/` | **所有决策都在这里**，主文件 `lib/index.js` 约 9,959 行，另有约 110 个模块 |
| 记忆插件 | `dsh-go-memory/` | 本地 SQLite：事实、话题、原话留底 |
| 模型 | DeepSeek（用户自己的 key） | 聊天、判官、夜间整理、思考层 |
| 触发器外部 App | Gemini（`com.google.android.apps.bard`），经 NekoBox 代理 | 看屏、语音陪练 |

**关键约定：插件决定「说什么、锁不锁」，手机负责执行「锁、退回桌面、发通知」。**

- 手机大约每分钟问插件一次 `POST /plan`，切 App 等事件发生时会立即再问。
- 插件返回一大包结果，手机照着执行。

## 3. 一天的流水线

```
 前一晚           早上              白天（每一局）                         晚上 21:30          每周六
┌─────────┐   ┌─────────┐   ┌──────────────────────────────┐   ┌──────────────┐   ┌────────┐
│鲸澜备课 │→ │排局/计划│→ │开局→第一步→触发→交付→验收        │→ │晚报 + 硬日判 │→ │ 周报   │
└─────────┘   └─────────┘   │  ↑偏离→推进器/接管/锁            │   └──────────────┘   └────────┘
                             └──────────────────────────────┘
        13:30 / 22:15：两条鱼后台思考（要紧的事、规律、建议、自我调参、她们自己的日常）
```

- **局（bout）**是原子单位：一个工作包 + 一个时段 + 一套事先定好的验收标准。
- 工作包有七个字段：目标、第一步（2 分钟内能开始的物理动作）、后续步骤、必需和允许的 App、交付物、验收方式、卡住时怎么办。

## 4. 两条鱼

| 角色 | 性格 | 职责 |
|---|---|---|
| **鱼丸**（妹妹） | 19 岁，嘴欠、护短、会吃醋；养了一只叫"芝麻"的仓鼠 | 陪伴、局外拉他回来、空档出题、摇骰子。**不问进度** |
| **鲸澜**（姐姐） | 26 岁，冷静，结论先行；晨跑、下围棋 | 排局、备课、对账、推演；每个判断要引证据 |
| 局官 | 极简 | 局内只对着工作包问话 |
| 墙 | 不聊天 | 纯函数执法、验收、审计 |

- 两人各自绑定一个 DSH 对话，共享记忆，但人设和职责分开。互相可以递话（`sister_note`）。
- 权限很高：主动发球时可以调工具，`proactiveTools` 和 `fullToolAccess` 默认开。能开局、排局、锁 App、拉 Gemini、写笔记库。
- 每一轮的上下文由插件按块拼装，有优先级和预算。11-18 新增了几块：`handoff`（会话交接）、`verifier`（截止日 + 昨天判决 + 额度 + 昨天 App 账）、`reflect`（后台思考的结论和她们的日常）。

### 4.1 这一轮对人设的小改动

- 鱼丸：删掉了"手机直接给你灰掉"这种威胁式示范句。
  - 每次开口前随机挑一个角度，十次里至少七次跟正事无关。
  - 沾到正事时，只挑一个真看到的细节，比如笔记、回执或交付物里的原话。
  - 不知道他在干什么，就直接说不知道，只问一个具体的小问题。
- 鲸澜：每个判断都要引一条看得到的证据；催和锁交给代码和墙，她不当闹钟。

## 5. 调度器

### 5.1 锁机安全（11-18 修复的事故）

**事故根因：**
- 插件下发锁时，锁的目标取的是"当前前台 App"。
- 前台是桌面或 DSH 自己时，就把它们锁了。锁页本身就是 DSH，于是锁住 DSH → 前台变成 DSH → 再锁 DSH，形成死循环。
- 手机上有四条落锁入口，过去只有一条（`SessionPolicy`）排除了桌面和 DSH。之前用 Gemini 修了好几次，每次只修到一条入口，所以一直没修好。

**修法：**

| 措施 | 说明 |
|---|---|
| 唯一总闸 `neverLock` | 四条入口全部经过它：姐妹力度锁、拦截页、专注页、设置页自卫。插件侧（`never_lock.js`）和手机侧（`SystemSafeAllowlist.neverLock`）各一份，任何一边拦住都不锁 |
| 永不锁名单 | DSH 自己、默认桌面（运行时解析）、系统 UI、输入法、电话短信、地图、支付、NekoBox 等代理、相册、文件管理、选图片和选文件的页面、分享页、截屏、Jovi 负一屏 |
| **测试模式（默认开）** | 锁照常判断，但只弹提示"测试模式：这里本来会锁 X"，并记录到 `shadow-locks.jsonl`。只有用户在中枢里能打开测试模式；姐妹的工具只能关 |
| **紧急解除** | 通知栏按钮，必须写一句理由；每天 3 次，每次 10 分钟；纯本地执行，不依赖引擎；解除记录进当晚的日判 |
| adb 通道 | 需要 `DUMP` 权限（只有 adb shell 有），不计入次数，是开发者兜底 |

### 5.2 统一裁决器（目前是影子模式）

现在的问题：插件下发给手机的锁相关信号有十几个，包括 force、refuse、session、block、shield、lease、emergencyPass 等，手机里好几段代码各读各的。结果是互相打架，锁页上显示的理由和实际执法不一致。

**裁决器先用 P0–P6 优先级定出当前状态，命中第一条就停：**

| 级 | 状态 | 放行什么 |
|---|---|---|
| P0 | 紧急放行 | 全部 |
| P1 | Gemini 连麦舱 | Gemini + 代理 |
| P2 | 契约逾期严格锁 | 笔记和沟通工具 |
| P3 | 专注严格局 / 白天墙锁 | 这一局声明的 App + 通行证 |
| P4 | 深夜锁（0:30–7:00） | 只有底座 |
| P5 | 契约柔性期 / 干活中 | 白名单 |
| P6 | 自由态 | 额度内都放行 |

然后转换成**唯一输出** `lock`：

```
{ mode: open | allowlist | free,
  allow: [...], deny: [{app, why}], needPass: [...],
  why: "为什么锁", unlockHow: "怎么解", quota: {...}, lease: {...} }
```

手机对任何一个 App 只走一段逻辑：

```
是底座 → 放行
mode = open → 放行
在 needPass 里 → 锁，并提示"先跟鲸澜领通行证"
mode = allowlist → 在 allow 里就放行，否则锁
mode = free → 在 deny 里就锁，否则放行
```

**现状：** `/plan` 已经输出 `lock`。手机端的 `ArbiterShadow` 每次切 App 都会用新逻辑算一遍，**但不执法**，只在新旧结论不一致时记一笔到 `files/loop/arbiter-diff.jsonl`。等用户真机用几天、拿回这份记录，再切换成唯一执法依据。**目前实际执法的仍是旧的那十几个信号**（已经套上了永不锁总闸）。

### 5.3 App 分层（五层）

| 层 | 默认包含 | 干活时 | 自由态 |
|---|---|---|---|
| 系统底座 | 桌面、相册、文件、选图选文件页、分享页、相机、截屏、输入法、NekoBox、电话支付、其他系统自带 App | 放行 | 放行 |
| 工作 | Gemini、ChatGPT、Claude、百度网盘、BOSS 直聘、Obsidian、WPS | 放行 | 放行 |
| 双用途 | Chrome、vivo 浏览器、夸克、微信、QQ、B 站、小红书、知乎 | **要通行证** | 计入娱乐额度（通行证时段除外） |
| 娱乐 | 短视频、视频、信息流 | 锁 | 吃额度 |
| 游戏 | 王者荣耀等 | 锁 | 游戏单独额度 |

- 分层写在 Obsidian 的 `大肥鱼/墙/App分层.md`：往更严的层挪立即生效，往"工作"挪要等 24 小时。
- 新增工具 `app_tier`：
  - 改严可以直接做。
  - 改松必须引用他 30 分钟内说过的同意原话，比如"行""可以"。原话只在内存里保存，引擎重启后会丢。

### 5.4 通行证（双用途 App）

- 只有鲸澜能发，工具是 `grant_task_lease`。默认 15 分钟，最长 30 分钟，一张只对一个 App、一个用途有效。
- 一天超过 8 张后，要他先给出理由（工具参数 `whyAgain`）。
- 通行证期间，通过无障碍读屏幕上的文字做抽查。读到游戏、短剧、直播、打赏这类词，当场收回通行证并重新锁上，记一笔"偏航"（`lease-drift`）。
- 纯游戏不发通行证，这一条写死在代码里。

### 5.5 自由态额度

| 项目 | 规则 |
|---|---|
| 娱乐 | 每天 120 分钟；每通过一局验收 +15 分钟（复用原来的"挣来的娱乐"） |
| 游戏 | 另给 60 分钟 |
| 换算 | 娱乐超额时，自动用剩余的游戏额度按 2:1 去换（2 分钟游戏额度换 1 分钟娱乐） |
| 双用途 | 当天用时减去通行证时长后，计入娱乐 |
| 用完以后 | 娱乐 App 锁到第二天；双用途改为需要通行证 |

额度的计算依据是手机上报的"今天每个 App 用了几分钟"。

### 5.6 切换次数限制

- **只在干正事时计算**：开着局、契约期间、忙时、专时。
- 在统计窗口内，切到这一局白名单以外的 App，达到摇骰线就摇一骰并拉起 Gemini（20 分钟冷却），达到锁线就锁当前这个 App 15 分钟。
- 切到桌面、DSH、系统页面、工作类 App、Gemini 都不计数。
- 阈值写在 `大肥鱼/墙/规则.md`，默认窗口 10 分钟、3 次摇骰、5 次锁。次数调小或窗口调大是改严，立即生效；反过来要等 7 天冷却。
- 局外原有的雷达规则照旧：15 分钟内切换 8 次就锁。

### 5.7 原有的执法件（保留未删）

墙、法典（宪法 / 法律 / 法规 / 判例四级）、立场账本、预判账本、行为雷达、水位（tide 0–100）、脾气、力度（0–4）、预案、深夜锁、契约（逾期 1 分钟转严格）、题库解锁（答对 10 题换 5 分钟）等。详见 11-17 全景文档。

## 6. 触发器：骰子 → Gemini Live → 回执

**为什么交给 Gemini：** DeepSeek 看不到屏幕，Gemini Live 能共享屏幕、开摄像头。所以"识别他此刻在做什么"交给 Gemini，DSH 负责提供设定和上下文，并收回结果。

1. **设定文件**：`大肥鱼/Gemini设定.md`，第一次使用时自动生成，用户可以自己改。默认要点：
   - 它是验收者兼陪练，不说"加油"。
   - 先看屏幕再开口；看不清就问。
   - 他什么都没交时，直接点明。
2. **当下事实**（代码读得到的部分）：前台 App 和停留时长、这一局的标题和第一步、今天的娱乐用时、最近的截止日、这次摇到的骰子。一项都读不到时，让 Gemini 先只问一个具体问题（防空话门）。
3. **骰子**：六种思维方式——事实提取、预判推演、联想比较、关键提问、依据与结论、替代解释。点骰子卡上的"连 Gemini"，会把整份简报复制到剪贴板并拉起 Gemini。
4. **NekoBox 代理检查**：系统里没有 VPN 时，先打开 NekoBox，提示"点连接"；检测到 VPN 起来后自动打开 Gemini，最多等 90 秒。
5. **回执**：结束时他说"出回执"，Gemini 按固定格式输出：
   ```
   【复盘】做了什么：…… 结论：…… 卡在哪：…… 下一步：…… 几点前：…… 证据：……
   ```
   之后由姐妹通过无障碍读回 Gemini 的对话，或者他自己粘贴。代码从中抠出各个字段；缺"结论 / 下一步 / 几点前"任意一项就不算完整。**没有完整回执的那场连麦记为"无产出"**，计入日判。

> 限制：Android 不允许 App 替用户开启屏幕共享，"共享屏幕"那一下必须他自己点。

## 7. 验收器

### 7.1 硬日判（每晚 21:30，代码按账本算）

| 判决 | 条件 |
|---|---|
| **空转** | 没有一件通过验收的交付，也没有一场带完整回执的连麦 |
| **达成** | 交付件数 ≥ 计划数（至少 1）、娱乐 ≤ 120 分钟、没有错过截止日 |
| **部分** | 其余情况 |

- 理由逐条写成事实：交付数、主线和娱乐分钟、无回执连麦的场数、紧急解除次数、违约次数、错过的截止日。
- 判决写在晚报第一行和 frontmatter（`大肥鱼/每日报告/日期.md`）。晚报末尾附"App 账"：每个 App 用了多久、在哪一层、通行证几张、偏航几次。
- 第二天早上，两姐妹会在上下文里看到昨天的判决，被要求"不许替他找补"。

### 7.2 截止日（日历）

- 三层主线（长期 / 中期）新增 `due` 字段，在作战室卡片上点日历图标设置。
- 剩 7、3、1、0 天时，两姐妹在那一轮必须提一句。
- 截止日前一天到期、事情还没做完的，算"错过"，计入日判。

### 7.3 周报（每周六）

- 周六晚报出来后，写 `大肥鱼/周报/<周六日期>.md`。
- 内容：达成 / 部分 / 空转各几天，交付件数，主线、Gemini、娱乐的分钟数，每天的判决，这一周做成的事。
- **没有晚报的那天按空转写明**。

### 7.4 原有的验收件

墙的证据审查、墙的眼睛（读新写的内容判断是不是真在做，只能把"过"改成"不过"）、四个数（主动开局比、交付率、空局率、局内偏离分钟数）、对账等。

## 8. 两条鱼的主动调控架构（11-18 新增，核心）

### 8.1 推进器（`driver.js`，纯代码）

**每次 `/plan` 都算一次"此刻体系该往前推哪一步"，按下面的优先级取第一条：**

| 优先级 | 情况 | 动作 | 谁 |
|---|---|---|---|
| 1 | 接管条件成立 | 进入接管 | 两人轮流 |
| 2 | 契约验收点 ≤10 分钟到点（伙伴档也推） | 说清交什么、交到哪 | 鲸澜 |
| 3 | 截止日剩 0 / 1 / 3 / 7 天，且今天还没推过 | 问他做了什么，没做就排一局 | 鲸澜 |
| 4 | 工作时段（9:00–21:30），上一局结束 ≥5 分钟、没有局在跑 | 推下一局。**≥10 分钟还没动，代码直接把计划里的下一局提前开掉**；计划里没有就让鲸澜现排 | 鲸澜 / 代码 |
| 5 | 推手档、手上没局 | 一道思维题、摇骰子连 Gemini，或损两句（不催进度） | 鱼丸 |

- 推进器给模型的是一张带动作的球，例如"下一局「简历投递」提前开了，告诉他第一步"。
- 模型用自己的口吻说出来，再调工具执行。能撤回的直接做，做完告诉他。
- 每类推进都有冷却期，记录进账本（`drive`）。

### 8.2 三档模式

| 档 | 判定 | 表现 |
|---|---|---|
| 伙伴 | 水位清醒，一切正常 | 照旧随机发球，最快 8 分钟一球（间隔可由思考层在 5–30 分钟之间调） |
| 推手 | 水位"在滑 / 在沉"、局之间空着、9:30 后还没计划、切 App 到摇骰线 | 执行推进器给的事；**默认语音念出来**（`driveVoice` 可关） |
| **接管** | 水位"陷住"（≥75），或额度用完还在娱乐 App 里停留 ≥5 分钟，或 30 分钟内通行证偏航 ≥2 次，或契约逾期 | 见下 |

**接管时：**
- 锁成白名单：工作层 + Gemini + NekoBox + 他的默认白名单。走原有的 `aiWorkSession` 通道，**这一条已经真正执法**，测试模式下只提示。
- 界面顶部挂出"回位动作"卡，内容由代码决定，不让模型现编。
- 两姐妹每 4 分钟轮流来一句；"5 球没接就停"和"敷衍就冷处理"暂停；直接走语音。
- 可以拒绝"再玩一会"。
- **解除条件**：在工作 App 里待满 3 分钟、开了一局、交了完整回执（3 分钟内）。
- **边界**：一次最长 45 分钟，一天最多 3 次，解除后冷却 30 分钟。紧急解除、深夜、安静时段、连麦时让路。

### 8.3 会话换班（`rotate.js`）

- **问题**：两条鱼各绑一个对话，越聊越长；插件本身不能新建会话。
- **何时换**：绑定以来满 150 轮，或用满 7 天且至少聊过 20 轮；也可以随时手动换。
- **流程**：中枢"对话换班"卡 → 插件写交接 → App 新建对话（复用 DSH 自带的新建对话）→ 绑定，不允许和另一位绑同一个对话。
- **交接内容由代码拼**：答应过的事、没聊完的话题、立场、Gemini 回执、昨天的判决、常驻事实、最后 16 句原话。最长 2,600 字。写入 `companion/handoff-<角色>.json` 和 Obsidian 的 `大肥鱼/会话交接/`。
- 新对话的头 3 天或头 30 轮，每一轮都带这份交接。旧对话不删。

### 8.4 思考层（`reflect.js`）

- 参考了 Letta 的 sleep-time agent（后台整理记忆）和 Generative Agents 的反思机制。
- 每天 13:30 和 22:15 各跑一次。走 `llm.stream`，不占用聊天对话，失败不重试。
- **输入**：
  - 近 7 天判决、今天的 App 账、额度
  - 截止日、三层主线
  - Gemini 回执、推进和接管记录
  - 他最近的原话
  - 最近改过的笔记节选，总共 ≤3,000 字
  - 上一次的思考结果
- **产出**（严格 JSON，逐条校验，**没有依据的条目直接丢**）：

  | 字段 | 内容 |
  |---|---|
  | `urgent` | 最要紧的 1–3 件 |
  | `patterns` | 规律 |
  | `proposals` | 建议。**改严 App 分层的直接执行**，其余作为"想跟他提"进上下文 |
  | `self` | 她们自己调伙伴档间隔（5–30 分钟），直接生效 |
  | `diary` | 两人各一行自己的日常，用来维持个性 |

- 结果写入 `大肥鱼/两条鱼/思考/日期-午|晚.md`，同时注入每一轮上下文。
- 和原有的"夜间整理"（`nightly.js`）并存。夜间整理只读索引、不读笔记原文。

### 8.5 当下任务卡（`card.js` + `task_card.dart`）

- 参考了 Google A2UI 和 Flutter GenUI：**AI 只输出受限的 JSON，App 用预先写好的组件渲染，不执行任何生成的代码。**
- **组件**：标题、一句话目标、≤6 个步骤（可勾选）、倒计时（≤180 分钟）、交付物、验收方式、提示、≤3 个按钮。
- **按钮只能是白名单动作**：
  - `start_next_bout`：开计划里的下一局
  - `connect_gemini`：摇一骰并带简报连 Gemini
  - `open_app`：只能打开工作层或双用途层的 App
- 卡片 6 小时后过期，同时只有一张。
- 工具 `show_card` 给两姐妹用；接管开始时代码自动挂"回位动作"卡，解除时撤掉。
- 卡片显示在中枢和局工作台的顶部。

## 11. 已知缺口与风险（请重点看这一节）

按严重程度排列：

1. **真机零验证。** 无障碍读前台、锁页、语音、NekoBox 检测、Gemini 拉起、回执读回，全都没在真机上跑过。iQOO 系统页面的包名（相册、文件、选图片页等）是凭经验写的。
2. **裁决器只是影子模式。** 实际执法仍然靠旧的十几个信号。新旧逻辑的语义差异要等 `arbiter-diff.jsonl` 的数据。在切换之前，"锁页上的理由和实际执法一致"这一点还没实现。
3. **五套任务队列没有合并。** `plan.json`、`daily.json`、局队列、`plan-contract.json`、horizons 依然分散，统一视图只是只读合并。原计划的 `work.json` 还没做。
4. **自律等级（W-3）仍然只是单日积分。** 只影响伙伴档的发球间隔，没有接到锁和接管门槛上。"权力还回去"这件事基本还没做。（推进器和接管的门槛目前是固定的。）
5. **接管靠的是水位，水位靠的是娱乐 App 的停留时长。** 如果他在"工作类"App 里摸鱼，比如在浏览器的通行证期间刷别的、在微信里闲聊，只能靠读屏关键词和通行证偏航来发现，覆盖面有限。
6. **通行证读屏只认文字关键词。** DeepSeek 不能识图，能识图的 Gemini 只在连麦时在场。
7. **回执读回很脆弱。** 姐妹要通过无障碍去 Gemini 界面里读【复盘】那一段，Gemini 的界面一改就可能读不到。读不到就记"无产出"，这有可能误伤他。
8. **他说过的原话只存在内存里。** 引擎重启就丢。影响 `app_tier` 放松时的原话核对和会话交接里的原话。App 里直接聊天的人类消息，账本只记了"他说了话"，没存原文。
9. **上下文预算更紧了。** 新增了 handoff（优先级 80）、verifier（72）、reflect（70）三块。历史上发生过长人设把关键内容挤出预算的事。
10. **复杂度还在涨。** `index.js` 从 7,229 行（11-17）涨到 9,959 行，新逻辑虽然都放在独立模块里，入口拼装仍集中在 index。
11. **双时钟实现**（Kotlin 和 JS 各一份）依然存在。
12. **思考层的自我调参和自动改严 App 分层没有人审。** 有上下限和依据校验，但模型可能根据错误的依据把某个 App 改严。可以撤回，但需要他去 Obsidian 里改，而且改松要等 24 小时。
13. **额度的估算比较粗。** 双用途 App 的分钟数减去通行证时长是近似算法；手机上报的 today 用量也有颗粒度问题。
14. **单一模型供应商。** DeepSeek 接口超时会让思考层和发球失败；思考层失败不重试。
