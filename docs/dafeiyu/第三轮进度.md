### 7.8 T-P0-2 判性质结论（2026-11-09 10:34，已查证，尚未动码）

W-5 要求「先判性质、再决定改测试还是改代码」。两条都查清了，结论如下。

**① `BuiltinPluginGuestTest:50` 的 `assertEquals(5, PLUGINS.size)` → 测试写错，不是漏挂**

- `BuiltinPluginGuest.PLUGINS` 实际 4 项：`dsh-go-relationship` / `dsh-feiyu-mood` / `dsh-go-memory` / `dsh-go-companion`。
- `dsh-fish-strict` 与 `dsh-speak-up` 是**有意退役**，代码注释两处写死：
  `BuiltinPluginGuest.kt:63-64`（"The old dsh-speak-up timer is deliberately not deployed: two schedulers
  would race for the same voice"）、`:77-79`（"dsh-fish-strict ... and dsh-speak-up ... are retired (P0,
  2026-11-08) ... Their sources stay under assets for reference only"）。
- **同一个测试自己就断言它们不能出现**：`BuiltinPluginGuestTest.kt:39` `!yaml.contains("- id: dsh-speak-up")`、
  `:42-43` 对 `dsh-fish-strict` 同样两条。所以 `5` 与它自己的其它断言自相矛盾。
- git 佐证：`8fc97768` 一次提交里既把这两个插件从清单删掉，又写了 `assertEquals(5, ...)` —— 数错了。
- 判定：**改测试，5 → 4**。不存在「插件漏挂」缺陷，`assets` 下那两个目录是参考留存，不该挂。

**② `KernelChainTest:59` 的 `ClassCastException` → 测试在测已被推翻的设计**

- `:101` 发的是 `409 + error.code = "agent-busy"`。`AgentWire.kt:66`
  `status == 409 && code in SKIP_CODES -> Decoded.Skip(code)`，而 `SKIP_CODES = {no-topic, agent-busy,
  in-conversation, desk-busy}` —— 命中，返回 `Skip`，不是 `Reply`。
- `Skip` 的语义（`AgentWire.kt:28-33`）："The plugin said 'not this time' ... That is a decision, not a
  delivery failure: close the attempt quietly instead of feeding the not-delivered streak."
- 真实消费点是 `ProactiveRuntime.kt:899` 的 `is AgentWire.Decoded.Skip ->`，**根本不走
  `Coordinator.onAgent`**；测试却在 `:59` 强转成 `Reply` 再喂 `onAgent`，必然抛。
- 测试期望的 `Outcome.FAILED to "agent_agent-busy"`（`:104`）与现行 Skip 语义直接冲突：
  按现行设计，busy 不该记成 FAILED，也不该喂 not-delivered 连击。
- 判定：**测试过时**，非解码回归。改测试，让它按 `decode` 实际返回分派。
  另有一条岔路（把 `agent-busy` 从 `SKIP_CODES` 拿掉、恢复成普通失败）会改真实调度行为，**不建议**，
  需用户拍板才能走。

两条都**未动码**，等用户就改法拍板。在此之前状态仍记 `UNKNOWN`。
