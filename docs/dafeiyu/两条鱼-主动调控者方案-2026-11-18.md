# 两条鱼：主动调控者方案（2026-11-18）

> 写给用户，也写给接手分析的 AI。基线是 `feat/dafeiyu-v3-on-1016` 分支、fish-build-182。
> 这份文档只讲两条鱼背后的架构。调度器、验收器、触发器（Gemini）的现状见《真机测试单-2026-11-18》和《功能全景-给外部AI-2026-11-17》。

## 0. 一句话

两条鱼（鱼丸、鲸澜）要从"有信号才开口的陪聊"变成**整个体系的发动机**：
- 你专注的时候，她们是伙伴；
- 你在滑的时候，她们推着体系往前走；
- 你垮掉的时候，她们接管，可以拒绝你；
- 平时她们自己思考、自己优化，有自己的个性。

## 1. 现状：为什么一直"没闭合"

| 问题 | 代码位置 | 后果 |
|---|---|---|
| 权限其实给足了 | `proactiveTools`、`fullToolAccess` 默认开 | 能开局、锁 App、拉 Gemini，但很少用上 |
| 连着 5 球没接就停 1 小时 | `silence.js` | 你刷手机不回她，她就安静 |
| 连续 2 次敷衍就冷处理 45 分钟 | `withdrawal.js` | 最需要被拉的时候，她退场 |
| 只在有信号时开口 | `/plan` 掷骰子、雷达、巡逻 | 没人负责"此刻体系该推哪一步" |
| 语音默认关 | `voice` 默认 false | 你不看屏幕，就等于她没说 |
| 夜间思考被限得很死 | `nightly.js`：只给索引、不读笔记原文、每类最多 3 条 | 她们"想不了事" |
| 会话绑死两个对话，越聊越长 | `config.sessionId` / `strategistSessionId`；插件只能唤醒已有会话，不能新建 | 上下文越来越重，又没有"换班"机制 |
| 只能用文字说任务 | 没有界面组件 | 当下任务说不清、看不清 |

**结论：调度器知道该做什么，验收器知道你做没做，但没有一个角色负责把"下一步"推到你面前，并且在没人理的时候坚持下去。**

## 2. 总架构：代码决定"做什么"，两条鱼决定"怎么做、怎么说"

```
          ┌──────────── 调度器（局 / 契约 / 三层主线 / 额度 / 裁决器）
状态 ───→ │                                                     │
          └──────────── 验收器（日判 / 回执 / App 账）            │
                              ↓                                  │
                   【推进器 driver.js】纯代码，每次 /plan 跑一遍     │
                   → 模式：伙伴 / 推手 / 接管                       │
                   → 此刻该推的一件事（带动作、带负责人）           │
                              ↓                                  │
          鱼丸 / 鲸澜：用自己的口吻说出来 + 调工具做掉 ───────────┘
                              ↓
          Gemini Live（看屏、陪练） → 回执 → 验收器
                              ↓
          【思考层】一天两次：读账、读笔记、读回执 → 要紧的事 / 规律 / 自我调参
```

这和项目一贯的原则一致：**规则和时机在代码里（可测、模型无权减免），模型负责说话和执行。**

## 3. 推进器：此刻体系该推哪一步

每次 `/plan`（约每分钟一次，事件发生时立即）由代码算出**一件事**，按优先级取第一条：

| 优先级 | 情况 | 动作 | 谁 | 没人理会怎样 |
|---|---|---|---|---|
| 1 | 接管条件成立（见第 4 节） | 进入接管 | 两人 | 见接管规矩 |
| 2 | 契约验收点 ≤10 分钟到点 | 说清"交什么、交到哪" | 鲸澜 | 到点由契约自己转严格 |
| 3 | 截止日剩 0 / 1 / 3 / 7 天，且今天还没为它开过局 | 问一句，并排一局 | 鲸澜 | 当天只推一次 |
| 4 | 工作时段内，上一局结束 ≥5 分钟，没有局在跑、也没有排好的下一局 | 摆出下一局 | 鲸澜 | 今天计划里还有没开的局，**5 分钟后代码直接提前开**；没有就交给鲸澜现排 |
| 5 | 9:30 以后还没有今天的计划 | 替他排好，他只回"行"或"换" | 鲸澜 | 计划 10 分钟后自动生效（已有逻辑） |
| 6 | 局与局之间的空档、刷题到点 | 一道思维题、一次骰子、一组题、或纯聊天 | 鱼丸 | 不追 |
| 7 | 21:30 | 对账 | 鲸澜 | 已有 |

推进器给模型的不是"去找他聊聊"，而是**一张带动作的球**，例如：

> 推进：上一局 14:10 收了，下一局「简历投递」本来 15:00 开。现在提前开，第一步：打开 BOSS 直聘筛「上海 · 后端」。用你的口吻说一句，然后调 open_bout。

同一类推进有冷却期，不会每分钟推一次。所有推进都记进账本（`drive`），日判和周报能看到"系统推了几次、你接了几次"。

## 4. 三档模式

| 档 | 什么时候 | 两条鱼的样子 |
|---|---|---|
| 伙伴 | 水位清醒（`tide.js`）、在推进 | 低频（最快 8 分钟一球，可自己调）、随机、十次里七次不聊正事 |
| 推手 | 水位"在滑"；局之间空着；计划没排；切 App 次数到摇骰线 | 执行推进器给的那件事。能撤回的直接做，做完告诉一句 |
| 接管 | 水位"陷住"；或额度用完还在刷；或局内连续偏航；或契约逾期 | 见下 |

**接管档的规矩：**
- 不闭嘴：`silence`（5 球停 1 小时）和 `withdrawal`（敷衍冷处理）在接管期间暂停。
- 换渠道：文字没回应就语音念出来（勿扰、连麦时自动降成文字）。
- 锁先落下：裁决器进白名单模式（等裁决器从影子切成真执法后生效）。
- 给一个回位动作，例如"打开粉笔做完 1 道题"或"连 Gemini 说清下一步"。手机读到真的做了（在工作 App 里待满 3 分钟、交了东西、交了回执），才解除。
- 可以拒绝"让我再玩一会"。

**边界（为了不被卸载）：**
- 系统底座永远不锁，紧急解除（每天 3 次）永远有效。
- 一次接管最长 45 分钟；一天超过 3 次，晚上鲸澜必须复盘原因。
- 所有接管都进账本和日判。
- 自律等级上去以后，接管门槛跟着提高。

## 5. 会话换班：两个对话越聊越长怎么办

现在的问题：两条鱼各自绑定一个对话，上下文越积越多，又没有"换对话还记得"的机制。插件本身不能新建会话，新建要由 App 来做。

**做法：**
1. **插件判断该不该换班**：按绑定以来的轮数（默认 150 轮）或天数（默认 7 天），或你手动点"换新对话"。
2. **写交接**：
   - 最近 40 轮压成一份交接，内容包括：在聊什么、答应过什么、没说完的话题、他最近的情绪和状态。
   - 写进记忆库（标记"接班"）和 Obsidian 的 `大肥鱼/会话交接/日期-鱼丸.md`。
   - 这一步不靠模型自由发挥：结构化字段由代码校验，原话留底（`dialog.js` 已有）。
3. **App 新建对话并绑定**：两姐妹页"换新对话"按钮；到期时首页提示一次，一键完成。新对话第一轮自动带上交接，之后交接留在记忆库里，每轮按需召回。
4. **旧对话归档但不删**，随时能翻。

因为每一轮本来就会带上常驻档案、记忆、笔记、工作包（这些是插件按轮注入的，不靠对话历史），换班后丢掉的只是原始聊天流水，交接会补上其中要紧的部分。

## 6. 思考层：她们自己想事、自己优化

借鉴 Letta 的"睡眠时思考"（sleep-time agent 在后台整理主 agent 的记忆块）和 Generative Agents 的"反思"（重要事件累积到阈值就生成更高层的判断）。

**升级现在的夜间整理（`nightly.js`）：**
- 一天两次（13 点、22 点），另外在日判出来后加一次。
- **输入放宽**：近 7 天判决、App 账、Gemini 回执、截止日、最近改过的笔记（每篇节选，总共 ≤3000 字）、上一次的思考。原来"笔记原文一个字不进"的限制改为"有上限地读"。
- **产出**（严格 JSON，由代码校验）：
  - `urgent`：今天 / 这周最要紧的 1–3 件事，每件带依据（引用哪条账或笔记）；
  - `patterns`：反复出现的规律，例如"每天 15–17 点必滑""浏览器通行证偏航率 40%"；
  - `proposals`：给体系的调整建议，例如把某个 App 改严、某类局换时段、某个截止日要提前。**改严的可以直接执行**，放松的写进建议等他点头；
  - `self`：她自己的调参，有上下限，例如伙伴档间隔 5–30 分钟、哪类球最近被接得多。这接现有的 `brain.js`（Thompson 抽样）。
- 产出写进 `大肥鱼/两条鱼/思考/日期.md`，同时作为"她们最近在想的"注入每一轮上下文。
- 他问"你们觉得我最近怎么样"，她们能拿出有依据的回答，而不是空话。

**个性：**
- 保留现有人设和"活人感"设定。
- 加一份**她们自己的日常**：每天各自生成一两行，和人设保持一致（鱼丸的仓鼠、鲸澜的晨跑）。这些是聊天素材，让她们不只是"他的附属"。
- 两姐妹之间的"递话"（`sister_note`）继续保留：互相通气，各有立场。

**Token 平衡：**
- 推进器、模式判断、额度、裁决全部是纯代码，不花 token。
- 模型只在两种时候调用：真要开口时，以及每天 2–3 次的思考。
- 思考用便宜的模型档，单次约 4k 输入、800 输出。

## 7. 当下任务卡：把任务画成界面

借鉴 Google 的 A2UI 和 Flutter 官方 GenUI SDK：**AI 只输出受限的 JSON，App 用自己预先写好的组件来渲染，不执行任何生成的代码。**

- 新工具 `show_card`：两条鱼可以生成一张卡，由这些组件组成：
  - 标题、一句话目标；
  - 步骤清单（可勾选）；
  - 倒计时；
  - 交付物、验收方式；
  - 最多 3 个按钮，只能映射到已有动作（开局、领通行证、连 Gemini、交验收、换一局）；
  - 进度条、一段提示。
- 代码校验：组件只能从这份清单里选，字段长度有上限，按钮只能是白名单里的动作。
- 显示位置：局工作台的"现在"页签、悬浮窗收起时的小卡、锁页上（锁页直接显示"回位动作"卡）。
- 以后如果要更丰富，可以直接换成 Flutter GenUI SDK（它内部就是 A2UI 协议，项目用的 Flutter 3.47.7 满足它的版本要求）。

## 8. 和局、契约、主线、题库怎么串

推进器读的全是现有模块的数据，不另造一套：

| 模块 | 推进器怎么用 |
|---|---|
| 局 / 排局（`bouts`、`plan_bouts`、`open_bout`） | 局之间有空档时推下一局；到点没开就提前开 |
| 契约（`plan_modality`） | 验收点快到时提醒交付 |
| 三层主线（`horizons` + 截止日） | 截止日临近推一局 |
| 题库（`bank_unlock`）、思维题（`drills`）、六骰 | 空档时由鱼丸推 |
| 额度（`quota`）、裁决器（`lock_decision`） | 决定伙伴、推手、接管哪一档 |
| 日判（`verdict`）、App 账 | 思考层的输入；早上鲸澜的开场 |
| Gemini（`trigger`） | 推手和接管时的"看屏陪练"出口 |

## 9. 做的顺序

| 步 | 内容 | 风险控制 |
|---|---|---|
| 1 | 推进器 + 三档模式；接管时暂停沉默和冷处理、开语音 | 推进有冷却期；接管有时长和次数上限，全部记账 |
| 2 | 会话换班（插件判断 + 写交接 + App 一键换） | 旧对话不删 |
| 3 | 思考层升级 + 她们自己的日常 | 产出走 JSON 校验；只有改严的建议能自动执行 |
| 4 | 当下任务卡 `show_card` | 只用白名单组件和动作 |
| 5 | 裁决器从影子切成真执法（接管档的锁从这里来） | 先看 `arbiter-diff.jsonl` |
