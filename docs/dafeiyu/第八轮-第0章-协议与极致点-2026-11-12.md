# 第八轮 · 第 0 章：协议与极致点

> 2026-11-12 · 放在《第八轮计划-局与三器》所有工单之前。
> 这一章回答四个问题：手机到底能感知到什么（极致点）；思维怎么被调度和触发；沟通的硬限制是什么；敷衍怎么防。
> 工单里凡是和本章冲突的，以本章为准。

---

## 1. 极致点：不做贾维斯，先把能知道的用满

不追求实时识别万物。系统能依赖的信号只有下面这些，设计只能建立在它们之上。

### 1.1 行为感知（手机已有或易得）

| 信号 | 来源 | 现状 |
|---|---|---|
| 前台是哪个 App、开了多久 | 无障碍 | 已有 |
| 今天各类 App 累计时长、切屏次数 | 无障碍 | 已有 |
| 亮屏 / 充电 | 系统 | 已有 |
| 在移动（走路 / 骑车 / 静止） | 计步器或活动识别 API，不用定位 | 需加，一天工作量 |
| 现在几点、处于哪个作息时段 | 北京时间 + 作息模板 | 第七轮 P0-2、第八轮 S1 |
| 屏幕上的内容 | **只有 Gemini Live 能看** | 按需开，不常驻 |

### 1.2 思维感知（只能从他的输出里读）

系统看不见脑子，只能看他说出来、写出来的东西。所以「思维状态」在本系统里被定义为**对他每一条回复的代码级度量**：

| 指标 | 怎么算 | 说明什么 |
|---|---|---|
| 字数 | 直接数 | 太短 = 敷衍；太长 = 没压缩 |
| 话题数 | 句子级切分，统计不同对象（名词簇） | ≥ 3 = 想到什么说什么 |
| 具体名词数 | 与当前局的 what / 已知 / 中间结论做匹配 | 0 = 空话 |
| 有没有结论句 | 是否含判断词（是 / 不是 / 选 / 因为 / 所以）+ 一个对象 | 无 = 只在描述，没在推 |
| 问句数 | 直接数 | 一条回复里 ≥ 2 个问句 = 没聚焦 |
| 应答延迟 | 触发到回复的秒数 | 越长越可能已经漂了 |
| 填充词比例 | 「嗯 / 行 / 好的 / 等会 / 随便 / 再说」等命中数 ÷ 字数 | 高 = 口水话 |

这些指标全部纯函数、零模型。判官（V2）在此之上才看内容质量。

### 1.3 核心原则：不识别，只核对

系统不需要猜他在干什么。**开局时他已经声明了**：这一局做什么、在哪个 App、多长时间、交什么。
系统的工作是拿 1.1 和 1.2 的信号与声明**核对**，不一致就触发：

- 声明在学习局，前台却是购物 App 超过 2 分钟 → 触发
- 声明在外出局去店里，已过预算一半还在移动 → 触发
- 声明在思考局，连续两条回复话题数 ≥ 3 → 触发（降速）

这把「识别」这个做不到的问题换成了「核对」这个做得到的问题。代价是他必须开局——这正是 S3「不允许无局」存在的原因。

## 2. 沟通的硬限制

一个真人能看出他语无伦次，AI 看不出，因为没人给 AI 立规矩。这里立。

### 2.1 每种局型的数值上限

| 局型 | 他单条 ≤ 字 | 鱼单条 ≤ 字 | 鱼每条问句 | 单局来回 ≤ 次 | 每局话题数 |
|---|---|---|---|---|---|
| 题局 | 100 | 60 | 0 或 1 | 4 | 1 |
| 学习局 | 150 | 60 | 0 或 1 | 6 | 1 |
| 思考局 | 150 | 80 | 恰好 1 | 8 | 1 |
| 外出局 | 50 | 40 | 0 或 1 | 3 | 1 |
| 执行局 | 100 | 60 | 0 或 1 | 4 | 1 |

超限的处理全部由代码执行：

- **他超字数**：鱼不回答内容，只回「超了。分成两条，先说第一条。」
- **他话题数 ≥ 3**：鱼只做一件事——「你说了 N 件：A、B、C。选一件。」A/B/C 由代码从名词簇里抽，不由模型总结
- **来回次数用完**：这一局进入收局，必须交产出；没有就是空局
- **鱼超字数或多问**：重写，不发

### 2.2 混乱输入的唯一回应

他的回复命中「话题数 ≥ 3」或「无结论句且字数 > 80」时，判为**混乱**。此时鱼**不许回答他提的任何内容**，只能发出一条精简指令。这是全系统最重要的一条规则：混乱的输入得到的不是回应，而是一个压缩动作。

连续两次混乱 → 这一局切换到**写模式**：接下来的应答只收手写照片，不收文字。写比说慢，慢就是降速。

### 2.3 口水话的判定与后果

命中以下任一条判为口水话：字数 < 8；具体名词数 = 0；填充词比例 > 0.5；与他最近 5 条回复的重合率 > 0.7。

后果：**口水话不算应答**。触发器视为未应答，走模态阶梯（§4）。他用一点资源糊弄，系统就把下一次应答的最低资源抬高。

## 3. 五种协议

不建万物理论。五种协议覆盖他一天里九成的场景，剩下的归执行局。每种协议是一张固定的步骤表：步骤、时限、应答形态、代码判据都写死。**协议是训练，题目是素材。** 同一张表重复几百遍，习惯才会换。

### 3.1 题局（一手：刷题，但按我们的流程）

一道题一局。题库可以导入，流程不能改。

| 步 | 指令 | 时限 | 应答形态 | 代码判据 |
|---|---|---|---|---|
| 1 精简 | 「这题问什么？一句话。」 | 60 秒 | 文字 ≤ 30 字 | 含题干里的 ≥ 1 个名词 |
| 2 已知 | 「列出条件，最多 4 条。」 | 90 秒 | 文字，分行 | 2–4 行 |
| 3 预判 | 「用什么方法？答案大概是什么？」 | 60 秒 | 文字 | 含一个方法名或一个可核对的值 |
| 4 做 | 「做。」 | 按题型 | 手写拍照 | 照片时间在步 3 之后 |
| 5 对答 | 系统给答案 | — | — | — |
| 6 回想 | 「错在哪一步？不看过程说。」 | 60 秒 | 语音或文字 | 含步骤编号或步骤名 |

步 1–3 合计不超过 3.5 分钟；任何一步超时直接进入下一步并记「跳步」。一次刷题局 = 连续 N 道题，N 由预算定。
步 3 的预判和步 5 的答案自动对账，命中率按题型累计——这是他「预判」能力唯一可量化的曲线。

### 3.2 学习局（看视频 / 听课）

老师讲 10 个点，他看完只剩「似是而非」。问题不在没听，在听的时候没有动作。协议给动作。

| 阶段 | 指令 | 形态 | 判据 |
|---|---|---|---|
| 开局前 | 「这节会讲什么？猜 3 条。」 | 文字 3 行 | 恰好 3 行，每行 ≤ 20 字 |
| 播放中，每 6 分钟 | 浮层盖住视频：「刚才讲的，一句话。」答完才放行 | 文字 ≤ 30 字 | 含 ≥ 1 个具体名词，与前几次不重复 |
| 播放中，若前台切到非视频 App > 2 分钟 | 「你在学习局。回去，还是收局？」二选一 | 点选 | — |
| 预算剩 1/4 | 「停。不看，列出讲了哪几点。」 | 手写拍照或分行文字 | ≥ 3 行 |
| 收局 | 「哪一点没懂？写出那个问题。」 | 文字，恰好 1 个问句 | 问句含列表里的一个名词 |

产出物固定三段：猜了什么 / 讲了什么 / 没懂什么。判官只比对三段之间的对应关系（猜中几条、没懂的那条是否在「讲了」里），**不需要知道视频真的讲了什么**。

要知道视频真的讲了什么，只有一条路：**Gemini Live 学习模式**（§6）。它听得到音频、看得到屏幕，能在收局时交回「它听到的点」和「他列出的点」的差集。高价值的课用它，普通的课用上面的协议。

浮层盖视频这一步用的是已有的拦截页能力，不需要控制视频 App 本身。

### 3.3 思考局（开放问题：设计、决策）

这是他最容易一想一下午的局型，所以资源上限不只是时间。

| 字段 | 值 |
|---|---|
| 时间预算 | 默认 25 分钟，上限 40 |
| 展开上限 | 最多 2 个方案；第 3 个出现时鱼只说「停放」，记进停放区 |
| 挂载卡 | 开局即建：目标 / 已知 / 中间结论，三栏常驻浮层 |
| 触发序列 | 回想 → 精简 → 预判 → 提问，每 4 分钟一条，循环 |
| 混乱处理 | 按 §2.2：只给压缩指令，连续两次进写模式 |
| 产出 | 一句结论，或一句「卡在哪个问题」。二者必居其一 |
| 每日上限 | 3 局（含设计局） |

**设计局**是思考局的子类，专门给「想 DSH 该怎么建」这类事：每天 1 局、30 分钟封顶、产出必须是写进 `docs/dafeiyu/提议/` 的一段文字，否则算空局。想系统本身也要进局，否则它就是下一个逃避口。

### 3.4 外出局（以贴膜那天为对照）

那天发生的事，逐步对照协议会拦在哪一步：

| 那天 | 协议里的那一步 | 会发生什么 |
|---|---|---|
| 出门去贴膜 | **开局前检查**：「这件事还需要做吗？拍一张现状。」 | 拍手机屏幕 → 看到已经有膜 → 局作废，整天保住 |
| 骑车一个半小时 | 开局时预算：去程 + 办事 + 回程，默认 90 分钟 | — |
| 点了奶茶 | 移动停止但未到目的地 > 10 分钟 → 「到店了？还是停在别处？」 | 第一次漂移被点名 |
| 逛了一个半小时 | 预算过半仍未报「到店」→ 「还没到。现在去，还是取消？」二选一 | 没有第三个选项 |
| 在店里又逛 | 报「到店」后 15 分钟未交产出 → 「办完了吗？拍小票。」 | — |
| 回来附近又逛一天 | 预算到 → 强制收局；回到工作时段 → 无局 5 分钟自动开下一局 | 下午不会空着 |
| 求职什么都没打开 | 晨间计划里的求职局到点自动开；外出局空局 → 明天外出预算减半 | 代价在系统内 |

外出局的指令全走语音（骑车能答），应答只认「地点 + 下一步动作」两个要素，口水话不算。

### 3.5 执行局（默认）

写代码、写文、整理、做家务。只有三条触发：开局时「第一步是什么」；每 10 分钟「做到哪了」；预算剩 1/3「现在能交什么」。产出是文件、照片或一句话。

## 4. 模态阶梯：敷衍的成本必须高于认真

触发器对同一条指令的应答要求，按未应答或口水话的次数升级：

| 级 | 应答形态 | 最低资源 |
|---|---|---|
| 1 | 文字 | ≥ 8 字 + 1 个具体名词 |
| 2 | 语音 | ≥ 5 秒 + 转写后满足第 1 级 |
| 3 | 手写拍照 | 照片时间在触发之后，识图能提取出 ≥ 1 个局内名词 |
| 4 | Gemini Live | 开一场 10 分钟审讯模式，复盘作为应答 |

口水话用一点资源就能糊弄文字，糊弄不了手写。每升一级，糊弄的成本就超过认真答的成本。这是整个防线的原理，不靠劝。

同一局内升到第 3 级后不再降回。第 4 级每天最多 2 次。

## 5. 负反馈：系统内的代价表

| 事件 | 代价（次日生效） |
|---|---|
| 空局 1 次 | 该局型次日预算 −20% |
| 同一天空局 ≥ 3 | 次日作息切到严格模板（无局上限减半、放风额度归零） |
| 外出局空局 | 次日外出预算减半 |
| 连续 3 天空局率 > 50% | 墙锁定设定页 7 天，只能改紧不能改松 |
| 口水话占比 > 40%（当天） | 次日所有触发从第 2 级（语音）起步 |
| 局内切到娱乐 App | 当场锁（已有），且该局记「漂移」，判官扣分 |

代价全部作用于**明天的资源**，不是当场的惩罚。当场惩罚能顶回去，明天的预算顶不回去。

系统之外的那一个代价（每周有一个真人看到空局数），在计划里只提这一次，由他决定。

## 6. Gemini Live 的位置

它是唯一能看屏幕、听声音、每几秒说一句话的通道。它不替代三器，它是三器在高难度局里的执行臂。DSH 开局、交简报、收复盘、做验收；Gemini 在局内高频追问。

简报按协议生成，不是泛泛的「陪他学习」：

```
【学习模式 · 30 分钟】
他在看 <课程名>。每 6 分钟打断一次，让他一句话说刚讲的。
他说得空泛（没有具体名词）就追问一次，不给答案。
结束时让他不看屏幕列出讲了哪几点，你把自己听到的点和他列的做比较。
【复盘】格式：他列的 / 你听到的 / 差的 / 他说没懂的那一条。

【思考模式 · 25 分钟】
问题：<what>。只许展开 2 个方案。
每 4 分钟按顺序问：目标是什么 / 推到哪了 / 你猜结论是哪个 / 卡住的是哪个问题。
他开始说第三个方案，让他停，记下来。
【复盘】格式：结论或卡点一句话 / 两个方案各一句 / 停放了什么。

【审讯模式 · 10 分钟】
他刚才三次没有正经回答「<指令>」。只问这一件事，直到他给出含 <局内名词> 的回答。
【复盘】格式：他最后的回答原文。
```

复盘读回后直接进 `deliverables`，走 V 组验收。

## 7. 数据：每周看什么

| 指标 | 回答什么问题 |
|---|---|
| 各局型空局率 | 哪种事最逃 |
| 空局按小时分布 | 几点最容易漂 |
| 触发应答率 / 口水话率，按指令类型 | 哪种问法他真的会答 |
| 模态阶梯升级次数 | 防线被试探了多少次 |
| 题局预判命中率 | 预判能力有没有长 |
| 学习局「猜中条数」趋势 | 听课前的预判有没有长 |
| 思考局结论 vs 卡点比例 | 想清楚的多，还是卡住的多 |
| 主动开局 ÷ 系统开局 | 主动性有没有长——这是全系统的北极星 |

## 9. 第一周

只开两种局：**题局**和**思考局**。每天题局 1 次（10 道题）、思考局 2 次。其他时间不管。
一周后看三个数：题局跳步率、思考局空局率、口水话率。三个数定第二周开哪种局。

协议表在第一周不改。改表要等数据，不等感觉。
