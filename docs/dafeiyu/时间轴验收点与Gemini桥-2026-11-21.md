# 时间轴验收点 + Gemini 桥（2026-11-21）

> 接《验收体系-设计-2026-11-20》。用户反馈：「主动流程没跑通，意味着我必须提前一天把所有任务交上来——不如每天时间轴上的验证点」；
> 以及「Gemini App 和大肥鱼两个核心之间没有交互，不合适」。这一版把两件事接上。

## 一、验收点上时间轴

**一个对象，不是第四套系统。** 封印引擎（代码判、档位、到点锁、按档奖励、豁免）原样保留，验收点多了：

| 字段 | 含义 |
|---|---|
| 开始时刻 | 到点推进器自动开这一局（工作包写清交什么、几点前、保底多少）；没写就按「截止 − 预计分钟」算 |
| 来源 | night（前一晚封）/ morning（开工前定）/ live（开工后现加）/ ai（两条鱼加）/ gemini（Gemini 加） |
| 证据 | 原五种 + **通过验收的局的分钟数**（局本身已给过一份，这一类奖励减半）+ **Gemini 回执**（≥2 问 2 答的「过」才算） |

**冷热线（改了 11-20 的一条规则，用户可以否决）**：前一晚 23:00 前封的、当天 10:00 前且还没开过局定的——不打折；
开工后现加的 ×0.7。理由：时间轴成了主流程，再按「当天定的都七折」，主流程永远打折。

**推进顺序**（driveNow 里先看时间轴，再看别的）：

1. 22:30–23:00 明天一条没封 → 提醒一次。
2. 截止前 10 分钟没过保底 → 提醒一次。
3. 到开始时刻 → 能开就开局；被挡着（聊天 / 吃饭 / 紧急 / 深夜 / 温和档 / 在花自己挣的余额）只提醒，15 分钟最多一次。
4. 到截止 + 1 分钟没过保底 → 严格锁（和封印同一条 P2 通道），交够就解，最长 60 分钟。
5. 冷启动点火：时间轴上已有今天没交的点，就不再拉 Gemini「定第一局」。

## 二、Gemini 桥

```
Gemini（自定义应用 / MCP）──HTTPS──► Tailscale Funnel ──► 电脑上的桥（tooling/gemini-bridge）
                                                         ▲
                       手机 DSH Go 引擎 ──HTTPS 每 ~20 秒──┘（上行今天的快照，下行 Gemini 的命令）
```

**为什么是手机主动去连**：手机引擎只听 127.0.0.1；手机上 NekoBox（连 Gemini 要用）和 Tailscale 不能同时开（安卓只能一个 VPN）。

**Gemini 的权限 = 第三方验收人**：

| 能 | 不能 |
|---|---|
| 看今天（时间轴、进度、锁、局、余额、截止日）、公约全文、这一周的冷数据、电脑上的笔记（日记 / 私密不读） | 解锁、加娱乐额度、豁免、改小、删除——桥上没有这些工具 |
| 交回执（≥2 问 2 答才能判「过」，代码再验一遍）、加验收点（只加，手机按同一套冷热规则）、提议规矩（他批） | 直接改手机上的任何东西（写操作都是命令，手机按自己的规矩再验） |

**大肥鱼 → Gemini**：桥连着（10 分钟内同步成功过）时，所有拉起 Gemini 的背景里都多一段「先 dafeiyu_today、定了就写验收点、最后交回执」；
plan 口吻改成「定今天的时间轴」。

**Gemini → 大肥鱼**：回执进 gemini-receipts.json，同时记一条 gemini-recap（晚上对账、接管解除都认它），
写 大肥鱼/Gemini/回执/日期.md；绑了验收点的立刻重新结算（可能当场过档、解锁、发分钟）。

## 三、周冷数据包（验收第三批的雏形）

7 天只有数字的一包（每天几个点、过 / 没过 / 豁免原话 / 现加、挣的分钟、开局、回执、紧急、接管、想改小被拒），
末尾固定提问要【周验收】块（≤3 条调整）。两条路：手机验收点页「复制这一周的冷数据」粘给 Claude / GPT；
或 Gemini 用 dafeiyu_week 直接读。**调整的回收（粘贴【周验收】回来、逐条确认生效）还没做**，下一批。
