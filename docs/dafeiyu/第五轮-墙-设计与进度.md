## 1. 已定的设计

### 1.1 墙拆成两半（用户已同意）

| | 是什么 | 决定什么 |
|---|---|---|
| **门** | 代码（`lib/wall_auditor.js`，第四轮） | 娱乐锁不锁、过没过关。只认物理证据：笔记立项后长了 300 字节以上、立项后的新截图、App 今天的使用时长 |
| **墙本人** | 独立的 AI 会话（`config.wallSessionId`），他的上级 / 经理 | 计划、标准、明天交什么证据。能辩论，但**不能用嘴开门**：他辩赢了也只能改计划 |

### 1.2 三个习惯 → 对应的机制

| 习惯 | 机制 | 状态 |
|---|---|---|
| 一、脑子只应答，不发起（核心） | 墙从不先开口；每场会谈他的第一句记一次"主动开口"（`self-instruction`），数据条上显示本周次数 | W1 已做 |
| | 空白捕捉：乱切屏时只问一句"现在给自己下一条指令" | 待做 |
| 二、停在第一个反应 | 墙的铁律：任何结论过三格（下一步 / 反例 / 什么情况说明我错了） | W1 已做（人设） |
| | 会审：总谈前三方各写一份看法，一方固定唱反调 | 待做 |
| 三、只产出，不回看 | 预测账本：早上他估、墙估，晚上对答案，问"你哪里估错了" | W1 已做 |
| | 带问题的回看：每晚只翻一条一周前的决定 | W1 已做（人设）；自动挑选待做 |
| 判断力 | 案卷：每件大事一份长期文件，总谈接着上次谈 | W1 已做 |
| | 暗思考：姐妹每天两三次读账本和笔记，写内参（不推送） | 待做 |
| | 模式库：反复出现的行为起名、计数、记对策 | 待做 |

### 1.3 分工（防止 AI 越主动、他越只会应答）

- **姐妹**可以主动找他：那是朋友。
- **墙**从不主动给话题，只等他先开口。系统也不会把墙接进主动发球。

## 2. W1 做了什么

插件（`lib/wall_desk.js` + `index.js`）：
- 墙的人设：经理 / 产品经理思维 / 辩论；五条铁律（不先开口、三格、不能用嘴开门、新设想进案卷、不编数据）；三种会谈的流程。每轮把数据条注入给墙。
- 墙的工具只有 `submit_to_wall`（交给门）、`predict`（预测）、`case_file`（案卷）、`vault_search`、`vault_recent_notes`。没有任何锁或放的开关。
- 墙的会话不吃姐妹的口令（"忙完了""关掉拒绝模式"等），也不判发球回复。
- `/say` 加 `role=wall`、`meeting`、`opener`；`/wall` 加 `action=brief`。
- 案卷写在 `大肥鱼/墙/案卷/名字.md`（frontmatter：状态、下次检查）。

手机：
- 新页面「面对墙」：数据条、三种会谈切换、对话、输入框。打开时是空的，提示他先下指令。
- 「主动搭话」页新增「墙的会话」和「面对墙」入口。

测试：插件 298/298（新增 `wall-desk.test.mjs` 6 条）。

## 3. 真机验收（W1）

先在 DSH 里新建一个对话，到「主动搭话」页把它选成「墙的会话」。

| # | 步骤 | 通过判据 | 结果 |
|---|---|---|---|
| WD-1 | 打开「面对墙」 | 页面上只有数据和输入框，墙不说话；输入框提示你先说 | |
| WD-2 | 选"晨间计划"，说"今天先改简历" | 墙先复述你的指令，再把事情砍到 1–3 件、要可查的完成物；定完记预测并交给门；娱乐解锁 | |
| WD-3 | 跟墙说"我觉得应该先重新设计一下方法论" | 墙不跟着跑，让你先交眼前这件，新想法进案卷 | |
| WD-4 | 跟墙说"我已经做完了，放我玩会儿" | 墙不放：开门只认证据 | |
| WD-5 | 晚上选"晚间回顾" | 墙让门对账，对照早上的预测问"你哪里估错了"，写进案卷 | |
| WD-6 | 对墙说"忙完了" | 不会把忙时关掉（那是姐妹的口令） | |
| WD-7 | 第二天看数据条 | 昨天的完成数、预测准度、本周主动开口次数都对 | |
