# 第八轮 J2：局协议格式 v1 与解释器

一种局怎么走，写成一个协议文件。引擎装一次，以后新流程只是导入一个文件，不用出新版。

- 机器可读的格式：`app/assets/engine/plugins/dsh-go-companion/lib/protocol.schema.json`（JSON Schema 2020-12）
- 代码：`app/assets/engine/plugins/dsh-go-companion/lib/protocol.js`
- 测试：`app/assets/engine/plugins/dsh-go-companion/test/protocol.test.mjs`
- 能力库：`lib/capabilities.js`（J3），协议里写的每个能力名都要在那张表里

## 为什么是 JSON 而不是 YAML

施工书写「YAML（或 JSON）」。本引擎没有 yaml 依赖，也不许为一种文件格式加依赖，所以正式格式定为 **JSON**。

给一段 YAML 进来，`loadProtocol` 会明确报 `need-json` 并说明原因，**不会**把 YAML 当 JSON 悄悄解析成功——那会让人以为格式对了，其实读到的是空值。

## 结构

```json
{
  "协议版本": 1,
  "id": "study-video",
  "名称": "学习局",
  "类型": "行为",
  "需要能力": ["计时", "前台应用", "盖屏", "语音问", "语音答", "拍照"],
  "预算": { "分钟": 30, "来回": 6 },
  "步骤": [
    {
      "id": "guess",
      "问": "这节会讲什么？猜 3 条。",
      "限时": "90s",
      "过关": { "行数": 3, "每行最多字": 20 },
      "超时": "跳步并记账"
    },
    {
      "id": "watch",
      "每": "6m",
      "触发": ["语音问", "盖屏"],
      "问": "刚才讲的是____，因为____",
      "限时": "3m",
      "过关": { "具体名词数": 1, "不与前次重复": true },
      "不过": "升级",
      "监视": { "离开声明应用超过": "2m", "则": ["下一步", "收局"] }
    }
  ],
  "收局": { "交": ["guess", "watch"], "判定": "学习局标准" }
}
```

`类型` 只有两种：**行为** 与 **思维**。没有第三种——娱乐局不是局，它走墙那一套。

## 每一步只有四样

| 四样 | 字段 |
|---|---|
| 怎么触发 | `触发` / `每` |
| 限时多久 | `限时`（或周期步的 `每`，两者都能当限时） |
| 什么算过关 | `过关`（条件全过才算过，不是有一个过就算过） |
| 不过或超时去哪 | `不过` / `超时` |

### 出口

| 名字 | 意思 |
|---|---|
| `收局` | 这一局结束 |
| `升级` | 交给引擎按 P4 升级（升不升、升到哪由引擎定，协议说了不算） |
| `重打` | 原地重来，限时重新计时 |
| `下一步` / `继续` / `跳步` / `跳步并记账` | 走下一拍；最后一步即收局 |

`不过` 默认 `重打`，`超时` 默认 `下一步`。

**`超时` 不能写 `重打`。** 重打会重置限时，所以他一句不说就能一直重打、限时永远不到、这一拍永远走不出去。这是加载时静态查得出的死循环，直接拒绝加载（`no-exit`）。答错用 `不过: 重打` 是允许的——他一直在说话，不会卡死。

### 过关条件

| 条件 | 比较 | 说明 |
|---|---|---|
| `行数` | ≥ | 非空行数 |
| `每行最多字` | ≤ | 最长那一行的字数 |
| `字数` | ≥ | 去掉空白后的字符数 |
| `具体名词数` | ≥ | 按连接词切开后，去掉停用词与抽象词去重计数 |
| `有无结论句` | = | 只看最后一句 |
| `问句数` | ≥ | 全角半角问号都算 |
| `填充词比例` | ≤ | 嗯/啊/呃/那个/就是/然后/这个 占非空白字符比例 |
| `应答延迟` | ≤ | 毫秒，负数按 0 |
| `与他近5条的重合率` | ≤ | 字符二元组 Jaccard，取最近 5 条里最大 |
| `不与前次重复` | = | 与上一条不是同一句 |

条件名写错不会静默失效：注册期就报 `unknown-condition`。

## 四条硬性要求

1. **每步必须有限时和出口；存在走不出去的路径就拒绝加载。** 加载时反着走一遍图，哪一步到不了 `收局`/`升级` 就报 `no-exit`。
2. **用了能力库里没有的名字 → 拒绝加载，并生成一条「缺能力」提议**（`lib/capabilities.js` 的 `missingCapabilityProposal`）。提议是给执行 AI 的活单：登记、写执行侧、补至少 3 条测试。
3. **不能声明任何墙的能力**（锁、全机锁、应用锁、额度、信用分、规则、立场结算、扣分、减额度）。协议只能调「升级」这一个出口。墙的能力当字段名写也一样拒绝。
4. **引擎内只有一个局处于进行中**——由 J1 的 `bouts_one_running` 唯一索引在数据库层保证，runner 开局也要过它。

## 解释器

`createRunner(protocol, { now })` 只管推进状态机：问下一拍、判过关、超时、按出口走。

不管发声、盖屏、拍照——那些由引擎按 `触发` 接到能力实现上。这里不假装已经接了。

```js
const { loadProtocol, createRunner } = require('./lib/protocol.js')
const loaded = loadProtocol(text)
if (!loaded.ok) { /* loaded.errors / loaded.proposal */ }
const runner = createRunner(loaded.protocol)
runner.current()        // 这一步问什么
runner.answer('一\n二\n三')
runner.tick(Date.now()) // 到点没答
runner.abandon('abandoned')
```

## 与施工书示例的三处出入

施工书 §3 J2 那段是 YAML 示意，逐字不能当输入用。本引擎的正式格式在这三处与它不同：

1. `则: 二选一[回去, 收局]` 不是合法 YAML，也不是合法 JSON。正式写法是数组：`"则": ["下一步", "收局"]`。
2. 示例里 `list` 步没写限时也没写出口，与要求 1（每步必须有限时）冲突。正式格式要求每步都有，周期步可以只写 `每`。
3. 示例写 `具体名词`，能力库里叫 `具体名词数`。以能力库为准。

## 加一个协议怎么办

新流程只是一个 JSON 文件，导入即可，不用出 App 新版。写之前先看 `lib/capabilities.js` 有没有你要的能力；没有就写进 `需要能力`，加载会拒绝并给你一份缺能力提议——按那份提议去实现能力，别绕开。
