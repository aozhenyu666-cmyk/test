## 2. 三层原则（本轮所有设计的总纲）

`vibe.js` 头注释已经定了这个划分，本轮把它扩到整个系统。**每个新功能在回报里写明自己属于哪一层。**

| 层 | 内容 | 允许随机吗 | 谁能改 |
|---|---|---|---|
| **约束层**（墙） | 规则表、锁、额度、时区、立场账本的「硬立场」、上下文预算 | 绝不 | 只有用户清醒时改；改松有冷却期 |
| **判据层**（墙） | 什么算完成、什么算敷衍、预判对没对、训练题过没过 | 绝不 | 只有代码按证据算；模型没有写权限 |
| **内容层**（鱼） | 说什么、用哪张素材、什么情绪、发几条、出不出声 | 随机，带防抖 | 模型 + 随机器 |

用户说的「确定性」= 约束层 + 判据层更硬；「随机性」= 内容层更活。两者不冲突，**冲突只发生在把判据放进内容层的时候**（例如让鱼自己决定「他今天算完成了」）。

## 3. P0：三个必须先做的工单

### P0-1 Gemini 连麦舱闪退

**现象**：连麦期间打开图库、文件夹会被踢回桌面；有时 Gemini 自己也被踢。

**根因（已读代码确认的部分）**

`ProactiveRuntime.kt` 的 `listed()`：

```kotlin
if (sessionActive()) return !sessionAllows(pkg)
```

舱一开，判定就从「在娱乐名单里才拦」翻转成「不在白名单里就拦」。`sessionAllows()` 只放行：
插件下发的 `allow`（`gemini.js` 里只有 `com.google.android.apps.bard`、`com.google.android.googlequicksearchbox` 两个包）、
`NEUTRAL`（写死的 10 个桌面/系统包名）、用户放行名单、DSH 自己。
命中后 `onFrontChanged()` 和 `/plan` 回调两条路都直接上 `Force(4, …, refuse = true)`。

所以以下窗口全部会被当成「切到别的 App」并触发 4 级锁：

| 被误拦的 | 典型包名 | 为什么会出现 |
|---|---|---|
| 系统照片选择器 / 图库 | `com.google.android.providers.media.module`、`com.android.providers.media.module`、各厂商图库 | 在 Gemini 里点「添加图片」 |
| 文件选择器 | `com.android.documentsui`、`com.google.android.documentsui`、厂商文件管理 | 在 Gemini 里点「添加文件」 |
| Google 服务弹层 | `com.google.android.gms` | 账号选择、权限确认 |
| 相机 | 厂商相机包 | Live 的拍照入口 |
| 非名单桌面 | 荣耀、realme、第三方桌面等 | `NEUTRAL` 是写死的，没覆盖的桌面一回去就被锁 |

**待实测确认的部分**：「Gemini 自己也闪退」具体是哪个包名触发的，代码里看不出来。`ForegroundRecorder.kt` 就是为这个建的，**第一步先用它抓真实数据**，不许凭猜测加包名。

**修法：把舱内判定从「白名单」改成「分级策略」，并抽成纯 Kotlin 对象**

新建 `phone/a11y/SessionPolicy.kt`（无 Android import，可在 JVM 单测，做法照 `FrontChange.kt`）：

```kotlin
enum class SessionVerdict { ALLOW, GRACE, LOCK }
fun judge(pkg: String, facts: SessionFacts): SessionVerdict
```

判定顺序（先命中先返回）：

1. `NEVER_LOCK`、DSH 自己、`FrontChange.isLayer` → `ALLOW`
2. 插件 `allow` + 用户放行名单 → `ALLOW`
3. **当前默认桌面**（运行时用 `PackageManager.resolveActivity(ACTION_MAIN + CATEGORY_HOME)` 解析，不再靠写死名单；`NEUTRAL` 保留作兜底）→ `ALLOW`
4. **娱乐目标**（`blockedNow()` ∪ 拦截目标 ∪ 插件 `block`）→ `LOCK`，立即，和现在一样
5. **系统应用**（`ApplicationInfo.FLAG_SYSTEM` 或 `FLAG_UPDATED_SYSTEM_APP`）且不在第 4 条 → `ALLOW`
   （图库、文件选择器、相机、GMS 都落在这里）
6. **从白名单 App 跳出去的短暂停留**：上一个真实前台是白名单 App，且离开不到 `sessionGraceMs`（默认 45 秒）→ `GRACE`
7. 其余第三方 App → `GRACE`，连续停留超过 `sessionGraceMs` 才升 `LOCK`

`GRACE` 不弹锁屏页，只发一条不打断的提示（「连麦还开着，45 秒内回去」），并启动一次性定时复查。回到白名单 App 即清零。

**同时修掉两处重复判定**：`onFrontChanged()` 和 `/plan` 回调里各有一份「连麦舱锁非白名单」的代码（约 850–870 行、1011–1023 行），统一改成调 `SessionPolicy.judge()`，逻辑只留一份。

**最小交付**

| `dsh-longing` | 注入的是「数值档位 + 当场处境」，不是整句模板 | 状态行改成结构化短行，禁止大段说明文字常驻 |

**新建 `lib/budget.js`（纯函数）**

```js
// blocks: [{ id, layer:'constraint'|'state'|'content', priority, text, minChars? }]
// 返回 { text, kept:[id], dropped:[{id, reason}], chars }
export function fitBudget(blocks, { total, perLayer })
```

规则：

1. **约束层永不裁**（铁律、我.md 摘要、当前主状态议程、硬立场）。约束层自己超了 `perLayer.constraint` 就**抛错并落账本**，不许悄悄截断——这是配置问题，要让人看见。
2. 状态层按 `priority` 降序装，装不下的整块丢，不做半截截断。
3. 内容层（随机块、悄悄话、暗思考产物）最后装，预算不够就一条都不带。
4. 每轮把 `kept/dropped/chars` 写一条 `ctx-budget` 账本。

**默认预算**（进 config，可调）：聊天侧每轮注入总量 ≤ **2400 字符**；约束层 ≤ 900，状态层 ≤ 1000，内容层 ≤ 500。

**工具瘦身：按主状态暴露**

22 个工具全量注册是最大的固定开销。在 `machine.js` 的 `STATE_TABLE` 每一行加 `tools: [...]`，`mountOne()` 按当前主状态注册子集：

| 主状态 | 暴露的工具（上限 8 个） |

## 4. A 组：确定性与墙

### A1 立场账本：两条鱼不被同化

**问题**：她今天说「这件事必须 6 点前做完」，用户磨三句，她就改口「那明天也行」。没有任何机制记录她说过什么、检测她改口、让改口有代价。

**设计**

新建 `lib/stance.js`。**立场是约束层对象，不是提示词里的一句劝告。**

```js
// 一条立场
{ id, by:'strategist'|'companion', at, text,           // 她的原话（≤120 字）
  kind:'hard'|'soft',                                   // hard = 不能被聊天改变
  about: taskId | ruleId | topicId,                     // 绑到一个可查对象
  until,                                                // 到期时间，必填
  evidence: [ledgerSeq...],                             // 为什么立：账本行号，至少 1 条
  status:'held'|'revised'|'expired'|'kept'|'broken' }
```

规则（全部代码层）：

1. **立**：工具 `take_stance`。`hard` 立场必须绑定一个墙认得的对象（当日任务、规则项），且必须带 `evidence`。每天 `hard` 上限 3 条，`soft` 上限 5 条——她得挑重要的立。
2. **守**：`hard` 立场在 `until` 之前，**她没有修改它的工具**。`revise_stance` 对 `hard` 一律返回 `{ok:false, code:'stance-locked'}`。能让它变的只有三件事：到期、墙按证据判定已完成、用户在**晨间窗口**里重新定计划。
3. **改口检测**：`soft` 立场可以改，但每次改必须带 `reason` 且引用一条**立场之后**新出现的账本证据。「他说不想做」不算证据（`classify.js` 判为 `avoid`/`refuse` 的用户话语不能作为 evidence 的来源）。改口无新证据 → 拒绝并记 `stance-cave-attempt`。
4. **注入**：当前生效的立场以结构化短行进**约束层**（走 P0-3 预算）：`[硬立场] 今天 18:00 前交 xx 的初稿 · 到期前不可更改`。
5. **事后对账**：到期时由墙的遥测算 `kept`/`broken`（做法照 `predict.js` 的 `settle()`，`verdict_source` 固定），她没有写权限。
6. **独立思考与进化**：每晚对账后，`stance.js` 汇总「她的立场里有多少条事后证明立对了」，写进 `判断.md`（`notes.js` 已有，每次最多 5 条变化的约束沿用）。立场命中率进 `brain.js` 的 beliefs，下一天她立场的 `hard` 额度随命中率浮动（2–4 条）。

**防同化的第二道闸：同意率监测**

新增纯函数 `agreementRate(ledger, windowTurns=20)`：统计最近 20 轮里她「顺着用户说」的比例（用 `judge.js` 现有判词扩一个 `yielded` 标记，由代码按「用户表达拒绝/回避 → 她下一句撤回或降低要求」判定，不问模型自己）。
超过阈值（默认 0.7）时，约束层加一行：`[提醒] 最近 20 轮你退让了 N 次，其中 M 次没有新证据。`

**最小交付**

- [ ] `lib/stance.js` + `test/stance.test.mjs` ≥ 25 条：hard 不可改、无证据不能立、用户回避话语不能当证据、额度、到期结算、结算字段模型不可写、重启后从账本重建
- [ ] `take_stance` / `revise_stance` 两个工具，按 P0-3 的状态表暴露

### B4 情绪池

**设计**：借 `dsh-longing` 的状态机结构（多维数值、事件推动、半衰期回落、余怨跨天），**只借结构，不借它的维度**。

新建 `lib/emotion.js`（替代 `temper.js` 的单轴，`temper.js` 保留为兼容薄层）：

| 维度 | 0 ↔ 100 | 日常值 | 半衰期 |
|---|---|---|---|
| 耐心 | 炸了 ↔ 很有耐心 | 70 | 3 小时 |
| 在意 | 懒得管 ↔ 很上心 | 60 | 12 小时 |
| 火气 | 平静 ↔ 生气 | 15 | 90 分钟 |
| 兴致 | 没劲 ↔ 想聊 | 50 | 4 小时 |

事件表（进代码，一行一个事件，照 `dsh-longing` 的 `events.js` 写法）——至少包含：

| 事件 | 判定来源 | 效果 |
|---|---|---|
| 敷衍回复 | `judge.js` 判 `brief`/`stock` | 耐心 −8，火气 +10；同类连发递减 |
| 连续 3 次敷衍 | 账本 | 火气 +15，挂一条 6 小时余怨 |
| 认真回 | `judge.js` 判 `engaged` | 耐心 +6，兴致 +8，火气 −10 |
| 守住硬立场 | A1 结算 `kept` | 在意 +10 |
| 违抗 | 账本 `defiance` | 火气 +20，余怨 1 天 |
| 被晾着 | 发球后无回应 | 兴致 −5；睡眠窗内不算 |

**情绪 → 行为参数**（「不只改说什么，也改怎么说」，借 `dsh-longing` 的 `behavior.js`）：

```js
behaviorOf(emotion) → { burst: 1|2|3,        // 这一轮连发几条
                         maxChars,             // 单条长度上限
                         delayMs: [..],        // 连发间隔
                         channel: 'text'|'voice'|'overlay',
                         tone: '档位标签' }
```

火气高且耐心低 → `burst` 2–3、每条更短、间隔 3–8 秒。**连发由手机侧按 `delayMs` 排队发送**，不是模型一次生成一长段。

**硬边界（约束层，测试守住）**

- 情绪**不影响**任何锁、额度、判定。`emotion.js` 不被 `wall*.js`、`force.js`、`machine.js` import（源码扫描测试）。
- `burst` 每小时总条数有硬上限（默认 12），安静时段为 0。
- 不许说伤害性的话：沿用人设卡里「能说多狠」的上限，情绪只在上限内移动。

**最小交付**

- [ ] `lib/emotion.js` + `test/emotion.test.mjs` ≥ 25 条：每个事件的数值变化、半衰期回落到日常值而不是 0、余怨跨天、同类递减、从账本重建

### C1 工作记忆挂载卡（防「内存漏水」）

**问题**：用户推导到一半断掉，回头不知道自己在解决什么、已经知道什么、推到哪一步。

**设计**：新建 `lib/mount.js`。一张卡固定三栏，**内容必须是用户自己的话**：

```js
{ id, topicId, openedAt,
  goal:   { text, by:'user', at },                    // 当前目标：1 条
  givens: [{ text, by:'user', at, src? }],            // 已知条件：≤5 条
  steps:  [{ text, by:'user', at, from:[givenIdx] }], // 中间结论：≤5 条，必须标出由哪几条已知推出
  status: 'open'|'parked'|'closed' }
```

规则：

1. **她不替他填。** 工具 `mount_propose` 只能把用户说过的原话（带账本行号）提议挂上去，用户确认后才落卡。她自己总结的话进不了卡（代码校验：`text` 必须是某条用户消息的子串或用户在面板上手写）。
2. **同时只有 1 张 open 卡。** 开新卡前旧卡必须 `parked`（带一句「停在哪」）或 `closed`。
3. **断链检测**（纯函数）：用户新消息与 open 卡的 goal/givens/steps 关键词重合低于阈值，且连续 2 轮 → 判为「漂了」。此时她这一轮**只做一件事**：把卡亮出来，问一个二选一——「继续这张，还是先停放」。
4. **注入**：open 卡以 ≤ 300 字符进状态层最高优先级：
   `[挂载] 目标：… ｜ 已知：①…②… ｜ 推到：… ｜ 上次动：14:20`
5. **手机侧常驻**：浮层小卡（复用现有 overlay），用户随时点开看三栏；一次点击可追加一条已知或结论。
6. **训练的目标是让他自己学会挂**：统计「用户主动挂载次数 / 她提议挂载次数」，这个比值是 C 组的核心进步指标，进周报。比值上升时她的提议频率自动下降（脚手架撤除）。

**最小交付**

- [ ] `lib/mount.js` + `test/mount.test.mjs` ≥ 25 条：非用户原话拒绝、单 open 卡、上限、断链检测、停放与恢复、结论必须引用已知
- [ ] `mount_propose` / `mount_park` / `mount_close` 工具，进状态表

### C2 四个基本操作：精简、预判、提问、回想

**设计**：扩 `drills.js`。每个操作有独立的题型、**代码可判的合格线**、进度曲线。合格与否不问模型（判据层）。

| 操作 | 题型 | 合格线（全部代码判） | 素材来源 |
|---|---|---|---|
| **精简** | 把刚才那段话压成一句 | ≤ 30 字；包含挂载卡 goal 的至少 1 个关键词；与原文 bigram 重合率在区间内（太低 = 跑题，太高 = 没压） | 用户最近一段 > 100 字的话 |
| **预判** | 动手之前写下「我猜结果是 X，依据是 Y」 | 必须含一个可核对的断言（数字 / 是非 / 先后）；事后由 `predict.js` 的 `settle()` 结算 | A2 时间块开始时、连麦开始前 |
| **提问** | 只许问一个问题，问那个能改变答案的 | 恰好 1 个问句；不是是非题；包含挂载卡里一个 given 或 step 的关键词 | B2 的 `gaps` |
| **回想** | 不看任何东西，说出上次推到哪 | 与对应挂载卡 steps 的关键词召回率 ≥ 阈值；作答期间浮层挂载卡被遮住（手机侧上报 `recall-blind: true`） | 已停放的卡、昨天的四部记录 |

**训练链路是固定顺序**：一个主题上，回想 → 精简 → 预判 → 提问。不是每次走完四步，但出题时**不能跳到后面的步骤**（上一步今天没过，不出下一步）。

**调度**：

- 每天每个操作至少 1 题、合计 ≤ 6 题；出题时机挂在已有触发点上（时间块边界、解锁训练题 `InterceptDrill`、晚间对账），不新建闹钟
- 题目文本可以由模型按素材现编（内容层），但**题型、合格线、判定**在代码里
- 没过：只告诉他差在哪条合格线（模板文案），不给示范答案；第二次没过才给一个示范

**最小交付**

- [ ] `drills.js` 四个题型各自的判定纯函数，`test/drills-ops.test.mjs` ≥ 32 条（每个操作 ≥ 8 条，含边界）
- [ ] 链路顺序约束 + 测试
- [ ] 每日额度与触发点接线
- [ ] 进度：每个操作近 14 天通过率，进 `sisters.js` 快照和面板
- [ ] `InterceptPageActivity` 的训练题接上这四个题型（现有 `InterceptDrill` 扩，不新建页面）

**超额项**

- [ ] 难度自适应：通过率 > 80% 连续 3 天，该操作合格线收紧一档（精简 30 字 → 20 字）；< 40% 放松一档。每档写死在表里
- [ ] 周报加四操作曲线与「主动挂载比」
