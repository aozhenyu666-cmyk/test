# 首次启动：边解压，边设置

> 2026-10-27。回答 owner 的问题：首次启动选了本机，解压运行环境要等一两分钟，能不能一边解压、一边让用户把其他设置做完，减少体感等待。
> 范围：只改首次启动（「DSH 在哪里运行？」选「本机」之后）。远程主机路径、升级 / 重置运行环境、设置里的「安装本机运行环境」都不变。

## 0. 结论

| 问题 | 结论 |
|---|---|
| 能不能并行 | 能。解压本来就不归页面管：原生 `RuntimeController` 的工作线程在跑，`DshService` 前台服务 + 唤醒锁保着进程，进度从 EventChannel 进 `localRuntimeProvider`。页面翻走、切后台都不影响它；缺的只是「谁来发起、谁来显示、什么时候收尾」 |
| 新流程 | 选「本机」→ 立刻在后台开始解压 → **外观** → **连接 DeepSeek** → 解压还没完就进一个安静的等待页，完了直接进首页。步数 2 → 3，但第 2、3 步是在等待时间里做的，纯等待从一两分钟降到「设置做完后剩下的那一截」 |
| 进度怎么可见 | 外观页、连接页底部一枚固定的玻璃胶囊：`◔ 运行环境 42%`。不弹窗、不挡操作；点开是状态弹层（进度 / 剩余时间 / 日志；失败时是重试 / 改用远程主机 / 查看日志） |
| 提前做完怎么办 | 等待页：大光环 + 百分比 + 剩余时间，「完成后自动进入」；通知开着时多一行「完成时会通知你」——用户可以直接离开，装好了会收到通知。**不**放用户先进 App（理由见 §4） |
| 账号登录要引擎 | DeepSeek 账号登录走本机引擎的回调，解压完之前做不了。连接页照常显示「用 DeepSeek 账号登录」；解压中点它，页内换成等待态「就绪后自动打开 DeepSeek 登录」，装好后自动接上登录。API Key 不依赖引擎，随时能存 |
| 中断恢复 | 新增一个偏好 `onboarding_setup_step` 记住做到哪一页；App 被杀后重进回到那一页，解压没完就自动重新开始（原生会清掉 staging 从头解，不改解压格式） |
| 原生改动 | 很小：解压完成 / 失败时 App 不在前台就发一条通知，进度通知点了能回 App。有单测（§7） |

## 1. 现状

### 1.1 流程

```
欢迎 ─[开始]→ DSH 在哪里运行？
   ├─[远程主机 · 继续]→ 主机列表 → 选中 → 首页
   └─[本机 · 继续]→ 解压页（光环 0→100%） ─ 约 40 s – 2 min，只能看着 ─→ 准备就绪（0.9 s）
         → 连接 DeepSeek ─[账号登录]→ 启动引擎（数秒）→ 浏览器授权 → 首页
                        ─[使用 API Key]→ 输入、保存 → 首页
                        ─[其他服务商 / 稍后设置]→ 首页
```

步骤条：选择 / 解压算第 1 步，连接 DeepSeek 第 2 步，共 2 步。

### 1.2 耗时点

| 段 | 耗时 | 用户在干什么 |
|---|---|---|
| 解压 rootfs（约 150 MB xz → 750 MB） | 约 40 s – 2 min，看机型（文案「首次准备约需一两分钟」，模拟器日志 41 s） | **什么也不能做**，盯着光环 |
| 账号登录前启动引擎 | 冷启动 2–3 s（模拟器，`runtime-cold-start.md`），真机更久 | 看「正在启动引擎」 |
| Android 13 通知权限弹窗 | 一次 | 出现在解压页 |

### 1.3 解压由谁驱动（读代码得到）

- **发起**：`RuntimeSetupPage._install()` → `LocalRuntimeController.install()` → MethodChannel `install` → `RuntimePlugin` 先 `startForegroundService(ACTION_INSTALL)`（前台通知 + 唤醒锁），再 `RuntimeController.install()` 在单线程 worker 上解压。
- **防重复**：原生两道——插件里 `phase == INSTALLING` 直接回 `install_busy`；`RuntimeController.install()` 自己也查一次。Dart 侧没有去重，靠页面只调一次。
- **进度**：`RuntimeInstaller` 每读 512 KB 报一次 `(done, total)` → `emit(progress)` → EventChannel → `localRuntimeProvider.progress`；同一个 sink 也更新前台通知的百分比。
- **剩余时间**：`RuntimeSetupPage` 页面里自己采样估算（页面状态，不共享）。
- **离开页面 / 切后台**：不受影响（worker + 前台服务）。设置里的安装页注释写着「返回键随时离开，安装在后台继续，通知显示进度」。
- **失败**：`phase = error`，`error = "install failed: …"`（空间不足、校验失败等）；页面给「重试 / 查看日志 / 改用远程主机」。
- **被系统杀掉**：进程死了解压也死了；下次启动 `installedVersion == null`、`phase == notInstalled`，根门禁回到「DSH 在哪里运行？」重新问一遍。只有 Activity 被划掉而进程还在时，`phase == installing`，回到解压页接着看。

## 2. 新流程

```
欢迎 ─[开始]→ DSH 在哪里运行？
   ├─[远程主机]→ 主机列表 → 首页                                   （不变）
   └─[本机 · 继续]→ ① 后台开始解压（前台通知 + 唤醒锁，Android 13 在此时问通知权限）
         │
         ├→ 外观（2/3）         深浅色 · 配色（· 低端机：轻量模式）      底部胶囊：◔ 运行环境 42%
         │     └[继续]
         ├→ 连接 DeepSeek（3/3）                                      底部胶囊
         │     ├[用 DeepSeek 账号登录] ─ 已就绪 → 照旧登录
         │     │                       └ 解压中 → 页内等待「就绪后自动打开 DeepSeek 登录」→ 就绪 → 自动登录
         │     ├[使用 API Key] → 保存 ┐
         │     ├[其他服务商] → 保存   ├→ 解压完了？ 是 → 首页
         │     └[稍后设置] ──────────┘              否 → 等待页 → 完成 → 首页
         │
         └ 任何时候解压完成：胶囊 ✓ 一下后淡出，后台立刻启动引擎（账号登录、其他服务商保存都要它）
```

升级、重置、设置里的安装：仍是原来的解压页 → 连接 DeepSeek（2 步），不进并行流程——那些用户已经配好了，没有可并行的东西。

### 2.1 并行期间配置什么

| 候选 | 进不进 | 理由 |
|---|---|---|
| 连接 DeepSeek | **进，放最后** | 唯一真正必要的一步。账号登录依赖引擎，放在最后能让解压尽量先跑完；API Key 不依赖引擎，任何时候都能存 |
| 外观（深浅色、配色） | **进，放在中间** | 不依赖任何东西，点一下全 App 立刻换色——等待时间里最有「回报」的事；复用设置里同一套 `ThemeModePicker` / `PalettePicker`，用户之后在设置里看到的就是这一页 |
| 性能模式 | **只在低端机上出现**，并入外观页 | 低端机在「自动」下本来就是轻量，这里只是让用户确认：一个开关「轻量模式」，默认开。中高端机「自动」就是完整效果，没有可确认的，不打扰 |
| 界面语言 | 不进 | 默认跟随系统，目标用户（中 / 英）几乎不会错；设置 › 语言随时能改 |
| 手机操控 | 不进 | 要本机运行环境就绪、要去系统里开无障碍，引导里只能放一段说明——违背「每步一个问题，不堆说明」。空对话页和设置里都有入口 |
| 宠物 | 不进 | 要悬浮窗权限（去系统设置），轻量模式下默认关；在设置 › 主题里 |
| 可视化回复 | 不进 | 默认开，没看过回复之前讲不清它是什么 |
| 自定义色 / 跟随壁纸 / 功能图标 / 桌面图标 | 不进 | 都在设置 › 主题；引导里只放六套预设，320 dp 宽也能一行放下 |

结果：并行期间只多一页（外观），连接 DeepSeek 原本就有。总共 3 步，比现在多 1 步，但纯等待基本消失。

### 2.2 每一页都能走

- **外观页只有「继续」**，没有单独的「跳过」：选项即点即生效，默认值（跟随系统 · 雾蓝）已经在用，什么都不点按「继续」就等于跳过。再放一个「跳过」只会和「继续」做同一件事。这跟 iOS 设置助理里外观页的做法一致（只有「继续」）。
- 连接 DeepSeek 保留原来的「稍后设置」和「其他服务商」。
- 页内等待登录有「取消」，回到连接页可以改用 API Key 或稍后设置。
- 等待页没有按钮可按也不需要：完成后自动进入；失败时给重试 / 改用远程主机 / 查看日志。

## 4. 提前做完：为什么是等待页，不是先进 App

| 方案 | 好处 | 问题 |
|---|---|---|
| 先进 App 的只读部分 | 看起来不用等 | 新装的 App 没有对话、没有工作区，能「浏览」的几乎为空；输入框可以打字但发不出去，第一印象是「坏了」；首页各处都要处理「运行环境还在装」这个新状态，改动面大、风险高 |
| **等待页 + 离开也会通知**（采用） | 安静、可预期；剩余时间一般只有几十秒；想离开就离开，好了会收到通知 | 用户确实要等剩下那一截 |

设置做完时解压通常已经过半（外观十几秒、连接 DeepSeek 几十秒），剩下的等待短。慢机型上剩得多，正好由通知兜住：等待页写「完成时会通知你」，用户回桌面也行。

通知只在 App 不在前台时发（在前台时等待页自己会进首页），点通知回到 App。通知权限关着时，等待页不写这句（不许诺做不到的事），换成原来的「全程在本机完成」。

## 5. 完成 / 失败 / 提前做完的表现

| 时刻 | 外观页 / 连接页 | 页内等待登录 | 等待页 |
|---|---|---|---|
| 解压完成 | 胶囊 ✓「运行环境已就绪」2.4 s 后淡出；后台启动引擎 | 原地开始登录（启动引擎 → 打开浏览器）；App 在后台时等用户回来再打开 | ✓ 0.9 s → 首页 |
| 解压失败 | 胶囊变红「安装未完成」，不打断当前页；点开：重试 / 改用远程主机 / 查看日志 | 退回连接页，自动弹出失败的状态弹层 | 原失败视图：重试 / 查看日志 / 改用远程主机 |
| 设置先做完 | — | — | 进等待页 |
| App 在后台时完成 / 失败 | 通知「运行环境已就绪」/「运行环境安装未完成」，点了回到原页 | 同左 | 同左 |

「改用远程主机」走原来的主机列表；选中主机就进首页，外观和已存的 API Key 都保留（无害）。

## 6. 回访与中断恢复

新增偏好 `onboarding_setup_step`（`appearance` / `connect` / `finishing`）：选「本机」时写 `appearance`，每进一页更新，进首页或改用远程主机时清掉。没有它就是原来的行为，所以老版本中途升级上来的用户不受影响。

| 被打断时 | 进程 | 重进后 |
|---|---|---|
| 外观 / 连接页，解压中 | 只划掉了界面，进程还在（前台服务） | 回到那一页，胶囊接着显示同一次解压的进度 |
| 外观 / 连接页，解压中 | 进程被杀 | 回到那一页，**自动重新开始解压**（原生清掉 staging 从头解），胶囊从头走 |
| 外观 / 连接页，已解压完 | 任意 | 回到那一页，胶囊不出现 |
| 连接页，已有 API Key / 已登录 / 选过稍后 | 任意 | 直接到等待页（未完成）或首页（已完成） |
| 等待页 | 任意 | 未完成：等待页（必要时重新解压）；已完成：首页 |

解压格式不改，所以没有断点续解：被杀就从头来，这是原生现有行为。

### 6.1 解压不中断、不重复、进度只有一个来源

- 解压仍由原生 worker + 前台服务执行，页面翻页、切后台都碰不到它。
- Dart 侧新增唯一入口 `runtimeInstallProvider.install()`：同一时刻只会有一个请求在路上，第二个请求拿到的是同一个 Future；原生的 `install_busy` 仍是第二道闸。根门禁（选本机、重进续解）、等待页、失败后的重试都走它。
- 进度只读 `localRuntimeProvider`；剩余时间从页面状态挪到 `installEtaProvider`，胶囊弹层、等待页、页内等待登录显示同一个数。
- 完成后谁启动引擎：根门禁监听「运行环境就绪」，并行流程里一就绪就 `EngineControl.ensureStarted`（和原来解压页结束时做的一样，只是不再等页面）。

## 7. 原生改动（小）

| 改动 | 位置 | 为什么 |
|---|---|---|
| 解压结束时，App 不在前台且通知可用 → 发「运行环境已就绪 · 点按继续设置」/「运行环境安装未完成 · 点按查看」 | `DshService` `ACTION_INSTALL_DONE`；判断逻辑抽成纯函数 `InstallAlert.choose()` | 等待页许诺「完成时会通知你」 |
| 安装结果随 `ACTION_INSTALL_DONE` 带上（`ok`） | `RuntimePlugin` | 上一条要知道成败 |
| 解压进度通知可点，点了回 App | `DshService.buildInstallNotification` | 现在点了没反应 |
| 新通知渠道「运行环境」（默认重要性，有提示音、无横幅） | 同上 | 已有的低重要性渠道太安静，「引擎已停止」渠道名字不对 |

## 10. 增补（2026-10-28）：按功能开启权限

外观之后、连接 DeepSeek 之前多一步「想让 DSH Go 帮你做哪些事」，并行流程变成 4 步（选择 → 外观 → 功能 → 连接）。它也在解压的等待时间里，不拉长首启；只在本机首启出现，远程主机、升级、重置不进。

```
功能多选（默认全不勾，可跳过）→ 逐项开启（一次一项，回到 App 自动检测）→ 汇总 → 连接 DeepSeek
```

| 功能 | 用到的项（按走的顺序去重） |
|---|---|
| 读写手机里的文件 | 文件访问（勾选时先过「让 AI 访问手机文件？」） |
| 桌宠与悬浮窗 | 显示在其他应用上层 |
| 手机操控 | 通知、无障碍（勾选时先过显著披露；受限制的设置按系统状态分三步）、后台弹出界面（vivo、小米） |
| 后台持续运行 | 通知、忽略电池优化、厂商后台开关（vivo 后台高耗电 / 小米省电策略 / 华为荣耀应用启动管理 / OPPO 后台行为）、自启动（vivo、小米） |
| 语音输入 | 麦克风；勾选前写明约 241 MB 模型、移动数据时提示流量；选择写入 `onboarding_wants_voice` |

- 勾选「手机操控」：显著披露之后再选一次确认方式，二选一、不预选——「关键步骤先问我」（`ask`）或「全程自动」（`always`，选中时说明系统设置和权限页面、密码和验证码、DSH Go 自身仍由用户操作，银行、支付类默认不碰，以及去 设置 › 手机操控 › 解除限制 可以放开）。关掉选择框就不勾选。按「开启所选」时写入手机操控的 policies（与 设置 › 手机操控 › 确认方式 同一个 `setPolicies`）；写不进去就存在 `phone_confirm_pending`，汇总页「继续」、下次启动、打开手机操控页时再写。三个「解除限制」开关不在首启里出现。
- 能检测的项回到 App 时重读，开了打勾进下一项；厂商开关系统不报状态，去过之后由用户点「设好了」，状态记作「已去设置」，不当成已开启。
- 汇总页按「继续」时（当场重读一次，汇总里补开的也算）：文件可达才打开「访问手机文件」，手机操控打开总开关，宠物能画才打开「App 外显示」；引擎在跑或正在启动（启动时已带走旧设置）时只重启一次。
- 被杀后回到同一步：已选功能和跳过的项存在 `onboarding_access`，按「继续」且上面这些设置写完才清掉。
- 设置 › 通用 › 系统权限 是同一份清单，按功能分组，点未开启的行进同一个单项页。
- 代码：`lib/state/access_state.dart`、`lib/ui/access/`、`lib/ui/onboarding/access_step.dart`；厂商页面表在 `VendorSettings.kt`，受限制的设置状态在 `RestrictedSettings.kt`。
