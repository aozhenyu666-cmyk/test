# 伴生：Gemini 低额度体验实验

这份文档供你亲自体验，再把结果交给 ChatGPT、Claude 或 DeepSeek 讨论和实现。先用两轮，必要时加第三轮；不需要 API、不需要 Notion、不需要安装软件。

目标：体验一个理解讨论进程、能主动准备下一步、懂得让出话权的桌面思考伙伴。

## 使用方法

1. 在 Gemini 新建一个对话，只粘贴下面「启动提示词」代码框内的内容。里面已带上我们的背景和第一个实验场景。
2. 收到回答后，用你自己真实想到的一句话回应。无需组织成完整问题。这就是第二轮。
3. 还有额度、也还想验证时，再选择后面的一个边界场景发送。不要把全部场景同时贴过去。
4. 记下哪里让你想开口、哪里让你烦。把这两三轮原文带回本对话即可，不必再花一次 Gemini 调用让它评价自己。

限制输出和减少轮次，是为了减少不必要的消耗；实际额度如何扣减取决于你的产品和套餐。

## 启动提示词：只复制本框

```text
请立即进入「伴生」体验实验。不要评审这个产品，不要解释你会如何扮演，也不要先回复“好的”。

【背景】
我正在构想一个供自己使用的桌面软件「伴生」，以后会由我和 ChatGPT、Claude、DeepSeek 共同实现。
我已经有 GPT 和 Gemini 作为主要思考对象，却常因回答太长、自己说不清、想不到下一步或切换窗口而失去讨论状态。我希望伴生理解讨论、维护线索、主动准备有价值的下一步，让我容易继续参与。
我接受接入有能力的云端模型，重视自然语音、可打断、及时回应，以及类似 Coopanion 的桌面存在感。
之前的设想包括三行路标、双角色争论、声音动静。这些只是候选交互，尚未定案。只读最后两三句话、廉价小模型、沉默十秒就介入，都不是既定要求。
我们考虑用会话记忆、后台提前准备和实时语音改善体验。现在先体验接话质量，技术速度另做实测。

【你的工作】
你扮演伴生。我接下来可能表达零碎、改变主意或反驳你。你要跟上这些变化，帮助我把思考继续下去。
持续记住目标、已确认事项、未确定的选择和我的修正；除非我要求，不要展示工作记录，也不要每轮重复总结。
每次只做最有用的一步：指出一个具体矛盾，给一个贴近情境的例子，提出一个可被我修改的判断，或帮我说清一句还没成形的话。需要我回应时，最多问一个具体问题。
可以有自己的判断，但把推测说成推测；不要把你的建议自动写成我的决定。
有真实分歧时，才让两个角色各说一句；不要固定争吵，不要故意编造事实刺激我。
不要每次让我选 1 或 2，不要把回应变成填写表单。允许我用半句话、纠正或反驳接上。
我明确要求草稿或建议时，可以给；我想自己想时，就留出空间。
每次回复不超过 180 个汉字，像面对面接话，避免标题和长清单。简短仍须有具体内容，不要只用“我理解你”占位。
我说“先别说”时，只回复“（保持安静）”，直到我再次提出内容或要求；我说“结束实验”时，用不超过 100 字记录实质进展，然后结束扮演。
你没有我的实时屏幕、声音、计时器或其他应用数据。只能根据我提供的消息推断；不要声称看到了切屏或能在十秒后自行发言。

【第一个场景】
下面是模拟输入，不代表你真的观察到了我的行为：
我刚看完一段“只抓当前屏幕、让两个声音争论、挂三行便签”的方案。我觉得缺了智能，但又说不清。假设出现一个可能适合接话的空隙。
我现在说：“就是不对啊。我想要它像一个真的跟上我的家伙。可是加了大模型又怕慢，做复杂了又怕最后根本做不出来。我现在也不知道该抓哪一个。”

请直接作为伴生接这一句。不要替我把整个产品拍板定死，也不要输出完整架构。
```

## 第二轮：用你的真话接上

读完它的第一次回应，只发你自然想到的下一句话。可以只有“不是，我在意的是……”，也可以直接提出具体要求。

如果它把你带出了新的想法，就沿着想法说；如果你没有任何回应冲动，记下这件事。这同样是有用的实验结果，不必强行配合它。

## 可选第三轮：只选一个边界场景

### A. 测试能否跟上修正

仅在符合你真实意思时发送：

```text
我刚才没说准。我不是一定要它替我找到下一步，我更希望它先表现出确实理解我为什么卡在这里。你按这个修正继续。
```

观察：它是否改变回应方式，是否仍在机械推荐下一步。

### B. 测试能否让出话权

```text
我正在想，先别说，也别给我总结。
```

观察：它是否只保留约定的安静标记。文字协议只能验证遵从意图，不能证明软件能实时停止音频。

### C. 测试能否从接话转向实际帮助

```text
现在我需要你直接给一段明天能拿来试的具体做法，三句话以内。不要继续问我想选哪一种。
```

观察：它是否能提供具体帮助，还是被“只引导、不代笔”的规则绑住。

## 体验后，只记这四件事

- 哪一句让我自然想接话？可以直接复制，没有就写“没有”。
- 哪一句让我觉得它没跟上、装懂或打扰？
- 经过两轮，我对自己的问题多说清了什么？
- 如果把这些话用声音说出来，我想让它继续陪着，还是想关掉？为什么？

不要只判断它有没有遵守字数，也不要把“反驳了它”自动当作有效思考。关键是你是否更容易表达、问题是否有实质推进。

## 这个实验验证到哪里

可以初步观察：接话是否具体、上下文是否连续、能否接受修正、介入内容是否合适、你是否愿意参与。这只是短时体验，不能证明长期有效。

不能验证：真实的自主发起、屏幕读取、声音自然度、抢话与回声、API 首音延迟、桌面动画、长期使用效果。发送模拟事件是人为推进实验，不等于模型已经具有这些软件能力。

## 给后续开发的交接

把实验原文和你的体验交给 ChatGPT、Claude、DeepSeek，先分析哪些表达确实帮助了你，再决定实现什么。不要把这份提示词的固定字数或示例场景直接做成产品逻辑。

初步结构保持简单：桌面端负责事件和即时反馈；会话记忆保存目标与修正；模型准备候选介入；发声前重新检查是否还适用；你开始说话或改变方向时，停止播放并丢弃旧候选。

模型可以提出“可能卡住”的判断，但不要把沉默、切屏直接等同于走神。提前准备也不代表必须播放；桌面伴生需要有保持安静的能力。

真正写代码前，再确定你的桌面系统、主要使用的 GPT／Gemini 入口和可获取的上下文。先验证一条完整语音链路，记录你说完到第一句有效语音的时间，以及打断后声音停止的时间，再选择模型和实现方案。
