# 提案：档位 → 后台动作与强度（待用户拍板）

- 提出：主界面线，2026-09-26
- 实现：流程线（工作流、`drift_scan.sh`、`action_guard.sh`、`EXEC_RULES.tsv`）
- 性质：**立法提案**。按"狱卒不立法"，下面的数值要用户逐项确认后才能写进规则表。

## 原则

1. **规则保持神秘**：规则只存在于后端文件。主控台只显示心情四档，花火角色卡只用戏里的话暗示，都不显示阈值、次数和下一步动作。
2. **只有一个档位真相**：档位由后端偏离扫描决定，写进一个状态文件；主控台和花火都读它。主控台现在自己算的心情只是临时近似，后端状态文件出现后就改为只读展示。
3. **一张脸**：所有提醒、追问、解锁谈判都由花火在她的会话里完成，不再用多个提醒窗。
4. **越往上越少说话、越多动作**：念叨会让人疲劳，升档要靠后果，不能靠更频繁的提醒。

## 四档对应什么（请逐项确认或修改）

| 心情 | 后端条件（沿用现有 drift 定义） | 花火做什么 | 系统做什么 | 默认强度（待确认） |
|---|---|---|---|---|
| 安心 | 无偏离 | 基本不打扰；3 小时没动静才轻轻问一句 | 无 | — |
| 在意 | `drift_level=1` | 念一句（语音），不弹窗 | A1 提醒 | 同一状态 2 小时内最多 1 次 |
| 担心 | `drift_level=2` | 在她的会话里追问，要你用四个动作之一回应 | A2 追问 | 30 分钟不回应视为未回应，可进入下一档 |
| 要谈谈 | `drift_level=3` | "这一幕得换布景了"，然后执行动作 | A3 暂停当前干扰 App（仅 `ent.list` 组 A，经 `action_guard`、`app_suspender`） | 暂停 **20 分钟**；向花火说明理由可提前解除（走 `UNLOCK_POLICY`） |
| （连续要谈谈） | 当天第 3 次进入"要谈谈" | 同上 | A4 锁屏 | **建议暂不启用**，直到 A3 在真机上连续一周稳定 |

需要你拍板的数值：
- [ ] A3 暂停时长：20 分钟？（可选 10 / 20 / 30 / 直到说明理由）
- [ ] "担心"等待回应多久算未回应：30 分钟？
- [ ] A4 锁屏：暂不启用？
- [ ] 每日人工解锁上限：沿用现有 2 次？

## 状态文件（流程线产出，主控台读取）

`/sdcard/Download/Operit/state/now.json`（覆盖写）：

```json
{
  "updated_at": "2026-09-26 14:30:00",
  "level": 2,
  "drift_level": 2,
  "streak": 3,
  "target_pkg": "com.baidu.tieba",
  "last_action": { "id": "A2_ASK", "at": "2026-09-26 14:10:00", "state": "ACCEPTED" },
  "pending_user_response": true
}
```

`last_action.state` 取值为 `REQUESTED` / `ACCEPTED` / `EFFECT_VERIFIED` / `USER_CONFIRMED`。字段可以由流程线在读完 `drift_scan.sh` 后调整，但请先通知主界面线。**这个文件只给程序读，界面上不展示规则含义。**

## 和主控台已有功能的衔接

- 打卡工具 `focus_hub_nav:check_in(message?)` 已经能用你的 `voice_bar` 念话，并且有节制（深夜、冷却、同档不重复）。"在意"档的 A1 提醒可以直接调用它，传入花火的台词。
- 用户点"继续 / 卡住 / 提交 / 暂停"会写入 `progress/<日期>.jsonl`（`origin: REAL_USER`）。A2 的"是否回应"以这里有没有新记录为准。
- 花火角色卡（`cards/huahuo.json`）里已经写好：解锁先问理由、规则不背条文、工作流消息不当成用户说话。
