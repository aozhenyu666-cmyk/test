## 3. P0 问题（阻断品牌识别）

### P0-1 应用图标实际上不存在正确的 Launcher 资源

证据：
- `AndroidManifest.xml`：`android:icon="@drawable/ic_pet"`。
- `res/` 下**没有 `mipmap-*` 目录**，**没有 `mipmap-anydpi-v26/ic_launcher.xml`**，**没有 adaptive icon**。
- `res/drawable/ic_pet.xml` 是一个 `24dp`、`viewport 24x24`、`fillColor="#FFFFFFFF"` 的纯白极简脸。

后果（源码推断）：
1. Android 会把 24dp 矢量放大到 108dp 图标的尺寸，**纯白填充在浅色桌面上几乎不可见**。
2. 没有 adaptive icon → 在 Android 8+ 上被强制裁成圆形/方形并套白色底板，进一步糊成一团。
3. 没有 monochrome → 主题图标（Material You）下显示为空白。
4. 这与用户“图标看起来像没有”的描述完全一致，属**资源与配置缺陷**，不是审美问题。

### P0-2 品牌名在界面里自相矛盾

证据：
- `res/values/strings.xml`：`app_name` = **同桌**。
- `MainActivity.kt`：眉标写 `COMPANION / 桌宠`，主标题写 **桌宠**。
- UI 层硬编码 **22 处**“桌宠”。

后果：桌面图标叫“同桌”，打开后满屏“桌宠”，用户无法确认是不是同一个产品。这是**信息架构问题，不是文案偏好**。

### P0-3 悬浮层与页面是两套互不相关的配色

证据：
| 位置 | 主色 |
|---|---|
| 页面 tokens | 纸 `#F6F1E7`、墨 `#1E1C18`、珊瑚 `#E4572E`、柠檬 `#E8FF6A` |
| `PetView.kt` | 身体 `rgb(255,214,165)`、描边/墨 `rgb(70,48,38)`、纸 `rgb(255,252,240)`、强调 `rgb(108,142,230)` |
| `BubbleView.kt` | 墨 `rgb(70,48,38)`、强调 `rgb(108,142,230)`、底色 `rgb(255,244,230)` |

后果：**悬浮角色和气泡完全没接入设计 token**。角色是暖橘 + 蓝色强调，页面是暖纸 + 珊瑚，两者摆在一起像两个产品。

## 4. P1 问题（显著影响体验）

### P1-1 设置页 15 个分区挤在一页（66.9 KB 单文件）
分区：搭话用的模型 / 能力 / 设备操作 / 让它自己动手 / 本机主动陪伴 / 开口节奏 / App 名单 / 深聊用哪个 AI / AI 会话 / 专注守护 / 严格陪伴 / 想一想 / 其他 / 连续性 / 调试。
虽然有 `SETTINGS_GROUPS` 5 组导航，但每组内仍是长滚动列表，次级说明文字密集。

### P1-2 强调色使用过载
`signal = #E8FF6A`（柠檬黄）同时用于：选中态、高亮按钮、徽标、强调标签。黄色在浅色纸面上对比度尚可，但作为**大面积按钮底色**缺乏层级区分，主次操作看起来一样重。

### P1-3 深色模式未实测
`DarkCompanionColors` 存在，但 `themes.xml` 只有 `Theme.Material.Light.NoActionBar`，未声明 `values-night`。Compose 侧可跟随系统，但**启动闪屏与系统栏仍走浅色**，切换时会有跳变。

### P1-4 字体放大与窄屏未验证
设置页大量 `Row` + 固定权重 + 长中文说明，字体放大到 1.3× 时大概率出现换行挤压。未实测。

## 5. P2 问题（细节）

- 统计页表格用 `horizontalScroll` + 固定 64dp 列宽，8 列共 604dp，窄屏需横向滚动，无滚动提示。
- `Eyebrow` 使用 `text.uppercase()`，中文不受影响但英文字母全大写在小字号下偏挤。
- `SourceTag` 用 `RoundedCornerShape(999.dp)` 胶囊，与整体 12/16/24dp 圆角体系不完全统一。
- 空状态只有 `EmptyNote` 一行灰字，没有下一步操作。

## 6. 根因分析：为什么“功能都有但看起来廉价”

1. **没有单一设计源**：页面走 Compose token，悬浮层走 Android Canvas 硬编码，两套系统各自演化。
2. **品牌符号缺位**：图标是 24dp 白色占位矢量，没有 adaptive icon，等于没有品牌入口。
3. **命名分裂**：产品叫同桌，界面叫桌宠。
4. **强调色承担了太多角色**：选中、主按钮、徽标共用一种高饱和黄，导致视觉焦点分散。
5. **信息密度失控**：设置页把 15 个分区平铺，用户无法建立心理地图。

## 7. 三个设计方向

### 方向 A：纸感同桌（Paper Companion）

- 概念：像一本摊开的笔记本，同桌坐在纸边陪你读。延续现有暖纸 + 墨色，收敛强调色。
- 情绪：安静、可信、温和；俏皮只体现在角色，不体现在版式。
- 配色：纸 `#F7F3EA`、面板 `#FFFDF8`、墨 `#1C1A16`、次要 `#5F594E`、线 `#E0D8C9`、珊瑚 `#C9512E`（降饱和）、强调仅用于单一主操作。
- 字体：标题衬线，正文无衬线；层级靠字号 + 字重，不靠颜色。
- 布局：单列、宽留白、细分割线；**取消卡片套卡片**，只用 1px 线与留白分组。
- 角色：暖橘身体 + 墨色描边，**强调色改为珊瑚，取消蓝色**。
- 动效：120–240ms，只用于状态变化与按压。
- 风险：偏保守，个性主要靠角色承担。

### 方向 B：编辑式工作台（Editorial Desk）

- 概念：把同桌当成一个编辑台，材料、记忆、目标像稿件一样陈列。
- 情绪：清晰、专业、略有距离感。
- 配色：冷白 `#FAFAF7` + 墨黑 + 单一深绿 `#2F6B4F` 作为强调。
- 字体：全无衬线，标题靠字重拉开。
- 布局：双栏（宽屏）+ 左侧索引；信息密度高。
- 角色：几何化的抽象伙伴，弱化脸部。
- 风险：**与“陪伴”定位冲突**，更像知识管理工具；窄屏双栏会塌。

### 方向 C：角色优先（Character First）

- 概念：让角色成为视觉中心，界面退成舞台。
- 情绪：鲜活、有性格、略俏皮。
- 配色：深色舞台 `#171512` + 角色暖色 + 高饱和点缀。
- 布局：每页顶部一个大的角色状态区，功能下移。
- 角色：多状态动画（待机/思考/说话/困）。
- 风险：**每页顶部大图会挤压真实功能**；深色舞台与用户“不要黑黄原型”的诉求接近，容易被认为换皮不换骨。

## 8. 选定方向：A 纸感同桌

理由：
1. 现有代码已经是暖纸 + 墨色，选 A 是**收敛与修正**，不是推翻重来，改动可控、回归风险最低。
2. 用户明确排斥黑黄原型；B 太冷、C 太接近深色舞台，都不符合“有温度但成熟”。
3. 悬浮角色已经是暖橘 + 墨色描边，与 A 天然同源；只需把蓝色强调换成珊瑚即可统一。
4. A 的“细线 + 留白”能直接解决卡片套卡片与强调色过载。

不混合 B、C 的元素，避免变成没有主张的折中。

## 10. 影响分析

- **不影响**：包名、签名、数据模型、记忆迁移、API Key 存储、前台服务、无障碍、悬浮窗、主动搭话节奏、语音、深聊桥接、测试断言。
- **会影响**：`AndroidManifest.xml` 的 icon 引用、`res/` 新增资源、`Tokens.kt` 色值、`PetView`/`BubbleView` 颜色常量、UI 文案。
- 文案改动需检查测试是否断言“桌宠”字样。

## 11. 未验证与风险

- 无真机 / 无模拟器 → **所有视觉结论未经渲染验证**。
- adaptive icon 在 vivo/iQOO 桌面上的实际裁切形状未验证。
- 深色模式、字体 1.3×、窄屏未验证。
- 悬浮层换色后与系统深色壁纸的对比度未验证。
