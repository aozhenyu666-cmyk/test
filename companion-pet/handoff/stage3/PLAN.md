## 二、任务 3.1：专注流程做成可用基础

### 现状
机制齐全（Guard + Overlay + Controller），**缺的是「让用户看得懂、信得过」**。

### 要做

1. **首页状态卡**（新增，`ui/HomeScreen` 或 `StartTab`）
   - 大字显示：当前状态（未开始 / 专注中 / 已完成）、剩余时间、限制范围
   - 缺权限时：红色提示「缺无障碍服务，限制不会生效 → 点这里开启」，**绝不显示"已保护"**

2. **限制能力如实说明**（文案，`ui/SettingsTab` 或首页展开）
   - 能做：切到被限制 App 时弹全屏遮罩、自动拉回目标
   - 做不到：阻止 Home/返回/最近任务、阻止关机、阻止分身内操作
   - **明确写「这是应用层拦截，不是整机锁定」**

3. **回归验证**（修复 B1）
   - 定位 `FocusStore` 每秒写盘的第二条路径
   - 加回归测试：`tick()` 120 次内写盘次数 ≤ 2

### 验收
- 模拟器：开始专注 → 切到别的 App → 遮罩出现 → 到期解除
- 首页三个数字正确（状态/剩余/范围）
- 撤权限后首页显示「限制未生效」

## 四、任务 3.3：约定驱动的主动交流（本轮**核心**）

### 现状
**这是最大缺口。** 现有 `ThreadBook` 是"还不定时地回来问问"的话题线，用户说「十分钟后问我进度」无法变成确定时间的约定。

### 要做

#### 4.1 新增 `Appointment`（约定）数据模型

```kotlin
data class Appointment(
    val id: String,
    val topic: String,            // 具体问什么，用户可见
    val dueAtMillis: Long,        // 确定时间
    val basis: String,            // 依据（用户原话）
    val status: PENDING / DUE / DONE / CANCELLED / EXPIRED,
    val createdAt: Long,
    val version: Int,             // 改期/取消 +1，旧生成结果作废
)
```

**与 `ThreadBook` 的分工（不重复造第二套调度）：**
- `ThreadBook` = 不确定时间的话题线（现有，保留）
- `Appointment` = 用户明确给了时间的约定（新增）
- 两者都进同一个 `ProactiveGovernor` 候选池，由同一套调度器处理

#### 4.2 从原话解析约定

用户说「十分钟后问问我进度」→ 解析出：
- 时间：`parseRelativeTime("十分钟后") → 10 分钟`
- 话题：`"进度"`（从上下文取）
- 依据：用户原话

**时间或话题不明确时只问必要信息**，绝不猜。

#### 4.3 约定的可见管理

- 创建成功 → 显示「已记下：10 分钟后问你《项目进度》，取消 / 改期」
- 列表页：所有即将到期的约定
- 取消 / 改期入口

#### 4.4 主动跟进要基于依据

主动消息不能是固定模板，要带上 `basis`（用户原话）：
> 「你说十分钟后让我问问进度——现在到点了，[具体进展]？」

#### 4.5 回应后只结算相关事项

- 用户回「做完了」→ 只 `DONE` 那一条
- 其他未到期的事项不受影响
- 无法判断对应哪条时 → 保留全部，简短确认

#### 4.6 随机闲聊默认关闭

阶段 3 要求「无约定主动闲聊暂时默认关闭」。改动：
- `Settings.presenceEnabled` 默认改为 **false**？不——专注伙伴仍需它
- 改为：`ProactiveMode.DAILY` 下 `LIGHT_SMALL_TALK` 候选默认不参与，只保留 `APPOINTMENT_DUE`
- 新增开关 `allowRandomSmallTalk`，默认 false

#### 4.7 修重复检测（G6）与 ignored 误判（G7）

- 同 `anchorSource` + 同锚点前缀 → 24 小时内不重复
- `ignored` 只在**用户确实看到过**（通知已发出）时递增；单纯没说话不算

### 验收
- 说「十分钟后问我」→ 出现可见约定 → 到点主动问 → 回答 → 事项正确结束
- 取消后再无主动消息
- 改期后按新时间
- 主动消息内容引用用户原话，不是模板
