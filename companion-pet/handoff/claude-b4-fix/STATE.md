# 0.5.1 修复：B0–B4 独立审计后的五项修补

日期：2026-10-24。分支：`ccr-2899d69f-xlzjh6`。
基线：DeepSeek `deepseek/moling-b4-e2e-release` 的 fcc2e61（0.5.0 / 18）＋ 0.3.7 修复线 27456b9。
审计报告的结论与复现见本轮对话；下面只写改了什么、怎么验证、还缺什么。

## 1. 合并 0.3.7 修复（审计 P1-1）

B4 是从 7124768 分出来的，没有 0.3.7 的修复和“同桌”改名，而且和 0.3.7 线撞了 versionCode 10。
本轮把 B4 合进 0.3.7 线（合并提交 50e3cc6），版本改为 **0.5.1 / versionCode 19**，两条线都能覆盖升级。

## 2. 确认链路（P0-1、P1-4、P2-2、P2-3、P3）

| 问题 | 改法 |
|---|---|
| 待确认项存的是显示名（“哔哩哔哩”），批准时比对包名，永远批不下来 | `AgentContext.foregroundPackage` 传包名，待确认项绑定包名 |
| 在设置页批准时前台已是桌宠自己，点击/输入基本不可能成功 | 模型提议写动作时，直接在悬浮气泡上问“允许这次 / 不用”，用户仍在原 App 里 |
| nonce 从不校验 | `approve(..., nonce)`，气泡和设置页都传当时显示那一条的 nonce |
| 批准后、执行前崩溃，条目永远停在 APPROVED | 启动时 `recoverInterrupted`：账本里有结果补成 EXECUTED，否则标 INTERRUPTED；绝不自动重做 |
| `pending.json` 损坏后下次新建直接覆盖 | 损坏文件改名为 `pending.corrupt-<时间>.json` 保留 |
| 已结束条目不清理 | 只保留最近 20 条已结束条目；待处理/已批准的一条不删 |
| 设置页和气泡各写一套执行逻辑 | 统一走 `PendingExecutor`，执行 ID 固定为 `pending-<id>`，结果回写目标任务 |

## 3. 事件账本（P1-2、P2-4）

- 高水位改记事件**发生时间**。原来记处理时间，积压 2 条以上时只处理第一条，其余永久跳过。
- 模型失败/超时/被取消：退避重试（1 分钟、5 分钟），第 3 次仍失败才放弃；退避期间不跳到后面的事件。
- 预算用完、自主模式关闭：没调模型，不记账、不计次。

## 4. 目标链路（P0-2、P2-1）

- 目标没有可执行步骤时 `handled=false`，照常走普通 AgentLoop；不再每次弹“目标还缺可执行的下一步”。
- 设置页每个目标可以“加一步”，并选它能用的工具（查记忆 / 看素材 / 记念头）；模型选了别的工具会被拒绝。
- 只读步骤成功即 DONE；写步骤创建待确认后 WAITING，批准执行 SUCCESS 才 DONE；已执行但无法核实、失败、被拒绝都停在 BLOCKED，等用户点“重试”或“这步已完成”。
- 确认还开着时不重复提议；过期后才再提一次。
- 全部步骤 DONE 后，目标完成仍由用户点“确认目标完成”。
- 连续同一条计划结论只记一条 episode。
- 改动的旧断言只有一处：`GoalAgentCoordinatorTest` 里“只读成功后 WAITING”改为 DONE——原断言正是“永远完不成”的缺陷。

## 5. 设备与视觉绑定真实活动窗口（P1-3、P1-4、P2-5、P3）

- `DeviceSnapshot` 增加 `activeWindowPackage`（rootInActiveWindow）。策略以它为准；活动窗口是桌宠自己时拒绝操作别的 App 的观察。
- 动作后等 0.7 秒重新观察：打开应用看活动窗口包名、输入文字读回同一个输入框，能给出 SUCCESS/FAILED；点击/滚动/返回只附“页面是否变化”，仍是未核实。
- 未核实的回执不再说成“没成功”，改为“我已经……了，但还没法确认结果”。
- 截图：活动窗口是桌宠自己时拒绝；观察记录用实际被截窗口的包名；超时后迟到的截图缓冲会被释放。
- “看一眼”移到点桌宠弹出的气泡上（在要看的 App 里点）；设置页按钮只用于检查权限。

## 仍未做 / 需要真机确认

- `observationId` 仍未绑定到待确认项：设备动作在执行时由策略重新检查节点、观察时效和活动窗口，没有再额外比对观察 ID。
- 点击/滚动/返回只能报告“页面是否变化”，无法自动判断是否达到用户意图。
- GoalStore 的删除墓碑仍只写不读（目标 ID 是随机 UUID，不会复用，影响很小）；目标上限 50 仍把已完成的计算在内。
- Shizuku 只读 Binder 版本号，注释里“getprop / 系统 SDK”的说法已在审计中指出，未改代码。
- 真机建议顺序：记一条念头 → 气泡里出现确认 → 允许 → 设置页看到 EXECUTED；“看一眼”在一个白名单 App 里截图；锁屏中途取消后重新亮屏应重试。
