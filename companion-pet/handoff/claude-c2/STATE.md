# 0.5.4：合并 C0–C2，修“看一眼”和 C2 冒烟脚本

日期：2026-10-24。分支：`ccr-2899d69f-xlzjh6`（唯一主线，下一轮请从这里开分支）。

## 先说分支

DeepSeek 的 C0/C1/C2 又是从 B4（fcc2e61）分出来的，没有 0.5.1–0.5.3 的修复、固定签名和直链，而且版本号又是 0.5.2 / 20，和 Release 上的 0.5.2 撞号。
本轮把 `deepseek/moling-c2-device-acceptance`（9044507）合并进主线，版本改为 **0.5.4 / versionCode 22**。
**以后请都从 `ccr-2899d69f-xlzjh6` 开新分支**，这样构建出来的 APK 用仓库固定钥匙签名，能直接覆盖手机上的版本。

## 设备上到底装的是什么

设备 base.apk SHA-256 `0659B7647155844E…`，就是 Release `tongzhuo-latest` 的 0.5.2（提交 23650e8，固定钥匙）。
C1 本地包 `C01D7CB7…` 用的是本机默认调试钥匙，签名不同，即使在手机上点了允许也会因签名不一致装不上。不要卸载；用 Release 包或本分支构建。
`INSTALL_FAILED_ABORTED: User rejected permissions`：vivo 会在手机上弹安装确认，需要有人点；并且不要加 `-g`。

## “看一眼”返回“视觉模型没给出可用的结果”

根因是配置：0.5.2 里视觉模型名写死为 `deepseek-flash`、和搭话共用 DeepSeek 地址与 Key，没有入口修改；DeepSeek 接口多半不接收图片，请求失败后只显示一句笼统的话。截图本身是成功的（失败时会显示“没截到”）。
0.5.4：

- 视觉单独配置：地址、模型名、Key（留空沿用搭话的）；“千问看图 / GPT 看图”一键填好。搭话可以继续用 DeepSeek。
- 没配视觉模型时直接提示去设置，不发注定失败的请求。
- 失败时说清是哪一步：截图失败 / 调用失败（带原因，如 Key 不对、模型名不对）/ 模型回了但解析不了。
- 输出上限 320 → 600 token；模型不按 JSON 回时取第一句作主题（低置信），不再整个丢掉。

## 合并 C0–C2 时做的调整

- C0 的 `reopen` 原来复用同一个执行 ID，动作账本会把重新确认当成同一次而永远不执行。现在每次重新确认 `attempt+1`，执行 ID 变成 `pending-<id>-r<n>`；INTERRUPTED 也可以重新确认。
- C0 的参数指纹校验、observationId 绑定保留；包名仍按 0.5.1 的修复绑定**包名**，不是显示名。
- C1 的“生成脱敏诊断”（设置页）和 0.5.3 的“复制诊断信息”（开始页，含崩溃堆栈和系统退出原因）都保留，互补。

## C2 冒烟脚本（tools/c2_device_smoke.py）

- B1 点“记忆”失败：uiautomator dump 在悬浮角色有动画时常失败，原脚本只试一次、只按精确文字匹配。现在重试 4 次、也匹配 content-desc、点最近的可点击父节点（算出来正是 787,465）；失败时写明 DUMP_FAILED / NOT_FOUND。
- 启动判定改看 `topResumedActivity`，不再看可能被悬浮窗占住的 mCurrentFocus。
- 安装判定拉回设备 base.apk 比对 SHA-256，不再用“版本号里有 0.5.2”判定。
- 去掉 `install -g`。
- 离线自测：`python tools/test_c2_device_smoke.py`（3 个用例）。
