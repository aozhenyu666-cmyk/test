# C2：跨重启写动作记录

版本：0.3.6 / versionCode 9。C1 独立提交为 71970bb。

## 执行与恢复

生产 AndroidActionAdapters 为 ActionRunner 注入 FileActionJournal；读操作不进入持久化内容缓存。
写操作先在 memory/action-journal/writes.json 原子保存 prepared，再调用 adapter，最后保存 committed 回执。
元数据包含 ID、请求 SHA-256 指纹、类型、准备时间、阶段、四态结果和必要定位符。原因使用固定短句，data 仅允许 noteId/eventId/day/deleted，账本没有正文、query、prompt、凭证或只读结果。

同 ID 换类型或参数，在重建执行器后仍拒绝。单执行器同 ID 并发等待同一结果；不同执行器通过文件锁争取唯一准备记录，看到 prepared 的实例只尝试核对，不执行原动作。

- SAVE_NOTE：先保存有稳定 ID 的独立念头记录，再追加稳定 ID 的 NOTE 事件。回执前中断时，核对可修复缺失事件，不重复保存念头。核对只需要账本和已有念头，不需要再次提供正文。
- OPEN_ASSISTANT / SPEAK：有成功回执才报告系统/引擎已接受；prepared 且无回执时显示需要核对，不自动重新打开或朗读。
- 系统调用超时或等待被中断保留未确认状态。取消是停止请求，不能回滚已发生的原子操作；已保存的念头完成落盘后，最终回执仍如实记录成功。
- 准备记录或回执不可读/不可写时不删除旧证据、不清空重做；回执写入失败保留 prepared。
- 默认界面提供最近十项元数据和核对入口。应用冷启动也可找回这些记录；核对不重发原动作。旋转由 ViewModel 保留面板作用域。

ActionSession 将“自己发起的执行”和“只查一个历史 ID”分开。关闭面板只取消自身执行；排队中的核对关闭后不再启动，已运行的核对可能完成已有记录的修复，晚到结果不更新已关闭界面。

## 旧数据与删除

普通念头仍写 notes/YYYY-MM-DD.md。工具念头写入 notes/.action-notes/，每个 action ID 一个哈希文件；不会再复制一份 Markdown 正文。list/dates/digest 合并两种格式。

工具念头删除经过 DurableNoteAdapter：先追加引用 NOTE 的 FORGET，再把念头正文改为 null，保留身份和指纹，防止旧请求使已删除内容复活。事件历史遵循原有追加语义，删除影响来源可见性，不宣称抹除所有历史字节。旧格式删除不把新格式内容重写进 Markdown。

removeLast 专用于原有悬浮层普通念头撤销，继续只撤销旧 Markdown 最后一条；工具念头从记忆页单独删除，避免撤销按钮误删后来保存的工具念头。

## 保存窗口与容量

- 持久化写记录默认 4096 项，不按时间过期，不自动淘汰；幂等窗口持续到应用数据被移除。已删除念头的身份墓碑同样保留。
- 容量满时拒绝新写 ID，已有 ID 仍可核对；不以清掉旧记录恢复可写。没有清空账本按钮，也没有自动容量迁移。本进程身份表仍有原来的 2048 项上限；核对不占新增执行身份。
- 后续容量扩展或迁移必须保留全部旧身份、指纹、阶段及定位符；不能只拷贝念头正文。卸载/清数据会终止这一保存窗口，不作为本轮升级或容量修法。
- 文件落盘使用同目录临时文件、fd.sync 和 ATOMIC_MOVE 替换；不支持或写失败则停止，不先删除旧文件。本轮验证进程中断与重建，没有进行突然断电/存储硬件故障认证。

## 验证边界

确定性 JVM 测试覆盖：重建回执、换参数、准备后中断、念头落盘后事件前中断、回执前中断、外部效果不重放、同 ID 并发、取消后仍保留实际写入结果、容量边界、账本损坏、遗忘后新鲜读取、旧格式与删除/摘要兼容、冷启动历史以及核对取消作用域。

Android instrumentation 新增文件系统重建与删除防复活用例；旋转与 Compose 确认测试使用合成 adapter。均仅编译，尚未设备执行。没有模型工具循环、自动评论或新的 Android 权限。
