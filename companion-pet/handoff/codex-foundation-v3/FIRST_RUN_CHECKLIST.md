## 一、启动到能说话

| # | 用户做什么 | 应该看到什么 | 看不到时怎么办 |
|---|---|---|---|
| 1 | 安装 `app-debug.apk`，打开“桌宠” | 直接进设置页，“开始”标签选中；顶部标题“屏幕边上的同伴”，下面一行提示 | 装不上报签名冲突：不要卸载旧应用，回原构建环境用原签名重新出包 |
| 2 | 点“悬浮窗”那一行 | 跳到系统“显示在其他应用上层”页；回来该行变成“已开启” | “启动桌宠”是灰的，说明系统仍认为没给权限，回上一步重开 |
| 3 | 点“无障碍服务”那一行，找“桌宠 · 感知”，打开开关 | 返回后该行显示“已开启”，描述后面不再有“服务还没连上”那句 | 开关灰：应用详情 → 右上角 ⋮ → 允许受限制的设置，再回来开；已开启但仍提示没连上：关掉再打开一次 |
| 4 | 点“麦克风和通知” → 允许麦克风和通知；点“不限制电池” → 允许 | 两行都变“已开启” | 只有麦克风给了、通知没给，这一行仍是“未开启”（两项都开才算） |
| 5 | vivo / iQOO：分别处理“允许自启动 / 后台高耗电”“后台弹出界面”“在最近任务里锁定” | 前两行跳到对应系统页（打不开会退回应用详情）；第三行没有开关，只是说明 | 系统里找不到入口属正常，按说明文字手动找；这一步无法由 App 判定，只能人工确认 |
| 6 | “设置 → 搭话用的模型”：点“DeepSeek”，填 API Key，点“保存” | 提示“已保存”；Key 输入框标签变成“API Key（已保存，留空不改）”，输入框清空 | 提示“Key 保存失败”：设备 Keystore 写入失败，重试或换机；提示“接口地址要是 https 开头”：地址不合法，检查是否带了 `?` `#` 或账号密码 |
| 7 | 回“开始”页，点“启动桌宠” | 角色出现在屏幕边缘；状态标签变“正在陪伴”（高亮）；按钮文字变“重新唤出” | 提示“启动失败，检查悬浮窗权限”：回第 2 步；无提示但角色不出现：查厂商后台限制 |
| 8 | 等一个开口间隔（默认 6–12 分钟，可在“开口节奏”改短到 1 分钟） | 角色做动作后弹出气泡，一到两句话；通知栏出现“桌宠在你身边” | 见下方“不开口”排查，不要直接判定成权限问题 |

## 二、暂停、停止、记忆

| # | 用户做什么 | 应该看到什么 | 看不到时怎么办 |
|---|---|---|---|
| 9 | 点“暂停” | 状态标签变“已暂停”；角色仍在屏幕上但不再开口；按钮文字变“继续”；通知标题变“桌宠在安静待着”，动作变“让它说话” | 标签一秒内会自对齐，等 1–2 秒再看，不要连点 |
| 10 | 点“继续” | 状态回“正在陪伴”，恢复开口节奏 | 同上 |
| 11 | 点“停止”，然后重启手机 | 服务停止、角色消失；重启后**不会**自动拉起，“开始”页显示“已停止” | 重启后角色自己回来了，属缺陷，记失败 |
| 12 | 手动点“启动桌宠” | 角色回来 | 提示失败则回到第 2 步检查权限 |
| 13 | “记忆”页 →“它对你的了解”，点某行的“删” | 该行消失，不弹确认框 | 需要先有内容；新装时这里是“还没有。每晚整理后会慢慢积累。”属正常 |
| 14 | 点“整段编辑”，改一句，点“保存” | 正文变成改后的内容 | 提示“没有保存成功，请重试。”说明没写进去 |
| 15 | “它记住的事”里点“更正”，改完点“保存” | 该条文本更新，来源标签和日期保留，不新增第二条 | 出现两条相似事实 = 缺陷，记失败 |
| 16 | 点另一条“忘记” | 该条消失，无二次确认 | **这一步不可撤销**，测前先准备好不重要的合成事实 |
| 17 | “今天的交流”下方点“清空今天的记录” → 弹窗点“删除” | 弹窗标题“清空今天的记录？”，正文说明档案、日记、信会保留；确认后当天列表清空 | 若连日记、信一起没了 = 缺陷 |
| 18 | 清空后再看“它写给你的信”“它给自己的日记” | 两个区块内容仍在 | 被清掉 = 缺陷，记失败 |

## 三、调用余量

| # | 用户做什么 | 应该看到什么 | 看不到时怎么办 |
|---|---|---|---|
| 19 | “开始”页状态框 | “今天已调用 X / Y 次”，Y 等于“设置 → 每日调用上限”（默认 150） | 整行不显示：上限被填成 0（保存时会被夹到 1，所以正常不会出现） |
| 20 | 让它说几次话，回“开始”页 | X 变大；间隔约 1.5 秒自动刷新，不用手动重进 | 数字不变：服务可能已停止 |
| 21 | 对照“统计”页当天那行的“调用”列 | 与“开始”页的 X 数字相同 | 不一致 = 口径缺陷，记失败 |
| 22 | 先把“每日调用上限”改成一个不大于当天已调用次数的数字，再触发一次开口 | 不再请求模型；顶部提示“今天的调用额度用完了。它会继续陪着你，明天恢复开口。”；动画、震动仍在 | 弹了报错弹窗属预期外，记失败 |

注意 X 的口径：**每次真实请求前先占一格，失败也算**。所以 X 涨而界面没出气泡，可能是模型侧失败，不是权限问题。

### 每页重点看什么

先有数据再截：新装时“记忆”“统计”多半是空的，空态也要各留一张（标注“空态”），但满态才是主目标。

**开始页**

- “启动桌宠 / 重新唤出”“暂停 / 继续”“停止”三颗按钮在 360dp + 1.3 字体下**是否换行、有没有被截断**（它们放在 `FlowRow` 里，本来就允许换行，看的是换行后是否难读）。
- 状态标签 + “今天已调用 X / Y 次”是否同屏不打架；1.3 字体下 `X / Y` 会不会换成多行。
- 权限行右侧的“已开启 / 未开启”是单行省略（`maxLines = 1`），窄屏 + 大字体下会不会被压成“已开…”。
- 深色下“正在陪伴”高亮标签的文字对比度。
- 顶部提示是最长的一段文字，1.3 字体 + 360dp 下会不会顶到边缘。

**设置页**

- 这是最长的一页，重点看滚动是否顺畅、分组标题（较大字号 + 一条分隔线）在深色下是否还分得清层次。
- 接口地址、模型名、API Key 三个输入框：360dp + 1.3 字体下标签会不会挤压输入内容；API Key 已保存后标签变长成“API Key（已保存，留空不改）”，此时是否换行。
- 服务商三个按钮（DeepSeek / GPT / 千问）与“保存 / 清除 Key”在同一 `FlowRow`，看换行后的间距。
- 两两一行的数字输入框（最短/最长间隔、安静开始/结束）在 1.3 字体下是否挤成两行字。
- 深色下输入框边框、光标、Placeholder 是否可见（主题把 primary 设成墨色就是为了光标可读，这是回归重点）。
- 人设输入框固定 `min = 160dp`，大字体下是否过矮。

**记忆页**

- 每行正文 +“对 / 删”按钮：1.3 字体下正文被压成窄柱、按钮挤到第二行，属于要记录的问题。
- “它记住的事”每条下面的来源标签 + 日期 + “对 / 更正 / 忘记”三连，`FlowRow` 换行后是否和上一条粘连。
- 长事实文本（手工造一条 80 字以上的）在 360dp 下是否溢出右侧。
- 深色下来源标签“你说过 / 尚未确认”的底色与文字对比度。
- 清空确认弹窗在 1.3 字体下按钮是否被挤出屏幕。

**统计页**

- 表格是横向滚动（日期列 92dp，其余每列 64dp），360dp 下一屏能露出几列、430dp 下多几列——“调用”列是否在首屏可见。
- 表头与数字在深色下的对比度；数字列是居中的，看大字体下是否错位。
- 无数据时的“还没有数据。”与顶部说明文字“最近 0 天……”是否读得通。
