# 关系光谱 · 设计说明

## 1. 这个产品要解决什么

你描述的问题，归结起来有三种：

1. **用错了关系的规则**：把父母"无条件兜底"的模式带进朋友关系，觉得付出了就该有回应；在父母那边又把这份爱当成理所当然，连生日都不记。
2. **看不懂信号，一冲动就掀桌**：朋友一次次找借口不来，你没看出这是"软拒绝"或者对方处境困难，回了一句"你爱咋咋吧"，关系就断了。
3. **社会上的利益冲突看不清**：员工和老板、学生和学校、男女之间，只看到情绪化的吐槽，看不到各方的利益、成本和底牌。

所以这个 App **不是记账本，也不是厚黑学工具**。它的核心价值按重要程度排：

| 优先级 | 能力 | 对应痛点 |
|---|---|---|
| 1 | **冷静阀**：想发火之前，先把想发的话丢进来，AI 告诉你风险，并给三档替代回复 | 第 2 点 |
| 2 | **规则校准**：每个人先归到一个圈层，不同圈层用不同的算法和语气 | 第 1 点 |
| 3 | **信号预警**：连续被推脱、单向付出、该关心父母了，系统自动提醒 | 第 1、2 点 |
| 4 | **博弈拆解**：把一个利益冲突拆成各方诉求、筹码、底牌和可谈的空间 | 第 3 点 |
| 5 | **流水记录**：给上面四件事提供依据，本身不是目的 | — |

> 记账只是证据，不是结论。分数是给你自己看的"体感仪表"，从来不显示"对方欠你多少"。

## 2. 对 Gemini 方案的调整

Gemini 给的框架整体可用，我做了这几处修改：

| Gemini 方案 | 问题 | 调整 |
|---|---|---|
| 前端直连 Notion | Notion API 不允许浏览器跨域调用，直接连一定失败 | 加了一个零配置的本地小服务器（`server/`），负责转发 Notion 和大模型请求，Key 也只放在服务器端 |
| 三个圈层各算各的 | 没错，但缺了"冷静阀" | 潜台词解码器加了 `draft_check`：输入你**想发**的话，先评估风险再给改写 |
| AI 只分析对方 | 你的问题有一半出在自己的解读上（"把怀疑当事实"） | 每个提示词都要求 AI 指出**你自己的认知偏差**，并给出低成本的验证办法 |
| 只算"投入失衡" | 失衡预警容易变成"讨债心态" | 预警同时检查"过度索取"和"自己的承诺兑现率"，建议永远是先调整自己的投入，而不是去讨回 |
| 没有安全边界 | 博弈话术可能滑向操控 | 提示词明确禁止 PUA、操控、欺骗类策略；发现虐待或人身危险时，优先给出安全建议 |
| 父母只做"倒计时" | 不够触动 | 加了"按过去一年的见面频率，大约还能见多少次"的估算（需要填出生年份） |

## 3. 核心模型

### 3.1 三个圈层（每个对象必须先归类）

| 圈层 | 代码 | 典型对象 | 算什么 | 不算什么 |
|---|---|---|---|---|
| 亲缘兜底圈 | `kin` | 父母、至亲 | 主动关怀频率、关键日期、剩余陪伴 | 不算谁付出多 |
| 情感互惠圈 | `bond` | 朋友、伴侣、熟人 | 双向投入是否平衡、谁更主动、邀约回应、软拒绝 | 不算金钱回报率 |
| 契约博弈圈 | `deal` | 老板、公司、学校、商家、相亲对象 | 投入产出比、实际时薪、承诺兑现率、底牌 | 不在情绪上内耗 |

圈层可以随时改。比如同事变成朋友，就从 `deal` 挪到 `bond`。

### 3.2 一次交互记录的四个维度

每条记录同时记下"我给出的"和"我得到的"，各有三项：

- **钱**：金额（元）
- **时间**：分钟
- **情绪**：0–5，表示这次在情绪上投入或得到了多少（陪考研焦虑的朋友聊一小时，大概是 4）

另外记录：谁发起的、是不是一次邀约以及结果（接受 / 婉拒 / 改期 / 没回 / 临时爽约）、有没有承诺以及是否兑现、这次的感受（-2 到 +2）。

### 3.3 算法（`web/js/core/scoring.js`）

**投入单位**（防止一次大额送礼压过一切）：

```
单位 = 钱权重 × log2(1 + 金额/100) + 时间权重 × log2(1 + 分钟/30) + 情绪权重 × 情绪×0.6
```

每个圈层的权重不同：亲缘圈更看重时间和情绪，契约圈更看重钱。

**时间衰减**：越久以前的记录越不重要，半衰期 60 天。

**投入失衡度**：`(我给的 − 我得到的) / (我给的 + 我得到的)`，范围 -1 到 1。正数说明我付出更多。

**关系温度**（0–100）：

```
温度 = 100 × (0.35 × 新鲜度 + 0.25 × 感受 + 0.20 × 互惠 + 0.20 × 回应度)
新鲜度 = e^(−距上次联系天数 / 期望联系间隔)
```

"互惠"在不同圈层含义不同：情感圈看是否平衡，亲缘圈看主动关怀是否及时，契约圈看对方承诺的兑现率。

**阶段判断**：升温 / 维持 / 隐性降温 / 濒临破局。最近 30 天的活跃度和此前相比明显下降，或者连续 2 次邀约被推脱，就判为"隐性降温"。

**预警规则**（节选）：

| 预警 | 触发条件 | 给你的建议 |
|---|---|---|
| 软拒绝信号 | 你的邀约连续 2 次以上没被接受 | 暂停邀约，换成不需要对方回应的关心，别追问原因 |
| 单向付出 | 失衡度 > 0.45 且有一定数据量 | 别去讨回，先降低主动投入，看对方会不会主动 |
| 过度索取 | 失衡度 < -0.45 | 找机会主动回馈 |
| 关怀逾期 | 亲缘圈超过设定间隔没主动联系 | 今天打个电话 |
| 关键日期 | 生日等 14 天内到来 | 提前准备 |
| 承诺兑现率低 | 对方承诺兑现率 < 40% | 把口头承诺改成书面、分阶段兑现 |
| 自己失信 | 你自己的承诺兑现率 < 50% | 少承诺，承诺了就做到 |

## 4. 三个 AI 引擎（`web/js/core/prompts.js`）

三个引擎都强制返回 JSON（Claude 用 Structured Outputs，OpenAI 兼容接口用 JSON 模式），前端直接渲染成概率条、筹码图和话术卡片。

1. **潜台词与软拒绝解码器**：给出对方行为的几种解释及概率（必须包含善意解释）、你可能的认知偏差、当前关系阶段、冷静阀检查、三档回复话术、建议观察几天再行动。
2. **多方博弈拆解器**：各方的公开立场、真实利益、隐性成本、筹码、底牌（BATNA）、话语权对比，以及可能达成协议的空间和三档策略。
3. **关系账本审计**：扫描最近的记录，判断你是不是把父母当理所当然、对朋友付出或索取过度，或者用错了圈层的规则，给出本周能做的具体行动。

调用时会自动带上对象档案、算法结果和最近 10 条交互记录，让 AI 基于事实而不是只听你一面之词。

## 5. 架构

```
浏览器（手机/电脑）                         本地 Node 服务器 (server/)
┌───────────────────────────┐           ┌──────────────────────────┐
│ 看板 / 关系 / 记录 / 沙盘   │  /api/*   │ /api/analyze → Claude 或  │
│ scoring.js（纯本地计算）    │ ────────▶ │     OpenAI 兼容接口        │
│ IndexedDB（离线可用）       │           │ /api/notion/* → Notion   │
│ notion-sync.js（双向同步）  │           │ 静态文件服务              │
└───────────────────────────┘           └──────────────────────────┘
```

- **离线优先**：所有数据先存在浏览器的 IndexedDB 里。不配置 Notion 也能完整使用（AI 分析除外）。
- **Notion 双向同步**：先拉取 Notion 上的改动，再推送本地改动；两边都改了同一条时，以后改的为准。
- **隐私**：发给大模型的只有你选中的那个对象的档案和最近 10 条记录。建议给真人起代号。

## 6. V2 新增

### 6.1 冲动原话破坏力测试
沙盘的两种模式都可以填“我本想发的话”。AI 必须先输出：
- `their_first_reaction`：对方读到这句话第一秒的内心独白（对方第一人称）
- `defense_mechanism`：对方最可能启动的防御（反击、合理化、冷处理、拉黑）
- `blowup_risk`：0–100 的翻脸/拉黑风险，提示词里给了分档标准，宣判式告别语（“你爱咋咋吧”）通常在 70 以上
这张卡片排在所有分析前面，先让人看到后果，再看替代话术。

### 6.2 结局回填与直觉校准
- 沙盘多了一个“我现在的猜测”。AI 被要求把这个猜测列进潜台词，并如实给出概率
- 每次分析自动存入案例库。两天后看板会提醒回填：用了哪一档、对方的实际反应、真相更接近哪一个、关系变好还是变差
- `core/calibration.js` 统计：我的直觉准确率、AI 首选命中率、AI 是否列出了真相、发出冲动原话后关系变差的比例，以及按话术档位统计的效果
- 最近 5 条“我以为 X，实际是 Y”会作为 `<我过往的误判>` 带进下一次分析，AI 会指出用户是否在重复同样的误判

### 6.3 聊天记录 / 口述解析
新的 `parse` 引擎把一段对话或大白话变成一条结构化记录（类型、日期、双方投入、邀约结果、承诺、软拒绝信号）。没有 Key 或 AI 不可用时，用 `core/parse-local.js` 的关键词和正则规则兜底：识别“改天/下次/最近忙”等软拒绝词、“来不了/鸽了”等爽约词、金额、时长（含“一个多小时”“半小时”）和承诺。

### 6.4 3 回合对线预演
新的 `roleplay` 引擎扮演对方：读取对方的圈层、核心诉求和雷区，像真实聊天一样回复，并给出对方没说出口的想法、紧张程度和教练提示。第 3 回合结束后给出复盘和最推荐的说法。预演记录保存在对应的案例里。

### 6.5 手机随身可用
- PWA：`manifest.webmanifest` + 图标 + `sw.js`。首次打开后缓存全部页面文件，断网也能打开
- 直连降级：`services/api.js` 先探测本地服务器（`api/health`），连不上就从浏览器直接调用大模型。Claude 直连使用 `anthropic-dangerous-direct-browser-access` 请求头
- 请求构造集中在 `core/llm-request.js`，服务器和浏览器发出的 Claude 请求参数完全一致（有测试保证）
- 所有路径改成相对路径，`web/` 可以直接部署到任意静态托管的子路径下
