# 02 · 状态机、数据结构、手机端权限与事件协议

[返回 README](../README.md)

代码是权威：`plugin/lib/core/driver.js`（主状态机）、`bandwidth.js`（水位）、`telemetry.js`（推进日志）。

## 1. 两层状态

**会话阶段**（守门员，管"你在不在"）

```
IDLE ──start──▶ LOCKED ──切出允许的应用 / Live 被关──▶ INTERRUPTED_BY_SWITCH
                 │  ▲                                        │
                 │  └──────── 有效微反馈（记 RESUMED）◀────────┘
                 ├──声明休息(1–30 分钟)──▶ PAUSED ──到点──▶ INTERRUPTED_BY_SWITCH（拉回原断点）
                 ├──到时间──▶ WRAPPING ──一句结论──▶ ENDED(completed)
                 │                     └──3 分钟没结论─▶ ENDED(no_conclusion)
                 └──紧急结束（永远可用）────────────────▶ ENDED(stopped:<原因>)
```

- 切屏**只**进 `INTERRUPTED_BY_SWITCH`，从不自动结案。回到 Gemini 也不算接回，必须给一条有效微反馈。
- 休息不吃思考时间：`endsAt` 顺延。
- 同一时刻只有一条主线：已有进行中的会话时，`POST /session` 返回 `409 session-active`。

**带宽水位**（驾驶员，管"你脑子在不在"）

| 状态 | 判据（按顺序，先中先停） | 驾驶动作 |
|---|---|---|
| `ESCAPED` | 前台不在允许名单；或 Live 被关（`liveActive=false`，`null` 不算） | 拉回：报断点 + A/B |
| `THROTTLED_EMPTY` | 回复是放弃（不知道/不懂…）或敷衍（嗯/好/知道了…）；或慢于 45 s 且信息量 < 0.4；或 60 s 没有任何对话迹象 | 六骰子降维：只给"念两个词"或"A/B" |
| `HIGH_SPEED_SKIMMING` | 3 s 内回复且没依据；或这句不到 6 字、最近三次两次没依据 | 踩刹车：点破老毛病，只要一个词的依据 |
| `ACTIVE_FLOW` | 有依据（因为/题干/第 X/对称/递增/数字…）或命中这题期望的关键词；或点了 A/B | 往前推一格 |

"对话迹象"= 回复驾驶员，或 Gemini 开口（它只在你说完后才说，所以 Gemini 在说 ≈ 你刚说过）。

**升级**

| 级别 | 何时 | 手机端表现 |
|---|---|---|
| 0 | 正常追问 | 顶部悬浮小卡，不抢焦点，Live 照常听 |
| 1 | 第 1 次切屏 / 沉默 60 s / 卡片 30 s 没回 | 全屏断点卡，返回键无效 |
| 2 | 连续第 2 次（再切走或再不回） | 全屏 + 震动 + 语音念题，每 20 s 重复 |

解除 level ≥ 1 只有三种方式：有效微反馈（点了 A/B、念出两个词、或信息量 ≥ 0.2 的一句）、声明休息、紧急结束。"嗯"不算。

你在和 Live 正常对话时（Gemini 在说话），之前攒的升级清零，没回的驾驶员卡悄悄过期——和 Live 聊本身就是目的。

**主动开口的三个时机**（都走同一个唤醒账本：任意两次之间至少隔 20 s；被拒的也记一笔 `wake_skipped`）

| 原因 | 何时 | 出什么 | 冷却 |
|---|---|---|---|
| `turn_gap` | Gemini 说了 ≥ 1.5 s 后停下，8–15 s（随机）内没有任何新迹象 | level 0 的"轮到你了，念给 Live：…问我一个二选一"；替换掉这段对话之前出的、还没答的驾驶员卡 | 90 s |
| `silence` | 60 s 完全没有对话迹象 | 第一次念给 Live，再一次 A/B 骰子；只在"说话 → 沉默"这次变化里触发一次，之后交给不应答升级 | 无（靠"只触发一次"） |
| `periodic` | 聊得顺、没有待答的卡，到了随机插问时间（每次 2–4 分钟里重抽） | 一张推进卡 | 90 s |

**防重复**：新卡和最近 5 张真正显示过或答过的卡比字面相似度（汉字两两切词的 Jaccard），≥ 0.6 就依次试：推进模板 → 接回断点的别种说法 → 没用过的骰子 → 用过的骰子。都换不开才保留，并记 `repeat_unavoidable`。拉回、沉默提醒、结论、议程开场这些本来就该重复的卡不参与。

## 2. 数据结构（TypeScript 描述，实际是 JS 对象）

```ts
type Phase = 'IDLE' | 'LOCKED' | 'INTERRUPTED_BY_SWITCH' | 'PAUSED' | 'WRAPPING' | 'ENDED'
type Cog = 'ACTIVE_FLOW' | 'HIGH_SPEED_SKIMMING' | 'THROTTLED_EMPTY' | 'ESCAPED'

interface Card {
  id: string
  kind: 'open' | 'one_word' | 'ab' | 'read_two_words' | 'say_to_live' | 'conclusion'
  text: string
  options?: { A: string; B: string }      // kind=ab 必有
  expects: 'evidence' | 'choice' | 'words' | 'spoken' | 'conclusion'
  anchor?: string                          // 断点描述，切屏时原样报出
  missing?: string                         // 还缺的那个依据（模型给）
  intent: 'open' | 'probe' | 'brake' | `dice:${string}` | 'pullback' | 'resume' | 'silence' | 'conclude'
  source: 'llm' | 'template'
  resumes?: string                         // 拉回卡：它要接回的断点卡 id
  level: 0 | 1 | 2
  generatedAt: number
}

interface Directive {                      // 插件 → 手机
  seq: number                              // 单调递增，手机按 seq 去重
  type: 'show_card' | 'pullback' | 'escalate' | 'release' | 'end'
  at: number
  level?: 0 | 1 | 2
  card?: Card
  relaunch?: string                        // 答完后回到哪个应用（最近一次在前台的 Live 包名）
  reason?: string                          // left_anchor_app | live_ended | unanswered | silence | pause_over | not_valid
  until?: number                           // release：休息到几点
  conclusion?: string | null; summary?: Summary   // end
}

type Signal =                              // 手机 → 插件，都带 {sessionId, at}
  | { kind: 'foreground'; pkg: string; allowed?: boolean }
  | { kind: 'live'; active: boolean | null }
  | { kind: 'audio'; assistantSpeaking: boolean }   // true=开始说，false=停下（必须是布尔，否则 400）
  | { kind: 'surface'; cardId: string; status: 'displayed' | 'not_shown' | 'dismissed'; via: 'page' | 'overlay' }
  | { kind: 'reply'; cardId: string; text?: string; choice?: 'A' | 'B'; channel: 'tap' | 'text' | 'overlay' | 'voice' }
  | { kind: 'pause'; minutes: number; reason?: string }
  | { kind: 'stop'; reason: string }

interface Summary {                        // 推进统计
  generated: number; displayed: number; replied: number; advanced: number; resumed: number
  interruptions: number; displayedUnproven: number; advanceRate: number
  awake: number        // 醒：卡亮出 15 s 内有对话迹象，或回了这张卡
  responded: number    // 回：任何一种 ADVANCED（点 A/B、念两个词、对 Live 开口……）
  grounded: number     // 想：ADVANCED 且说出了依据 / 命中关键词 / 结论带依据 —— 主指标
}
```

## 3. 推进日志（五个状态）

每张卡只能按顺序前进，跳步不补写：

```
GENERATED ─▶ DISPLAYED ─▶ REPLIED ─▶ ADVANCED
     └ 被切屏冻结为断点：INTERRUPTED_BY_SWITCH … 之后被接回并答上：RESUMED
```

- `DISPLAYED` 只来自手机端的可见证明（窗口拿到焦点 / 悬浮窗贴上）。有回复却没有可见证明 → 不补写，计入 `displayedUnproven`。
- `ADVANCED` 由驾驶员判：期望依据的卡要有依据词或命中关键词；A/B 卡点了就算；念两个词的卡要 ≥ 2 字且不是敷衍；结论卡信息量 ≥ 0.3。
- 推断出的完成也如实标注：`say_to_live` 卡在亮出后 Gemini 开口，记为 `REPLIED(推断：已对 Live 开口)` + `ADVANCED(spoke_to_live)`。
- `advanceRate = advanced / generated`，不用聊天轮数。
- 主指标是 `grounded`（有依据的思考次数）。点 A/B 是为了把人拉回来，只算 `responded`。

## 3.5 思考议程（跨会话）

存在 `$DSH_HOME/storages/dsh-driver-core/agenda.json`，最多 30 条。

| 何时入账 | source | 说明 |
|---|---|---|
| 会话结束时，被切屏冻结过但始终没接回的断点 | `unresumed` | |
| 卡上标了缺的依据（`missing`），最后没给出有依据的回答 | `missing` | |
| 结论里有"可能/好像/不确定/再看…" | `conclusion_doubt` | 必须带原话，且原话要真的出现在你这次说过的话里，否则不收 |

下次 `start` 时用主题+任务匹配（数字归一：第七题 = 第7题）：
- 命中 → 开场卡是"上次停在【X】没接上。A 从这接着做 / B 先做新的"。
  - 选 A：回到那个断点，追问缺的依据；之后第一次有依据的回答就把它标成已解决。
  - 选 B：记一次跳过，连续 3 次跳过就标为放弃。
- 没命中但议程里还有别的 → 作为"以前没解决、还挂着的"进提示词的隐秘层。

落盘：`$DSH_HOME/storages/dsh-driver-core/sessions/<sessionId>.jsonl`，一行一条。

## 4. HTTP 协议（前缀 `/dsh-driver-core/v1`，要求和 `/api` 同等凭据）

| 路由 | 请求 | 应答 |
|---|---|---|
| `POST /session` | `{topic, task, minutes?, anchors?}` | `201 {sessionId, anchors, directives, state}`；`409 session-active` |
| `POST /signal` | 上面的 Signal | `200 {directives, state}`；`404 no-session`；`400 bad-kind` |
| `GET /directives?sessionId&after&waitMs≤25000` | 长轮询 | `200 {directives(seq>after), phase}` |
| `GET /state?sessionId` | — | 阶段、级别、当前卡、断点、水位、统计 |
| `GET /status` | — | 配置、当前主线、出题计数 |
| `POST /config` | `{brainSessionId?, memorySessionIds?, anchors?}` | 存 `config.json` |
| `POST /profile` | `{goals?, habits?}` | 存 `profile.json`（你的主线和死穴） |
| `GET /agenda` | — | 当前议程全部条目 |

`at` 偏离插件时钟超过 60 s 就按插件时间算（手机和引擎在同一台设备上）。

## 5. 手机端：权限与事件

### 权限

| 权限 | 用途 | fork 里 |
|---|---|---|
| 无障碍服务 | 读前台包名（只读包名，不读屏幕文字） | 已有 |
| `SYSTEM_ALERT_WINDOW` | 悬浮小卡；Android 10+ 后台启动 Activity 的豁免 | 已有 |
| `POST_NOTIFICATIONS`、前台服务 | 引擎常驻 | 已有 |
| 忽略电池优化 | 别被系统杀 | 已有 |
| `VIBRATE` | level 2 震动 | **新增**（普通权限） |
| `<queries>` Gemini / Google / ChatGPT | 拿启动 Intent 回到 Live | **新增** |
| MIUI/HyperOS「后台弹出界面」「自启动」 | 小米系统额外拦后台弹页 | 要你手动开 |

不需要麦克风：驾驶员只看系统"有没有人在录 / 在播"，不录音（`AudioManager` 录音/播放回调）。

### 事件（Kotlin → Dart → 插件）

| 何时 | 发什么 |
|---|---|
| 每次前台复核（350 ms 去抖后） | `foreground {pkg, allowed}`；不允许时**先**盖断点卡再发 |
| 录音占用出现 / 消失 ≥ 8 s | `live {active}` |
| 助手类播放开始 | `audio {assistantSpeaking:true}`（自己的 TTS 不算） |
| 助手类播放持续 ≥ 1.5 s 后停下 | `audio {assistantSpeaking:false}`（插件据此开"轮到你"窗口） |
| 卡片窗口拿到焦点 / 悬浮窗贴上 | `surface {status:'displayed'}`；起不来 → `not_shown` |
| 点 A/B、发送文字 | `reply` |
| 选休息时长 / 紧急结束 | `pause` / `stop` |

### 反射（不等插件）

`DriverReflex.judge`（已编译、6 项测试通过）：锁定中且前台不在 `anchors ∪ DSH Go ∪ 输入法 ∪ 系统/来电` → 立刻用缓存的当前卡盖住。**桌面和设置都算切走**。传了窗口类名时，弹窗、Toast、输入法这类非 Activity 窗口不做判断（规则思路来自 closepaw）。
