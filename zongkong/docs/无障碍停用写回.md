# 被停用后的无障碍自动写回

本次只补总控自己的无障碍组件被移出系统启用列表后的修复，不改健康协议与业务逻辑。

入口：权限与运行状态 → 无障碍自动修复 → 开启被停用后的自动写回（默认关闭）。仍需用户先通过 adb 授予 `android.permission.WRITE_SECURE_SETTINGS`；原权限页可复制命令。要手动关闭系统无障碍，请先关本功能及哨兵对应看护。

开启后：启动、首页 onResume、开机/更新广播检查；常驻服务独立每 30 秒检查；持久 Job 最短 15 分钟检查（系统可延后）。只追加总控自身组件，保留其他已启用服务，兼容 `.短类名`，写入后读取回验。权限页显示最近写回时间。原有“开着但失联”的有限重绑与真实 ack 健康判断保留，设置写入不能当健康凭据。

NOT_TESTED：真机无障碍被关、国产系统清后台、强制停止后由哨兵写回是否触发重新绑定。整包强制停止后，自身前台服务、任务和广播不能保证恢复，需要用户打开或由独立哨兵尝试。哨兵改动在 `codex/sentinel-a11y-guardian`，这里只补总控自身写回。

验证：新增纯逻辑服务列表合并测试（保留其他项、空串、短组件去重）；完整单元测试与 APK 构建、CI 结果见 PR。CI 的固定下载页发布限制为原项目分支，验证分支只产出 artifact，避免测试版本覆盖已发布安装包。
