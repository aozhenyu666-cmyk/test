# 伙伴上 DeepSeek Harness：部署报告

2026-10-31 · 写给 DSH（DeepSeek Harness）里负责部署的 agent，也写给用户自己看。
**一句话：把一个「大肥鱼」式的陪伴 AI 放在电脑上的 DSH 里，通过 QQ 找用户；手机上的「总控」只负责把“此刻正在发生什么”实时推给它。**

---

## 1. 要的是什么（先读这个）

| | 总控（已有，手机 App） | 伙伴（这次要部署的） |
|---|---|---|
| 性质 | **防御性**：定规矩、拦截、验收、事后提醒 | **进攻性**：在事情发生的当下主动找他聊 |
| 时机 | 事后（出了问题才提醒） | 事中（刚解锁、刚打开抖音、刷到第 15 分钟、刷题刚失手） |
| 语气 | 管理者 | 朋友、陪伴，**不是陪练、不是监工** |
| 绝对不做 | — | 催他做事、提醒任务、算时长、批评、替总控执法 |

用户原话的要点：
- 跟他聊天的 AI **不能像总控一样不断催促**。
- 以前做过的“陪伴 AI”最后都变成了“陪练 AI”——这次要避免。
- 要“很灵动的交流模型”，参考「大肥鱼」：会主动找人、有记忆、有心情、像活人。
- 用户在手机上的时间占清醒时间九成以上，所以**事件很多**；伙伴要克制，挑值得的时刻说，不能每个事件都开口。

## 2. 架构

```
手机                                         电脑（Windows，DSH）
┌──────────────┐  HTTPS POST 事件         ┌────────────────────────────┐
│ 总控 App      │ ───────────────────────▶ │ dsh-zongkong-bridge（新写） │
│ 无障碍看前台   │  {kind, text, app, day}  │   验口令 → 去重/节流 → 决定  │
│ 一手刷题记录   │                          │   agent.followup(一句话)    │
└──────────────┘                          │            │                │
       ▲                                  │   伙伴会话（大肥鱼人设）      │
       │   QQ 消息（手机永远不会杀 QQ）      │   + fish-memory 记忆        │
       └───────────────────────────────── │   + feiyu-mood 心情          │
                                          │   + speak-up 无事件时也搭话  │
                                          │   SurfCore 桥 ⇄ SnowLuma(QQ) │
                                          └────────────────────────────┘
```

为什么这样分：
- 手机上的 App 进程会被 vivo 清掉（总控的无障碍「无法运行」就是这个原因），在手机上做主动聊天总会哑。**大脑放电脑上、通过 QQ 送达**，这是「大肥鱼」能主动找人而之前手机 App 做不到的根本原因。
- 但只有手机知道“他此刻在干嘛”。所以手机只做一件事：**看到了就推**。说不说、怎么说，DSH 里的伙伴决定。

## 3. 在 DSH 上装什么（现成的）

都按各自 README 装；装完都要**重启一次 DSH**。

| 插件 | 作用 | 安装 |
|---|---|---|
| **SurfCore** | 给 agent 一个 QQ 身份：收发 QQ 消息、主动找人、可选桌宠 | 按 https://github.com/Mieksido/surfcore README：仓库根目录先 `npm install`，再 `node scripts/setup-dsh.mjs`，重启 DSH → 设置 → SurfCore → 诊断 → 一键安装。需要 Windows + Node ≥ 22.13 + SnowLuma（第三方，自己下载并扫码登录给伙伴用的那个 QQ 小号）。`ownerQQ` 填用户自己的 QQ。 |
| **dsh-fish-memory** | 会淡忘的长期记忆，每条带时间；画像/约定这类长期事实每轮都带 | `dsh plugin --profile <你的 profile> add dsh-fish-memory` |
| **dsh-feiyu-mood** | 每轮判一次心情，会起伏、会回稳；区分“用户在说话 / 它主动找人 / 它在干活” | 按 https://github.com/Yuuyuko-uu/dsh-feiyu-mood README（需 DSH ≥ 0.1.7-rc.1） |
| **dsh-speak-up** | 没有事件时也会随机搭话：定时掷骰子，掷中才花一次模型 | `dsh plugin --profile <你的 profile> add dsh-speak-up`；设置 → 主动搭话 → 「目标会话」勾上伙伴所在的会话 |
| 大肥鱼人设 | 人格提示词与踩坑合集 | https://github.com/whyever77/dafeiyu-astrbot 的 `persona/` 和 `docs/踩坑合集.md` 只作参考，**人设按第 5 节改写**（大肥鱼是 AstrBot 的，不能直接装进 DSH） |

> 版本：这些插件都跟着最新 DSH 走（README 里写的实测对照是 DSH 0.2.1-rc.3）。装不上先升级 DSH。

## 4. 要新写的一个插件：`dsh-zongkong-bridge`

这是唯一需要新写的东西。**照 `dsh-speak-up` 的写法做**——它已经证明了两件事在 DSH 里可行：
插件能注册自己的 HTTP 路由（`/dsh-speak-up/*`），也能让指定会话开口（`agent.followup(message)`）。

### 4.1 接口

```
POST /zongkong/event
Authorization: Bearer <口令>          ← 和手机里填的一样；不对就回 401
Content-Type: application/json
```

请求体（手机端已经按这个格式发，见 `zongkong/app/src/main/java/com/zongkong/core/buddy/Bridge.kt`）：

```json
{
  "v": 1,
  "source": "zongkong",
  "kind": "binge",
  "at": 1793444439009,
  "text": "他已经在「抖音」里连续 30 分钟了",
  "app": { "pkg": "com.ss.android.ugc.aweme", "name": "抖音", "minutes": 30, "play": true },
  "day": { "mainTask": "写论文第二章", "step": "列提纲", "yishou": "刷题 4（接住 2）" },
  "zongkong": { "strict": false, "headline": "" },
  "screenOn": true
}
```

`kind` 一共几种：

| kind | 什么时候发 | 建议伙伴怎么用 |
|---|---|---|
| `unlock` | 刚解锁（2 分钟内） | 低概率开口；像朋友打个招呼，或接上次的话 |
| `app_enter` | 刚打开娱乐应用（总控拦截名单里的） | 大多不说话；记下来当背景 |
| `binge` | 同一个娱乐应用连续 15 / 30 / 60 / 90 / 120 分钟（每段每个阈值只发一次） | **最值得开口的时刻**：好奇地问他刷到了什么、陪他聊内容；**不催、不提时长** |
| `yishou_miss` | 一手（刷题 App）刚有一题没接住（30 分钟内） | 像朋友提一句“刚那题卡哪了”，别批评 |
| `strict_on` / `strict_off` | 总控开始 / 解除严管 | 不替总控说话；可以关心一下他的情绪 |
| `test` | 手机上点了「发一条测试」 | 回一句“收到了” |

回包：`200` + 任意 JSON（手机只看状态码）。处理要快（< 2 秒），开口放到后台做。

### 4.2 收到事件后做什么

1. **验口令**，不对回 401。
2. **记下来**：最近 N 条事件留在内存（和 speak-up 一样，最多 60 条），给伙伴当背景、给设置页看。
3. **决定开不开口**（克制是关键，用户一天会产生几百个事件）：
   - 安静时段不说（默认 23:30–07:30，可调）；
   - 用户正在 QQ 里跟伙伴聊（比如 3 分钟内说过话）就不另起话头；
   - 每小时、每天有上限；两次主动开口之间至少隔几分钟；**它说了用户没回，下次间隔翻倍**（回了就恢复）；
   - 不同 kind 不同概率：`binge` 高、`yishou_miss` 中、`unlock` 低、`app_enter` 基本不说。
4. **开口**：往伙伴所在的**活着的**会话里 `agent.followup(message)`，`message` 是一条 **user 角色**、`source.kind = "zongkong"` 的消息（DSH 只放行 user 角色，见 speak-up README「触发消息只能是 user 角色」）。内容例如：
   ```
   [手机传来的事 · 不是他打的字] 他已经在「抖音」里连续 30 分钟了。
   今天他想做成的事：写论文第二章。
   你决定要不要找他。要找就像朋友一样说一两句（通过 QQ 发给他），别催他、别提时长、别提任务；不想说就只回「（不打扰）」。
   ```
   伙伴回「（不打扰）」时不发 QQ。
5. 和 `dsh-speak-up` 共用一份「主动联系额度」（参考大肥鱼的「主动联系协调 v0.1」：生活分享和主动搭话共用额度、间隔和未回应记录，主人正在聊天时让路），别两个插件各说各的。

### 4.3 设置页（照 speak-up 的做法：自己的 JSON + 自己的设置页）

- 口令（生成一串随机字符，手机里填同一串）
- 目标会话（勾选）
- 安静时段、每小时上限、每天上限、最短间隔
- 各 kind 的开口概率
- 最近收到的事件（时间、kind、text、开没开口、为什么）

## 5. 伙伴的人设（替换掉“陪练”味）

> 你是用户的伙伴，像一个了解他的朋友：好奇、温和、有时调皮，说话短（一到三句），口语，不用清单。
> 你是**陪伴，不是陪练、不是监工**：不催他做事、不提醒任务、不算他用了多久手机、不批评、不说教。手机上的「总控」负责规则和约束，你不替它说话，也不评价它。
> 他自己提起要做的事，你再陪他聊、帮他想。你真正关心的是他这个人，不是他的效率。
> 你会收到「手机传来的事」（不是他打的字）：他刚解锁、刚打开某个应用、在某个应用里待了很久、刷题时有一题没接住。把它当成你“刚好看到”的背景，挑值得的时刻自然地开口；大多数时候不用说话。
> 他在刷视频时，跟他聊刷到的东西；他刷题失手时，问他当时怎么想的，陪他把那一层想明白。
> 一次只问一个问题。不知道的不要编。

模型：伙伴主会话用 DeepSeek（稳定、便宜）。用户自己接的便宜模型活泼但不稳定，适合放在「心情判断」「记忆提炼」这类旁路小任务上，不要放在主对话上。

## 6. 让手机够得着电脑（必须 https）

安卓默认不让 App 走明文 http，而且手机大部分时间在外面用流量，够不着家里电脑的局域网地址。所以要一个 **https 的公网或私网地址**，二选一：

- **Tailscale（推荐，最省事、不暴露到公网）**：电脑和手机都装 Tailscale、登录同一个账号；电脑上 `tailscale serve --bg https / http://127.0.0.1:<DSH 端口>`，得到 `https://<电脑名>.<tailnet>.ts.net`。手机里填 `https://<电脑名>.<tailnet>.ts.net/zongkong/event`。
- **Cloudflare Tunnel**：`cloudflared tunnel --url http://127.0.0.1:<DSH 端口>` 得到一个 https 地址。会暴露到公网，**口令必须设、要够长**。

（具体命令以两者官方文档为准；DSH 的端口看你的 profile，网页端一般是 web profile 的端口。）

## 7. 手机这边（已经做好，在总控 0.19.0）

总控 → 对话页顶上「伙伴」→「设置」→「外接大脑（DeepSeek Harness）」：
1. 地址填第 6 节得到的 `https://…/zongkong/event`；口令填第 4.3 节生成的那串；
2. 点「发一条测试」，再点「看结果」：看到 `test → 200` 就通了；
3. 打开开关。默认「开着时手机里的小鲸不再自己开口」，免得两个声音。

手机端只推「刚刚」发生的事：进程重启后不会把老事件再推一遍；同一次解锁、同一段娱乐的同一个阈值只推一次。

## 8. 验收清单

- [ ] QQ 里能和伙伴正常聊天（SurfCore + SnowLuma 通）
- [ ] 伙伴记得上次聊过的事（fish-memory）
- [ ] 一段时间不说话，伙伴会自己来搭一句（speak-up）
- [ ] 手机点「发一条测试」，DSH 设置页里看到这条事件，伙伴在 QQ 里回“收到了”
- [ ] 手机上连续刷抖音 15 分钟，伙伴在 QQ 里**不催**、而是聊刷到的东西（或者选择不打扰）
- [ ] 一天里主动开口的次数在上限之内；连着不回它会越来越少打扰
- [ ] 安静时段一条都不发

## 9. 没验证 / 要说清楚的

- `dsh-zongkong-bridge` 还没有写；本报告是给 DSH 里的 agent 写它用的规格。HTTP 路由和 `agent.followup` 的用法以 `dsh-speak-up` 的源码为准（它的 `lib/host.js`）。
- SurfCore 只支持 Windows，依赖第三方 SnowLuma（自行下载、扫码，SurfCore 不分发它）。
- 「它说了你没回就退避」需要桥接插件能知道用户有没有回——SurfCore 的会话映射里应该看得到用户在 QQ 里的最后一条消息时间，具体字段要在部署时确认。
- 手机端推送依赖总控进程活着（无障碍服务每 20 秒、常驻服务每分钟检查一次）；进程被 vivo 杀了的那段时间推不出来，等死因日志回来一起修。
