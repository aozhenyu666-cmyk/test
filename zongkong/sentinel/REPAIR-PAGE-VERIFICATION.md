# 主动故障页与可见兜底

原先 :watch 发现异常只尝试恢复、记日志或锁屏，BlockActivity 只在下一次打开名单内 APP 时触发。这次使用应用内、签名权限保护的广播，把真实健康结论送到无障碍交互进程。总控无障碍关闭、确认失联或恢复中时，主动打开故障处理页，不要求先打开受限 APP。

一次连续故障只主动展示一次；息屏/锁屏及正在系统修复页时延后。紧急暂停、业务暂停及解除期间不弹。处理页保留修复、打开总控、回桌面和现有紧急暂停通道。单任务页面处理 onNewIntent，避免显示旧的触发应用。

页面启动后等真实 onResume 确认；1 秒未确认时显示全屏无障碍处理入口与通知。无障碍服务断开时撤除。v2 确认故障可覆盖旧心跳，但不覆盖休假和放行。

本地用 Kotlin 1.9.24 和 Android 14 API 类库编译了哨兵全部主源码、全部测试源码及三个项目新增页面组件。运行 96 个哨兵测试，加上一手的 3 个 PageDelivery 测试，共 99 项通过。同时修正了原分支 LockExecutor.facts/WatchProvider.certSha256 中表达式函数体使用 return 导致的编译错误。

未完成 Gradle APK 打包或真机测试。必须在目标手机上验收：停留桌面时关闭总控无障碍，故障页主动出现；系统拒绝后台启动时出现全屏入口；正在设置中不被反复拉走；息屏不弹，解锁后可处理；紧急暂停能生效；修复后下一次故障可再次提示。哨兵自身无障碍未开启时，无法保证自动显示页面，应使用现有常驻通知进入。

此改动针对 deepseek/sentinel-v2；总控的名单同步修复来自 deepseek/zk-client-v2 对应分支。仓库现有 zongkong-latest 附件较旧，不能当成本次修复产物。
