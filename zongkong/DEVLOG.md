## 2026-10-31 · 0.18.0：伙伴——会主动找你说话、但不是总控的那个

### 你提的

- 按「大肥鱼」那几个插件的思路做一个会主动跟你对话的 AI。它能降低你对总控的防备感。

### 做法

总控是水坝：定规矩、拦、验收，你天然防着它。所以这次**不是**给总控加主动消息（总控本来就会主动找你），而是在总控里住进一个**不是总控**的伙伴（默认叫「小鲸」，能改名）：

- **人设**：不管规则、不锁手机、不验收、不打分、不说教。像了解你的朋友，说话短（一到三句），一次只问一个问题。顺着聊，轻轻把话头往你自己想做的事上带一点——河道的弯，不是水坝。你刷手机时不批评，问你刷到了什么。
- **什么时候开口**（`core/buddy/Buddy.kt`，纯逻辑 + 8 个单元测试），照搬那几个插件的克制：
  - 每 5 分钟掷一次本地骰子（不花钱），掷中才调一次模型（dsh-speak-up）；
  - 每小时上限（默认 4，可调到 12）、每天上限 40、两次之间至少 8 分钟；**你没回就把间隔翻倍**（16、32、64 分钟），回了就恢复（dafeiyu 的未回应记录、bili-whale 的克制）；
  - **让路**：你正在和总控说话、在总控时间里、屏幕灭着、安静时段（默认 23:30–7:30），都不开口；你们正聊着时不另起话头；
  - **有事由时更容易开口、带着事由开口**：早上第一次见、一手刚有题没接住（同一题只聊一次）、刚解锁、在娱乐应用里连着 15 分钟以上、睡前、接着你上次说的话头。
- **从通知里找你**：独立的「伙伴」通知渠道，通知里直接回复，它的回答也回到通知里（像聊天软件）。点开是伙伴页。
- **记忆**：它觉得值得记的（喜好、近况、约定）单独记下，每次都带着；伙伴页能看、能删（dsh-fish-memory 的「长期事实每轮都在」）。
- **和总控互通但不混**：两边对话各存各的。伙伴能看到总控的背景（今天的主线、手上这一步、此刻在哪个应用、一手今天的账），但不替总控说话；你明确让它转告总控的（比如答应了几点开始），它记成一条「伙伴转达」结论进总控。
- **进程被杀也尽量不哑**：除了无障碍服务每 20 秒看一眼，常驻服务每分钟也看；看门狗闹钟把进程拉起来时同样会看。
- 入口：总控对话页顶上「伙伴」。伙伴页能看它现在为什么安静、叫它先说一句、改名字 / 频率 / 安静时段 / 说话方式。

### 没做 / 要说清楚

- 用的是你在总控里配的同一个 AI 接口；每次主动开口是一次模型调用（DeepSeek 一天几十次也就几分钱）。
- **「强制色彩」没做**，按你说的留到最后。伙伴现在是纯软的，它的价值就在于不像总控。
- 模拟器测试里，伙伴会和别的测试抢同一个模拟 AI 的回答（0.18 第一次跑 `chatRunsTheDay` 没等到回答），所以测试开始时把伙伴关掉，和关掉「参谋主动找人」同理。
- CI 现状（如实）：哨兵四项（SENTINEL_LINKED / TAKEOVER / SURVIVES_FORCE_STOP / HEALS_MAIN）在这条线的起点 e3fbbe8 上就是失败的——总控这条线要 v2 哨兵（`com.zongkong.sentinel.health`），但这条线上的哨兵模块还是旧版（v2 在 `deepseek/sentinel-v2`）。不是这次改坏的，没动；所以 `zongkong-latest` 发布这一步会一直被跳过，直到哨兵 v2 并进来。
- 0.17 那次还有 `hqSession`、`fullLoop`（窗口拿不到焦点）和 `dayPlan`（剪贴板读不到，同样是没焦点）失败，0.18 那次这三个又都过了：看起来是模拟器的焦点抖动，记下来继续观察。
- 进程真的被 vivo 杀了且不让自启动时，伙伴也会哑——这和无障碍「无法运行」是同一个根，等死因日志回来一起修。真要做到「永远叫得应」，得把伙伴的大脑放到电脑 / 云上，通过 QQ 之类找你（见 `PLAN-弯道助手.md`）。

## 2026-10-31 · 0.16.1：死因日志——无障碍为什么「无法运行」，让系统自己说

### 你提的

- 以刷题为核心重建体系之前，先弄清楚：为什么手机上的无障碍老是崩，设置里直接显示「无法运行」。要有一个日志能看出原因。
- 另外几件大事（思考流 / 能争论、聊天与工作两种模式、高频互动、主动发消息、信息收集部）见 `PLAN-弯道助手.md`。

### 查出来的

- 「无法运行」是系统打的标记：**无障碍服务所在的进程死过一次**，系统还没把它重新拉起来（vivo 不允许自启动时就一直挂着这个标记）。
- 以前的眼睛日志**只能猜**：进程是被直接杀掉的，`onUnbind` / `onDestroy` 根本来不及执行；崩溃护盾只接得住 Java 异常，接不住被系统/厂商杀、内存回收、ANR、原生崩溃。所以日志里只看得到「掉了」，看不到「谁杀的」。
- Android 11 起系统会自己记每个进程的死法（`ApplicationExitInfo`）：原因码、当时的重要程度、内存、系统说明，ANR 和原生崩溃还附带线程栈。总控从来没读过它。
- 顺带找到一个**会连坐**的地方：总控调哨兵、一手用的是 `contentResolver.call()`，调用期间持有对方的「稳定引用」。按安卓的规矩，对方进程这时候死了（比如被 vivo 清理），**总控会被一起杀掉**（死因 `DEPENDENCY_DIED`，说明是 "depends on provider … in dying proc"）。总控每 5 秒就要 ping 一次哨兵，窗口不大但一直在。

### 做了什么

| # | 做法 |
|---|------|
| 1 | **死因日志**（`guard/ExitLog.kt`）：每次进程启动、每次无障碍接上、每次导出日志，读系统的死亡记录，新的写进眼睛日志（种类 `exit`，界面上显示「死因」）。去重；第一次装上这一版会把系统还留着的历史死亡一次补齐。 |
| 2 | **人话翻译**（`guard/ExitWhy.kt`，纯逻辑 + 6 个单元测试）：原因码 + 系统说明 → 归到 12 类之一（自己崩了 / 主线程卡死 / 内存 / 被连坐 / 强行停止 / 从最近任务划掉 / 厂商后台管理 / 耗电 / 冻结 / 更新…），每类写好「怎么修」。多条记录给一句结论：最近几次主要是谁杀的。 |
| 3 | **ANR / 原生崩溃现场**：系统附带的线程栈存到 `filesDir/zk/exits/`（留最近 12 个），日志里直接写「主线程卡在 哪个文件哪一行」。 |
| 4 | **导出日志带上手机环境**：手机型号、系统版本、总控版本、无障碍开关、系统是否标记「无法运行」、电池优化、后台受限、待机分组、准点闹钟、自动修复权限、哨兵状态、死因结论。分享一次就够排查，不用来回问。 |
| 5 | **眼睛日志页**：摘要里新增「系统记录的死因」和「系统标记：无法运行」；有真实死因时，「原因猜测」直接换成系统记录。修了一句没翻译的英文提示。 |
| 6 | **跨进程调用不再连坐**（`system/SafeCall.kt`）：调哨兵、一手全部改成「不稳定引用」——对方中途死了，这边只当没回包，自己不死。 |
| 7 | 版本 0.16.1（versionCode 20）。 |

### 怎么用

装上新版后照常用。下次又看到「无法运行」：先在设置里关开一次无障碍（让进程起来），然后打开 **眼睛日志** —— 摘要里「系统记录的死因」就是答案；点「分享日志」把文本发过来。

### 接下来按日志对症（不再先猜）

- 主要是「系统 / 厂商后台管理杀的」或「内存不够」：把无障碍服务挪进独立的小进程（不带 AI、界面、同步），主进程随便死。
- 主要是「主线程卡死」：按存下来的现场，把那一段挪出主线程。
- 主要是「总控自己崩了」：按同一时间的 crash 记录修那一行。
- 主要是「强行停止 / 划掉最近任务」：这是操作层面的，锁定最近任务卡片、i管家白名单；哨兵兜底。

### 没验证的

- 这里的云端环境下不了安卓 SDK，`ExitWhy` 的单元测试在本地 JVM 上跑过（6/6）；整个 App 的编译、单元测试和模拟器冒烟交给 GitHub 的 zongkong-android 流程。
- vivo 杀进程时系统说明里具体写什么字，要等真机日志回来再补关键词。

## 2026-10-24 · 0.15：哨兵自律体——解除闸门（冷静期 + 手写二次核验 + 防卸载）

### 你提的

- 哨兵是整套体系的核心，总控崩了只能靠它。所以要做一个“自律体”：想改松、想紧急退出、想停用，必须**提前**申请，**手写**将近 100 字分析（不能复制粘贴），而且不是审一次等一会儿就开，还要**二次核验**。防卸载、防绕过。放哨兵上，把哨兵加强。

### 做了什么（全放在独立的哨兵 App 上）

| # | 做法 |
|---|------|
| 1 | **解除闸门**（`sentinel/Release.kt`，纯逻辑 + 单元测试）：要「改松 / 紧急退出 / 准备卸载」都走这一条。 |
| 2 | **第一关·手写分析**：手写约 100 字（去掉空白、标点、数字，还要不是凑字数才算），写清为什么解除。输入框（`NoPasteEditText`）**禁止粘贴 / 自动填充**，长按菜单也挡掉，只能手打。 |
| 3 | **冷静期**：提交后等一段提前量（默认 2 小时）。关键：**同时看墙上时间和开机计时**（`elapsedRealtime`），两头都要走够。改系统时间往前跳没用——跳一次只会算得更久；重启也只会更保守。改钟绕不过去。 |
| 4 | **第二关·手写核验**：冷静期到了之后开一个限时窗口（默认 30 分钟）。要**再手写一段**（默认 40 字，且不能跟第一段几乎一样）。过了窗口没做，整个作废，重头来。 |
| 5 | **解除有限时**：两关都过，才真正解除，而且只解除一段时间（默认 30 分钟），到点自动恢复。中途随时可以撤销（撤销是立刻的，收紧不设防）。 |
| 6 | **总控让路**：哨兵把“解除到几点”通过连接口告诉总控，总控活着时也不拦、不进总控时间（`SentinelClient.released`）。总控崩了只剩哨兵，哨兵自己据此放开。 |
| 7 | **防卸载（可选，真正管用）**：普通安装挡不住卸载。把哨兵用一条 adb 命令设成**设备所有者**（`dpm set-device-owner`，要在没登录账号的手机上设一次），哨兵就能锁住自己不被卸载（`setUninstallBlocked`）；只有解除闸门放行「准备卸载」时才临时解锁。不想要了得先 adb 撤销才能卸。没设也行，只是卸载挡不住、只能提醒。 |

测试：哨兵单元测试新增 6 个（手写字数 / 凑字数、二次不能照抄、冷静→核验→解除、改钟缩不了、重启只会更久、错过窗口作废）。总共 196 个，全过。

### 还没做 / 要观察 / 说清楚

- **防卸载的边界**：不设成设备所有者的话，没有任何普通 App 能真正阻止被卸载——这是安卓的限制，不是没做。设成设备所有者是唯一真正挡得住的，代价是要 adb 设一次、以后要撤销也得 adb。
- 闸门的参数（100 字、2 小时、30 分钟窗口、解除 30 分钟）现在写死，之后可以让你自己调（但“调松”本身大概也该走闸门，不然就绕过了）。
- 二次核验目前只核验“又手写了一段、且不同”，还没做到“证明是本人”（比如指纹）——可以之后加系统生物识别当第三道。
- 解除闸门现在只管哨兵和手机总控；电脑上的总控还没接这条。

## 2026-10-22 · 0.14：以总控对话为中心

### 你提的

- 事实证明，现在主要是和 AI 总控说话，不怎么用别的页面，也不怎么去 GPT。整体流程照这个优化。

### 查出来的问题

- 一天里**必须**做的几步，对话里做不了：早上的“今日部署”只能在首页点确认卡；晚上的“日终验收”、写字的关卡只能进关卡页填表。参谋没有对应的工具，只能口头说“你去首页点一下”。
- 打开 App 先到“今天”页，要多点一下才到对话；到了对话又看不到现在的状况（严管没有、下一段做什么、眼睛掉没掉）。
- 好几处按钮还把人往 GPT 推：“让 GPT 排一整天”“带着结果去 GPT 判断下一步”。参谋的规则里也写着“排计划主要是 GPT 的事”。

### 做了什么

| # | 做法 |
|---|------|
| 1 | **对话里走完一天**：参谋新增三个工具——`confirm_plan`（你在对话里说“好”，排好的今天就算今日部署，本人确认）、`close_day`（晚上照清单交日终验收，问清明天第一步）、`submit_gate`（写字的关卡，用你在对话里说的话交）。 |
| 2 | **参谋的规矩改了**：你主要跟它说话。早上没部署 → 它问固定安排、帮你排成时段、你说好再确认；白天到点盯、过点问、做完收证据；晚上过清单、问明天第一步、交日终验收。GPT 只在你想长时间深聊时用，不往那边推。 |
| 3 | **主动找你时先说最要紧的**：早上还没部署，问候就是“今天几点做什么”；晚上 8 点后还没收尾，就是“今天收个尾”。 |
| 4 | **打开就是对话**（配了 AI 时；对话右上角 ··· 里可以改回先到“今天”页）。 |
| 5 | **对话顶上的“今天”**：严管 / 放行和娱乐用量、现在或下一段做什么；眼睛掉了直接一行红字去修；今天还差的步骤一排按钮，点“今日部署”“日终验收”就在对话里做。 |
| 6 | **输入框上的常用说法**：排今天、我现在要做…、做完了、往后挪、现在做什么、今天收尾。 |

## 2026-10-22 · 0.13：哨兵独立成另一个应用；交付（验收）能交照片、总控看一眼

### 你提的

- 总控崩了，哨兵也跟着一起崩，原因一样。要一个真正独立的、专门监督总控的东西。
- 现在几乎都交给 AI，对话框以外的页面很少用；提交任务、推进、验收这一套不好弄：验收只有文字和链接，连图片都没有。可以优化，甚至重构。

### 查出来的原因

- **哨兵为什么跟着掉**：0.11 的哨兵和总控是同一个应用（只是换了个进程）。Android 处理“强行停止”（vivo 的一键清理、后台清理就是这个）是按应用来的：
  这个应用的所有进程一起杀，**它所有的无障碍服务一起从“已开启”列表里删掉**。所以不管哨兵本身多稳，总控一被清，两个一起没。换进程解决不了，得换应用。
- **验收为什么难用**：“记录结果”页只有一个文字框和三个自评按钮；照片只能绕去对话里发，发了也不会记到那一步上；
  结论全靠自己选，AI 不参与。另一头，日终那种 AI 验收又会一轮轮打回，越交越烦。

### 做了什么

| # | 做法 |
|---|------|
| 1 | **独立的「总控哨兵」应用**（`zongkong/sentinel/`，包名 `com.zongkong.sentinel`，单独安装）：单独的包名、进程和用户 ID，不联网、不用 AI、不用 Compose，几百行。总控出什么事都碰不到它。 |

## 2026-10-21 · 0.12：今天的安排——把“做计划”这一步补上

### 你提的

- 界面太多太杂。实际用下来最基本的流程——**做计划：这个时间段做什么，没做怎么办**——反而没有。
- 跟总控说“我要做这件事”，它只出现在今天要做的事里，总控既没接住、也没当成记录；说“那件事延期，下午去刷题”，它不知道下午这回事，等于放开了，到点也不会催。
- GPT、Notion 同步来的只是“待办”；首页那张卡不知道从哪抽出来一件，反复追问，又没有任何获取信息的途径。
- 定位：GPT 是谋划的主力，总控是监察的。核心流程不变，简单优化、精简归纳。参考两张线描风格的图。

### 查出来的原因

- 首页“现在这一步”在没有排了时间的事时，会按优先级从**没排时间的待办**里挑一件推给你（`Focus.current` 的 UNSCHEDULED 分支）——这就是那张“随机抽出来、反复追问”的卡。

- 延期只是改个时间字段，首页没有一处能看到“今天几点做什么”，所以改了也看不出来。
- GPT 排好的一天要一件一件复制交接块，导入一次只认一个块。

### 做了什么

| # | 做法 |
|---|------|
| 1 | **今天的安排**（`ui/DayPlanCard.kt`，首页的主角）：一条时间线，几点到几点做什么；做完的、正在的（沙漏）、过点的、还没到的一眼看完。点一段：开始 / 做完 / 延到一小时后、下午、今晚、明天 / 不做了。 |

## 2026-10-19 · 0.11：哨兵——掉线不再等于畅玩

### 你提的

最常碰到的问题：无障碍里总控显示“此服务出现故障”，首页写“开着但没在运行”。手动关开一次就好，但自律最怕的就是“我不在的时候”——好几次就是趁这个空子一直玩。别的 App 的无障碍很少这样，只有总控。能不能修；修不好的话，能不能再做一个专门监督总控的东西。

### 查出来的原因

- “此服务出现故障”是系统打的标记：**无障碍服务所在的进程死过一次**（崩溃、被系统或厂商清理），系统就不再自动拉起它，直到你手动关开。
- 总控的无障碍服务和**整个 App 在同一个进程**：AI 对话、Notion 同步、语音、截图、所有 Compose 界面都在里面。任何一处崩了，或者内存大被清理，眼睛就跟着掉。别的 App 的无障碍服务很小、几乎不干别的事，所以很少遇到。
- 以前的自愈（0.8）要先在电脑上 adb 授权一次，没授权就只能提醒；而“掉线”这段时间是放行的——这才是空子。

### 做了什么

| # | 做法 | 为什么 |
|---|------|--------|
| 1 | **哨兵**（`guard/Sentinel.kt`）：第二个无障碍服务「总控·哨兵」，跑在自己的小进程 `:sentinel` 里，不碰 AI、网络、界面库，几乎不会崩。总控每 5–20 秒给它写一次心跳和拦截名单。心跳停了 90 秒（总控正常下线时是立刻），哨兵接管：**拦截名单里的应用一律拦**，弹一个极简页面——“一键修复 / 去无障碍设置修复 / 打开总控 / 回桌面”。 | 修不好进程崩溃的所有原因，但能让“掉线”从放行变成关着：空子没了，你修它的动力也有了。 |
| 2 | **互相挂回去**：有“写安全设置”权限时，哨兵发现总控掉了就把它重新挂上（2 分钟最多一次）；总控发现哨兵开着没跑，也把它挂回去。 | 授权一次，以后两边互相兜底，不用你手动。 |
| 3 | **崩溃护盾**（`system/CrashShield.kt`）：后台线程的异常吞掉不让进程死；主线程的异常关掉出错的页面、主线程接着跑（30 秒连崩 5 次才放手）。每次都记进“眼睛日志”（哪个文件哪一行）。 | 先少死几次；再从日志里找出到底是哪里在崩，下一版对症修。 |
| 4 | 首页、权限页：哨兵没开会提示“还差一双眼睛”；总控掉了而哨兵在，首页写“总控的眼睛掉了，哨兵在替它拦着”。 | |

测试：冒烟测试新增 `SENTINEL_TAKEOVER`——把总控的无障碍从列表里拿掉、心跳写成很久以前，打开被拦的应用，必须出现哨兵的拦截页。

### 你要做的一次性设置

1. 无障碍里打开「总控·哨兵」（和「总控」是两个开关）。
2. 最好在电脑上执行一次：`adb shell pm grant com.zongkong.app android.permission.WRITE_SECURE_SETTINGS`——之后掉线基本都能自己挂回去。

### 还没做 / 要观察

- 哨兵只拦拦截名单里的应用；总控时间的“全屏锁”掉线时不由哨兵接管（只拦娱乐）。
- 进程被系统清理时，最后一次心跳之后有最多 90 秒的空档。
- 一周后看眼睛日志里 `crash` 记录：如果总是同一处崩，就修那一处；如果几乎没有 crash 却还是“出现故障”，说明是 vivo 在清进程，要把总控主进程也瘦身（把无障碍服务整个挪到独立进程）。
