## 2026-10-22 · 0.13：哨兵独立成另一个应用；交付（验收）能交照片、总控看一眼

### 你提的

- 总控崩了，哨兵也跟着一起崩，原因一样。要一个真正独立的、专门监督总控的东西。
- 现在几乎都交给 AI，对话框以外的页面很少用；提交任务、推进、验收这一套不好弄：验收只有文字和链接，连图片都没有。可以优化，甚至重构。

### 查出来的原因

- **哨兵为什么跟着掉**：0.11 的哨兵和总控是同一个应用（只是换了个进程）。Android 处理“强行停止”（vivo 的一键清理、后台清理就是这个）是按应用来的：
  这个应用的所有进程一起杀，**它所有的无障碍服务一起从“已开启”列表里删掉**。所以不管哨兵本身多稳，总控一被清，两个一起没。换进程解决不了，得换应用。
- **验收为什么难用**：“记录结果”页只有一个文字框和三个自评按钮；照片只能绕去对话里发，发了也不会记到那一步上；
  结论全靠自己选，AI 不参与。另一头，日终那种 AI 验收又会一轮轮打回，越交越烦。

### 做了什么

| # | 做法 |
|---|------|
| 1 | **独立的「总控哨兵」应用**（`zongkong/sentinel/`，包名 `com.zongkong.sentinel`，单独安装）：单独的包名、进程和用户 ID，不联网、不用 AI、不用 Compose，几百行。总控出什么事都碰不到它。 |
| 2 | **两边怎么说话**：各开一个 ContentProvider，只认同一把签名（别的应用一律拒绝）。总控 → 哨兵：心跳 + 拦截名单 + 休假到几点（最多 5 秒一次）；哨兵 → 总控：问一句“你的眼睛在不在”，顺便把总控的进程拉起来让它自查。 |
| 3 | **接管**：心跳停了 90 秒，先直接问总控一句（防手机深睡醒来误判），确认不在才接管——拦截名单里的应用一律拦、发一条常驻通知“总控掉线了，哨兵在拦”。 |
| 4 | **互相挂回去**：给过“写安全设置”权限（adb 一次），哨兵会把总控的无障碍挂回去，**包括被强行停止从列表里删掉的**；总控也同样把哨兵挂回去。没给权限就只拦、只提醒。 |
| 5 | 总控里原来的 :sentinel 进程、服务和拦截页删掉；权限页的“哨兵”一项改成“下载安装 / 去打开”，自动修复那一栏把两条授权命令一起给。 |
| 6 | **交付页**（原“记录结果”，`ui/DeliverScreen.kt`）：证据可以是现拍的照片、相册里的图 / 截图、链接、一句话，有一样就行。 |
| 7 | **总控看一眼**（`core/work/Proof.kt`）：配了 AI 就“交给总控看”——照片拼成一张图连同完成依据发过去，回“达到 / 部分达到 / 没达到”+一句理由。规则写死：看得出做了、大体符合就算达到，不吹毛求疵。 |
| 8 | **最多两轮**：第一轮不是达到时可以说一句“补什么就够了”，你补一次，第二轮必须给结论，不再追问。结论不认可以按“达到”记，但会标“本人改判”，行动页和档案看得到。 |
| 9 | **照片防糊弄**：同一张照片不能交两件事（按原图指纹）；没有拍摄时间（截图、转存）、拍在这一步开始之前的，标成疑点，AI 和你都看得到——不直接拒收，截图交电子产出很正常。 |
| 10 | **对话里交付**：在对话里发一张照片说“做完了”，参谋看图后 `complete_action(photo=是)`，这张照片就记成这一步的证据（同样查重）。没法拍的按你说的记，标“自评”。 |
| 11 | 分享一张图进总控：多一个按钮“当作「当前这一步」的交付证据”。行动页能看到交过的照片和每一轮结论。 |

测试：单元测试 189 个（新增哨兵的接管判断 5 个、交付 4 个、对话里交照片 1 个）。端到端新增 `deliveryWithPhotoReview`：一张照片 → 部分达到、让补 → 补一句 → 达到 → 记下 → 行动页看得到。
模拟器冒烟新增：哨兵和总控的口子只认对方；总控确实在给哨兵写名单；**强行停止总控后，哨兵进程不变、照样拦**；给了权限后哨兵把总控挂回无障碍列表。

### 还没做 / 要观察

- 哨兵要单独装、单独在无障碍里打开（vivo 上也要给它“允许后台运行”）。只装总控不装哨兵，权限页会一直提醒。
- 两个应用签名必须一样（都用仓库里的调试签名），从发布页下载的就是一对。
- 日终验收、关卡那一套还是原来的文字验收，这次没动；先看交付页用起来顺不顺，再决定要不要把关卡也改成“交证据”。
- 交付照片只在手机里，Notion 里只记“照片 N 张，几点拍的”。

## 2026-10-21 · 0.12：今天的安排——把“做计划”这一步补上

### 你提的

- 界面太多太杂。实际用下来最基本的流程——**做计划：这个时间段做什么，没做怎么办**——反而没有。
- 跟总控说“我要做这件事”，它只出现在今天要做的事里，总控既没接住、也没当成记录；说“那件事延期，下午去刷题”，它不知道下午这回事，等于放开了，到点也不会催。
- GPT、Notion 同步来的只是“待办”；首页那张卡不知道从哪抽出来一件，反复追问，又没有任何获取信息的途径。
- 定位：GPT 是谋划的主力，总控是监察的。核心流程不变，简单优化、精简归纳。参考两张线描风格的图。

### 查出来的原因

- 首页“现在这一步”在没有排了时间的事时，会按优先级从**没排时间的待办**里挑一件推给你（`Focus.current` 的 UNSCHEDULED 分支）——这就是那张“随机抽出来、反复追问”的卡。
- 参谋的 `add_action` 必须挂在一件事项下，零散的“下午刷题”挂不上，参谋就只能口头答应。
- 延期只是改个时间字段，首页没有一处能看到“今天几点做什么”，所以改了也看不出来。
- GPT 排好的一天要一件一件复制交接块，导入一次只认一个块。

### 做了什么

| # | 做法 |
|---|------|
| 1 | **今天的安排**（`ui/DayPlanCard.kt`，首页的主角）：一条时间线，几点到几点做什么；做完的、正在的（沙漏）、过点的、还没到的一眼看完。点一段：开始 / 做完 / 延到一小时后、下午、今晚、明天 / 不做了。 |
| 2 | **说一句就排上**（`core/plan/QuickPlan.kt`）：“下午2点到4点刷题”“明天上午九点改简历一小时”“现在开始背单词半小时”——认出时间和要做的事；没说时间的进待安排。零散的事统一挂在「日常安排」下。 |
| 3 | **延期不放手**：延期 = 改到一个具体时间（时长不变），到新的时间照样提醒、过点照样关娱乐（0.10 的欠账规则按新时间算）。 |
| 4 | **待安排**：没排时间的待办（GPT、Notion、随手记的）放在单独一栏，点“上午 / 下午 / 今晚 / 明天”排进去；**不再被拿来当“现在这一步”反复追问**。 |
| 5 | **让 GPT 排一整天**：带着已经排的、待安排的、手上的事去 GPT，要它按交接块交回时段；回来一段里有几个交接块就“全部导入”。分工写进参谋的规则：谋划主要是你和 GPT，总控负责把它变成今天的时段、到点盯住。 |
| 6 | **参谋当场记**：你说“我现在要做 X”“下午 2 点刷题”，它直接排进时段（不用挑事项）；说“延期”，它改到具体时间，没说就问几点。系统提示里一直带着今天的安排。 |
| 7 | **首页精简**：去掉四个部门方块（在“四部”页）、随手按钮、战友栏（信用在“总控”页顶上）、电脑栏（在“我 → 电脑”）、“接下来”（时间线里有）。留下：远方、问候、告警、该处理的、现在这一步、今天的安排、清单 / 总控时间 / 本周计划。 |
| 8 | **线描**（`ui/LineArt.kt`，参考图里的“光环 / 月相 / 沙漏 / 流动波纹”）：问候旁一轮太阳（夜里换成月牙），时间线上正在的那一段是个沙漏，空的时候是几道水纹；状态牌上直接写今天娱乐 已用 / 能用。 |

测试：单元测试 179 个（新增 `QuickPlanTest`：一句话拆时段、延期保持时长、日常安排只建一个、多块交接拆分）；端到端 `dayPlan`：待安排不进“现在这一步” → 说一句排上 → 点开延到明天 → 待安排点“今晚” → 两个交接块一次导入。

### 还没做 / 要观察

- 时间线只看今天；明天的安排要等明天早上才出现在首页（在事项里能看到）。
- “四部”页本身也还偏长，这次没动；用一阵看哪些部门页从来不点，再收。
- 一句话识别的写法：几点、几点到几点、上午 / 下午 / 今晚、今天 / 明天、“现在”、“一小时 / 半小时”。认不出的会放进待安排，不会丢。

### 0.12.1（同一天，看截图修的）

- 首页顶部：日月小图放在左边时，长一点的状态牌（“严管 · 娱乐 45/20”）把问候挤成一个字一行。改成问候在左、一行写完，日期下面是状态牌，日月图放右边。
- “今天接下来 / 下一个安排”如果已经在今天的时间线里，就不再单独出一张任务卡；明天的下一步不在时间线里，照样出卡（第一次改成一律不出，端到端测试发现做完一步后明天那步就看不见了，改回来）。
- 输入框提示缩短，不再折成两行。

## 2026-10-19 · 0.11：哨兵——掉线不再等于畅玩

### 你提的

最常碰到的问题：无障碍里总控显示“此服务出现故障”，首页写“开着但没在运行”。手动关开一次就好，但自律最怕的就是“我不在的时候”——好几次就是趁这个空子一直玩。别的 App 的无障碍很少这样，只有总控。能不能修；修不好的话，能不能再做一个专门监督总控的东西。

### 查出来的原因

- “此服务出现故障”是系统打的标记：**无障碍服务所在的进程死过一次**（崩溃、被系统或厂商清理），系统就不再自动拉起它，直到你手动关开。
- 总控的无障碍服务和**整个 App 在同一个进程**：AI 对话、Notion 同步、语音、截图、所有 Compose 界面都在里面。任何一处崩了，或者内存大被清理，眼睛就跟着掉。别的 App 的无障碍服务很小、几乎不干别的事，所以很少遇到。
- 以前的自愈（0.8）要先在电脑上 adb 授权一次，没授权就只能提醒；而“掉线”这段时间是放行的——这才是空子。

### 做了什么

| # | 做法 | 为什么 |
|---|------|--------|
| 1 | **哨兵**（`guard/Sentinel.kt`）：第二个无障碍服务「总控·哨兵」，跑在自己的小进程 `:sentinel` 里，不碰 AI、网络、界面库，几乎不会崩。总控每 5–20 秒给它写一次心跳和拦截名单。心跳停了 90 秒（总控正常下线时是立刻），哨兵接管：**拦截名单里的应用一律拦**，弹一个极简页面——“一键修复 / 去无障碍设置修复 / 打开总控 / 回桌面”。 | 修不好进程崩溃的所有原因，但能让“掉线”从放行变成关着：空子没了，你修它的动力也有了。 |
| 2 | **互相挂回去**：有“写安全设置”权限时，哨兵发现总控掉了就把它重新挂上（2 分钟最多一次）；总控发现哨兵开着没跑，也把它挂回去。 | 授权一次，以后两边互相兜底，不用你手动。 |
| 3 | **崩溃护盾**（`system/CrashShield.kt`）：后台线程的异常吞掉不让进程死；主线程的异常关掉出错的页面、主线程接着跑（30 秒连崩 5 次才放手）。每次都记进“眼睛日志”（哪个文件哪一行）。 | 先少死几次；再从日志里找出到底是哪里在崩，下一版对症修。 |
| 4 | 首页、权限页：哨兵没开会提示“还差一双眼睛”；总控掉了而哨兵在，首页写“总控的眼睛掉了，哨兵在替它拦着”。 | |

测试：冒烟测试新增 `SENTINEL_TAKEOVER`——把总控的无障碍从列表里拿掉、心跳写成很久以前，打开被拦的应用，必须出现哨兵的拦截页。

### 你要做的一次性设置

1. 无障碍里打开「总控·哨兵」（和「总控」是两个开关）。
2. 最好在电脑上执行一次：`adb shell pm grant com.zongkong.app android.permission.WRITE_SECURE_SETTINGS`——之后掉线基本都能自己挂回去。

### 还没做 / 要观察

- 哨兵只拦拦截名单里的应用；总控时间的“全屏锁”掉线时不由哨兵接管（只拦娱乐）。
- 进程被系统清理时，最后一次心跳之后有最多 90 秒的空档。
- 一周后看眼睛日志里 `crash` 记录：如果总是同一处崩，就修那一处；如果几乎没有 crash 却还是“出现故障”，说明是 vivo 在清进程，要把总控主进程也瘦身（把无障碍服务整个挪到独立进程）。

## 2026-10-18 · 0.10：既不放纵，也不死板

### 你提的

1. **不交流反而最舒服**：设计是早上定任务、做完；没做完就严格控机。实际上不理总控，手机反而一直能畅玩，它只会不停提醒。
2. **几大娱乐 App 根本没被限制**；一手那个“每次打开要先刷题”也没看到。总控已经成了摆设。
3. **晚上的总控验收太折磨**：一直让交、交了还说不行，想完了它还觉得不够。最后“不配合”反而成了最省事的路。两头都要修：不能这么放纵，也不能死板到这种程度。
4. 新下载的 APK 好像没有新功能。
5. 看看之前让 GPT 写的超级语音助手。

### 查出来的原因（不是猜的，是代码里找到的）

| 现象 | 原因 |
|------|------|
| 不交流 = 畅玩 | ① 早上的部署关卡用“今天排了行动”当证据，**总控早上会替你排**，守护服务又在后台**自动验收**——你一下没碰，部署就“过了”。② 部署过了以后，娱乐只受“每天 120 分钟”管，做没做事完全不影响。 |
| 娱乐 App 没被限制 | 拦截名单只在你**第一次打开“拦截名单”页**时预勾常见娱乐应用，**不点保存就一直是空的**。名单空，严管、额度、答题全都管不到任何 App。 |
| 打开不用刷题 | 0.9 的低屏模式默认关、规则为空；一手的入口题要一手自己的无障碍开着，总控严管时一手还会让路。 |
| 晚上折磨 | 总控时间里“谋”这一步必须写出一条判断才能往下走；“封”要等整段 30 分钟用完；参谋被要求“至少来回四次”。 |
| 下载没新功能 | 查了：下载链接里的 APK 是 0.9.1，0.8 / 0.9 的代码都在里面。功能在，但上面这些规则让它们管不到你。 |

### 做了什么

| # | 做法 | 为什么 |
|---|------|--------|
| 1 | **挣来的娱乐**（`core/plan/Earn.kt`、`Engine` 的 `Budget` 原因）：每天先给 20 分钟；做完一步 +20，实打实做事每 30 分钟 +10；上限还是每天的总上限。用完就严管，做完一步就又开。状态栏写着“娱乐 已用/能用”。 | 不交流、不做事 → 只有 20 分钟。做事 → 能玩更多。奖励跟着行动走，而不是跟着沉默走。 |
| 2 | **欠账**（`Engine` 的 `Debt` 原因）：排了时间的事（定了主线就只看主线）过了开始时间 30 分钟还没开始 → 严管。开始做、改个时间、标卡住（写原因）任一个就解开。拦截页上直接有“现在开始”“改时间 / 标卡住”。 | 这就是“没完成就控机”。但解开的门槛很低：交代一下就行，不审作文。 |
| 3 | **早上的部署要本人确认**：后台自动验收不再给“今日部署”打勾；首页出现“今天排了 N 步，确认一下就开始”，点一下才算。晨间向导里自己排的照常直接过。 | 总控替你排可以，但“开始一天”这一下得是你。 |
| 4 | **娱乐应用自动进拦截名单**（`guard/AutoBlock.kt`）：手机上装的常见娱乐应用（名单扩充了知乎、虎扑、豆瓣、闲鱼、X、YouTube、几款常见游戏等），以及系统标成“游戏 / 视频”的应用，自动加进名单；每次打开总控、守护服务每次同步时检查一遍。你自己拿掉的不再加回去。微信、QQ 这类不按分类加。 | 名单空是一切失效的根源。 |
| 5 | **打开就答题**（`WatchConfig.openGate`，复用 0.9 的做题页）：放行时打开拦截名单里的应用，先答一题，冷却 10 秒，答完给 10 分钟；10 分钟到了再答一题。严管时照旧直接弹回。做题页上写着今天还能玩多久。 | 就是一手“每次打开先刷题”那一下，现在由总控自己做，不依赖一手的无障碍。 |
