## 1. 总控：iQOO 12 上无障碍被关掉（最高优先）

### 现状

- 总控有好几条开发线没合：主线 `claude/master-app-accessibility-debug-c7y3bi`（0.20.1，有“被冻结 / 被杀”诊断和眼睛日志），另有 `codex/zongkong-a11y-restore`（0.16.1，无障碍写回）、`codex/sentinel-a11y-guardian`（哨兵写回三个 App 的无障碍）、`codex/ai-focus-mode`（0.17.0，AI 专注）都停在旧的 0.16 线上。
- 用户的体验：总控的无障碍经常被系统关掉；哨兵和总控**会同时掉**，所以哨兵救不了。
- 总控的 `GuardService`（无障碍）和整个应用（AI 伙伴、Notion 同步、DSH 连接……）**跑在同一个进程里**。系统冻结或杀掉这个大进程，无障碍就跟着没了。用户自己也怀疑是“总控太复杂、后台消耗太大”。

### 要做的

1. **先合线。** 以 0.20.1 为底，把 `codex/zongkong-a11y-restore` 的写回和定时检查合进来（用 merge，不 rebase），冲突以 0.20.1 为准。`codex/ai-focus-mode` 留到第 2 节再处理。
2. **把无障碍服务搬进独立的轻进程。** `GuardService` 和 `KeepAliveService` 都加 `android:process=":guard"`。
   - `ZkApp.onCreate` 先判断当前进程名；在 `:guard` 进程里只初始化拦截需要的最少东西（读拦截规则、放行记录），**不初始化** AI、Notion、DSH、数据库大对象。
   - 拦截规则由主进程写成一个小 JSON 文件（私有目录），`:guard` 读它并缓存 3 秒；放行和拦截记录通过 `ContentProvider` 或广播回主进程。
   - 目标：`:guard` 进程常驻内存控制在 30MB 以内（在 PR 里写实测值）。
3. **常驻通知放在 `:guard` 进程。** 无障碍连上时启动 `KeepAliveService`（前台服务，`specialUse`），通知低优先级，写“总控正在守护”。
4. **自己写回无障碍。** 从思维驾驶员搬 `A11yGuard.kt` 和 `Shell.kt`（分支 `feat/driver-autonomy-hardening`，`dsh-driver-app/app/src/main/kotlin/com/dshdriver/app/`）：
   - 有 `WRITE_SECURE_SETTINGS` 时（用户用 adb 授权一次），发现自己不在“已启用无障碍”列表里，就**只追加**写回，不覆盖别人的。
   - 在这些时机各查一次：解锁（`ACTION_USER_PRESENT`）、开机、亮屏、充电、覆盖安装、每 5 分钟的闹钟兜底。
   - 首页显示 adb 授权命令和一键复制：`adb shell pm grant com.zongkong.app android.permission.WRITE_SECURE_SETTINGS`。
5. **使用情况兜底。** 从驾驶员搬 `UsageMonitor.kt`：无障碍掉线的那段时间，用“使用情况访问”判断前台 App，照样能拉起拦截页；拉不起就发一条可点的高优先级通知。
6. **iQOO 设置引导页。** 一页列出要开的东西，每项带“去设置”按钮（打不开就显示路径文字）：
   - 电池 → 后台耗电管理 → 总控 → **允许后台高耗电**
   - 应用与权限 → 权限管理 → **自启动** 和 **关联启动** → 总控
   - 应用与权限 → 应用管理 → 总控 → 权限 → **后台弹出界面**、**悬浮窗**
   - 最近任务里把总控 **下拉锁定**
   - 首次开无障碍是灰色时：应用管理 → 总控 → 右上角 → **允许受限制的设置**
7. **查清“为什么和哨兵一起掉”。** 在眼睛日志里给每次“无障碍断开”记上时间、屏幕状态、是否在充电、当时的前台 App，两边的日志能按时间对上。PR 里写出从日志能看到什么，以及还需要用户在手机上做什么来确认。
8. **哨兵降级。** 只保留：看到总控无障碍断了 → 有权限就写回，没有就弹一条通知。不加别的功能。

### 验收

- [ ] CI 绿（单元测试和模拟器测试）
- [ ] 模拟器上：杀掉总控主进程（`adb shell am kill com.zongkong.app`），`:guard` 进程还活着，打开测试应用照样被拦
- [ ] 模拟器上：用 `settings put` 把总控从无障碍列表里删掉，有权限时 1 分钟内自己写回
- [ ] 真机（用户测，未测）：熄屏过一夜、清一次后台、重启一次，眼睛日志里无障碍在线时间和断开原因

## 2. 只留一个拦截器：总控拦截，一手出题

1. **总控是唯一拦截器。** 一手里 `GateService` 的拦截改成“由总控负责”：一手设置里检测到装了总控，就停用自己的拦截（无障碍服务保留，供第 4 节读前台 App 用，或者改从总控的连接口读）。
2. **总控的关卡里加一种“一手出题”。** 总控拦下娱乐 App 时，可以按设置调起一手的收费站：
   - 一手新增一个只接受总控签名的入口（照 `link/LinkProvider.kt` 的签名校验写法），比如 `TollActivity`，参数：被拦的包名、应用组。
   - 一手答完后，通过总控的连接口回报“放行 N 分钟”（签名校验），**放行由总控记账、到期由总控复锁**。
   - 一手不在或没配模型时，总控用自己的关卡，不放水。
3. **专注时段归总控。** 把 `codex/ai-focus-mode`（AI 专注：限时只许用 AI 应用）合进主线，再按一手 `focus/Focus.kt` 的规则补齐（文件在 `claude/yishou-c1-judge` 分支，纯 Kotlin，可以直接拷进总控的 `core/`）：
   - 计划模板（任务、目标、总时长、每组、休息、允许的应用），可以让 AI 生成后粘贴；
   - 一组一组走，可以中途换节奏，总时长只能延长；
   - 专注时段里只放行系统界面、白名单和通讯应用，**休息时也拦，收费站的放行不算数**；
   - 提前结束要等 3 分钟，离开页面重新计时。
   - 原来给 GPT 的一手专注流任务卡 `02-yishou/tasks/G3-focus.md` **作废**，以本节为准。
4. 专注时段开始和结束时，总控通过连接口通知一手，一手据此开始和停止陪练流（第 4 节）。

### 验收

- [ ] 同时装着总控和一手：打开 B 站只出现一个拦截页
- [ ] 总控调一手出题 → 答对 → 总控记下放行 → 到期复锁
- [ ] 专注时段里打开 B 站被拦，休息时也被拦；ChatGPT、微信能用

## 3. 总控：长期统筹（先调研，再做最小版）

### 用户要的

> 我对当下的事情都漠不关心，更不要说对未来的安排。总控现在只能盯着当下的任务，管不了之后。我需要一个**统筹规划者**，像一个长期的领导。

现在总控已有参谋、四部门、日程统筹、Notion 同步，但都围着“今天”。缺的是一个**会自己往前看、到点主动来找人**的统筹层。

### 第一步：自己去 GitHub 调研（写成 `zongkong/docs/统筹调研.md`）

至少看 6 个项目，每个写：做什么、计划是怎么拆和怎么调整的、怎么根据执行情况改计划、怎么主动提醒、用什么存长期记忆、许可证、维护情况、能借什么。

建议的搜索方向（自己判断，不限于这些）：

- 长期记忆的 AI 助手：Letta（原 MemGPT）、mem0
- 目标拆解和周计划：OKR、GTD 周回顾、“AI life coach” 类开源项目
- 规划型智能体：plan-and-execute、反思（reflection）类的智能体实现
- 个人任务系统：Super Productivity（用户仓库里已经有给它做的插件，`14-sp-assistant`）、Taskwarrior、Vikunja
- 间隔复盘：FSRS（一手调研过的 OpenTutor 用它安排复习）

**判断标准：** 能在安卓本机跑，或者思路能用 Kotlin 几百行实现；许可证 MIT、Apache 或 BSD；不依赖用户自建服务器。

### 第二步：做最小版统筹（总控里新建 `plan/`）

| 层 | 内容 | 什么时候更新 |
|---|---|---|
| 目标 | 2–4 个长期目标（就业、备考、思维能力……），每个写“做到什么算成” | 用户建立，统筹每月提议修改 |
| 里程碑 | 每个目标拆到月 | 每月 1 号 |
| 周计划 | 这周每个目标推进到哪；每天 1–3 件事 | 每周日晚，**统筹先写草稿，用户只改不写** |
| 今天 | 今天的三件事（写进总控现有的事项） | 每天早上 |

**主动性（关键）：** 用户不会自己打开，统筹要按时来找人：

- 早上第一次解锁：一屏“今天的三件事”，点“好”或改一件；
- 计划的时间到了还没开始：通知“到点了：第一件是……，现在开始还是推到几点？”（只能二选一，不能忽略）；
- 晚上固定时间：三句回顾（做了什么、没做成的原因选一个、明天第一件事）；
- 周日：统筹根据这周的真实数据（总控事项完成情况、专注时段分钟数、一手连接口的周报数据）写下周草稿，用户改完确认。

**数据：** 目标、里程碑、周计划、每次回顾都存成本机 JSON 或 Room 表，作为统筹的长期记忆；调模型时只带摘要（这周的数、上周的计划、最近 3 次回顾），不带全部历史。

**不做的：** 不接大肥鱼；不做聊天陪伴；不做 Notion 之外的新同步。

### 验收

- [ ] `统筹调研.md` 至少 6 个项目，每个都写了能借什么
- [ ] 建好目标后，周日自动出下周草稿；早上解锁出现今天三件事
- [ ] 到点没开始会来问，晚上会来收

## 4. 一手：陪练流（高频互动）

### 用户要的

> 我需要一个高频的刺激流。之前一直开 Gemini Live 就是这个意思，但我不可能一直开着它。不这样我就会一直玩手机。可它又看不到我当下在想什么，只能给宽泛的指示。

### 已经写好的规则（`claude/yishou-c1-judge` 分支，`yishou/app/.../act/`，纯 Kotlin，有测试）

| 文件 | 作用 |
|---|---|
| `Pulse.kt` | 节拍：这一拍说不说、说哪种（追问 / 推一下 / 拉回 / 收一句 / 暂停）；间隔随状态伸缩；十分钟最多六次。出题提示词；出的那句话**必须用「」引用屏幕或用户刚说的原词**，本机核对，不合格就换本机兜底句 |
| `Stall.kt` | 连着三拍没接：分清没看懂、卡住、太累、不想做；一键自报优先，不受罚 |
| `NextAction.kt` | 下一步动作（到了什么时候就做什么，几分钟）；太大太空的退回；到点问做没做 |
| `FinalReview.kt` | 选项题终审：原文证据 + 最犹豫的另一项错在哪 |
| `Weekly.kt` | 周报：专注分钟、说到做到、正确率和用时、抢答 |

**不要改这几个文件**，有问题写进 PR。

### 要做的（安卓接线）

1. **只在总控的专注时段里跑**（第 2 节第 4 条的通知），也可以在一手首页手动开。
2. **看屏：** 复用 `look/ScreenLookService` 的投屏授权，每拍前截一帧；和上一帧差别小就不重新识图；识图用设置里的识图模型，只要屏幕上的文字。
3. **听你说话（边做边念叨）：** 接 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)（Apache-2.0）做离线流式中文听写 + Silero 静音检测，只保留最近 2 分钟的文字，不存录音。模型选小的中文流式模型，在 PR 里写清模型名和大小。陪练流说话（朗读）时暂停听写。
4. **每秒一次 `Pulse.decide`：** 出题用 `PulsePrompt.SYSTEM/user`，结果过 `PulsePrompt.accept`，不合格就用 `PulsePrompt.fallback`。
5. **显示：** 屏幕顶部一张小浮窗卡：那一句话、四个一键按钮（没看懂 / 卡住了 / 太累 / 不想做）、一个“暂停 10 分钟”。可选朗读（设置里开关）。回答就直接说话，或者点按钮；说完了算“接住了”（`Pulse.answered`），一拍过去没动静算“没接”（`Pulse.missed`）。
6. **连着三拍没接：** 用 `Stall.read/move` 决定怎么接（重问、换说法、拆小、休息、要一个回来的时间）。
7. **每十分钟收一句：** 存成思维线程的断点；专注时段结束时，用 `NextAction` 让用户定下一步动作，写回总控的事项。
8. **记账：** 每一拍（问了什么、接没接、用时）记进 `DayLedger`；总控的连接口能读到。
9. **周报页：** 用 `Weekly.summarize/compare` 做一页，数据来自 `DayLedger`、题库作答记录和专注时段记录。

### 验收

- [ ] CI 绿
- [ ] 模拟器：专注时段开始 → 浮窗出现；切去测试应用 → 拉回那句话带着下一步动作
- [ ] 每一句提示都引用了屏幕或用户刚说的原词（单元测试覆盖 `accept` 不合格时用兜底句）
- [ ] 真机（用户测，未测）：做 20 分钟言语题，记下提示了几次、接住几次、有几句让你觉得“说中了”

## 5. 交付
