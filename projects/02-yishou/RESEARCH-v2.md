# 思维与行动系统：研究与方案 v2

[返回一手](README.md) · 上一版：[治水方案 v1](PLAN.md)

> 这份是给你本人看的，也可以直接交给 GPT、DeepSeek 当总纲。
> 结论先放前面；后面每一条都标了是“比较可靠的观察”还是“还只是假设”。

## 0. 结论

1. **合并：以一手为底座，把思维驾驶员并进来，做成一个 App。** 总控不再拦截，只管任务。三个 App 各开一个无障碍拦截服务，互相抢着弹页面，本身就是拦不住的原因之一。
2. **系统的重心要从“拦和考”挪到“下一步动作”。** 拦截只能堵漏，不会让人开始做事；入口题练出来的多半是“过关”，不是迁移到生活里的思考。
3. **最该训练的不是“想得多”，是三件小事：** 定出具体的下一步并按时开始、选之前做终审（找证据、想一想第二个选项）、离开以后能接回断点。
4. **衡量只看软件外面也成立的数：** 专注了多少分钟、说到做到几成、行测正确率和用时，外加每月一次不开一手的“裸考”。
5. **一个不舒服但最可靠的观察：** 做自律软件本身已经成了最大的逃离通道。方案里要有一条规矩管住它（第 6 节 M6）。

## 1. 合并：选一手还是思维驾驶员？

**选一手做底座，思维驾驶员的好东西搬进来，它自己的拦截和答题门不要了。**

| | 一手 | 思维驾驶员 |
|---|---|---|
| 规模 | 约 3.2 万行，219 个文件 | 约 6500 行 |
| 测试 | 400+ 个单元测试；Android 10 和 14 模拟器实测（真无障碍、真外部 App） | 41 个核心测试，没有模拟器实测 |
| 判卷 | 锁死要点、引原话核对、防套话 / 照抄 / 粘贴 / 指挥判卷 | 认“因果、引原文、命中词或够字数” |
| 已有 | 题库、思维线程、触发器、退坡、专注流规则、拦截体检和日志、遮罩兜底、AI 助手 | **无障碍自愈**（写回设置、Shizuku、设备所有者、看门狗）、**UsageStats 兜底**、**大肥鱼连接**、**5/10 分钟察觉和 App 时间线** |

思维驾驶员最值钱的，正好是一手最缺的“拦得住、活得久”和“接上大肥鱼”。两边的答题门、Live 陪练是重复的，留一手的。

**要搬过来的（按文件）：**

| 驾驶员的文件 | 搬到一手哪里 | 作用 |
|---|---|---|
| `A11yGuard.kt`、`GuardService.kt`、`Shell.kt` | `gate/guard/` | 无障碍被系统摘掉后自己写回（`WRITE_SECURE_SETTINGS`、Shizuku），常驻巡检 |
| `UsageMonitor.kt` | `gate/guard/` | 无障碍掉线时用“使用情况访问”判断前台 App |
| `DshLink.kt`、`Install.kt` | `link/dsh/` | 和大肥鱼配对、出题、上报观察 |
| `AwarenessRuntime.kt`、`ObservationStore.kt` | `act/aware/` | 专注流里每组结束的察觉问题和 App 时间线 |
| `DriverDeviceAdmin.kt`（设备所有者、禁止卸载） | **先不搬**，等你决定（见第 10 节） | |

**不要的：** 驾驶员的 `GateActivity`、`Intercept` 答题门、`Gate` 判卷（一手的更严、测得更全）；`Engine` 里和一手语音伙伴重复的陪练逻辑，搬之前两边比一次，留一个。

## 2. 问题模型：哪些可靠，哪些是假设

| 观察 | 可靠程度 | 依据 |
|---|---|---|
| 有人持续推着时愿意配合，独处时很难自己开始 | **可靠** | 你自己的描述，加上这段时间的合作方式本身：有外部节奏时推进很快 |
| 容易被低成本、高频率的即时刺激打断 | **可靠** | 自述，加上娱乐 App 拦截需求反复出现 |
| 选项题“看到关键词 → 马上有解释 → 提前选 → 不核对” | **比较可靠** | 24 道言语题复盘里反复出现同一路径 |
| 局部读得懂，整合成全文目的有困难 | **比较可靠** | 同上，主旨题的错法集中在这里 |
| 换个界面或话题，上一步的判断就没了 | **比较可靠** | 自述，加上“想不连续”的需求反复出现 |
| 用研究自律软件代替学习和求职 | **可靠，而且是最大的一条** | 仓库里有 17 个项目、100 多个分支；光“拦截 App 然后出题”就做了三遍（总控、一手、思维驾驶员）；同时让三四个 AI 并行在改。你自己在背景里也写到了 |
| 工作记忆容量偏小 | **假设** | 只有表现，没有测量。也可能是疲劳或没兴趣 |
| 注意力方面的个人特质（比如类似 ADHD 的表现） | **假设，不下结论** | 只有行为描述。如果困扰很大，可以找专业的人评估，那比任何软件都直接 |
| 沉默就是逃避 | **不成立** | 你自己也写了：可能是没看懂、负荷太高或累了。系统必须先分清再接 |

## 3. 为什么“长期目标很强，当下就是动不起来”

下面是几种互相不冲突的解释。除了第 4 条，都有比较多的研究支持，但用到你身上仍要靠第 8 节的数据来验证：

1. **目标是抽象的，行动需要具体的一刻。**“要备考”在任何一刻都不告诉你现在该做什么。从目标到动作中间缺了一层“到了什么时候，我就做什么”。这一层在研究里叫执行意图，是少数被反复验证过、效果比较稳的办法。
2. **当下没有一个和刷手机抢注意的东西。** 即时刺激总是在眼前，学习任务不在眼前。所以要在关键时刻（解锁、切 App、专注时间段开始）把“下一步动作”推到眼前，而不是等你想起来。
3. **你对外部结构反应很好。** 有人推就配合，说明缺的是结构，不一定是意志力。系统该当那个“结构”：定时出现、一次只要一件事、做完马上看到下一件。有人陪着做事比一个人做容易开始，这也是专注流要做“在场感”的原因。
4. **状态一断就回不来**（假设）。离开一次，任务上下文就蒸发，重新开始的成本比当初开始还高。所以每次离开都要自动存下“停在哪、下一步是什么”，回来第一屏就是它。
5. **累和时段。** 晚上、连续做了很久之后，什么都难。这时候硬逼只会练出更会逃的人，要识别出来，换成“定好明天几点接着做”。

## 4. 没回应、敷衍、转移话题：怎么分清是真困难

核心思路：**让说实话比沉默更省事。**

- 每次追问旁边都有四个一键按钮：“没看懂 / 卡住了 / 太累 / 不想做”。点一下就行，不用解释，**点了不受罚**。
- 没点的时候，才看行为痕迹，而且只给“可能是”：

| 痕迹 | 可能是 | 怎么接 |
|---|---|---|
| 问题没被点开过 | 没看到 | 再提醒一次，只留一句 |
| 打了又删好几次 | 卡住了 | 拆小：二选一，或者只做第一步 |
| 很晚了，或已经连续干了 90 分钟 | 累了 | 先停 5 分钟，断点记下 |
| 问完切去了娱乐 App，最近还反复如此 | 在躲 | 不追问原因，只要一个回来的时间，到点再叫 |
| 看了但一个字没写 | 说不准 | 亮出四个一键按钮问一句 |

- 同一个问题最多接三次，第三次一律改成“说一个回来的时间”。不纠缠：纠缠只会把你练得更会关通知。
- 每周统计一次：哪类原因最多、出现在几点。这是给你看的规律，不是用来罚的。

（这一套已经写成代码：`act/Stall.kt`。）

## 5. 对现有思路的取舍

| 方法 | 结论 | 原因 |
|---|---|---|
| 应用拦截 | **留一个，不再加码** | 能堵漏，但不会让人开始思考。三个 App 各拦各的反而更不稳。以后只修“拦得住”（搬驾驶员的自愈），不再加新的拦法 |
| 入口答题 | **降级成“下一步动作确认”为主，题目为辅** | 入口题练出来的是过关能力。真正要的是打开 B 站那一刻想起“我本来要做什么” |
| 限时答题 / 判卷 | **留，但题目换成真材料** | 用你真实在做的行测题（粉笔导入、题库），不要模型现编的题 |
| 乒乓追问 | **留在专注流里，带退坡** | 投入度高，但会变成跟着 AI 想。必须逐步改成你先问、你先说 |
| 苏格拉底提问 | **只用在终审一步** | 开放式追问容易越聊越散；终审的两个问题是固定的、可核对的 |
| 主动聊天 / 人格（大肥鱼） | **留，但每次聊天都要落到下一步动作** | 陪伴感对“开始”有用；可聊完没有动作，就只是另一种刷手机 |
| 严格模式 | **只在你自己开的时间段里严** | 全天候加严，会把你的精力引到研究怎么绕过上 |

## 6. 新机制

**M1 下一步动作（核心循环）。** 每次和系统的互动（察觉、复盘、聊天、入口）都只用一个结果收尾：“到了【什么时候】，我就【做什么具体的事】，做【几分钟】”。太大的（“复习行测”）、太空的（“认真学习”）、没有开始时刻的（“有空的时候”）都会被退回。到点了系统问一句“做了吗”，只问做没做，不验收内容。代码：`act/NextAction.kt`。

**M2 专注流 + 在场感。** 已有任务卡 G3。它把“有人陪着做”变成节奏：一组一组走，每组结束点一下“做完了 / 没做完”，接着自动接到下一步动作。

**M3 终审。** 只用在选项题：落笔前必须做两步，本机就能核对：
1. 从原文抄一句证据（必须真在原文里）；
2. 说出最犹豫的另一个选项错在哪（要点到那一项的说法，不能只写“不全面”）。

没写证据、8 秒内就落笔的，记一次“抢答”。只记不罚，周报看它有没有下降。代码：`act/FinalReview.kt`。

**M4 断点。** 离开前存好“停在哪、下一步是什么”，回来第一屏就是它。一手的思维线程已经有这个，要扩到专注流和下一步动作上。

**M5 真实周报和每月裸考。** 见第 8 节。代码：`act/Weekly.kt`。

**M6 管住“做系统”这条逃离通道。** 这条最难接受，也最重要：
- 做自律系统的时间设一个上限，比如每周日 1 小时，平时不做；
- 专注流里，开发工具（GitHub、Claude、Codex 等）默认不在白名单，除非这一段的任务写的就是“开发”；
- 新功能先过一关：说清楚它会让第 8 节的哪个数变好。说不清就不做。

## 7. 怎么避免它又变成“一个要我自己打开的 App”

- **不靠你打开，靠时机触发：** 解锁、切 App、专注时间段开始、下一步动作到点。
- **不用进 App 就能回应：** 通知里直接回复、浮窗小卡、一键按钮；语音用 sherpa-onnx 离线识别，说一句就行，不用联网。
- **首页只放一件事：** 现在该做的那个下一步动作，加上“开始”按钮。其余功能全部收起来。
- **没回应也不会把你踢走（第 4 节），但会记下。** 系统是你的外部结构，不是对手。

## 8. 先练什么，怎么证明有用

| 能力 | 每周看的数 | 在 App 外面怎么验证 |
|---|---|---|
| 启动：定下一步并按时开始 | 说到做到的比例 | 求职：每周投出去几份、面试几次；备考：粉笔记录里实际做了多少题 |
| 终审：不抢答 | 抢答次数；做了终审 vs 没做的正确率 | 每月一次不开一手的限时套题，和上月比正确率 |
| 整合：读出全文在解决什么 | 主旨题正确率和用时 | 同上，只看主旨和意图题 |
| 状态保持：接得回断点 | 从断点回来到开始做的时间 | 专注流里中断后多久回到任务 |

先记两周不干预的数作为起点。之后每月比一次：**裸考的数没有变好，说明 App 里的分再好看也没迁移出去**，就该改方案，而不是加功能。

| 阶段 | 做什么 | 谁做 | 完成标准 |

| P0 止血（1 周） | 只保留一手的拦截：卸载或关掉驾驶员和总控的拦截；把驾驶员的自愈和 UsageStats 兜底搬进一手 | GPT 搬代码，Claude 审 | 拦截体检里连续 3 天没有“服务断开”；真机上打开 B 站都被挡住 |

## 10. 参考项目（看了四个）

| 项目 | 结论 | 原因 |
|---|---|---|
| [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) | **直接用（作依赖）** | 离线语音识别、语音合成、静音检测都有，有 Kotlin 接口，支持中文模型；Apache-2.0，15.7k 星。接进来前要量一下模型大小 |

| [OpenTutor](https://github.com/zijinz456/OpenTutor) | 只借思路 | FSRS 间隔复习、根据疲劳和回答长短调难度，这两点值得学；代码是 Python 加网页，用不上 |
| [socratictutor](https://github.com/ccascio/socratictutor) | 跳过 | 太小（0 星、26 次提交），没有比一手更多的东西 |

## 12. 需要你决定的

1. **合并方向：** 以一手为底座、驾驶员并入、总控不再拦截。同意的话，我写 P0 的任务卡。
2. **防卸载：** 驾驶员有“设备所有者 + 禁止卸载”。一手原来的规矩是不做防卸载（随时能退出）。这是你自己手机上的选择，我建议先不开：越难退出，越容易把精力花在研究怎么退出上。
3. **M6：** 做系统的时间每周设上限，专注流里默认拦开发工具。这一条要你本人点头才有意义。
