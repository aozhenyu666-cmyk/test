## 4. 行为契约（改代码前先看这一节）

### 4.1 主动开口只有一个入口

`CompanionRunner.tick()` 是唯一入口，`ProactiveEngine.decide()` 是唯一决策点。**不要在别处再加定时器、Handler、WorkManager 或第二个“该不该说话”的判断。** 这是 P1 的硬约束。

`decide` 的判定顺序：

1. 总开关关闭 → 沉默。
2. 一手自己的页面开着、正在说话、已有待答问题 → 沉默。
3. 不在活跃时段 → 沉默。
4. 处于 RESTING 且未到 `restUntil`，或 DEFERRED 且未到 `deferUntil` → 沉默。
5. 处于 BACKOFF 或未回应次数达到阈值 → **只有到期话题**能开口，否则沉默。
6. 距上次提问或上次回答不足 `minGapMinutes` → 沉默。
7. 本小时/本日次数达上限 → 沉默。
8. 机会判定 `roll` 不在 `0..opportunityPercent` → 沉默。
9. 有到期话题 → 话题跟进。
10. 前台应用在关注名单且连续停留达到 `presenceMinutes` → 有任务/卡点问任务，否则问“休息还是回去”。
11. 其余 → 沉默。

`roll` 由调用方传入 0–99 的整数，测试固定它，运行时用 `Random.nextInt(100)`。

### 4.2 回答之后发生什么

`answer()`：

- 话题跟进用 `ProactiveAnswer.checkTopic`：说出进展即可，不要求立场和理由。
- 本地模式用 `CompanionLocal.checkAnswer`；AI 模式用 `JudgementRules.check`。
- 通过后：
  - `ProactivePolicy.onAnswer` 判定为 REST / DEFER / BACK / DONE / ANSWERED，写入 `ProactiveMode` 与 `restUntil` / `deferUntil`；
  - Echo 写一条 `kind=conclusion, scene=companion`；
  - 关系记忆写一条（休息、完成等额外写 EVENT）；
  - 有话题则更新 summary/followUpAt，说“解决了”则关闭；
  - 说“定个时间”或“现在回去”时新建约定话题；
  - `markAnswered` 让间隔从回答时刻重新起算，避免刚答完立刻再问。
- 未通过：`attempt + 1`，允许重答；不允许重答时记一次 miss、清 pending、进退避。

`skip()` 与浮窗超时收回同样走 `ProactivePolicy.onMiss`。

### 4.3 关系记忆

七类：`FACT`、`PREFERENCE`、`COMMITMENT`、`EVENT`、`SHARED`、`CORRECTION`、`TOPIC`。

- 存在 `yishou.db` 的 `relation_memory` / `relation_topic` 两张表，SQL 全部用 `?` 绑定。
- 纠正不删历史：旧记录写 `validTo`，新记录带 `correctsId`。
- 召回走 `selectForPrompt`，只挑当前用得上的几条；不要把整库塞进提示词。
- 话题状态：`OPEN` / `RESOLVED` / `PAUSED` / `CLOSED`。
- 否定词已处理：“还没搞定”不会被当成“搞定”。

### 4.4 人格

`PersonaConfig(tone, maxFollowUps)`，四档：`BALANCED` / `DIRECT` / `GENTLE` / `BRIEF`。

硬约束：不奉承、不无意义赞同、不复述用户的话、一次只问一个动作。人格只改措辞，不改事实、边界和调度逻辑。

### 4.5 运行时持久化的键

调状态时直接看这些键（都在 `CompanionPrefs`）：

| 键 | 含义 |
|---|---|
| `p_mode` | IDLE / ASKING / ANSWERED / DEFERRED / RESTING / BACKOFF |
| `p_last_ask` / `p_last_answer` | 上次提问 / 回答时刻 |
| `p_rest_until` / `p_defer_until` | 休息 / 推迟截止 |
| `p_unanswered` | 连续未回应次数 |
| `p_prompts_hour` / `p_prompts_today` | 小时 / 日计数 |
| `p_last_topic` | 上次跟进的话题 id |
| `pending_q` / `pending_at` / `pending_kind` / `pending_topic` | 当前待答问题 |
| `pending_local` | 是否本地模式 |
| `persona_tone` / `persona_followups` | 人格设置 |

## 6. 已知缺陷与坑

1. **AVD 会清空无障碍列表。** 这不是应用 bug，但它会让所有“服务是否活着”的测试结论失效。凡是依赖无障碍在线的测试，先确认 `settings get secure enabled_accessibility_services` 非空。
2. **第三方无障碍应用会改写列表。** `com.dshdriver.app` 和 `io.github.ccch1mneyyy.dsh_app` 都观察到过。做共存测试前先停掉它们。
3. **一手服务重连后不补读当前前台应用。** 如果用户已经停在某个应用里，要等下一次窗口切换才开始计时。
4. **总控不会覆盖“用户主动关闭”。** 从设置里移除总控会被判为用户行为，不自动加回。这是有意保留的判断。
5. **AI 模式的识图是 mock。** DeepSeek 不支持图片；真实视觉链路没验证。节点文字路径已接通，但干净内容页未验证。
6. **服务共存仍有生态风险。** “只追加不重绑”解决了自己人互相踩，但解决不了第三方观察者改写列表。
7. **schema 目录漂移。** `16.json` 未跟踪，`15.json` 不在目录里；Room 版本没变，但交接时应知道这一点。
8. **窗口路径。** 中文路径会让 Gradle 测试 worker 挂掉；不要在原路径直接跑。

   - “现在回去” → `p_mode=ANSWERED`、约定话题；
   - “已完成” → 话题 `RESOLVED`；
   - 连续两次不答 → `p_mode=BACKOFF`，且只有到期话题能再开口。
4. 补 P0 四个边界：空回答、重复提交只写一次、手动收起不强制展开、通知点击进设置。

### 第二步：收尾工程质量

1. 对照基线复现并处理 `GateBlockedIntegrationTest` 的遮罩失败；确认是环境还是回归。
2. 跑总控 `LoopTest` Instrumentation。
3. 决定是否修总控 lint 的 28 个既有错误（建议单独提交，不要混进功能改动）。
4. 补提交 schema JSON，消除目录漂移。

### 第三步：才进 P2

P2 是思维教练：识别敷衍、回避、证据缺失、过早闭合，做连续但有限次的追问。**在第一步和第二步完成前不要开 P2**，否则会叠在未验证的地基上。

P3（总控协作/仲裁）、P4（长期稳定）排在 P2 之后。

### 事先写死的判据

- 结算率没有明显高于基线 → 换机制，不加功能。
- 结算率上去了但现实产物没变 → 系统在制造“感觉在推进”，立刻降温。
- 只有状态好时才有效 → 它是顺风车，不是系统。
- 第四周停用一周：结算率大幅回落 → 它是拐杖；基本维持 → 有真实行为改变。

## 10. 交接问答

**问：一手是否已经可以在完全没有 AI 的情况下，主动发起对话、接收回答、判断回答、持久化记忆，并在下一轮继续交流？**

**答：可以，核心链路已闭环，且有设备日志。**

具体链路：

1. **主动发起**：GateService 每秒调 `tick`，`ProactiveEngine.decide` 在关注应用停留达标后开口。设备日志：`本地提醒：你在YouTube 待了 1 分钟…`。
2. **接收回答**：浮窗内输入或点预设，不启动 Activity。设备日志：`判断通过：xianzai` / `判断通过：休息`。
3. **判断回答**：本地模式用 `CompanionLocal.checkAnswer`；话题跟进用 `ProactiveAnswer.checkTopic`；AI 模式才走 `JudgementRules`。
4. **持久化记忆**：Echo 写 `conclusion`；关系记忆写 `relation_memory` / `relation_topic`。设备查询到 `EVENT | 休息：休息一下` 与 `OPEN | summary=休息一下`。
5. **下一轮继续**：下一轮优先召回上次回答或到期话题。设备日志：`上次你说「xianzai」…`、`话题跟进：上次你说「登录接口还没搞定」——现在到哪一步了？`。

**没有断在某一环。** 但有三条限定：

- 触发依赖“关注名单里的应用 + 连续停留”，不是随时主动说话；这是有意的，避免变成骚扰。
- 长期存活没有真机 24 小时证据；模拟器的服务存活不能当生产结论。
- 边缘分支（推迟/回去/完成/退避）与 P0 的四个 UI 边界只有单测，设备证据待补。
