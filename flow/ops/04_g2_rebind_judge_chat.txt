【指令 04：修复判断官（G2）会话断链】（纯文本版，整段复制）

用户批准执行本指令。

背景：G2_Judge_Flow（b3b65845-74ad-4834-9806-73d859775284）的 e_judge 节点把判断发往会话 28f6fbb9-e08c-4536-8500-60cde7647094，但这个会话已经不存在（执行日志：Chat not found by query）。本轮新建一个绑定"判断官"角色卡的会话，把 e_judge 的 chat_id 换过去，并把 persist_turn 改为 false（每次判断只看当次证据包，不在会话里累积历史）。

严格按步骤执行，共 7 步，每一步都要有工具回读证据；遇到任何与预期不符的情况，立即停止并报告，不要自行变通。

禁止事项：
- 只修改 G2_Judge_Flow 的 e_judge 节点里的 chat_id 和 persist_turn 两个参数。不改其他节点、连线、触发器、开关，也不改其他工作流。
- 不删除任何会话、工作流或文件。
- 不手动触发任何工作流。
- 不调用 app_suspender 的任何工具；不向判断官或任何会话发消息。

---------------------------------
第 1 步：确认前提。
(a) 调用 extended_chat:find_chat，参数 query = 28f6fbb9-e08c-4536-8500-60cde7647094，match = exact。预期：找不到。如果找到了，立即停止。
(b) 调用 extended_chat:list_character_cards，确认存在名字恰好是 判断官、id 为 1bd093cf-1a17-459f-92ed-6e8c8ea788a7 的卡片。不符就停止。

---------------------------------
第 2 步：备份。
调用 workflow:get_workflow，workflow_id = b3b65845-74ad-4834-9806-73d859775284，把完整返回 JSON 原样写入这个文件：
/sdcard/Download/Operit/00_AGENT_HANDOVER/g2_backup_20260926/b3b65845-74ad-4834-9806-73d859775284.json
然后用 super_admin:shell 执行下面这一行命令，确认文件非空并且包含旧会话 ID（第二个数字应大于等于 1）：

F=/sdcard/Download/Operit/00_AGENT_HANDOVER/g2_backup_20260926/b3b65845-74ad-4834-9806-73d859775284.json; wc -c < $F; grep -c 28f6fbb9 $F

---------------------------------
第 3 步：新建判断官会话。
调用 create_new_chat，参数：
group = 后台角色
set_as_current_chat = false
character_card_id = 1bd093cf-1a17-459f-92ed-6e8c8ea788a7
记下返回的新 chatId，下文称为 NEW。返回为空或失败就停止。

---------------------------------
第 4 步：改标题，防止被误删。
调用 update_chat_title，参数 chat_id = NEW，title = 判断官·G2后台（勿删）

---------------------------------
第 5 步：回读新会话。
调用 extended_chat:find_chat，参数 query = NEW，match = exact。确认能找到，并且绑定的角色卡名字是 判断官。不是就停止，不要进行第 6 步。

---------------------------------
第 6 步：改节点。
调用 workflow:patch_workflow，只传两个参数：
workflow_id = b3b65845-74ad-4834-9806-73d859775284
node_patches = 下面这一行 JSON，把其中的 NEW 替换成第 3 步的真实 chatId，其他字符一个都不要改：

[{"op":"update","id":"e_judge","node":{"actionConfig":{"chat_id":"NEW","persist_turn":"false"}}}]

不要传 name、description、enabled、connection_patches。

---------------------------------
第 7 步：回读工作流。
再调用一次 workflow:get_workflow（同一个 workflow_id），逐项核对：
- e_judge 的 chat_id = NEW
- e_judge 的 persist_turn = false
- e_judge 的 character_card_name = 判断官，message 仍引用节点 e_pack，timeout = 240
- 节点数、连线数、enabled 与第 2 步备份一致
任何一项不符：用备份里 e_judge 原来的 chat_id 和 persist_turn 再 patch 回去，然后停止并报告。

---------------------------------
输出格式：
逐步列出第 1～7 步，每步一行，写明：结果（OK / STOPPED / FAILED）和证据（ID、回读值或错误原文）。
最后写一句结论，例如："e_judge 已改绑到 NEW（判断官），persist_turn=false，其余与备份一致；等下一次定时运行验证。"

=================================

tail -n 5 /sdcard/Download/Operit/judge/save_log.tsv; ls -t /sdcard/Download/Operit/workflow/_execution_logs/b3b65845-74ad-4834-9806-73d859775284 | head -3

再调用 extended_chat:find_chat（query = NEW，match = exact），报告消息数量（预期是 0 或接近 0）。
