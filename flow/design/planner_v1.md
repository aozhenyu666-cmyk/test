# 统筹规划系统 设计稿 v1（2026-10-03）

> 只是设计，不改任何东西。用户确认后再按阶段做。

## 一、目标

把"任务 / 日程 / 时间 / 目标分层 / 四象限"统一起来，让几个 AI 各司其职、协同运转，并由小满按时间主动来找用户。核心原则不变：**用户随时能看、能改、能关；AI 只建议和执行，不替用户立规矩、不单方面限制用户。**

## 二、各部分落在哪（不从零造 App）

| 能力 | 放在哪 | 说明 |
|---|---|---|
| 任务、子任务、项目、标签、日程 | Super Productivity（SP） | 日常记录和操作的本体，已在用 |
| 手动计时 + 时间统计 | SP 自带 | 用户主动记"在做什么" |
| App 实际使用时长 | Operit `system_tools:get_app_usage_time` | 自动记"实际在用什么"，和手动计时对照 |
| 目标分层（长/中/短期） | SP 项目 + 父任务 | 方向=项目，长期目标=父任务，中期里程碑=子任务，本周/当天=带日期的任务 |
| 四象限 | SP 标签 `重要` `紧急` + 插件视图 | 两个标签组合出四个象限 |
| AI 拆解 / 排期 / 复盘 | SP 的 AI 插件 | 已能接 OpenAI 兼容接口 |
| 跨 AI 调度 | Operit 工作流 | 按时间触发，取数据、调模型、写回 |
| 主动提醒、到点来问 | 小满（companion_brain） | 复用现有的大脑 |
| 复盘写入 / 待办提取 | IMA（`scripts/ima_note.sh`，已跑通） | 复盘 append 进笔记；从指定笔记提取待办回 SP |

## 三、方向与目标分层（初版，用户可改）

```
方向：求职        方向：学习
 └ 长期：拿到 offer   └ 长期：（待用户定）
    └ 中期：每周投 N 家   └ 中期：…
       └ 本周任务           └ 本周任务
          └ 今日任务           └ 今日任务
```

- 方向先两个：求职、学习；以后可加（健康等）。
- 每层在 SP 里的载体：方向→项目，长期→置顶父任务，中期→子任务，本周/今日→带 due date 的任务。

## 四、数据怎么流动

SP 的数据通过它自带的同步（WebDAV / SuperSync）落到手机，Operit 读得到。约定一个交换目录 `/sdcard/Download/Operit/planner/`：

- `plan_today.json`：今天计划做的任务（从 SP 导出，或 AI 排好写入）。
- `usage_today.json`：今天各 App 实际用时（Operit 采集）。
- `review/<日期>.md`：当天复盘（AI 生成 → 推 IMA）。
- `inbox_from_ima.md`：从 IMA 笔记提取出来、待确认转成 SP 任务的待办。

**谁写谁读，边界清楚**：
- SP 插件：写 `plan_today`，读 `usage_today` 和复盘。
- Operit 工作流：写 `usage_today`、生成复盘、推 IMA、从 IMA 提待办。
- 小满：只读这些文件，到点来提醒，不改计划内容。

## 五、几个 AI 怎么协同（Operit 当总调度）

Operit 工作流按时间触发，每种活派给合适的模型（都走 API）：

| 时机 | 做什么 | 谁来做 |
|---|---|---|
| 早 8:00 | 读昨日未完成 + 今日日程，排出今天的计划，写 `plan_today` | 规划模型（如 GPT/Claude，用户选） |
| 白天每 1–2 小时 | 采集 App 使用时长，和计划对照 | Operit 脚本（不用模型） |
| 到任务时间点 | 小满来问一句"该做 X 了" | 小满 |
| 晚 22:00 | 读当天计划 vs 实际，生成复盘，推 IMA | 复盘模型 |
| 每周日 | 汇总一周，更新中期里程碑进度 | 规划模型 |

模型选哪个、各管哪段，做一张配置表，你随时改。某个模型不可用时自动退到下一个。

## 六、降低"回应成本"（替代更强硬的监督）

让"回她一句"几乎不费力，而不是让她更强硬：
- 提醒通知里带快捷按钮：`在做` / `完成` / `卡住` / `晚点`，点一下就算回应，回写成一条进展。
- 早上计划、晚上复盘都由她先写好，用户只需要"好"或改一句。
- （实现取决于 Operit 通知是否支持按钮，先查，不支持就退回"回一个词"。）

## 七、分阶段做

- **P1 目标分层落到 SP**：建"求职""学习"两个项目和分层父任务结构（指令交给你在 SP 里建，或 AI 插件建）。
- **P2 时间对照**：Operit 每天采集 App 使用时长写 `usage_today`；SP 插件加一个"计划 vs 实际"视图。
- **P3 复盘 → IMA**：每晚生成复盘，用 `ima_note.sh` append 进一个固定笔记。
- **P4 IMA → 待办**：从指定 IMA 笔记提取待办写 `inbox_from_ima`，你在 SP 里确认转成任务。
- **P5 跨 AI 调度**：Operit 工作流 + 模型配置表，把早晨排期、晚间复盘串起来。
- **P6 四象限视图 + 快捷回应按钮**。

每个阶段独立可用、可停、可回退，和现在的小满/判断官并行，不互相破坏。
