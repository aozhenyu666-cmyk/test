# 回路（Huilu）

一个 Android App，陪着“接下来十分钟做 X”这个意图走完这十分钟。

你声明一个具体的行动，它就记住当时的局面。随后它会在合适的时候主动重新出现：到了计划的检查点，或者你偏到娱乐 App 上的时候。每次出现，它都把“原本以为会发生什么”和“实际发生了什么”放在一起，问你下一步怎么办，并把这次偏差记下来。

为什么做成这样、第一阶段验证什么、有哪些取舍，见 [docs/DESIGN.md](docs/DESIGN.md)。

安装包：[`dist/huilu-0.1.0.apk`](dist/huilu-0.1.0.apk)（约 870 KB，Android 8.0+）

---

## 一轮是什么样的

```
10:00  你：学网课第 3 节，10 分钟，在「网课 App」里做，为什么：周五交作业
       → 通知栏常驻：现在：学网课第 3 节（0/10 分钟）· 下次检查 10:05 · 为什么：周五交作业
10:03  你切到了 B站
10:05  B站已连续 2 分钟 → 回路主动出现（通知，或直接弹出检查页）：
       “原计划「学网课第 3 节」，但「哔哩哔哩」已经在前台连续 2 分钟。发生了什么？”
       系统观察到：网课 3分，哔哩哔哩 2分
       [偏了，现在回去] [其实在做] [休息] [太难，改小一点] [改做别的] [这次别管我]  或者说一句
10:05  你在检查页上点“偏了，现在回去” → 网课 App 被直接打开；回路：“好，10:08 看看是不是真的回去了。”
10:07  （两分钟后评估这次干预的效果：回到了目标）
10:08  短间隔复查：“看起来一直在目标 App 里。实际进展到哪了？” → 在做
10:10  到点：“计划的 10 分钟到了（目标 App 6分，哔哩哔哩 2分）。结果如何？”
       [完成了] [还没完，再 5 分钟] [没做成，先停下] [改做别的]
```

所有这些都会进入“回顾”页：

- 偏离通常发生在第几分钟、偏到了哪个 App；
- 从开始偏离到系统重新出现隔了多久；
- 每种干预的请求次数、确认生效的次数，以及之后你是回到了目标、留在原处，还是转去了别的娱乐 App；
- 你自报“在做”、但观察到偏离的次数。

## 安装后先做这几步

1. 安装 `dist/huilu-0.1.0.apk`。这是侧载安装，系统可能会提示“未知来源”。
2. 打开后允许**通知**。没有通知，回路就无法主动找你。
3. 主页顶部会提示授予**使用情况访问权限**，点“去授权”，在列表里打开“回路”。没有这个权限，系统只能靠你自报，检查里会明确显示“无法观察”。
4. 打开 **设置与权限**，按需开启下面几项。每一项都会显示“现在能不能做”，以及做不到时会发生什么。
   - **精确闹钟**：进程被杀后仍能准时回来检查。
   - **不受电池优化限制**：国产系统上还要在系统设置里允许“自启动”和“后台运行”。
   - **显示在其他应用上层**：偏离时可以直接弹出检查页，而不只是发通知。
   - **无障碍 → 回路**：在你允许强干预的轮次里，可以把你送回桌面。Android 13+ 侧载安装时，要先到 应用信息 → 右上角菜单 → 允许受限制的设置，才能打开它。
5. 在“设置与权限”里检查**娱乐 App 列表**。默认已经包含 B站、抖音、快手、小红书、微博、知乎、头条、爱奇艺、优酷、腾讯视频、番茄小说、王者荣耀、YouTube 等。
6. 回到主页，试一轮 10 分钟。

## 你会看到的

- **主页**：空闲时是“接下来做什么？”。你填写做什么、为什么、多久、怎么判断你真的在做（指定 App / 离开手机 / 不限），以及这一轮是否允许强干预。最近做过的行动可以一键复用。行动中，主页显示当前局面和系统此刻看到的现实，例如“前台：哔哩哔哩（娱乐）1分20秒”。
- **常驻通知**：倒计时、为什么、下一次检查的时间和理由。
- **检查**：既是通知（可以直接点按钮，或回复一句话），也是一个独立页面。页面上有当时的局面、系统观察到的各 App 时长和判定，以及只针对这次检查的选项。
- **回顾**：偏差统计和每一轮的完整记录，包括每次检查、每次干预的理由、真实结果和之后的效果。可以导出完整日志（JSONL）。
- **设置与权限**：能力边界、娱乐 App 列表、节奏参数，以及 AI 判断层的配置。

## AI 判断层（可选）

在“设置与权限”里填一个 OpenAI 兼容接口（默认是 DeepSeek）。启用后，你在检查里写的一句话会被理解成下一步，比如“刚才查资料顺手点开了视频，现在回去”会被理解成“偏了，现在回去”。

除此之外的所有判断都在本地按规则完成，不联网。模型的输出只能落在这次检查给出的选项里，不能自己升级干预强度。

## 数据

全部保存在本机。

- 事件日志在 App 私有目录的 `events.jsonl`，只追加，每次写入后立刻落盘。当前局面完全由它重放得到，所以进程被杀、重启之后都能恢复。
- 设置和 API Key 存在 App 私有的 SharedPreferences 里。
- **卸载会删除这些数据**，需要的话请先在“回顾”页导出日志。

升级时直接覆盖安装即可：仓库里的调试签名是固定的（`tools/debug.keystore`，公开、仅用于侧载），不同机器和 CI 打出的包都能互相覆盖。

## 开发

```
core/       纯 Kotlin 的闭环逻辑：模型、事件与编码、局面重放、偏差评估、规则策略、引擎、统计、AI 判断层的提示词与解析
app/        Android 适配层：观察（UsageStats）、前台服务、闹钟、通知、检查页、无障碍、界面（只用 Android 框架，无 AndroidX）
robotest/   Robolectric 集成测试，在 JVM 上运行真实的 Android 组件
tools/      备用构建脚本、invokedynamic 检查、调试签名
docs/       设计说明
```

**用 Android Studio 或 Android Gradle 插件构建**（需要 Android SDK）：

```bash
./gradlew :core:test :app:assembleDebug     # APK 在 app/build/outputs/apk/debug/
```

**没有 Android SDK 时**，用 aapt + kotlinc + dx + apksigner 直接打包。`dist/` 里的 APK 就是这样打出来的：

```bash
sudo apt install aapt dalvik-exchange zipalign apksigner zip
./tools/build-apk.sh          # core 单元测试 + 打包签名 → dist/huilu-0.1.0.apk
./tools/build-apk.sh --test   # 另外在 Robolectric 里跑 App 的集成测试
```

**只改闭环逻辑时**：`./gradlew :core:test`。最重要的回归测试是 `LoopTest.tenMinutesWithADriftInTheMiddle`，它就是项目方向的判断标准。

CI（`.github/workflows/huilu.yml`）两条路都会跑：标准的 Android Gradle 插件构建，以及备用构建加 Robolectric 测试。
