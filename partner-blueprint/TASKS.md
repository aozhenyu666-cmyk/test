## S1 哨兵 App

**目标**：总控的无障碍一掉，2 分钟内恢复；恢复不了就冻结娱乐 App，并让你知道。

**位置**：仓库新目录 `sentinel/`，独立 Android 工程，包名 `com.zongkong.sentinel`，用和总控相同的调试签名（方便互相校验）。体积越小越好，不用 Compose，一个设置页就够。

**做什么**：
1. **常驻**：一个前台服务（通知写“哨兵在看着总控”）+ AlarmManager 每 60 秒兜底唤醒 + 开机广播。
2. **心跳**：总控每 60 秒给哨兵发一个显式广播（带时间），哨兵只接受总控签名的发送方；哨兵也每 60 秒给总控发。两边都记“最近一次心跳”。总控那边的改动只加发送 / 接收心跳和“哨兵掉线”记录，不动别的。
3. **检查**：总控的无障碍是否在 `enabled_accessibility_services` 里；总控心跳是否在 2 分钟内。
4. **修**：没开或心跳断了 → 用 `WRITE_SECURE_SETTINGS` 把总控的服务从列表里去掉再加回去，再用显式 Intent 拉起总控；等 60 秒复查。设置页给出一键复制的 adb 授权命令（`adb shell pm grant com.zongkong.sentinel android.permission.WRITE_SECURE_SETTINGS`）和授权状态。
5. **顶上**（修了两次还不行）：
   - 全屏页“总控看不见了”，按钮：去权限页 / 重启总控；
   - Shizuku 可用时，对总控拦截名单里的 App 执行 `pm suspend`（名单从总控读，读不到就用内置的常见娱乐名单）；每个冻结写到期时间，最长 12 小时；
   - 有“使用情况访问”权限时，每 5 秒看一次前台应用，娱乐 App 在前台就弹回全屏页（第二双眼睛），并把这段时间记下来，总控恢复后交给它。
6. **恢复**：总控回来后，哨兵解开自己做的冻结（总控会按自己的规则重新管），把掉线记录（开始、结束、原因、期间前台应用）交给总控的眼睛日志（`app/guard/Diag.kt`）。
7. **安全阀**：永不冻结名单写死（电话、短信、设置、微信、支付宝、地图类、总控、哨兵）；过期冻结在每次检查和开机时解开；设置页“全部解开”（记录并通知总控扣信用）。
8. **权限页**：无障碍以外需要的权限逐项列出（通知、WRITE_SECURE_SETTINGS、Shizuku、使用情况访问、全屏通知、vivo 自启动和后台耗电），能查到的显示状态，查不到的标“请确认”。

**不做**：哨兵自己的无障碍服务；读屏幕内容；任何 AI 功能。

**验收**：
- 单测：判断逻辑（各种心跳 / 开关 / 权限组合下该修、该顶上还是没事）、冻结到期计算、永不冻结名单。
- 真机：在系统设置里关掉总控无障碍 → 2 分钟内被重新打开；强行停止总控 → 被拉起；拔掉 WRITE_SECURE_SETTINGS 再关无障碍 → 全屏提示 + 抖音变灰；重启手机 → 哨兵自己起来，过期冻结被解开。

## G1 总控 ↔ Google Tasks / 日历

**目标**：Gemini 和总控通过 Google Tasks 和日历直接交换信息，不用人传话。

**先读**：G0 的测试结果、`core/work/Sync.kt`（Notion 同步的增量 / 去重写法可以照搬）、`core/agent/Snapshot.kt`、`core/plan/DayReport.kt`。

**做什么**：
1. **登录**：Google 登录 + OAuth，只申请 Tasks 和 Calendar 权限。README 写清楚用户要在 Google Cloud 建一个项目、加 Android 客户端（用仓库固定调试签名的 SHA-1）、把自己加为测试用户。网络不通时明确报错，不卡界面。
2. **建清单**：首次连接时建“墨灵·局面”“墨灵·话题”“墨灵·收件箱”三个清单和“墨灵”日历；已有同名的就复用。
3. **写局面**（`core/bus/Situation.kt` 纯逻辑生成，`app/bus/` 负责同步）：5–8 条，每条标题一句话、≤ 40 字，能单独看懂：今天的主线及状态、主线断点、今天做事 / 娱乐分钟和剩余票、今天零食 / 支出、信用和态度、昨晚收线、明天第一步。有变化时 2 分钟内同步，否则 15 分钟一次；只改有变化的条目。
4. **写话题**：把 T1 给出的当前话题卡写进“墨灵·话题”，第一条是“现在该聊的”。T1 完成前先用一张固定卡占位。
5. **写日历**：今天已排时间的行动写进“墨灵”日历，改期、完成同步更新；只管总控建的事件。
6. **读收件箱**：每 2 分钟和每次回到前台时拉取。解析 `收线｜结论｜下一步｜时间`（容错：全角半角竖线、少字段、口语化的时间用 `core/work/TimeParse.kt`）。收线 → 记录 + 把下一步建成行动 + 交给 R1 验收；其他条目 → 进收集箱。处理完把这条标记完成，避免重复导入。
7. **剪贴板备用**：G0 测试 Tasks 不通时，同样的格式从剪贴板导入（总控已有剪贴板检测，复用）。

**验收**：单测覆盖局面生成、收线解析（20 条样本，含口语和格式错误）、去重。真机：在 Gemini Live 说“看看我的局面”能说出主线；在 Gemini 里收线，5 分钟内总控出现对应的行动。

## G2 墨灵设定

**目标**：Gemini Live 进来就知道你是谁、现在什么局面、该聊什么，并按规矩带你想。

**交付**：`partner-blueprint/moling-gem.md`，包括：
1. **Gemini Gem / 技能的设定全文**（纯文字，迁到哪里都能用）：人格、开口前先读“墨灵·局面”“墨灵·话题”和今天的日历、对话规矩（一次一问、用户先说、不替他总结、口水话就拉回、到时间收线）、收线格式和写入清单、不能做的事（不答应放宽规则、不发娱乐时间、“这件事总控说了算”）。
2. **GPT 项目说明**：用于深度长文思考（写方案、大判断），结论同样按收线格式输出。
3. **每类话题卡的开场白模板**（晨会、拆事、接着昨天、判断、学习口述、复盘、空档），在剪贴板路径里使用。
4. **试跑记录**：用 G0 的环境在 Gemini Live 里每类卡至少跑一次，记下哪里太软、太长、替用户想完了，改到满意。

## T1 话题卡

**目标**：总控每时每刻都知道“现在该聊什么”，用户永远不用自己想题目。

**位置**：`core/topic/`（纯逻辑，带单测）。

**做什么**：
1. 话题卡结构：类型、标题（≤ 50 字，能单独看懂，含时长和收线要求）、来源（哪件事 / 哪条收线）、建议时长、优先级、过期时间。
2. 七种类型和触发条件按蓝图第 4 节；输入是总控现有数据（行动、计划、断点、收件箱里的待决、昨晚收线、当前时段、前台应用状态）。
3. 挑选规则：同一时刻最多 3 张；同一件事一天最多出 2 次“拆事”；用户刚收线的话题 2 小时内不再出；晨会和复盘每天各一次。
4. 学习口述类：主线是考试或求职时，从用户导入的题库（总控低屏模式已有题库导入）里抽题，生成“口述 3 分钟”的卡。
5. 标题由代码按模板生成，不用模型；只有“拆事”和“判断”可以选择性调用总控的文字模型把问题问得更具体（失败就用模板）。

**验收**：单测覆盖每种类型的触发和不触发、挑选规则、过期、去重。给出 10 个典型的一天的模拟数据和每个时刻的话题卡输出，附在 PR 里供用户看。

## R1 唯一通路：推你去聊、验收收线

**目标**：偏离剧本又不回应时，只剩一条路：去和墨灵聊。

**先读**：一手 `codex/voice-partner-*` 分支 `yishou/docs/voice-partner.md` 的 T1、T2，以及 `yishou/app/src/main/java/com/yishou/app/partner/Partner.kt`；总控 `core/plan/Earn.kt`、`core/Engine.kt`、`app/system/Partner.kt`、`app/system/TakeoverRunner.kt`。

**做什么**：
1. 把一手 T1 的 `Presence`（在场统计）和 `Closing`（收线判定）搬进总控 `core/talk/`，带原有单测。
2. **去聊**：总控“墨灵”页和通知上的“去聊”按钮：把当前话题卡写进 Tasks（G1），剪贴板放开场白（G2 的模板），打开 Gemini（`com.google.android.apps.bard`；如 G0 证明有直达 Live 的入口就用它），没装就打开网页。
3. **在场**：会话期间统计 Gemini 在前台的时间；离开超过 2 分钟提醒一次；拦截名单里的 App 一律弹回；常驻通知显示还剩几分钟。
4. **验收**：收件箱（或剪贴板）里出现收线，并且在场时间 ≥ 话题时长的 70%，`Closing` 加文字模型判定有内容 → 算完成：+1 信用、按挣娱乐规则 +20 分钟、下一步建成行动。只有在场没有收线 → 算没完成。
5. **阶梯**：触发条件（主线过点没开始、空档里连续娱乐 ≥ 15 分钟、晨会 / 复盘时间到）→ 第 1 次：通知 + 朗读话题卡；15 分钟没反应 → 第 2 次：带二选一；再 15 分钟 → 娱乐 App 进严管（复用 `Engine` 的严管原因，新增原因“该聊了”），通知只有“去聊”一个按钮；完成收线即解除。睡觉时段、专注计时中不触发。
6. 现有 `app/system/Partner.kt`（解锁就问）改成：解锁时如果有到期的话题卡，就朗读那张卡，不再另外问。

**验收**：模拟器端到端：主线过点 → 两次提醒 → 严管 → 去聊 → 中途切抖音被弹回 → 收线写入 → 严管解除、行动建好。真机跑 7 天，按 README 第 9 节第 3 步验收。

## K1 减法

**做什么**：
1. 总控底栏改成三页：**今天**（墨灵此刻的话、现在这一步、今天的票和支出）、**墨灵**（话题卡、收件箱、去聊、与总控参谋的文字对话）、**我**（设置、权限、实验室入口）。
2. 四部页面、脉络、战役、预案、大统筹 / 大谋划、计划模式、多余的宠物形象、新增动效画廊收进“我 → 实验室”，默认隐藏。代码不删，相关后台任务在隐藏时停掉。
3. 总控时间的六个环节换成“复盘”话题卡流程：手机仍然只留白名单，中间是“去聊”和收线；没接 Gemini 时保留现在的简化版作为备用。晨间部署向导换成“晨会”话题卡。
4. 总控对一手的依赖改成可选：一手没装时，“一手训练”关卡自动停用，不报错；首页不再显示一手相关内容。
5. 写一页“从一手迁移”说明：一手里还有用的数据（当前任务、断点、题库）怎么导出、导进总控。

**验收**：打开总控只看到三页；卸载一手后总控一切正常；实验室里的功能打开后仍能用。
