# 她的心智：记忆和十二种能力

> 配合 [`README.md`](README.md)（第三版）使用。README 讲“导演、演员、接力棒、小窗”怎么配合，这份讲**导演这个人**：她怎么记事、怎么看、怎么想。
> 写给 DeepSeek：这里是能力地图，不是施工顺序。每种能力都写了“现在有什么”和“第一步”，按你的判断挑着做。

---

## 0. 为什么要把她当成一个人来设计

没有记忆，Gemini 和 GPT 每次都是陌生人；有了记忆却没有判断，她只是一个档案柜。一个靠得住的人，是好几种能力一起在工作：看得见、记得住、想得远、判断得准、说话得体、会反思。

前几版只做了其中几样（眼睛、手、规矩），所以总控像一个规则很硬、但不懂人的管家。这份文档把一个人的能力列全，每一样都落到具体的数据和机制上。

## 1. 记忆：大脑总得有个存储

### 1.1 一个原则：一个本体，几面镜子

- **本体在总控里**（手机本地数据库）。总控一直开着、有事件、有规矩，所以记忆的主人是总控。
- **镜子给演员看**：GPT 看 Notion，Gemini 看小窗开场白和 Google Tasks / 日历。镜子是副本，可以过时，但不能和本体打架。
- **演员只能往“收件箱”里写**。GPT 写进 Notion 收件箱，Gemini 通过小窗收线或写进 Tasks 收件箱。导演检查过才把内容收进本体。这条沿用谋划思考部仓库的原则：**记忆不是事实**，AI 的记忆和总结只是线索。

```text
                   ┌─────────────── 本体：总控本地记忆 ───────────────┐
                   │ 工作记忆 · 日记 · 画像 · 约定 · 打法 · 元记忆          │
                   └──────┬──────────────────┬──────────────────┬──┘
                    镜像 ↓ ↑ 收件箱       镜像 ↓ ↑ 收件箱        ↓ 开场白
                  ┌───────┴──────┐     ┌──────┴────────┐   ┌───┴────────┐
                  │ Notion        │     │ Google Tasks  │   │ 小窗        │
                  │ （GPT 读写）    │     │ / 日历 / 文档   │   │ （每次开场） │
                  └───────┬──────┘     │ （Gemini 读写） │   └───┬────────┘
                          │            └──────┬────────┘       │
                        ChatGPT            Gemini（文字）     Gemini Live
```

### 1.2 七种记忆（照着人脑分）

| 记忆 | 人脑里是什么 | 她这里存什么 | 存多久 | 现在有什么 |
|---|---|---|---|---|
| **感觉记忆** | 刚看到听到的 | 原始事件：前台应用、亮屏、付款通知、小窗按钮 | 3–7 天 | 总控时间线、眼睛日志 |
| **工作记忆** | 正在想的事 | “此刻”：局面 + 接力棒 + 议程第一项 | 随时覆盖 | 总控首页“现在这一步”、一手断点 |
| **情景记忆** | 发生过的事 | 每次会话、每天的经过，用一段话记录：发生了什么、我说了什么、结果如何（就是“她的日记”加会话记录） | 长期，旧的压缩 | 总控记录、外接谋划单、一手每晚总结 |
| **语义记忆** | 知道的事实 | 对我的了解：目标、偏好、作息、模式（“晚饭后最容易刷视频”“申论归纳题常卡”） | 长期，可修正 | 总控“它记住的事”、档案 |
| **前瞻记忆** | 答应过、要去做的 | 约定、到期的事、要回访的事 | 到期为止 | 总控约定和回访 |
| **程序记忆** | 会做的事 | 打法：什么情况用什么方式说、什么管用（第一版 5.8 的“打法本”） | 长期，按效果调整 | 总控规则（写死的） |
| **元记忆** | 知道自己知道什么 | 每条记忆的来源、把握、最后确认时间；眼睛现在能看见多少 | 跟着记忆走 | 无障碍诊断（只有一部分） |

**每条记忆都带**：来源（总控记录 / 我说的 / GPT 说的 / Gemini 说的 / 导演推出来的）、把握（高 / 中 / 低）、最后确认时间、有没有被我认可。

### 1.3 睡觉时整理记忆

人在睡觉时整理白天的记忆，她也一样。每晚（复盘之后）导演做一次整理：

1. 把当天的感觉记忆压成一段日记（情景记忆）；
2. 从日记里找出重复出现的模式，提成语义记忆的候选，例如“这周第三次在 14 点后卡住”。出现一次只算线索，三次以上才升级成模式；
3. 发现新旧记忆矛盾时，标出来，第二天问我，而不是悄悄覆盖；
4. 很久没被用到、也没被确认的记忆降低把握，旧的情景记忆压缩成更短的摘要；
5. 更新 Notion 和 Google 那边的镜子。

### 1.4 演员怎么用记忆

| 演员 | 怎么读到记忆 | 怎么写回 | 要验证 |
|---|---|---|---|
| **ChatGPT** | 通过 Notion 官方连接器（Notion MCP）读“墨灵·此刻”页面和记忆库。也可以把说明放进 ChatGPT 项目 | 写进 Notion 的“墨灵·收件箱”库，总控已有的 Notion 同步（`core/work/Sync.kt`）拉回来 | 你的 ChatGPT 档位能不能用 Notion 连接器写入（资料说法不一） |
| **Gemini 文字对话** | 读一份 Google 文档“墨灵·此刻”（总控通过 Drive 接口每天更新） | 收线写进 Tasks 收件箱或靠小窗 | Gemini 能否读到最新版本的文档 |
| **Gemini Live** | 小窗开场白（最可靠）；或让它读 Tasks 里的“墨灵·此刻”清单 | 小窗收线（对着小窗说一句）；或让它写进 Tasks 收件箱 | README 第 10 节的 P3、P6 |
| **它们自己的记忆** | ChatGPT 的记忆、Gemini 的个人设置可以存几句固定人格 | — | 只当缓存，不当本体 |

Gemini 普通版目前不能直接连 Notion（只有企业版有 Notion 连接器；Connected Apps 里加自定义 MCP 的做法只有第三方资料，没有官方说明）。所以 **Notion 给 GPT，Google 那边给 Gemini**，两边都由总控同步，不用 GPT 来回传话。

### 1.5 Notion 里放什么（够用就好）

总控已经能一键在 Notion 建库、双向同步。新增的只要四样：

| Notion 里 | 内容 | 谁写 |
|---|---|---|
| 页面“墨灵·此刻” | 工作记忆：局面、接力棒、议程前三项、昨天的日记。总控有变化时刷新 | 总控 |
| 库“墨灵·记忆” | 语义记忆和约定，每条带类型、把握、来源、是否已确认 | 总控（整理后写入） |
| 库“墨灵·日记” | 每天一条情景记忆，加重要会话的记录 | 总控 |
| 库“墨灵·收件箱” | GPT 写进来的结论、判断、新任务 | GPT，总控读走后标记已处理 |

原有的事项、行动、记录三个库继续用。

## 2. 十二种能力

| # | 能力 | 她要做到什么 | 现在有什么 | 第一步 |
|---|---|---|---|---|
| 1 | **感知** | 知道发生了什么：手机、电脑、钱、地点、小窗回应 | 总控眼睛（前台应用、截图、照片、账单）、电脑版 | 把所有感知统一成带时间、来源、质量的事件；记下哪段时间是看不见的 |
| 2 | **注意** | 在一堆事里只挑一件说 | 四个各管各的主动运行器 | 议程：一条队，一次一件（README 5.3） |
| 3 | **记忆** | 见第 1 节 | 分散在总控、一手、Notion | 先做工作记忆（此刻）和日记 |
| 4 | **理解** | 把事件读成“这个人现在大概在干什么” | 无 | 局面 + 假设账本（README 5.1–5.2）；看不清就点选问 |
| 5 | **眼界** | 不只看眼前这一刻（见第 3 节） | 总控有长期目标（远方）、周计划 | 每次判断前看一眼三个尺度：今天、本周、长期 |
| 6 | **推演** | 提前想到会在哪卡住，想到“如果……会怎样” | 一手预判本、总控预案 | 今日预演 + 晚上对账（README 5.4） |
| 7 | **决断** | 在几个方案里选一个，并说清代价；知道什么时候该停止讨论、开始做 | 无 | 谋划类会话的收线必须有“选了哪个、放弃了什么” |
| 8 | **表达** | 说话像同一个人；时机对、长短对、语气对 | 宪章、墨灵、朗读 | 人格卡 + 话术随模式变（README 第 7、14 节） |
| 9 | **共情** | 分得清累、烦、卡住、在逃避，回应不一样；记得我最近的状态 | 无 | 状态点选（累 / 烦 / 卡住 / 还行）进记忆，影响下一次怎么开口 |
| 10 | **行动** | 能改变现实：排程、开专注、控机、打开 App、派活 | 总控的手、参谋工具 | 所有动作走现有工具，导演只做决定 |
| 11 | **反思** | 知道自己哪里错了、系统哪里坏了，并且改 | 无障碍诊断 | 事故簿 + 每周一处试验（README 5.5） |
| 12 | **原则** | 有她自己的立场，不会被我一句“这次特殊”说动；也不越权 | 宪章、冷静期 | 不变；导演的所有决定先过宪章 |

另外有两种能力容易被忘掉：

- **自知**：她知道自己看得见多少、有多大把握、最近错了几次。说话时带上把握，比如“我猜（不太确定）……”。错得多的时候，她会主动少说话。
- **节律**：她也有自己的作息。睡觉时段安静；我刚说完话，她也安静一会儿；每天的打扰和花费有上限。一个随时都在说话的人，不会被当回事。

## 3. 眼界：判断要看得远、看得宽

你说的“判断的眼界”，拆成三个方向：

### 3.1 时间上：变焦

每次重要判断，导演都把同一件事放到三个尺度上看一眼：

| 尺度 | 问的问题 | 例子 |
|---|---|---|
| 此刻 | 现在这 30 分钟最该做什么？ | 申论第二题卡住，先聊 5 分钟 |
| 本周 | 这件事和本周要交的东西是什么关系？ | 这周要交两篇大作文，第二题不是关键，可以先跳过 |
| 长期 | 这件事还值不值得做？方向对不对？ | 如果求职和考试在抢时间，要不要重新排？ |

大多数时候只看“此刻”。但同一个卡点反复出现、或者某件事拖了一周，就要把镜头拉远。“这件事不值得继续”也是一个合格的判断。

### 3.2 视角上：几个参谋

导演做重要判断时，可以在内部让同一个文字模型分别站在几个角色上各说一句，再合起来：

- **教练**：怎么让他现在动起来？
- **军师**：从目标倒推，这一步对吗？有没有更省力的路？
- **对手**：这个判断哪里站不住？他可能根本不是在逃避。
- **朋友**：他是不是累了？今天是不是该放过他？

这几个角色只在内部商量，我只看到最后那一句。只有遇到大事（改计划、换方向、判断我是否在逃避）才这样做，平时不必，这样也省钱。

### 3.3 信息上：往外看

导演自己不上网，它的“外面”有三个来源：

1. **派给演员查**：开场白里让 Gemini 或 GPT 先查（例如本周时政、某岗位的要求），把查到的写进收线；
2. **我收进来的**：分享到总控的链接、截图、在 GPT 里聊出来的长文，进收集箱后由导演消化，挂到相关的事上；
3. **电脑上的情报员**（以后）：晚上让 Agent Bridge 派 Claude Code / Codex 整理材料包。

## 4. 这些能力怎么串成一次“思考”

导演被一个事件叫醒后，按一个人的思路走一遍。大多数步骤不花钱，只有真要开口时才调用模型：

```text
感知：发生了什么？（事件 + 我能看见多少）
  → 回忆：工作记忆、相关的日记和画像、有没有约定到期
  → 理解：我猜他在干什么？还可能是什么？（假设账本）
  → 眼界：放到今天 / 本周 / 长期看，这件事有多重要？
  → 注意：和议程里别的事比，现在该说这件吗？
  → 推演：说了会怎样，不说又会怎样？
  → 决断：说什么、用什么方式、多大力度（先过宪章）
  → 表达：用她的语气，一句话
  → 行动：小窗 / 通知 / 朗读 / 工具
  → 记住：结果如何 → 当晚整理 → 改打法
```

## 5. 给 DeepSeek 的建议顺序（可以改）

1. **工作记忆 + 日记**：先让“此刻”和“昨天发生了什么”存在总控里，开场白自动带上。马上能感觉到“她记得我”。
2. **Notion 镜子**：“墨灵·此刻”页面和“墨灵·收件箱”库，接上 GPT（先验证 Notion 连接器能不能写）。
3. **睡前整理**：日记 → 模式候选 → 矛盾待问。
4. **元记忆**：每条记忆带来源和把握，导演说话时带上把握。
5. **眼界和参谋**：只在大判断时用。
6. **共情点选**：状态进记忆，影响开口方式。

### 守住的底线（补充 README 第 9 节）

- 演员写进来的东西先进收件箱，导演检查过才收进记忆；关于我的重要结论（例如“他在逃避”“他不适合这个岗位”）要我确认才算数。
- 我可以查看、修改、删除任何一条记忆。
- 记忆只存在总控本地和我自己的 Notion、Google 账户里，不发给别的服务。
