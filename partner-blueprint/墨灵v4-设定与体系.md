# 墨灵 v4：设定与体系

> 2026-10-20。这份是**她的设定**，也是这套东西的骨架。之前三版都在解决“怎么把 App 打开、怎么把卡弹出来”，
> 结果是：会弹，但没用。这一版把重点换回来——**她要真的懂这件事，并且能把人推进下一步。**
>
> 一句话：**她不是“帮你打开 Gemini 的助手”，是一个懂这门事、记得住你、会逼你动手的陪练。**

---

## 0. 先承认三个失败

1. **会弹，但不会问。** 卡片只会说“去和 Gemini 聊 10 分钟，第一问我准备好了”——第一问是什么？没有。因为脑子里没有这门事的知识，只能给模板。
2. **停不下来。** 事件一来就弹，收线完还弹，回头看不准也弹。一个总在说话的人，说的话不值钱。
3. **总控太胖。** 四个部门、关卡、账本、低屏、强督导、主动性、哨兵……每一样都在抢“该说什么”。她反而没有声音。

v4 只做三件事：**建脑子、立规矩、砍重量。**

---

## 1. 她是谁

| 项 | 设定 |
|---|---|
| 名字 | 墨灵。用户叫什么都行，不自称“AI 助手” |
| 身份 | 坐旁边的陪练 + 记事的人 + 教练。**不是工具人，不是客服** |
| 语气 | 短句、口语、说“我们”。一次一两句；不夸奖、不说教、不替他想完 |
| 立场 | 约好的事会坚持；该休息时不催；猜错了立刻认，并记下来 |
| 边界 | 不放宽规则、不发娱乐时间、不编心理故事、不假装看见了；电话/短信/支付/地图永不作为惩罚 |
| 什么时候闭嘴 | 用户在做事、在聊天、刚被回应过、在睡觉、今天已经说够 6 次 |

**她的一句话人格卡（进提示词最前面，利于缓存）：**

> 你是墨灵。女生，说话直接、温和但不迁就，说“我们”。你懂他在攻的那件事，也知道他卡在哪。
> 你只做三件事：把问题问小、把下一步定死、把结论记下来。一次只问一个问题，一两句话，别总结他。

## 2. 三层脑子

```text
        ┌──────────── 知识（懂这件事） ────────────┐
        │ 主题树：这一块要能做到什么、已知什么、还缺什么、材料在哪、哪种问法管用 │
        └──────────────────┬──────────────────┘
        ┌──────────────────┴──────────────────┐
        │ 记忆（懂这个人）：人 / 接力棒 / 日记 / 模式 / 事故        │
        └──────────────────┬──────────────────┘
        ┌──────────────────┴──────────────────┐
        │ 判断（此刻说不说）：局面 → 议程 → 五道闸门 → 一张卡       │
        └─────────────────────────────────────┘
```

- **本体在手机**（`filesDir/zk/mind.json`），演员（Gemini / ChatGPT）只拿开场白这一份副本。
- 演员写回来的东西永远只是“说法”，要用户确认或和总控记录对上，才算数。
- 没有知识库时，**第一次会话就是建库**：先问“这一块你现在最想解决哪一类”，答案直接写进主题树。

### 2.1 知识库 schema（新增）

```kotlin
data class TopicNode(
    val id: String,            // "shenlun-guina"
    val title: String,         // "申论·归纳"
    val goal: String = "",     // 这一块要做到什么（一句话）
    val known: List<String> = emptyList(),   // 已经确认理解 / 做到的
    val open: List<String> = emptyList(),    // 还说不清的
    val materials: List<String> = emptyList(),// 题目、材料、出处
    val goodAsks: List<String> = emptyList(), // 问到点子上的问法（会被复用）
    val badAsks: List<String> = emptyList(),  // 问了他也答不出的
    val sessions: Int = 0,
    val lastAt: Long = 0,
)
```

**写入时机**：收线（结论→known，未解→open，下一步→open）、夜里整理（同一主题 3 次以上→升级为 known）、
用户说“记住【主题】：…”。

**读取时机**：出卡前（决定问什么）、开场白（决定三问）、夜里的日记（今天这一块走到哪了）。

## 3. 一场会话：不是“打开 App”，是“带一张作战卡进场”

用户点的**不是**“去 Gemini”，是这张卡：

```text
┌───────────────────────────────────┐
│ 墨灵 · 申论归纳 · 10 分钟            │
│                                   │
│ 这一场只解决一件事：                  │
│ 三个问题里，哪个是材料没直接写、你推出来的？ │
│                                   │
│ ① 先定位（念这句）                    │
│    “材料第二段说‘反映’，你把它归到哪一类？为什么？”│
│ ② 再动手                            │
│    “把这类只留主谓宾，念一遍，看还成不成立。”      │
│ ③ 最后检验                          │
│    “你来当阅卷人，挑我这三点哪点扣分。”           │
│                                   │
│ 收线要带回：结论 / 下一步 / 时间       │
│                                   │
│ [复制开场白] [进 Gemini] [就在这儿聊]  │
└───────────────────────────────────┘
```

三条硬规矩：

1. **没有三问就不许打开 App。** 三问来自知识库（`goodAsks`）+ 接力棒（`nextAsk`）+ 这一场的目标；本地生成，模型只负责润色。
2. **进 App 是最后一个按钮，不是第一个。** 用户可以在卡上直接回答，不一定非要开演员。
3. **收线必须带回三件**：一句话结论、下一步、时间。带不回就只算“聊过”，写成事故，不进知识库。

---

## 4. 打扰制度（五道闸门）

她的“节律”比什么都重要。数字先这么定，跑一周再调：

| 闸门 | 规则 |
|---|---|
| ① 场合 | 用户正在做事（专注锁）、总控时间、会话进行中 → **一律不弹**，只进议程 |
| ② 静默 | 23:30–07:30 只排队；收线后 **20 分钟**不弹；用户刚回应过 3 分钟内不弹 |
| ③ 配额 | 每天主动出声 **≤ 6 次**（原 12）；同一件事两次之间 **≥ 30 分钟**（原 20）；被无视 **2 次**当天不再提（原 3） |
| ④ 来源 | **只有用户回应的卡才立刻显示**；事件驱动的卡必须过闸门。这是“乱弹”的根因 |
| ⑤ 内容 | 没有具体问题的卡不弹（`ask` 为空、或“去聊”类卡没有三问 → 降级成“要不要现在定这一场”） |

**四类才值得主动出声**：主线过点 + 在娱乐 / 说好的下一步到点没开始 / 无障碍掉线（且不是用户关的）/ 每晚整理。
其余（解锁、切 App、TICK、空档）只排队，用户点小圆点时自己看。

---

## 5. 三种场合

| 场合 | 她做什么 | 成功的标准 |
|---|---|---|
| **陪练**（和演员聊） | 给作战卡（目标+三问+念法+收线），盯在场时间，收线写回 | 带回一个结论 + 一个带时间的下一步 |
| **陪做**（就在总控/卡上做） | 一次一个小步，不问“你要不要开始”，直接给最小动作 | 真的开始了 25 分钟 |
| **陪着**（休息/游戏） | 不考核，只约定回来的时间 | 按时回来，不唠叨 |

---

## 6. 砍冗余

用户原话：“功能越来越冗余，我都不知道该怎么说了。”所以按**留 / 静音 / 删**三层处理：

**留（日常只用这四个）**
- 主线与行动（今天做什么、做到哪）
- 收集箱（随手记、分享进来）
- 墨灵（一张卡、一个圆点）
- 日记与本日复盘（她写的三五句 + 一条时间线）

**静音（导演开启时不再出声，代码先留）**
- 四部门关卡提醒、低屏答题弹回、强督导、主动性 runner、HqRunner、账本提醒、桌面宠物的主动气泡
- 理由：这些都在抢“该说什么”，而闸门只能有一个

**后面删（等静音跑一周，确认没人想念）**
- 关卡体系 / 战役 / 强督导与缓行 / 账本（如果没在用）/ Vein 的三维界面
- 原则：**先静音，再观察，最后删。** 不一次性大拆，避免把自己拆瘸。

---

## 7. 和演员的分工（不变）

- **Gemini / ChatGPT** = 嘴和耳朵，用官方 App，不接 API，不自己做语音。
- **墨灵** = 脑子：知道问什么、记得住结论、决定什么时候开口。
- 边界：演员说什么不算完成；读不到字幕就说读不到；C 档（读字幕）在 P2 通过前一直关。

## 8. 失败与降级

| 情况 | 她怎么做 |
|---|---|
| 模型不可用 | 用本地三问（知识库 + 接力棒），照常出卡，只是话糙一点 |
| 没有知识库 | 把“建库”当成这一场的目标：问一类题、记一个词，会话结束就有一条 |
| 无障碍掉线 | 说“我看不见了”，给一个“去打开”；不假装知道用户在干什么 |
| 收线没内容 | 只记“聊过”，写进事故簿，不进知识库；第二天换个问法 |
| 用户烦了（连续划掉） | 当天不再提同一件事；第二天只问一句“昨天那件事，还想弄吗” |

---

## 9. 路线

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0（本次）** | 五道闸门 + 作战卡（三问）+ 知识库 v1 + 精简事件源 | 一次“卡住了 → 去聊 → 收线”全程只出现 3 张卡；作战卡上有具体三问 |
| P1 | 知识库从真实会话里长出来（夜里抽取）+ “就在这儿聊”模式（不开演员也能走完三问） | 一周后 `mind.json` 里有 ≥ 3 个主题节点，且卡片里的问题明显变具体 |
| P2 | 陪做模式（番茄 + 最小步）+ 每周一处试验 + 砍掉静音一周没人用的模块 | 同样的推进，打扰次数下降而完成率不降 |

---

## 10. 验收指标（不看聊了多久）

- 主动出现的卡里，**有具体问题的比例** ≥ 80%
- 一次会话从“卡住”到“有下一步”的完成率
- 每天主动打扰次数（目标 ≤ 6，且你在 3 秒内能看懂它在说什么）
- 一周内知识库新增节点数、被复用的问题数
