## 所有任务共同遵守

1. **一次只做一个任务**，从 `zongkong-0.9-upgrade` 拉新分支，分支名用任务编号（例：`brain-B1`）。
2. **先读**：蓝图 README、`zongkong/README.md`、`zongkong/DEVLOG.md` 最近三节、任务里点名的文件。读完列出不确定的地方，等用户回答再写代码。
3. **纯逻辑放 `core/`**，不碰 Android，必须有单测；Android 相关放 `app/`。
4. **铁律不能被模型绕过**：放宽进 24 小时冷静期、宪章不可改、信用规则不变。新代码里任何“模型说了就放宽”的路径都算 bug。
5. **不新增设置页面**，除非任务里写了；数字先放 `Config`，第一周后再调。
6. 做完在 `zongkong/DEVLOG.md` 新加一节：你提的 / 做了什么（为什么）/ 测试 / 还没做 / 要观察。写一份真机验收步骤放进 PR。
7. 不改动和任务无关的文件，不顺手重构。

## B0 包挂起硬锁（Shizuku）

**目标**：娱乐 App 在没有票的时候打不开，即使无障碍服务掉了。

**先读**：`app/guard/`（拦截名单、`AutoBlock.kt`）、`core/plan/Earn.kt`、`core/Engine.kt`、`app/system/Watchdog.kt`、权限页。

**做什么**：
1. 接入 Shizuku（官方库），在权限页加一项“硬锁（Shizuku）”：未安装 / 未运行 / 未授权 / 可用，给出开启步骤（Android 11+ 用无线调试启动）。
2. `core/control/HardLock.kt`（纯逻辑）：输入当前拦截名单、`Engine` 的状态（严管 / 有票 / 欠账 / 总控时间）、无障碍是否在线、永不挂起名单 → 输出“应挂起的包”集合。永不挂起名单写死：电话、短信、系统设置、总控、一手、支付宝、微信、地图类，加用户白名单。
3. `app/guard/Suspender.kt`：通过 Shizuku 以 shell 身份执行 `pm suspend` / `pm unsuspend`，和目标集合做差量。每次挂起写到期时间（最长 12 小时）。
4. **安全阀**：看门狗每分钟、开机广播、总控启动时，解开所有过期挂起；权限页“全部解开”按钮（记一笔，扣信用 5，走现有的紧急放行规则）。
5. 有票时解挂，票到期重新挂起；无障碍掉线时立即对娱乐名单全挂起。

**不做**：Device Owner；挂起非拦截名单里的 App；修改 vivo 的系统设置。

**验收**：单测覆盖目标集合计算（各种状态组合、永不挂起名单、过期解开）。真机：关掉无障碍 → 抖音打不开；花票 → 能开，到期又灰；杀掉总控进程 + 重启手机 → 过期的挂起被解开。

## B1 大脑内核（纯逻辑）

**目标**：墨灵的心跳循环，除了“叫模型”和“执行”以外的全部逻辑，可单测。

**先读**：`core/initiative/Initiative.kt`（风格照它写）、`core/boss/`（宪章、信用、态度）、`core/agent/Snapshot.kt`、`core/agent/Tools.kt` 的工具列表、`core/plan/Earn.kt`。

**新包 `core/brain/`**：
1. `Event.kt`：事件类型（见蓝图 5.1）+ 时间 + 载荷。
2. `Frame.kt`：从各 Store 的快照拼局面卡。字段顺序固定，输出 ≤ 30 行纯文本，另有结构化版本给代码用。
3. `Tactics.kt`：打法 = id、条件（对 Frame 和 Event 的简单条件组合，JSON 可序列化）、建议级别、话术模板、统计（触发次数、15 分钟内成功次数）。内置 10–15 条初始打法，覆盖：空档刷短视频、欠账、主线过点、连续娱乐、深夜用机、打开购物 App、支付页、长时间不回应、做完一步没交结果、一天没开口。
4. `Triage.kt`：事件 + 局面 → 分数、命中的打法、建议级别、要不要叫模型。接触额度：今天目标 N 次（随信用变），欠得越多、时段越晚，分数越高。
5. `Decision.kt`：模型返回结构（蓝图 3.2）的解析，容错（字段缺失、多余文字）；解析失败时 `Fallback.decide()` 用命中打法的话术和阶梯出本机决定。
6. `Ladder.kt`：每个“话题”（打法 id + 当天）一个阶梯状态：被无视或拒绝 +1 级，回应或做了 −1 级；同话题两次升级之间的最短间隔。
7. `BrainGuard.kt`：铁律过滤：放宽类工具进冷静期；级别不超过信用允许的上限（信任 ≤ 3、正常 ≤ 4、审慎和严格 ≤ 5）；睡觉时段只记不说；每天打扰上限；总控时间和专注计时里只允许 0 级。
8. `Outcome.kt`：结果记录结构和“成功”的判定（15 分钟内离开娱乐、开始了行动、回了有内容的话）。

**不做**：网络请求、Android 代码、UI。

**验收**：单测 ≥ 60 例，覆盖每条初始打法的触发与不触发、阶梯升降、额度、铁律截断、解析容错和兜底。

## B2 事件源与大脑运行器

**目标**：让 B1 在手机上真正跑起来，墨灵开始不等你开口就找你。

**先读**：B1 全部代码、`app/guard/GuardService.kt`、`app/system/`（`Partner.kt`、`InitiativeRunner`、`HqRunner`、`TakeoverRunner`、`Watchdog`、`Pet.kt`）、`app/data/Chat.kt`、`core/agent/Agent.kt`。

**做什么**：
1. 事件源：解锁（`ACTION_USER_PRESENT`）、前台切换（从 `GuardService` 转发，带页面类名）、连续娱乐达阈值、计划到点 / 欠账产生（从 `Engine`）、空档开始、30 分钟兜底定时。
2. `app/system/BrainRunner.kt`：事件 → `Frame` → `Triage` → 需要时叫模型（复用参谋的接口配置和 `Chat.kt`；系统提示词用 B3 的，先放占位）→ `Decision` → `BrainGuard` → 执行 → 记 `Outcome`。同一时间只跑一个决定，事件排队合并。
3. 执行通道：通知（带点选按钮和“回复”）、墨灵气泡、朗读（亮屏或戴耳机且不在静默时段）、全屏题卡（复用 `GateActivity`，支持简答，判定复用一手式提示词）。
4. 工具执行复用 `agent/Tools.kt`，不新写一套。
5. **收编现有的主动逻辑**，旧路径关掉，避免几边同时弹：`app/system/Partner.kt`（解锁就问）、`InitiativeRunner`（收集箱催促）、`HqRunner.auto`（三个部门自动跑）都改写成打法，由大脑统一调度；`TakeoverRunner`（强督导接管）保留，作为第 5 级的执行器，由大脑决定什么时候触发。
6. 调试页（我 → 墨灵的大脑）：今天的事件、分诊分数、决定、结果，可导出。这是唯一新增的页面。

**验收**：模拟器端到端：一天不操作 → 墨灵按阶梯升级到简答题卡；空档刷短视频 → 第 1 级到第 3 级；回应后降级。真机跑 7 天，用调试页导出的数据对照蓝图第 8 节阶段 1 的验收标准。

## B3 大脑提示词与试跑集（DeepSeek）

**目标**：墨灵说话像一个盯着你的战友，不像客服；决定稳定、短、不软。

**做什么**：
1. 写大脑系统提示词：宪章（照 `core/boss/Charter.kt` 原文放最前面）→ 墨灵人格（战友、说“我们”、一次一两句、不夸、不说教、数字摆出来）→ 决定的输出格式 → 阶梯和题型规则（低风险点选、高风险简答）。固定部分放前面，方便缓存。
2. 造 40 张试跑局面卡（照 B1 的 `Frame` 格式）：覆盖早上、空档、欠账、深夜、购物、刚做完一步、一天没开口、信用很低、用户在找借口等。
3. 每张卡写“合格的决定”和“不合格的例子”（太软、太长、替用户想完、越权放宽）。
4. 用 deepseek 实际跑，统计格式错误率、平均字数、越权次数，改到格式错误 < 3%、越权 0 次。

**交付**：`zongkong/app/src/main/assets/brain/system.md`、`frames.jsonl`、一个跑分脚本和结果记录。

## B4 消费守门

**目标**：买饭买菜不拦，折扣零食和冲动下单要过一道，花了的钱自动进账本。

**先读**：`core/ledger/Ledger.kt`、`app/ui/LedgerScreen.kt`、`app/guard/`、蓝图 5.4。

**做什么**：
1. `app/spend/PayNotifyListener.kt`（NotificationListenerService）：识别支付宝、微信支付、常见银行的“支付成功 / 付款 ¥x / 商户名”通知，写进账本（`source = 通知`），按通知时间 + 金额 + 商户去重，和 CSV 导入的记录也去重。
2. `core/spend/Classify.kt`：先用词表（C2）按商户名 / 商品名分类：正餐、食材、零食饮料、其他；词表没命中的晚上批量交模型分，再不行进“待你确认”。
3. `core/spend/SpendRules.kt`：每周零食预算、每天份数上限、饭点时段、购物 App 名单；超标状态；收紧立即生效、放宽 24 小时。
4. 购物 App 守门：非饭点或已超标时，打开名单里的购物 App 先弹简答“这次买什么？”（复用 `GateActivity`）；超标后进“采购单”模式：写清要买什么才放行 10 分钟。
5. 支付页一问：`GuardService` 已收到窗口切换事件，把事件的 `className` 记下来。先做一个“页面记录模式”（设置里开，记一周包名 + 类名），用户在支付宝 / 微信付款码和收银台时点一下“这是支付页”，生成本机的支付页表。命中表时弹 5 秒卡：饭菜 / 零食 / 其他。
6. 晚间清单（`core/plan/DayReport.kt`）加一行零食：份数、金额、本周剩余预算。
7. B2 完成后，支付通知和支付页作为事件进大脑。

**不做**：读取支付页里的屏幕内容；拦截支付本身；地理围栏（单独评估后再做）。

**验收**：单测：通知文本解析（准备 20 条真实样式的样本）、去重、分类、预算状态。真机：扫码付一笔 → 账本自动多一条；非饭点打开闲鱼 → 先答题；超预算后 → 采购单模式。

## B5 外脑会话 `handoff`

**目标**：墨灵能把你推去 GPT / Gemini 深聊，看着你待够时间，回来验收收线。

**先读**：一手 `codex/voice-partner-*` 分支的 `yishou/docs/voice-partner.md` 的 T1、T2，`yishou/app/src/main/java/com/yishou/app/partner/Partner.kt`；总控 `core/plan/Directive.kt`。

**做什么**：
1. 把一手 T1 的 `Opening`、`Presence`、`Closing` 搬进总控 `core/brain/handoff/`（纯逻辑，带原有单测）。
2. 新工具 `handoff(target, topic, minutes, must_answer[])`：模型写谈话单 → 拼开场白 → 复制 → 打开 ChatGPT（`com.openai.chatgpt`）或 Gemini（`com.google.android.apps.bard`），没装开网页。
3. 会话期间：前台统计；离开目标 App 超过 2 分钟提醒；拦截名单里的 App 一律弹回；常驻通知显示剩余时间。
4. 收线页：一句结论 + 下一步，`Closing.ok` 加模型判定；结论写进外接谋划单，下一步建成行动。
5. 没收线：下次解锁先问；阶梯不降级。
6. 介入阶梯第 4 级默认用它。

**验收**：单测沿用 T1；模拟器端到端：大脑出 handoff → 打开目标 App → 中途切抖音被弹回 → 回来收线 → 外接谋划单多一条、行动多一条。

## B6 语音 V1：连续对话

**目标**：对讲页从“按住说话”变成“说完自动再听”的连续对话，墨灵用一个声音说话。

**先读**：总控对讲页和语音设置；一手 `voice/PartnerApis.kt`（T4）、`partner/` 导演卡（T3）；伴随 `companion-voice-assistant/app/src/main/java/` 里的 `AssistantService`（循环、前台服务、三次没听到暂停）。

**做什么**：
1. 等一手 T4 合并后，把 `voice/` 适配器整包搬进总控（STT / 文字 / 图片 / TTS 四套独立配置）。
2. 对讲循环：听 → 听写 → 文字模型流式 → 按句朗读（第一句先念）→ 再听；点按打断（停播、取消旧请求）；三次没听到暂停；麦克风前台服务，有通知和停止按钮。
3. 对话内容和大脑共用记忆：用户在对讲里说的话进档案；对讲里也能调用参谋的工具。
4. 导演卡（一手 T3）用在“伴读 / 陪练”模式里。

**不做**：唤醒词、全双工、实时音频模型。

**验收**：真机测一次 10 分钟连续对话：记录每轮从说完到听到第一句的时间、打断是否生效、误触发次数。

## B7 墨灵桌面与空档菜单

**目标**：按 Home 回到的是墨灵；空档有人管。

**做什么**：
1. 新 `HomeActivity`（HOME / DEFAULT 类别）：最上面墨灵此刻的一句话（大脑最近一次决定或固定问候）、现在这一步、今天的娱乐票和零食额度；下面白名单 App 网格；娱乐 App 标“要票”，点了走票逻辑。
2. 权限页加“设为默认桌面”引导；检测默认桌面被换掉时记一笔，第二天墨灵问。
3. 空档识别（B2 已有事件）→ 空档菜单：一手陪练 / 外脑讲一件事 / 语音伴读 / 运动 / 正式休息（定时）/ 自由娱乐（花票）。“正式休息”有闹钟和结束动作，闹钟后不动作 → 阶梯上一级。
4. 晨间部署加一步：“今天的空档准备干嘛？”预选 1–2 样。

**验收**：真机：设为默认桌面，按 Home 回墨灵；空档时解锁出现菜单；选“休息 20 分” → 20 分后震动，不动作 → 第 2 级开口。

## B8 打法本反思、预言账本、用户画像

**目标**：墨灵根据你的行为改自己的打法，并且能说出“我预测对了几次”。

**依赖**：B1、B2 在真机跑满一周，有真实的事件和结果数据。

**做什么**：
1. 晚上反思：总控时间前，把当天的事件、决定、结果、打法统计交给模型，返回“新增 / 修改 / 退役”打法提议（结构化）。代码判断收紧还是放宽：收紧直接生效，放宽进冷静期；每天最多改 3 条。
2. 周报：周日生成一页打法报告（哪条最管用、哪条退役、为什么）。
3. 预言账本 `core/brain/Predict.kt`：早上生成 2–3 条可自动对账的预言（只允许能从记录里算出来的：某时段娱乐时长、某件事几点开始、零食份数），晚上对账，算命中率和校准度；高把握预言触发提前介入。
4. 用户画像：每周压缩 ≤ 15 行，放进局面卡固定部分。

**验收**：单测：提议的收紧 / 放宽分类、每日上限、预言对账。真机两周后：打法本有自动改动记录；预言命中率在调试页可见。

## B9 一手训练引擎并入总控

**目标**：一个 App。

**做什么**：把一手的一轮引擎（`round/`）、判定提示词（`llm/Prompts.kt`）、断点、六骰子（`llm/Faces.kt`）、间隔回响（`recall/`）、分组训练（`training/`）搬进总控 `train/`；数据迁移工具（从一手导出 → 总控导入）；总控里的“一手训练”关卡改读本地数据；一手 App 保留到用户确认迁移完成。

**验收**：迁移后一手的任务、断点、棋谱、回响队列都在总控里；守门题、陪练窗口在总控里能用；卸载一手后总控所有功能正常。

## C1–C3 内容任务（DeepSeek）
