# 思考接续（thought_relay）v0.1 设计说明

> 一句话目标：开发一个可保存和恢复当前思考现场的交互工具，每轮只推进一个判断，让上一轮结果进入下一轮；支持卡住时分级提示、中断后返回，并记录帮助程度。先验证它能维持真实任务中的思考接续，再扩展推理训练和多模型协作。

第一阶段只证明三件事：

1. 同一个真实问题，能完成几个**相连**的回合；
2. 中断后能**接回原位置**；
3. 能区分哪些步骤是**独立完成**的，哪些是靠提示完成的。

不在 v1 范围：答得轻松就自动加难、“再想一个/比较/归类”式训练、Gemini/ima/强模型复盘接入。后面再接，接的时候也共用同一份现场。

---

## 1. 当前思考卡

界面始终只显示这一小块，历史链条留在后台：

```
【思考卡】
正在想：这个岗位要不要投？
刚才到：职责里的数据整理我实习做过（依据：实习时每周整理销售数据）［独立］
接下来：经验要求一年，我的两段实习能不能算？
暂存区：1 条 · 最新「查一下这家公司的评价」
判断：暂时考虑投，因为职责符合｜待确认：经验要求
```

| 行 | 含义 | 规则 |
|---|---|---|
| 正在想 | 只保留一个问题 | 换题必须用户明确同意，旧题暂停保留 |
| 刚才到 | 已说出的最后一条事实或推论 + 依据 | 保存支撑条件，不只保存结论 |
| 接下来 | 一个具体、能回答的小问题 | 必须用到上一步的结果；只含一个问题 |
| 暂存区 | 冒出的其他念头、待查资料 | 放下它们，继续当前问题 |
| 判断（可选） | 暂时判断 + 待确认条件 | 回来时能接着分析，而不是只剩“可以投” |

v1 没有独立面板：卡片由插件生成，主持角色**每次回复都把卡片放在最前面**。等这个流程跑通，再考虑升级成 ToolPkg 做常驻面板（需要 Compose DSL / 聊天 Hook，属于 API 1.0.1）。

## 2. 每轮只推进一个动作

动作只有四种（`kind`）：

| kind | 动作 |
|---|---|
| `fact` | 补一个事实 |
| `connect` | 连接两条信息 |
| `infer` | 推出一个结果 |
| `decide` | 决定下一项核实什么 |

卡住时逐级帮助，记录本步用到的**最高**一级（`help`）：

| help | 帮助 | 说明 |
|---|---|---|
| 0 | 独立 | 用户自己答出 |
| 1 | 提醒相关信息 | 指出材料或上一步里的某一条 |
| 2 | 给句子开头 | 例：“我那段实习里，有一项是……” |
| 3 | AI 示范 | AI 示范这一步，再让用户接下一步 |

卡住类型（`stuck`）和对应处理：

| stuck | 情况 | 处理 |
|---|---|---|
| `material` | 材料没读进去 | 缩短材料，请用户复述一个关键点 |
| `forgot` | 上一步忘了 | 重新显示上一步及其依据 |
| `connect` | 知道材料但不会连接 | 提示一种操作，再让用户尝试 |
| `absent` | 中途离开了 | 呈现返回点，先接原来那一步 |
| `refuse` | 没回应、明确不想做 | 保留现场，按约定时间返回；沉默只记“状态未知” |

## 3. 中断后的恢复

- **每一步都会落盘**，所以任何时候离开，返回点都在。主动暂停时用 `pause`，可以约定多少分钟后再提醒。
- 回来时用 `resume`，返回一句话：“刚才在想 X，你已经推到 Y。现在只需要接 Z。”
- 用户说“帮我恢复”时用 `resume(mode=help)`：用两三句重放最近几步、依据、材料和当前判断，再请用户确认一句或回答这一步。每次“帮我恢复”都计为一次恢复提示。
- 恢复后**继续原题**，不重新开题。`open_thread` 在已有进行中的题目时会拒绝，除非用户明确要换题。
- 提醒（`reminder_check`）一定带返回点；最近有活动不打扰；间隔可调；上一次提醒没有回应只记 `silence`（状态未知），不判定为走神。

## 4. 插件：`thought_relay`（普通 JS 包）

| 工具 | 用途 |
|---|---|
| `get_card` | 读当前思考卡；没有进行中的题目时列出最近未结束的题目（优先接回） |
| `open_thread` | 开题（question + 第一步 next + 可选材料） |
| `record_step` | 记下刚完成的一步（text/kind/help/next，可选 basis/judgement/pending/stuck） |
| `set_next` | 不记步骤，只把下一步换小、换说法 |
| `park` | 暂存区：添加，或标记某条已处理 |
| `pause` | 保存返回点，可约定返回时间 |
| `resume` | 回来：brief 只给返回点；help 重放必要信息 |
| `reminder_check` | 给定时工作流用：返回 REMIND（带返回点文本）或 SKIP |
| `stats` | 验收统计 |
| `close_thread` | 结题，列出暂存区剩余事项 |
| `main` | 自检：在独立目录走一遍完整流程，不碰正式数据 |

### 数据

```
/sdcard/Download/Operit/thought_relay/
  index.jsonl              # 题目激活/结束（追加）
  threads/<thread_id>.jsonl  # 每个题目的全部事件（追加）
```

- 只追加，不覆盖、不删除；状态由事件回放得到，没有会过期的快照文件。
- 事件类型：`open / step / reframe / park / park_done / pause / resume / recover_help / remind / silence / close`。
- 解析不了的行会跳过并计数（`stats` 里显示）。
- 自检数据在 `thought_relay_selftest_<时间戳>/`，可以删除。

## 5. 验收

| 要验证什么 | 看什么 | `stats` 里的字段 |
|---|---|---|
| 中断后能否接回来 | 是否接着原来的返回点继续 | `recoveries.count`，以及恢复后第一步是否沿用原题 |
| 恢复是否省力 | 恢复耗时、需要多少提示 | `recoveries.avg_min`、`avg_hints`、`without_hints` |
| 思考是否连续 | 一轮能完成多少个相连的步骤，独立与辅助分开记 | `segments.max/avg`、`help.*` |

锁机时长、聊天时长、记录条数**不**算作思考成绩，`stats` 不统计这些。

## 6. 分工

- **Operit**：负责触发和传递状态（插件、提醒工作流、送达通道）。
- **主对话**：主持角色卡负责显示思考卡和接续（见 `character_card.md`）。
- **锁机工具**：负责减少干扰，维持现状，v1 不改动。
- 提醒的工作流规格见 `reminder_workflow.md`。
- 烧录、启用、工作流创建和触发，都由设备侧 Operit AI 按它自己的规程完成。
