# Operit 主控系统：开始这里

最后更新：2026-10-06

## 完美结果（这个系统做到下面这些，就算成了）

每天早上不用你开口，主控先把今天的 2–4 个工作窗口摆到你面前。到点后它主动弹出来，告诉你这个窗口做什么、做到什么算完，然后问你第一个具体问题。你回答，它接住你的话再推一步；你说“我在想”，它不催你；你求助，它先帮你把事办了。中途断了，回来后它记得问到哪。窗口结束问三句，晚上自动写复盘，第二天的计划会参考昨天的复盘。

检验标准沿用《整合计划书》：连续 7 天，早计划自动出现；开场后 5 分钟内开工的比例 ≥ 60%；下一问能接上你的上一句；晚总结天天有；你每天花在维护系统上的时间 ≤ 5 分钟。

## 从结果往回推：只需要四个零件

| 零件 | 作用 | 怎么做 | 命令 |
|---|---|---|---|
| 共同局面文件 | 计划、当前问到哪、流水、复盘都存在这里，谁来都能读到同一份 | `/sdcard/Download/Operit/core/` 下几个文本文件 | 命令 1 |
| 主控角色（合伙人） | 平级搭档：排计划、拆成 15 分钟小步、点名、追问、核对成果、记押金账，全部在一个对话里完成；小满回去当朋友 | 一张角色卡和一个专用对话 | 命令 1 |
| 节拍 | 到点叫醒主控；没事不花模型额度 | `tick.sh` 只做时间判断，加一条每 5 分钟运行的工作流 | 命令 2 |
| 对话规矩 | 每句话先分清是回答、状态、求助、新想法、提交还是改计划，再处理 | 写在角色卡里，由主控用文件工具读写 | 命令 3 验证 |

为什么这样设计能成：

1. 只用手机上已经证明可靠的通道：文件工具、terminal 节点，以及陪伴打卡那种能弹出来的通道。“聊天里直接调用包工具”会卡住 3 分钟，这里完全不用。
2. 连续思考只放在一个对话里。主控每说一句话前都先读 thread.json，所以无论是节拍叫醒它，还是你主动找它，它都知道问到哪了。
3. 节拍脚本不依赖 Shizuku，也不依赖时区数据库。它在电脑上模拟过一整天，26 项检查全部通过（`kit/scripts/test_tick.sh`）。

## 每一步要回答的问题

| 步骤 | 必须回答的问题 | 判定 |
|---|---|---|
| 命令 1 底座 | 主控能读写 core 里的文件吗？tick.sh 在手机上能跑吗？ | 自检时主控说出了文件内容；tick.sh 输出了一行 NEED=… |
| 命令 2 节拍 | 手动触发后，主控对话真的弹到了你眼前吗？ | 由你本人确认“看到了” |
| 命令 3 试一轮 | 你回答后，它是接着你的话往下问，还是在复读？“我在想”会被当成答案吗？沉默后它会换个问法吗？ | 看 log 里的 kind 和主控原话 |
| 命令 4 跑一天 | 早计划、开场、追问、三问、晚总结，各自有没有按时发生？ | 看 tick.log、log 和 summary |

哪一步没过，就把 Operit 的回报原样发给我，我直接改套件，不再重新讨论方案。

## 分工

- **Operit AI**：在手机上搭建和核对，执行 `commands/给Operit的命令_免下载版.md` 里的命令。
- **我（Claude）**：维护这套套件；核对 Operit 交回来的结果；出问题时改脚本、角色卡和工作流说明。
- **GPT**：只当执行者，不做规划。比如 Operit 建工作流时 JSON 报错，就把报错和 `kit/workflows/主控节拍.md` 一起发给它，让它只改出能用的 JSON。

## 这一版不做的

- **锁机**：按《整合计划书》的口径不放进本系统，这一版不碰。手机上现有的锁机相关工作流也不动，是否停用由你决定。
- **语音球、跨 App 联动、电脑、ima**：等“开场 → 回答 → 追问 → 复盘”这条主线跑通 7 天以后再接。
- **30 条旧工作流的清理**：先不管。只有出现“两边重复弹窗”这种直接干扰时，才调整对应的那一条（见命令 4 第 3 步）。
