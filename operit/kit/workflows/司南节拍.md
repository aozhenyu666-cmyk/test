# 工作流：司南节拍

整个系统只有这一条新工作流：每 5 分钟跑一次节拍脚本。脚本说“有事”时，才叫醒司南并把她的对话弹出来；没事时不调用模型，不花额度。

## 怎么建

不要手工搭。用官方接口脚本 `core/scripts/create_workflow.js` 一次建好：
- 运行方式：用 `operit_editor:debug_run_sandbox_script`，把 `source_path` 设为这个脚本的路径。
- 如果已经有同名工作流，脚本会直接更新它，不会重复新建。

脚本按 Operit 官方 `Tools.Workflow` 类型定义编写（AAswordman/Operit 1.12.2）：

| 节点 | 类型 | 内容 |
|---|---|---|
| t_tick | 定时触发 | interval，300000 毫秒 |
| t_manual | 手动触发 | 测试用 |
| e_tick | `super_admin:terminal` | `command = sh /sdcard/Download/Operit/core/scripts/tick.sh` |
| c_go | 条件 | `left = {nodeId:"e_tick"}`，`operator = CONTAINS`，`right = "NEED=go"` |
| e_ai | `extended_chat:chat_with_agent` | `message` = 节拍提示，`character_card_name = 司南`，`chat_id` = 司南对话，`timeout = 180`，`notify_reply = true`（她回复时通知你），`hide_user_message = true`（不显示节拍提示这条机器消息） |
| e_pop | `focus_hub_nav:open_chat` | 把司南对话弹到前台 |

连线：
- t_tick → e_tick
- t_manual → e_tick
- e_tick → c_go（on_success）
- c_go → e_ai（true）
- e_ai → e_pop（on_success）

## 说明

- 节拍脚本走 terminal 通道，不依赖 Shizuku。
- 如果 open_chat 弹不出来，把 e_pop 换成 `focus_hub_nav:check_in`，参数为 message=“司南有新消息”、popup=true、speak=true。
