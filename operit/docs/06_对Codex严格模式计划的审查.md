# 对 Codex《严格模式整批部署计划》的审查（2026-10-06）

结论：安全底线写得对，但整体方向和现在的主控台 0.9 冲突。照这个计划做，会再次出现两个大脑、三只锁的手，而且一开始就会卡在 Shizuku 上。

## 保留的部分
- 未知状态不盲目重发；只解除自己加的锁；保留紧急停止入口。
- 不把 Shell 返回成功或 nohup PID 存在当作"已锁住"或"已解除"的证据。
- 先拿非关键 App 做一次短时测试；可行性结论 48 小时内收束。
- 现阶段不启用 provider；不把配置名改成 strict 就当作已启用。

## 自相矛盾或与现状冲突的地方
1. **两个大脑**。计划让后台做严格回合、密集承接、离开和回来、有限伴读，Claude 只做"对话台"。可是主控台 0.9 里的司南已经在做这些：直接调用模型，分追问、陪读、冲刺、复盘四种模式，主动叫回。后台再做一遍，就回到"几套东西并行、互不衔接"的老问题。
2. **"唯一执行者"其实会变成第三只手**。手机上已经有两只手在锁 App：S4_Lock_Queue_Worker，以及 P4_Event_Sampler 里的 incidentd 支线（工作流说明书 S-1）。control_plane 再加一个执行器，就是三只。
3. **执行器依赖的 Shizuku 现在没在运行**。A-026 卡在预检：`Shizuku binder is null`。工作流说明书的 F-01 也记录了，Shizuku 断线是全系统第一大失败来源：42 个 shell 节点都依赖它。计划里的 48 小时会先卡在这里，而不是卡在代码上。
4. **重启后可能留下解不开的锁**。`pm suspend` 的状态重启后仍然保留，但预先挂好的延时解除进程重启后就没了。计划自己也写了 app_suspender 是 `best_effort_until_reboot`。所以必须做到两点：
   - 任何一拍发现过期的锁，就补做解除；
   - Shizuku 不健康时根本不加锁。

   这两点计划里只写了"恢复依据待测"，没有给出做法。
5. **3 分钟的思考回合**和工作流最短 15 分钟的间隔冲突。要做到 3 分钟，只能每分钟重挂一次单次工作流，代价高；它还和主控台的「专注推进」同时说话，回到两个声音。计划自己写的"不持续轰炸"也和它冲突。
6. **对话门不需要后台再做一遍**。原版三问、判定、每天 2 把、冷却规则已经在主控台的 `gate_logic.js` 里实现，并且有测试。后台那套返回 `spec_required` 的 gate 工具可以删掉。
7. **批次 1 要装 C-1.1，但没说装完后谁说话**。后台的 live 调度会自己念 TTS、弹出认知主控台，和司南抢话。如果要装，它的主动联系（contact 和 live）必须保持关闭。

## 建议给 Codex 的新范围（C-2：只做执行器）
主控台负责"什么时候锁、给不给钥匙"；Codex 只负责"可靠地锁上、到点可靠地解开"。做成一个独立子包，提供六个工具：

| 工具 | 作用 |
|---|---|
| `strict_health()` | Shizuku 是否可用、`pm` 和 `dumpsys` 能否执行、账本能否写 |
| `strict_lock(pkg, until_ts, key_id?)` | 健康检查不过就拒绝。先写账本，再挂好到点解除，读回确认后才执行 suspend，最后用 dumpsys 读回 |
| `strict_release(pkg)` | 只解除账本里自己加的锁 |
| `strict_recover()` | 任何一拍都可以调用：把账本里已过期但仍处于 suspended 的 App 补解；读不到状态就记为 unknown，不重发 |
| `strict_status()` | 账本加上 dumpsys 实际状态 |
| `strict_emergency_release_all()` | 紧急解除自己加的全部锁 |

要求：
- 用模拟 shell 测试三点：先挂解除、后冻结的顺序；挂解除失败时不冻结；重启后能补解。
- 这个子包不新建对话、不说话、不调度。

调用方：主控台。
- 专注时段开始时，默认锁住名单里的 App；
- 签发钥匙时临时放开 N 分钟，到点再锁回；
- 时段结束时全部解除；
- 每 15 分钟的专注推进和每次打开主控台，都先调用 `strict_recover()`。

## 需要用户拍板
1. 专注时段里，只让新执行器碰 B站、抖音、贴吧、小红书；S4 和 incidentd 在时段内对这四个 App 让路。
2. Shizuku 怎样保活：手机重启后用户怎么重新开它、多久开一次。这决定严格模式能有多"硬"。
