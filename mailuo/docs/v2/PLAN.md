# 脉络 V2.0：「问 · 论 · 规」极简闭环

> **状态（v0.2.0）**：T00–T08 已全部完成并合并；T09（与一手 / 总控联动）暂缓。

> 原则：**后台重推演，前台轻交互。** 不增加节点类型、不要求手动维护多层表格。AI 在「录入 → 候选」阶段替你起草所有推演槽位，你只做批阅：确认 / 微调 / 驳回。

## 1. 为什么改

v0.1 把笔记拆成「体系 → 层级 → 节点 → 关系」，只能列出关键词和静态卡片，有两个问题：

- **只会切碎，不会撞击**：新材料总是变成新卡片，不会回头修正已有判断的把握度。
- **结构太重**：层级文件夹 + 5 种类型 + 7 种关系，日常维护成本高，和「系统全量与实操表现脱节」「总控交互频次不足」两个痛点正好相反。

V2 的终局形态是首席参谋，有 3 个本能：

1. **动态修正**：新信息先撞击旧体系。命中某条论的验证哨，就提议上调或下调它的把握度，必要时暂停它下面的规。
2. **对抗推演**：你只说直觉判断，AI 补齐支柱、反方盲区、验证哨、触发场景、破戒代价。
3. **实战供弹**：规带着触发场景推给「一手」，执行反馈回流过来，修正上游论的把握度。这条是 T09 的内容，暂缓。

## 2. 数据结构（已由 T00 实现，见 `www/js/model.js`）

只有三种节点：

- `问`：痛点 / 课题
- `论`：诊断 / 假设，带把握 %
- `规`：行动 / 铁律，带把握 %

节点之间用 `under`（挂在谁下面）组成链条：

```
问 为什么想到一半就停？
├── 论 下一问没有产生 50%            ⟷ 对立 ⟷  论 单步成本高 50%
│   └── 规 卡住时先写下下一问 60%
└── 论 第一反应停止 60% …
```

| 字段 | 类型 | 适用 | 说明 |
|---|---|---|---|
| `type` | 问 / 论 / 规 | 全部 | v1 的 问题→问、论断→论、规则→规、概念 / 案例→论（原类型记在 `legacy_type`） |
| `under` | 节点 id | 全部 | 挂载父节点。规则（`MOUNT_RULES`）：问→问；论→问/论；规→论/问；不能成环 |
| `confidence` | 0–100 | 论、规 | 把握 %，问 为 null |
| `keywords` | 字符串数组 | 全部 | 激活词，3–5 个，用于检索和给 AI 定位知识 |
| `pillars` | 字符串数组 | 问 | 破局支柱：决定成败的 2–3 个客观约束 |
| `blindspot` | 字符串 | 论 | 反方盲区：这条论断什么时候会失效 |
| `sentinels` | `[{when, delta}]` | 论 | 验证哨：看到 `when` 就把把握加减 `delta`（-50~+50）。v1 的 `verify` 迁移成一条 delta=0 的哨 |
| `triggers` | 字符串数组 | 规 | 触发场景：什么念头 / 情境下立刻调用 |
| `cost` | 字符串 | 规 | 破戒代价：不执行的最坏连锁反应 |
| `paused` | 布尔 | 规 | 被暂停的规（上游论被证伪时） |
| `checks` | `[{date, kind, source, …}]` | 全部 | 反馈记录。`kind`：回填 / 调整 / 有效 / 卡壳；`source`：温故 / 录入 / 一手 |
| `links` | `[{type, to, why}]` | 全部 | 横向关系，仍是 7 种，挂载以外的关系才用 |
| `status`、`verify`、`parent` | | | v1 字段，保留读写；`parent`（层级）在 T01 后不再用于界面 |

Store 提供的链条方法：

- `children(id)`、`ancestors(id)`、`descendants(id)`
- `chainRoots(system)`：根上的问
- `unmounted(system)`：没挂载的论 / 规
- `canMount(child, parent)`、`mount(child, parent)`

删除节点时，它的下级上移一层；合并节点时，挂载会改指向保留的那个。

**体系（system）保留**，作为顶层的大领域切换，对应文件夹第一层。**层级（level）废除**，由链条代替。

## 3. 四个模块怎么变

### 录入 → 碰撞与增量引擎（T03，逻辑已在 `www/js/collide.js`）

1. `libraryDigest(store, 材料)` 生成节点库摘要。
   - 库不超过 40 个节点时全发。
   - 超过时按激活词 / 触发场景 / 标题相关度挑出相关节点，再带上它们的上级链和直接下级。
2. 便宜模型按 `PROMPT_COLLIDE` 输出 JSON，按以下优先级处理：
   1. `adjust`：调整已有论 / 规的把握度，附原因、命中的哨、建议暂停的规。
   2. 补链：新节点挂到已有节点下面。
   3. 新建：每个新节点自带槽位草稿。
3. `normalizeCollide(raw, store)` 负责清洗输出：
   - 校验 id、挂载规则、数值范围；
   - 以库里的真实把握为 `from`；
   - 标出疑似重复 `dupe_of`。

### 候选 → 参谋批阅台（T04）

- **调整提案卡**：「【论】总控系统交互频次不足 85% → 65%」，附原因和命中的哨。
  - 滑块微调到值；可勾选暂停它下面的规。
  - 按钮：确认 / 驳回。
- **新节点卡**：「建议挂在【论：总控系统交互频次不足 85%】下方」，下面列出槽位草稿。
  - 按钮：确认入库 / 修改 / 驳回。右滑确认，左滑驳回。
- **写入时**：
  - 调整提案改 `confidence`，并在 `checks` 记一条 `{kind: 调整, source: 录入, from, to, result: 原因}`；
  - 被勾选的规设为 `paused`。

### 体检 → 逻辑与实操双轨巡检（T05）

| 规则 | 级别 | 判定 |
|---|---|---|
| 议而不决 | 高 | 把握 ≥ 75 的论，或任何问，其所有后代里没有一条未暂停的规 |
| 师出无名 | 高 | 规没有挂载（`under` 为空或指向不存在的节点） |
| 地基倒挂 | 高 | 规的把握 > 85，但它最近的上级论把握 < 70 |
| 盲信无哨 | 中 | 把握 < 90 的论，没有任何 delta ≠ 0 的验证哨 |
| 脱离实操 | 中 | 把握 ≥ 80、未暂停、创建超过 7 天的规，最近 7 天没有任何 有效 / 卡壳 / 回填 反馈 |
| 断链 | 高 | `under` 或 `links` 指向不存在的节点 |
| 可能重复 / 激活词不足 | 低 | 沿用 v0.1.4 的规则，以及「AI 补全激活词」「合并」按钮 |

### 温故 → 激活词实战演练（T06）

- 队列先放未暂停的规，按到期日排序；再放带哨的论。
- **规卡**：
  - 正面：「演练：〈随机一个触发场景〉——此时你的【论】和【规】是什么？」
  - 背面：上级论（标题 + 结论 + 把握）、规的动作、破戒代价。
  - 按钮：实操有效 / 实操卡壳 / 只是回想。
- **论卡**：保持现在的「记得 / 模糊 / 忘了」，背面显示验证哨。
- **反馈传播**：常量集中放在 `features.js` 的 `FEEDBACK`，计算写成纯函数 `applyFeedback(store, ruleId, kind)` 并配单元测试。
  - 有效：规 +3，最近的上级论 +2，上限 95。
  - 卡壳：规 −5，最近的上级论 −3，下限 5。
  - 每次都记一条 `checks`。7 天内卡壳 ≥ 2 次的规，进体检的「脱离实操」。

### 提问 / 延展 / 类比（T07）

- 打包路径改用挂载链（问 › 论 › 规），节点文本带上槽位。
- 邻居加入上级和直接下级。
- 「建议新增」改成 `类型｜标题｜一句结论｜激活词`，类型取 问 / 论 / 规，转候选时默认挂在当前节点下。

## 5. 我替你做的决定（可以推翻）

1. **体系保留、层级废除**：体系作为顶层领域切换，链条代替层级。旧文件里的 `parent` 字段保留，但不再影响界面和文件位置（T01 改为扁平存放）。
2. **概念 / 案例并入「论」**：原类型记在 `legacy_type`，不丢信息。
3. **`verify` 迁移成一条 delta=0 的验证哨**：体检会提示「验证哨没有加减分」，让你补上分值。
4. **反馈幅度**：有效 +3/+2，卡壳 −5/−3。偏保守，避免一次反馈就大起大落。
5. **下载链接只由集成分支发布**：`main` 或 `ccr-153bfa69-lm85up`。Codex 的任务分支只跑测试和打包，不会覆盖你手机上下载的版本。
