# T07 提问 / 延展 / 类比：适配 V2

**依赖**：T02　**改动范围**：`www/js/pack.js`（`buildPack`）、`www/js/llm.js`（`PROMPT_THINK`、`parseAnswer`、`parseSuggestion`）、`www/js/app.js`（`viewAsk`、`answerCard`、`suggestionsToCands`）、`dev/server.mjs`（`ANSWER`）、`dev/unit/`、`dev/e2e.mjs`

## 要做的

1. **打包**（`buildPack`）
   - 「路径」改为挂载链：`问 › 论 › 规`，取 `store.ancestors` 反序再加上节点自己。超预算时压缩为「… › 上级 › 本节点」，规则不变。
   - 「节点」文本按类型带上槽位：
     - 问：`破局支柱：a；b`
     - 论：`把握 60%｜反方盲区：…｜验证哨：+10 …；-15 …`
     - 规：`把握 60%｜触发：…｜破戒代价：…`
   - 新增两类邻居，排在「对立」之后：上级（`[上级·论] 标题：结论`）和直接下级（`[下级·规] 标题：结论`）。优先级：上级 = 1.5，下级规 = 2.5，加进 `PRIORITY` 排序。
   - 激活词合集也包括规的触发场景，去重。
2. **提示词 B**（`PROMPT_THINK`）
   - 「只输出」列表不变。
   - 末尾的「建议新增」格式改为：
     ```
     类型｜标题｜一句结论｜3 个激活词（顿号分隔）
     ```
     类型只能是 问 / 论 / 规，新节点默认挂在当前节点下。若不该挂在当前节点下，在类型前加横向关系，例如 `对立·论｜…`，关系取 7 种之一。
   - 另起一行要求：「建议新增的论请附一条验证哨（看到什么就加分 / 扣分），规请附一个触发场景」。
3. **解析**（`parseSuggestion`）
   - 能识别 `论｜…`、`规｜…`、`对立·论｜…`，以及旧格式 `导致｜标题｜结论｜激活词`。旧格式当作「论」，并保留关系。
   - 返回 `{type, rel, title, claim, keywords}`。
4. **转候选**（`suggestionsToCands`）
   - `type` 用解析结果。
   - `under`：没有 `rel` 且 `store.canMount` 允许时，挂在当前节点下；有 `rel` 时不挂载，生成一条对应的 link。
5. 模拟回答（`dev/server.mjs` 的 `ANSWER`）改用新格式，至少包含一条 `规｜…` 和一条 `对立·论｜…`。

## 验收

- `npm run test:unit`：新建 `dev/unit/pack.test.mjs`。
  - 打包路径；
  - 槽位出现在节点文本里；
  - 上下级邻居；
  - 1500 预算下节点本身不被砍；
  - `parseSuggestion` 新旧两种格式。
- `npm run test:e2e`：
  - 现有提问流程的检查全部通过，依赖旧格式的断言相应更新。
  - 新增 `check`：打包全文里有「【路径】为什么想到一半就停？ › 下一问没有产生」。
  - 新增 `check`：有「验证哨：」。
  - 「转为候选卡片」后，`规` 类型的建议挂在当前节点下。
